# 落笔前图状态：无向边、借力与困死的统一判定

## 适用范围

适用于纸笔足球、点线围地、封路棋、轨迹不能重复的迷宫，以及任何“玩家提交一条边，规则取决于落点此前是否被访问”的本地 HTML 游戏。

## 1. 先把轨迹当成图，不要先当成动画

这类玩法的最小权威状态是节点、已经使用的边和当前节点。线条颜色、粗细、虚线、球的位移和合法目标光圈都只是图状态的投影。

边若允许两个方向行走，就应使用无方向 key。把两个端点先按稳定坐标排序，再串成 key：

```text
canonicalEdge(a, b) = sort(a, b).join("|")
```

这样 `a→b` 与 `b→a` 天然命中同一个集合项，重复线和反向重走只需要一次查找。不要同时保存两条有向边，否则每个合法性、测试和导入路径都要记得检查两个方向。

## 2. “是否旧点”必须读取落笔前快照

假设玩家从 `u` 走到 `v`。正确顺序是：

```text
校验 u—v 未使用
→ 在旧 edges 上计算 v 是否已访问/是否边界
→ 追加 u—v
→ 结算进球、借力或换手
```

如果先追加边，再问 `v` 是否已有边相连，那么每个新点都会因为刚收到的 `u—v` 被判成旧点，所有普通移动都会错误地连续行动。

这个规律不限于纸上足球。任何“第一次进入”和“再次进入”语义都应明确写成 `wasVisitedBeforeMove`、`previousOccupancy` 或等价的前态查询，避免同一步写入污染判定条件。

## 3. 边界拓扑不必伪装成历史轨迹

传统纸上足球把边界视为可反弹墙，但边界并不是玩家画过的线。生产状态只保存真实移动边；合法移动生成器负责排除沿外边线行走，落点判定单独把场内边界节点视为可借力。

好处是：

- 玩家轨迹可以直接按 owner 渲染，不混入无主墙线；
- 重赛清空 edges 就足够，不需要重建固定边；
- 测试能分别证明“边界规则”和“重复边规则”；
- 状态更接近用户实际做过的事。

固定球场仍应由常量和纯函数唯一生成，不能让 SVG 成为第二份规则来源。

## 4. 困死只在行动权仍属于当前玩家时检查

一个普通新点 `v` 是通过此前未使用的 `u—v` 首次进入的。除边界拓扑外，它不可能在换手瞬间凭空成为封闭旧点。因此本规则中的困死 Gate 应写成：

```text
if goal: 结算进球
else if bounced:
  if legalMoves(v) is empty: 当前行动者自困
  else: 当前行动者继续
else: 换手
```

不要把“移动完成后，下一位玩家有没有路”当成通用尾处理。那会把不同阶段的行动权混在一起，也会掩盖规则上不可能出现的状态。

## 5. 输入只是适配器，reducer 才是裁判

SVG 落点点击、SVG Enter / Space、QWEADZXC 和方向按钮都先解析成同一个目标坐标，再调用同一个 `move(state, target)`。界面不能自己决定是否换手、是否继续或谁赢。

验证时也应跨输入证明一致性：

- 鼠标点一次新点，观察换手；
- SVG 用 Enter / Space 各推进一次；
- 方向键走到边界，观察同方继续；
- 触控方向盘完成另一步；
- 最终胜负只从 reducer 返回的 `phase/winner/winReason` 渲染。

这样规则测试可以在 Node 中穷举边界，浏览器测试只验证输入映射、焦点、文案和视觉结果。

## 6. 可访问 SVG 不是一张原子图片

纯展示 SVG 可以使用 `role="img"`。一旦 SVG 内部生成可聚焦按钮，外层就应使用 `group` 或更符合控件语义的复合角色，并给每个交互节点独立的名称、角色和键盘入口。否则 DOM 看似有 `tabindex`，accessibility tree 仍可能把后代全部折叠。

验收不能只检查选择器数量；至少同时检查 accessibility snapshot、真实 Tab/Enter/Space 和焦点恢复。

## 7. 最小验证矩阵

一款此类图游戏至少应证明：

- edge key 对两个方向完全一致；
- 反向重复、越界和固定墙边被拒绝；
- 新点换手，旧点/边界继续；
- 进球优先于借力，乌龙能自然映射到对方；
- 困死路径确实从借力点发生；
- 合法状态的非法动作保持原引用，公开状态递归冻结；
- 同一确定性键序列在 Node 测试和真实浏览器得到同一胜者；
- `file://` 下规则脚本、SVG 和本地资产都能运行。
