# 私人照片预处理与语义拼块

## 1. 原图、候选图和活动图是三个不同阶段

本地选图不应直接把 `File` 变成长期活动 URL。更稳的流程是：校验 MIME/大小 → 为候选创建临时 URL → 解码并校验像素尺寸 → Canvas 生成派生图 → 原子替换活动派生 URL。任一步失败都只清理候选，保留旧体验。

递增 token 只解决“哪个异步结果还能提交”，不能自动释放已经过期的资源。新操作开始时应立刻撤销旧候选 URL；候选完成、用户清除和页面退出再走同一个幂等清理路径。

## 2. Canvas 派生图同时统一尺寸与减少元数据暴露

交换拼图需要统一方形画布。固定中心裁切比加入完整裁切编辑器更符合最小实现：源区域取短边正方形，输出边长不超过 1200px，再转成质量 0.9 的 JPEG。这个过程通常不会继承原文件 EXIF/GPS，但不能把它宣传成恶意文件扫描或取证级擦除。

画布先填充页面底色，再绘制原图，可以让带透明通道的 PNG/WebP 转 JPEG 时得到确定背景，而不是依赖浏览器默认黑色。

## 3. 图片裁片不等于交互控件

CSS `background-size: 300% 300%` 和 `background-position: 0% / 50% / 100%` 足以显示九宫格裁片；但每个位置仍应是固定的原生 `<button>`。交换时只更新按钮的背景坐标、`aria-label` 和 `aria-pressed`，不要重建节点。

固定节点让鼠标、触摸、Tab、Enter 和 Space 共用浏览器原生行为，也保留当前焦点。可访问名称同时描述“这块来自原图哪一行哪一列”和“现在位于哪一行哪一列”，屏幕阅读器用户才能理解交换后的棋盘。

## 4. 任意两块交换避免不可解排列

带空位的传统滑块拼图存在排列奇偶性约束；直接随机打乱可能生成不可解局面。任意两块交换没有这个限制，任何排列都能通过有限次交换还原。

洗牌使用可注入随机值的 Fisher–Yates，测试可以得到确定结果。如果洗牌偶然仍是完成态，循环移动一格即可保证开局确实被打乱，不必引入额外重试循环。
