# 规则先于动画：固定步长、连续碰撞与 reduced motion

适用范围：抛体、赛车、弹球、航行、拖拽惯性等“画面持续移动，但结果必须稳定”的本地网页互动。

## 核心结论

动画帧只能告诉界面“什么时候重画”，不能定义“规则推进了多少”。可靠实现要把三件事分开：

1. 纯规则：状态与固定 `dt` 输入，返回下一份状态；
2. 时间消费：`requestAnimationFrame(timestamp)` 把真实经过时间装入 accumulator；
3. 画面投影：DOM / Canvas / SVG 只读取权威状态，不自行决定命中或输赢。

如果结果依赖“每帧移动 5px”，60Hz、120Hz、后台恢复和测试环境会得到不同答案；如果画面层自行判断碰撞，reduced motion 又可能绕过核心玩法。

## 固定步长仍不够

固定步长能消除刷新率差异，却不能自动保证窄目标不被高速物体跨过。假设上一点在目标左侧、下一点已经在右侧，只检查终点是否位于矩形内仍会漏判。

因此离散规则应检查“上一位置 → 下一位置”的整条线段与目标 AABB 是否相交。二维 slab 方法分别求 x/y 两轴的进入、离开比例，交集非空才是命中。结算顺序还应明确：

```text
连续命中
→ 触地/越界
→ 其他失败分类
→ 继续飞行
```

命中放在边界失败之前，避免同一步既穿过目标又越界时被错误判负。

## accumulator 的职责

典型循环：

```js
elapsed = clamp((timestamp - previous) / 1000, 0, 0.25);
accumulator = Math.min(0.25, accumulator + elapsed);

while (accumulator >= FIXED_STEP && state.phase === "flying") {
  state = step(state);
  accumulator -= FIXED_STEP;
}

render(state);
```

上限不是物理参数，而是后台恢复保护：标签页挂起很久后，不应在一个回调内追赶数分钟规则。终局还需要单调 token 或 revision，使旧回调发现自己过期后退出，避免重开后的旧动画修改新局。

## reduced motion 应复用答案

减少动态效果时，跳过的是跨屏动画，不是状态机。最简单可靠的降级是：在同一用户动作里反复调用纯 `step()` 直到终局，然后只渲染一次。

这样普通模式和 reduced motion 的差异只有观看时长：

- 相同初始状态；
- 相同固定步长；
- 相同碰撞与边界顺序；
- 相同终局与后续 Gate。

不要为 reduced motion 另写一套“直接判断角度范围”的捷径；第二份规则迟早会与生产规则漂移。

## 阶段内容与运动结果解耦

动作成功不等于内容必须立即出现。像“投递 → 打开信件”这类惊喜，应把物理终局 `arrived` 与内容终局 `revealed` 分开。`arrived` 只创建可打开的密封对象，用户主动操作后才创建正文 DOM；重开则销毁正文节点。

这样规则测试可以只证明“能否送达”，隐私测试可以单独证明“何时存在正文”，视觉动画不会意外成为内容 Gate。

## 验证清单

- 用同一输入分别逐步推进和一次演算，深比较终局；
- 覆盖稳定命中、短、低、高与恰好擦边；
- 人工构造一步跨过目标的线段，证明连续碰撞生效；
- 在 60Hz/高刷新率模拟、后台大间隔和 reduced motion 下比较结果；
- 终局继续 `step()` 应返回同一引用；
- 重开后触发旧动画回调，状态不应变化；
- 内容型惊喜在成功但未打开时，正文节点数量仍为 0。
