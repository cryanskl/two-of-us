# 热座风险玩法：随机公平、隐藏信息与视觉反馈要分层

单设备 push-your-luck 玩法看似只需要生成一个随机爆点，真正需要守住的却有三条边界：随机映射不能悄悄有偏，交接页面不能泄露私有阈值，动画也不能反过来成为规则真相。

## 有限整数映射不是默认等概率

`crypto.getRandomValues()` 给出均匀的 32 位无符号整数，但直接 `% 5` 不会严格均匀，因为 `2^32` 不能被 5 整除。这里余数为 1，所以最大值 `2^32 - 1` 会让其中一个结果多一个原像。

通用做法是先计算最大的可整除接受区间，只接受其中的随机值，再取模；被拒绝的尾部值重新抽取。气球胆量局的目标只有五个，恰好只需拒绝唯一最大值。测试必须覆盖接受区间首尾、拒绝边界与非法输入，不能用“概率差很小”替代契约。

## 私有随机值不应进入渲染模型

爆点属于当前回合的权威规则状态，但不是公开界面状态。浏览器层可以把整个状态对象留在 JavaScript 闭包中，却只向 DOM 派生：

- 当前玩家和轮次；
- 已打泵数；
- 当前待收分与总分；
- 阶段文案和按钮可用性。

不要把爆点写入 `data-*`、CSS 变量、隐藏文本、URL、日志或可访问名称。交接时更要检查 DOM 快照，而不只检查截图，因为视觉遮住不代表辅助技术或开发者工具读不到。

## 动画只消费公开状态

气球尺寸、表针角度和爆裂图都只由公开泵数与阶段派生。它们不能读取爆点来“预热”抖动、提前变色或改变增长速度，否则细心玩家能从动画猜出阈值。

同理，CSS 转场和生成资产只是表现层：规则测试不应读取元素尺寸来判定爆球，浏览器刷新或 `prefers-reduced-motion` 也不能改变结果。

## 固定机会比提前终局更容易解释公平性

随机独立回合不能保证某一局运气相同，但可以保证双方拥有相同次数、相同分布、对称先后手。采用固定八回合并把顺序排为 `甲乙 / 乙甲 / 甲乙 / 乙甲`，比“先到目标分立即获胜”更容易证明机会对称。

随机公平的表述也要克制：可以承诺分布和机会对称，不能把独立随机样本描述成竞技级绝对公平。

## 键盘长按是另一种隐性概率偏置

风险按钮若响应浏览器的 `keydown.repeat`，长按一次可能在几十毫秒内穿过多个泵数，玩家失去逐次止盈的机会。每个物理或触控动作只应推进一次；重复键事件要忽略，按钮状态在爆球或收分后立即锁定。

验证应分三层：纯逻辑穷举阶段和边界，静态契约扫描 DOM/网络/存储泄漏，真实浏览器跑安全收分、爆球、交接、最终结算和多个响应式视口。
