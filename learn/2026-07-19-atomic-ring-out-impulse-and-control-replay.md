# 双体互推游戏：原子出圈、冲量分层与控制事件重放

适用于同屏相扑、推箱出界、圆台对撞等“双方在同一固定步内都可能失败”的轻量物理玩法。

## 关键结论

### 1. 先完成双方同一步，再统一判出圈

不要按玩家数组顺序边更新边结算胜负。一个权威 tick 应依次完成：读取双方输入、更新两体速度与位置、处理碰撞、计算当 tick 场地半径、分别得到 `outside0/outside1`，最后一次性决定玩家 0 出圈、玩家 1 出圈或双出圈。

这样同 tick 双亡是明确规则，不会因为“先检查谁”产生先手偏置。交换输入数组后按 seat 归一、镜像初态与不同刷新率分组都应得到同一结果。

### 2. 穿透纠正不能偷偷制造速度

轻量等质量圆体碰撞至少要把两个概念分开：位置纠正只解除重叠，法向冲量才改变速度。若直接用纠正位移反推速度，静止重叠会凭空爆开，碰撞次数也会放大能量。

稳健顺序是：求稳定法向；按各移动一半的方式纠正穿透；仅当相对法向速度正在接近时施加等大反向冲量；最后统一限速与阻尼。完全重叠时必须使用可重放的稳定 fallback 法线，不能调用随机数。

### 3. 系统取消不是玩家松手

蓄力游戏里，`pointerup` 表示玩家主动松手并应触发冲刺；`pointercancel`、`lostpointercapture`、blur、hidden 和长帧则表示输入序列失去可信连续性。把它们走同一 release 路径，会把系统中止误解释为一次攻击。

正确做法是：主动松手走 release；系统取消先清理物理 inputId，再派发 PAUSE。PAUSE 把 `chargeTicks` 和 `wasCharging` 归零，但可按产品规则保留位置、速度与 cooldown，恢复前重新倒数。

### 4. 重放日志必须包含控制平面事件

只记录每 tick 的方向与 charging 不足以重放暂停。因为暂停会在没有物理 STEP 的时刻清空蓄力状态，若日志遗漏它，恢复后的第一步会把“原本被取消的蓄力”重放成冲刺。

可把轮日志定义为：

```text
{ type: "step", inputs: [input0, input1] }
{ type: "cancel-charge", atTick }
```

`atTick` 必须等于此前 step 事件数；相同 tick 的连续 cancel 去重，未来 tick、错位和重复外部日志严格拒绝。这样暂停是权威历史的一部分，同时不需要伪造一个物理 tick。

## 反例

- 更新玩家 0 后立即判负，再更新玩家 1：双出圈会按数组顺序变成单方失败；
- 对每个碰撞修正 pass 都增加速度：静止接触体会产生能量；
- `pointercancel → releaseCharge`：系统取消会触发一次 dash；
- 暂停只改内存、不记日志：当前状态看似正确，但 JSON 重放会分叉；
- 用 `requestAnimationFrame` 次数作为物理时间：后台限频和高刷屏会改变结果。

## 验证方法

1. 为玩家 0 出圈、玩家 1 出圈和同 tick 双出圈各保存一段 golden round log；
2. 交换调用者传入的 body 顺序，输出仍按 seat 一致；
3. 将同一 tick 日志按 30/60/120/144Hz 任意分组，重放结果深相等；
4. 在蓄力中插入 PAUSE/RESUME，JSON 往返后 `replaySession` 与在线 state 深相等；
5. 真实浏览器另测 pointer capture 生命周期、失焦、隐藏和长帧；逻辑单测不能冒充真实触屏证据。
