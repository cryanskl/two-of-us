# 热座记忆玩法：播放生命周期与 DOM 隐私要分层

单设备热座玩法的“别偷看”不是密码学安全，而是一套需要被实现和验证的交接礼仪。只把答案在 CSS 中设为透明，或者只在视觉上盖一层遮罩，都可能让下一位从 DOM、辅助技术或旧动画状态中读到上一轮内容。

## 规则状态不保存播放过程

权威状态只保留阶段、序列、当前玩家、输入进度和共享机会。当前亮起哪一拍、timeout ID、AudioContext 和动画类属于浏览器编排，不应进入 reducer。这样 Node 测试可以用显式 Gate 证明：

- handoff 不能输入；
- playback 完成前不能复现；
- 失误只扣一次并锁到明确重听；
- 只有完整复现才能追加并换棒。

浏览器层用单一计划器持有全部 timeout。每次播放前先取消旧计划；失焦、页面隐藏、重开和卸载也走同一取消函数。恢复页面时不要自动补播剩余 timeout，否则玩家可能错过隐藏期间的拍子，状态却已经进入输入阶段。

## 交接页要检查派生 DOM，而不只是截图

交接阶段可以显示已知长度，但不应把答案编码到颜色类、文本、`aria-label` 或隐藏节点中。节拍接力在 handoff 中把已占用纸带孔保持为中性空类，只保留 `4 拍序列，目标 10 拍` 这类公开信息；`coral` / `sage` 只在实际播放脉冲和完成页出现。

验收时同时检查：

- 阶段可见文案是否只说交接动作；
- 答案类名、文本或可访问名称是否残留；
- 核心输入是否 disabled；
- 上一轮动画类与输入进度是否清空。

## 音频必须是渐进增强

Web Audio 只能在用户手势之后创建或恢复。声音关闭、AudioContext 创建失败或浏览器不支持音频时，视觉脉冲必须仍携带全部规则信息；否则作品表面上“本地直开”，实际却把可玩性绑定到浏览器音频策略。

每拍临时创建 oscillator 与 gain，明确 stop 并在 ended 后断开；不要为十拍短局保留永久音频图。静音只改变声音输出，不改变状态机、播放节奏或视觉反馈。

## 两层验证比单一端到端更可靠

纯逻辑测试负责完整状态空间、畸形输入和重复事件；真实浏览器负责计时、键盘/触控、焦点、响应式、控制台与 DOM 派生信息。浏览器自动化若无法可靠制造真实失焦，应明确保留为人工 Gate，而不是用合成事件冒充通过。

这套分层适用于热座画猜、记忆序列、秘密答题、轮流看提示和同机密码盒等作品。
