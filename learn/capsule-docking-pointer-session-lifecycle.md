# Pointer 会话不能只靠 `pointerId`

日期：2026-07-25  
来源：`capsule-docking` 浏览器验收

## 现象

在同一个页面里连续长按两个不同控制按钮时，浏览器可能很快复用同一个
`pointerId`。前一按钮释放后产生的 `lostpointercapture` 还可能晚于后一按钮的
`pointerdown` 到达。如果应用只用 `pointerId` 找当前输入，旧事件就会错误释放新
按钮，表现为第二个控制偶发失效。

## 可复用的防护

每个输入会话至少同时记录：

- 当前规则运行的 `inputEpoch`；
- 输入来源（键盘或 pointer）；
- `pointerId`；
- 实际捕获 pointer 的按钮；
- 本次 `pointerdown.timeStamp`。

释放时同时核对 epoch、目标按钮和事件时间；旧事件时间早于当前会话开始时间时
直接忽略。暂停、失败、页面隐藏、失焦和离开页面统一提升 epoch，并一次性清空
全部物理输入和规则层 held 状态。

## 为什么不是只判断按钮

只判断 `event.currentTarget` 能拦住跨按钮误释放，却拦不住同一按钮快速重按后的旧
事件。只判断 `pointerId` 更不够，因为浏览器允许复用 ID。目标、时间和 epoch 三层
组合，分别隔离跨控件、同控件跨会话和跨规则阶段的晚到事件。

## 测试建议

静态契约应固定 session 字段与清理边界；真实浏览器再连续执行“长按控制 A →
立刻长按控制 B”，确认第二个控制确实改变公开状态、四键最终全部松开。若自动化
环境能派发多点触控，再增加两个不同 pointer 同时按住与乱序释放的回归。
