# 约束网络合作题：守恒、穷举、连续窗与平台事件边界

适用于供电路由、管线分配、通信带宽、双人调度等“有限开关组合 + 多条容量约束 + 连续安全时间”的本地合作玩法。

## 1. 先把题面写成守恒系统

不要从 UI 开关反推规则。先定义每个源、母线、联络线和负载的整数流量，并把每条边只计一次：

```text
源输出 = 本地负载 + 向外联络
母线占用 = 本地负载 + 经过该母线送出的联络量
总供给 = 总负载 + 被明确建模的损耗
```

如果联络线允许双向，方向必须进入规范状态，不能同时用“左送右”和“右送左”两个布尔量；否则非法状态会凭空制造环流。所有容量、最低供给和互斥条件都用整数表达，视图层只展示 evaluator 的结果。

## 2. 小状态空间应穷举，不靠手感调关

本作每班只有 324 个原始组合，因此关卡发布前直接枚举全部组合，并同时检查：

- 状态是否合法、有没有重复表示；
- 安全解数量是否恰为一；
- 解是否真正用到两席权限；
- 每个错误组合是否得到稳定、有序的故障码；
- 修改任一关键开关是否会离开安全解。

唯一解不是“测试过目标答案”就能证明的性质。测试必须统计完整状态空间的安全结果数，并把每班期望计数固定为 oracle。若以后增加开关导致空间变大，可先做约束剪枝，但不要把随机抽样冒充唯一性证明。

## 3. evaluator 与时间推进要分开

把瞬时安全判定写成纯函数：同一规范状态永远返回同一组容量、缺口和故障码。连续稳定三秒则属于 reducer 的整数状态：

```text
若当前安全：stableTicks += 1
若当前不安全：stableTicks = 0
达到 90 tick：原子进入完成态
```

浏览器层用 `requestAnimationFrame` accumulator 消费固定步；超长帧、页面隐藏、失焦和显式暂停必须清空时间基准，不允许恢复时一次性补算后台时间。这样“保持三秒”证明的是连续可见操作窗口，而不是墙钟经过了三秒。

## 4. 平局规则要成为决策表

当两个母线、两个来源或两类故障数值相等时，不能把对象遍历顺序当作裁决。把平局写成公开的决策表，例如：

| 条件 | 裁决 |
| --- | --- |
| 左侧余量更大 | 左向右供给 |
| 右侧余量更大 | 右向左供给 |
| 余量相同且关键负载在左 | 右向左供给 |
| 余量相同且关键负载在右 | 左向右供给 |

表本身应进入规格、测试和界面说明。这样规则改动是显式产品决策，不会藏在某个 `if` 的先后顺序里。

## 5. 平台事件与业务 action 使用不同读取边界

严格 reducer 只接受自有、可枚举、类型正确的普通对象字段，有助于拒绝 getter、原型污染和意外 DOM 对象。但原生 `KeyboardEvent.code` 通常是原型 getter；若复用同一套 `hasOwnProperty` 读取，Node 中伪造的普通对象测试会通过，真实浏览器快捷键却全部失效。

推荐分为两层：

- `safeRead(action, key)`：只读业务 action 的自有字段，失败即拒绝；
- `safeEventRead(event, key)`：只用于受信平台事件，允许原型 getter，但捕获 getter 异常并校验最终类型；
- `classifyKey(state, event)` 只把平台事件转换成枚举 action；reducer 永远不直接接收 DOM 事件。

对应缺陷与修复见 [`bugs/2026-07-20-moon-power-native-keyboard-event.md`](../bugs/2026-07-20-moon-power-native-keyboard-event.md)。

## 6. 焦点屏蔽应针对文本输入，不针对所有表单控件

全局快捷键常会在“焦点位于 input”时被整体屏蔽，但 radio、checkbox、button 本身也是游戏控制。点击一个 radio 后继续按另一席快捷键，是同屏合作的正常跨输入路径；把所有 `input` 都视为文本编辑区会让键盘席突然失灵。

只屏蔽会实际接收文本的控件：`input` 的文本型 `type`、`textarea`、`select` 和 `contenteditable`。radio/checkbox/button 仍可配合全局快捷键，同时保持原生焦点和空格键行为。对应实机缺陷见 [`bugs/2026-07-20-moon-power-radio-focus-shortcuts.md`](../bugs/2026-07-20-moon-power-radio-focus-shortcuts.md)。

## 7. 浏览器验收负责发现“组合失败”

纯逻辑测试能证明 324 状态、唯一解和 90 tick；静态扫描能证明无网络、无存储和经典脚本顺序。只有真实浏览器能同时发现：

- radio 焦点与全局快捷键冲突；
- 暂停按钮视觉上够大但计算样式不足 48px；
- 桌面首屏差几像素溢出，破坏“同屏控制台”构图；
- 三班混合鼠标/键盘输入能否真的走到完成页。

因此验收顺序应是：穷举规则 → 全仓静态边界 → 浏览器生产动作重放 → 计算样式与响应式几何 → 控制台和本地资源检查。每层证明不同事实，不能互相代替。
