# 可重放点线游戏：事件时间线、规范边投影与并行快照

## 适用范围

适用于 Dots and Boxes、纸上足球、连线占地等“多人轮流选择共享物理边”的本地游戏，也适用于多人或多进程同时修改同一 worktree 时的规格协作。

## 一条共享边只能有一个身份

几何上同一条边可能被两个格子从不同方向引用。状态层必须先把它规范成唯一 ID，例如 `H:row:column` 与 `V:row:column`。格子只保存四条规范边的引用，不再发明“上边”和相邻格“下边”两份记录。

细线的视觉宽度不等于交互宽度。运行页可以画 3px 墨线，但按钮命中区应保持至少 44×44px；规范 ID 放在这个按钮上，鼠标、触控、键盘和测试便会走同一个入口。

## 当前集合与事件时间线是两种不同模型

如果只需要知道“现在有哪些边”，一个排序后的规范边集合足够。如果还需要证明谁在第几步落笔、完整重放、审计错误玩家或生成回放，就应让时间顺序事件成为唯一事实：

```js
moves = [
  { edgeId: "H:0:0", player: 0 },
  { edgeId: "V:0:0", player: 1 },
];
```

界面需要的 `edges` 应从 `moves` 派生并按规范顺序排序。不要同时把 `moves` 和可编辑 `edges` 存进权威状态，否则二者迟早会漂移。

## 重放必须验证派生字段，而不只是重新算分

完整重放至少要拒绝：

- 同一条边重复出现；
- 事件里的玩家不等于当时合法落笔者；
- 终局后继续追加事件；
- 调用方伪造分数、格子归属、当前玩家、阶段、最后一步或步数；
- 非规范、越界或类型错误的边 ID。

生产 reducer 与 `replayMoves()` 应共享同一套闭格、续走和换手规则。测试既要覆盖正常单格/双格，也要逐项篡改每个派生字段，证明重放不是“宽松恢复”。

## 并行 worktree 中，摘要不是权威快照

当另一个执行流可能提交规格或实现时，压缩后的对话摘要只能当路线图，不能当当前事实。每次写入或提交前重新读取：

1. `git log --oneline`，确认是否出现新规格或实现提交；
2. HEAD 中的规格与测试，确认当前状态契约；
3. `git status --short`，区分自己的未提交文件与并行改动；
4. `git diff --cached`，确认暂存区没有在竞态中指向旧 blob。

本次反例是主线程沿用旧摘要，把已经升级为事件时间线的实现改回边集合。修复不是在旧模型上继续补丁，而是以最新规格提交、当前测试和 `git log` 重新建立权威快照，再恢复可重放状态。

## 验证清单

- 物理边数量和规范 ID 数量完全一致；
- 普通落边换手，闭一格和闭两格都由得分者续走；
- `moves.length === moveNumber`，视图边集合只由事件投影；
- 终局边数、总格数和双方分数形成闭合不变量；
- 44px 命中区不改变薄线视觉；
- 定向测试、全库测试、真实浏览器轨迹和窄屏都通过；
- 并行环境中每次提交前重新确认 branch、toplevel、HEAD 与暂存区。
