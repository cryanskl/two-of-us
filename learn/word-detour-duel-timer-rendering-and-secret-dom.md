# 绕词对决：计时增量更新与秘密 DOM 的分层渲染

## 背景

这个项目同时有两个看似冲突的要求：

- 状态机每约 200ms 接收一次 `TICK`，`revision` 也会随有效 tick 更新；
- 离开合法秘密阶段时，目标词与四个禁词必须从 DOM 中真正删除，不能只靠 CSS 隐藏。

如果每次 tick 都对整个舞台执行一次重绘，按钮节点和焦点会不断被替换，双击、
键盘操作与辅助技术体验都会变得不稳定。反过来，如果为了保留焦点而长期复用
秘密节点，又容易在暂停、交接或回合结束时留下泄露面。

## 采用的分层方式

1. 阶段、当前卡或主要操作发生变化时，用 `stage.replaceChildren()` 整体替换舞台。
2. 仅当同一张题卡仍处于 `describing` 时，tick 只增量更新公共计时文本和
   30 / 10 / 5 / 0 秒播报，不重建题卡与操作按钮。
3. timer driver 捕获启动时的 clock token；阶段或 token 改变后立即清理旧 interval，
   reducer 再用 token 和 revision 拒绝陈旧回调。
4. blur、hidden、pagehide 与手动暂停都走同一个精确 `INTERRUPT` action。第一次
   成功迁移后舞台立刻重绘成中性页，连续到达的后续生命周期事件自然 no-op。
5. 结果按钮同时使用一次性 `consumed` 门闩和 reducer 的 phase/revision 校验；
   浏览器真实双击验证只从第 1 张推进到第 2 张。

## 验证结果

- 30 秒计时模式可以开始、暂停并恢复，暂停后当前五个秘密 marker 在整页 HTML 中为 0。
- 不计时模式完整完成四回合，复核只列出本回合实际出现的卡，终局不回放题卡。
- Chrome 的真实触摸事件只记录一张卡；键盘 Enter / Space 和普通点击均可操作。
- reduced-motion 下 transition 与 animation 均为 `0s`，规则推进不依赖动画。

## 可复用结论

对“高频公共状态 + 低频秘密阶段”界面，不应在“全部重绘”和“全部复用”之间二选一。
更稳妥的边界是：公共高频值增量更新，秘密阶段边界整体换树。这样既保住焦点与输入
稳定性，也能把隐私保证落在 DOM presence/absence 上，而不是视觉样式上。
