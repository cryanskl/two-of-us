# 本地内容型游戏的三层 Gate：结构、语义与真实观察

## 背景

静态本地游戏经常把大量价值放在题库、卡片、提示和文字上。只要 JSON 或
JavaScript 能被加载，不代表内容已经公平、可理解或可分发。四符片名擂台在
32 卡首版中同时遇到了结构、题意和平台字形三种不同证据问题。

## 常见错误直觉

### “schema 通过，所以内容正确”

schema 能证明字段存在、ID 唯一和引用闭合，却不能证明“四个符号真的支持这个
答案”，也不能证明干扰项没有歧义。

### “搜索零结果，所以名称绝对安全”

公开索引零结果只表示当时未发现精确重名。它不能覆盖未索引内容、其他语言
译名、未来作品或法律上的混淆判断。

### “同一 Unicode 字符，所以各平台看起来一样”

字符序列稳定，不等于厂商字形一致。颜色、轮廓、组合支持和空框回退仍需实际
观察。

## 三层方法

### 第一层：可自动化的结构 Gate

用纯函数与测试证明：

- 固定总量、唯一 ID 和无稀疏数组；
- 所有引用存在且类型正确；
- 每卡四个不同 token、四个不同选项；
- 正确项存在一次；
- 提示只删除确定的错误项；
- A/B 配对具有相同难度和类型序列；
- 原始配置被防御性复制并递归冻结。

结构 Gate 应输出稳定错误码，让失败能定位到卡、token 或题包。

### 第二层：可复核的语义 Gate

逐卡同时阅读：

```text
tokens → rationale → answer → decoys
```

检查：

- 答案中的关键主体或事件是否由四符共同支持；
- rationale 是否只解释已有符号，而不是补写题面没有的信息；
- 干扰项是否可信但没有与答案同等合理；
- 等价标签是否只描述 glyph，不偷偷给出组合答案；
- 四符是否明显映射真实角色、剧情或品牌。

审计结果写在独立文档中，`reviewed: true` 必须能回指到具体方法和日期。

### 第三层：必须真实执行的观察 Gate

以下证据不能由 schema 代替：

- 公开网页名称近似检索；
- 至少两位未参与创作的玩家做 A/B 盲测；
- macOS Chrome、Safari 与一种非 Apple 平台观察字形；
- 屏幕阅读器按视觉顺序朗读中文等价标签；
- 真实 `file://` 页面完成一整局。

若当前阶段没有 UI 或设备，就明确写“未验证”，不要把低风险推断包装成实机
通过。

## 可复用测试骨架

```js
for (const card of cards) {
  assert.equal(card.tokens.length, 4);
  assert.equal(new Set(card.tokens).size, 4);
  assert.equal(card.options.length, 4);
  assert.equal(new Set(card.options.map((item) => item.id)).size, 4);
  assert.ok(card.options.some((item) => item.id === card.answerOptionId));
  assert.notEqual(card.answerOptionId, card.spotlightRemoves);
}
```

这段只属于第一层。第二、三层必须有单独记录。

## 验证清单

- [ ] 结构错误可由稳定测试复现；
- [ ] 每张内容有内部解释和原创字段；
- [ ] 名称检索记录日期、查询强度和证据限制；
- [ ] 等价文本不泄露组合答案；
- [ ] 平台字形风险按低、中、高分级；
- [ ] 盲测没有把小样本描述成统计证明；
- [ ] 未完成的实机检查明确留在安装 Gate；
- [ ] attribution 区分字符、数据文件和厂商图像。

## 适用边界

适用于离线问答、卡牌、猜词、符号解码、知识题库和提示型互动。纯几何游戏或
没有人工内容资产的状态机仍需要结构 Gate，但不一定需要名称检索与题意盲测。
