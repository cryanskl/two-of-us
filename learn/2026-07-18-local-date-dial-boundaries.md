# 离线纪念日仪器：近似边界、阶段 DOM 与圆环跨输入

## 适用范围

适用于把日期、季节、星象或其他周期数据做成“本地点开即玩”的纪念日谜题。目标是稳定、可解释的情感互动，不是替代天文、历法或观测工具。

## 一、先声明近似模型的用途

八档月相谜题只需要稳定映射，不需要引入完整天文库。可以固定 UTC 新月基准，以平均朔望月计算周期位置，再量化为八档；日期统一取 UTC 正午，避免本地时区把同一公历日推到相邻日。

模型必须同时满足三条边界：

- README 明确“适合纪念日谜题，不是精密天文工具”；
- 测试覆盖不同时区进程的同日一致性；
- 调研记录基准、周期常数和抽样对照来源。

如果产品要显示所在地升落时刻、照明比例或可观测方向，这个近似就不再够用，应升级数据模型，而不是继续包装精度。

## 二、秘密由阶段拥有 DOM

隐藏文字的 CSS 不等于隐私。开场 HTML 不预埋线索和结尾节点；状态从 `intro` 进入 `calibrating` 后创建线索，从 `unlocked` 退出时移除结尾。公开 view model 在解锁前不投影目标答案和最终文案。

这仍不是加密：本地 `config.js` 是明文，准备者分享目录前应知道接收者可以查看源码。阶段 DOM 解决的是“正常体验时不被读屏、搜索或复制提前揭晓”，不是抵御主动检查源码。

## 三、圆环手势使用累计角位移

把相邻 Pointer 样本先规范到 `[-π, π]`，再累计不足一格的余量；累计值跨过单格角度时才产生离散 reducer 步进。还要拒绝单帧超过合理阈值的瞬移样本，避免窗口切换或指针捕获异常造成跳档。

手势层只产生整数 `delta`，月份、日期和月相的环绕、钳制与反馈清理全部由 reducer 负责。这样按钮、键盘和拖动共享同一规则出口。

## 四、跨输入切换要显式管理焦点

Pointer 圆环通常需要 `preventDefault()` 防止滚动或浏览器原生拖放，但它也会阻止按钮默认获得焦点。捕获主指针后应先执行：

```js
ring.focus({ preventScroll: true });
event.preventDefault();
```

浏览器回归不能只分别测“拖动可用”和“方向键可用”，还要测“先点日期按钮，再点圆环，随后按方向键”的输入切换路径。

## 五、概念图是视觉规格，不是数据源

生成式概念图适合确认布局比例、材质、主次和情绪，但常会重复月份、错排月相或生成伪文字。运行时的十二个月和八个月相必须从确定数组生成，视觉只提取半径、色彩与层级。

本轮概念—实现 fidelity ledger：

| 维度 | 对照结果 |
| --- | --- |
| 桌面结构 | 保留约 34/66 的线索区与大仪器区；实现按真实内容高度允许页面略长 |
| 手机结构 | 保留标题 → 圆盘 → 三轴控制 → 读数 → 线索 → 主动作的单列顺序 |
| 色彩 | 保留午夜蓝、冷银、钴蓝选中态与朱红主动作 |
| 仪器层级 | 保留外圈十二月、内圈八相、中央月面和机械日期窗 |
| 交互尺寸 | 三组加减按钮保持至少 48px；圆环支持 Pointer、方向键与 `Home` |
| 内容正确性 | 实现由数据生成 12 个月和 8 个月相，修正概念图里的重复/错序标签 |
| 材质偏差 | 实现减少概念图的高光金属纹理，用平面描边保证离线体积、对比度和窄屏清晰度 |
| 状态偏差 | 中央月面显示当前选择；新月时主动变暗，不固定复制概念图中的满月 |

允许文案逐项对照：标题、引导句、三条示例线索与“核对这一天”均保持原意和顺序；实现只把概念图中不可靠的 AI 字形替换为真实 DOM 文本。终局留言不在概念图中，按阶段规格动态创建。

## 六、验证方法

1. 跑纯逻辑测试，覆盖时区、配置整份回退、环绕、角度余量和三项 Gate；
2. 跑仓库边界测试，确认 `file://`、无远程资源、无存储和借鉴声明；
3. 用真实 Chromium 从绝对 `file://` 打开，而不是只用 localhost；
4. 验证开场、错误核对、正确解锁、重开、图片失败回退和控制台；
5. 在概念原生桌面宽度、390px 和 320px 检查横向溢出；
6. 以原始分辨率查看概念图和最新实现截图，记录匹配项与有意偏差。
