# 无 JavaScript 基线要同时约束视觉树与无障碍树

日期：2026-07-25

## 结论

“没有泄露私有结果”不等于“无 JavaScript 体验正确”。如果静态 HTML 留下依赖脚本才能工作的按钮或空动态区域，它们仍会出现在视觉树和无障碍树中，形成误导性的可操作界面。

## 可复用做法

1. 静态 HTML 只让无需脚本即可成立的内容默认可见。
2. 依赖脚本的动态区域使用原生 `hidden` 建立保守基线。
3. 脚本准备成功后再解除隐藏；准备失败分支必须显式解除需要展示的错误与重试控件。
4. 静态合同测试锁定初始隐藏边界，真实浏览器关闭 JavaScript 后再检查可见节点和无障碍快照。
5. 正常脚本模式必须补一遍首屏回归，防止“修好无脚本、误伤有脚本”。

## 本次案例

Candle Wishes 原先无脚本时仍显示空舞台、进度和不可用的开始按钮。为四个动态节点增加初始 `hidden`，并由准备成功/失败分支分别解除必要隐藏后，无脚本页只保留公开说明，有脚本主流程保持不变。
