# 自由探索与确定成句：顺序分层和 public view 对账

适用于“任意顺序打开多个片段，最后按固定语义合成”的惊喜页、问卷、卡片和仪式型交互。

## 三种顺序不要共用一个概念

1. **探索顺序**：用户先打开什么，例如 `openedOrder`；它用于焦点、播报、重放和理解用户路径。
2. **语义顺序**：结果应怎样成立，例如 `when → where → together`；它来自产品含义，不应随点击顺序变化。
3. **渲染顺序**：当前屏幕怎样排版；它可以因响应式改变，但不能篡改前两者。

如果直接遍历 `openedOrder` 合成句子，用户的自由选择会意外改变语法。正确做法是保留真实探索日志，同时用冻结的语义 ID 序列投影结果。

## public view 是逐字段合同

“UI 只读 public view”不能只写成一句原则。应为每个阶段列出界面需要的全部字段，并逐项检查来源：

| 字段类型 | collecting | ready | finale |
| --- | --- | --- | --- |
| 开场文案 | 有 | 无 | 无 |
| 已打开正文 | 部分 | 全部 | 全部或摘要 |
| 完整结果 | 无 | 无 | 有 |
| 主动作 | 打开下一项 | 主动合成 | 重开 |

遗漏公开字段会迫使前端越过边界直读配置；过早公开字段则会让隐藏 DOM、属性或可访问树泄露后续内容。

## 阶段隐私的准确表述

纯前端直开页面无法阻止查看源文件。可承诺的是：

- 未到阶段的数据不进入当前 public view；
- UI 不把它放进 DOM、属性、注释、日志或 CSS 内容；
- 配置文本只用 `textContent` 渲染；
- 文档明确这不是密码学加密。

## 验证方法

- 穷举所有探索排列，断言最终语义文本完全相同；
- 序列化每阶段 view，检查不该公开的字段和文本不存在；
- 在真实浏览器检查正文、属性、隐藏节点、注释与可访问树；
- 让前端测试或静态 Gate 禁止直接引用配置对象，确保 public view 合同闭合。
