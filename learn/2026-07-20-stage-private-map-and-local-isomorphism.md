# 热座导航：阶段私密地图与局部同构合作证明

## 适用范围

适用于一人短暂读取完整信息、另一人接手后只看局部信息的本地热座玩法：领航迷宫、拆弹手册、路线记忆、秘密布阵、非对称拼图和轮流观察任务。

它保护的是正常面对面交接时的阶段信息，不是密码学隔离。同页 JavaScript、源文件和开发者工具都能被主动检查；需要抵抗恶意查看时，应改用双设备私密消息或独立裁判进程。

## 1. 私密地图应只存在于拥有它的阶段 view

推荐三层边界：

```text
权威 state + 固定关卡
        ↓ 按 phase 投影
briefing view / driver view / result view
        ↓ 整段重建
当前阶段 DOM
```

领航 view 可以包含完整网格、安全路径、危险和地标；驾驶 view 只返回固定大小的局部格、局部中心、步数与中性反馈。前端只调用 `getPublicView(state)`，不导入关卡全局，也不直接读取 state 的位置、路径或地图行。

阶段切换用 `replaceChildren()` 删除整棵旧节点。`hidden`、`display: none`、`aria-hidden`、透明度或遮罩都只是视觉隐藏，仍会把地图文字、危险 class、坐标和替代文本留给 DOM 搜索与读屏。

## 2. 隐藏格必须在规则投影时归一化

如果驾驶员“不应知道这里是陷阱”，不能把 `{ kind: "hazard" }` 交给 UI 后要求 CSS 画成普通路。class、aria-label、调试文本和未来组件都可能泄漏。

规则层应在生成驾驶 view 时直接把可见范围内的危险归一化为普通 `floor`。前端因此没有机会区分它们；进入危险后的 retry 也是 reducer 根据权威地图裁决，而不是 UI 根据格子类型触发。

同理，驾驶 view 不应包含世界坐标、完整 rows、安全路线、关键分叉或从局部索引可逆推出的绝对位置。局部中心可以永远固定在 5×5 的 `[2, 2]`，地图边缘用 `void` 表达即可。

## 3. “两个角色都重要”要变成可计算性质

只把全图给 A、方向键给 B，并不能证明 B 无法独自凭局部画面过关。固定地图应刻意包含关键分叉：驾驶员到达分叉前看到的局部结构，在另一个关卡或另一个方向中也可能出现，但正确转向不同。

可以把局部观测转换为规范签名：

1. 取关键点到达前两步的 5×5 投影；
2. 把危险归一化为道路、抹去具体地标身份；
3. 按到达方向旋转到统一朝向；
4. 允许左右镜像，取字典序较小的规范结果；
5. 断言需要不同正确转向的两个分叉具有相同签名。

这证明“只看局部结构不能唯一决定下一步”，领航员必须提供来自完整地图的信息。它比“地图看起来很绕”更稳定，也能在关卡调整后立即发现合作性被意外移除。

## 4. 路径正确与合作必要性是两套 oracle

BFS 可以证明：

- 起点到终点存在安全路径；
- 固定最短距离与规格一致；
- 路径相邻、端点正确且不经过危险；
- 每个危险本身可达，不是永远碰不到的装饰。

但 BFS 不能证明驾驶员需要领航员。局部同构签名也不能证明地图真的可通关。因此两套测试必须同时存在：一套保护可达性，一套保护信息不充分性。

## 5. 生命周期遮盖是隐私辅助，不是恢复机制

完整地图阶段遇到以下任一事件，都应原子进入 cover：

- 固定 tick 倒计时结束；
- 用户手动确认记住；
- `document.hidden`；
- `window.blur`。

页面重新可见或重新聚焦时不要自动揭图，因为设备可能已经交到驾驶员手上。业务状态保存首个遮盖原因，重复生命周期事件保持幂等；动画帧时间只负责生成固定 tick，不成为 reducer 的权威墙钟。

## 6. 浏览器验收要扫描“当前整棵 DOM”

进入 cover 与 driving 后，至少检查：

- `.navigator-cell` 数量为 0；
- 完整地标、陷阱说明、安全路径和关键分叉文本不存在；
- 驾驶格精确为 25，危险 class 为 0；
- 方向键、键盘与撞墙反馈都能产生真实 reducer 动作；
- 四轮生产安全路径能完成，角色次数为 2/2；
- 换轮、终局和重开都不重新挂载旧地图；
- 计算样式、页面 scroll 尺寸和控制台同时通过。

逻辑测试证明投影合同，浏览器扫描证明前端没有绕开合同。两者不能互相替代。

## 反例

- UI 导入 `LEVELS`，再按阶段选择不显示：完整地图仍在表现层作用域中。
- 驾驶 view 返回 hazard，CSS 把它涂成 floor：DOM class 与 aria-label 仍泄漏。
- 只证明起点到终点有路：不能说明双人合作是必要的。
- 两个分叉截图相似，但没有规范旋转/镜像签名：关卡一改就无法稳定回归。
- 失焦后自动恢复 briefing：交接后的驾驶员会看到完整地图。
- 宣称“本地加密”或“防作弊”：同页源码与开发者工具并未隔离。

## 验证清单

- 每个 phase 的 public view 有精确字段白名单；
- 完整地图只出现在 briefing view；
- 驾驶 view 固定 5×5、中心局部化、危险归一化；
- app 不导入关卡全局，只消费 public view；
- cover/driving DOM 全局扫描不命中私密节点与字段；
- BFS 同时证明安全路与危险可达；
- 至少一对不同正确转向的关键分叉通过局部同构 Gate；
- timer/manual/hidden/blur 遮盖幂等且不会自动揭开；
- 四轮真实浏览器路径完成，角色平衡与摘要正确；
- README 明确面对面边界与开发者工具限制。

## 本仓库实例

“雾里，跟着你走”使用四张固定 13×9 地图、7 秒即 210 个 30Hz tick、5×5 驾驶窗口和 `0/1/0/1` 领航席位。四条安全路径长度固定为 22、13、22、13；规则测试共 30 项，同时覆盖 BFS、局部规范签名、危险归一化、生命周期遮盖、重试、原生键盘事件、重放和 hostile config。

真实浏览器终验走完四条生产路径，确认四轮角色各领航/驾驶两次；cover 与 driving 阶段完整地图节点为 0，驾驶格为 25，控制台无 warning/error。对应实现见 [`logic.js`](../experiences/co-op/fog-navigation/logic.js)、[`logic.test.js`](../experiences/co-op/fog-navigation/logic.test.js) 与 [`app.js`](../experiences/co-op/fog-navigation/app.js)，来源与零复制边界见 [`ATTRIBUTION.md`](../experiences/co-op/fog-navigation/ATTRIBUTION.md)。
