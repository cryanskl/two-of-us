# 用确定性搜索同时证明关卡可解与双人决策真实

- 日期：2026-07-25
- 来源项目：`memory-merge-board`
- 适用：固定关卡、纯 reducer、多阶段双角色合作游戏

## 问题

“求解器找到一条胜利路径”只能证明关卡存在解，不能证明第二位玩家的动作真的有
价值。若补页者每次只有一个按钮，项目即使可解，也不满足双人合作合同。

本项目需要同时证明：

1. 三个固定关卡存在可由真实 reducer 重放的解；
2. 求解不依赖随机；
3. 搜索在明确状态上限内完成；
4. 两席都承担整理者与补页者；
5. 正式关至少多次出现实质候选分支和多落点分支。

## 做法

### 1. 规则状态与呈现状态分离

canonical key 只包含会改变未来规则的字段：

- 棋盘；
- 当前整理者；
- phase；
- 候选顺序；
- supply cursor；
- 待放线索；
- 来向方向；
- 分享队列；
- 已归档的不同主题。

它不包含：

- 公告文案；
- 动画；
- 焦点；
- DOM；
- 回合显示值；
- 重复归档的排列噪声。

这样既避免把同一规则局面重复搜索，也不会让 UI 细节污染可解性结论。

### 2. 优先级只影响搜索顺序，不改变合法动作

求解器从 reducer 枚举当前 phase 的全部合法动作：

- `slide`：四个实际改变局面的方向；
- `share`：唯一的继续动作；
- `choose`：每个候选索引；
- `place`：每个合法来向边缘空位。

稳定优先级偏向：

- 更多不同主题章节；
- 尚未归档主题的更高合成进度；
- 待完成的 choose/place/share 阶段。

优先级不生成动作、不跳过合法性检查，也不直接修改状态；每个后继都必须由真实
reducer 产生。因此它只让 witness 更快出现，不替代规则证明。

### 3. 状态上限必须是独立结果

达到上限时返回 `state-limit`，不能返回 `unsolved`。

- `solved`：找到可重放 witness；
- `unsolved`：在深度与状态范围内穷尽；
- `state-limit`：证据不足，需要提高上限或收缩内容；
- `invalid-level`：关卡 schema 不成立。

这避免把“搜索预算不够”误报为“关卡无解”，也避免为了通过测试伪造黄金路径。

### 4. 黄金路径必须回到真实 reducer

冻结的 hint path 不能只是求解器内部路径。测试必须：

1. 从 `createInitialState(level)` 开始；
2. 把每个 action 交给生产 `reduce`；
3. 断言每一步都改变状态；
4. 最终进入 `won`；
5. 断言三个不同主题章节；
6. 断言没有重复章节依赖。

如果搜索模型和生产 reducer 不一致，replay Gate 会失败。

### 5. 用不同后继证明候选选择“实质不同”

在黄金路径经过的每个 `choose` 状态：

1. 枚举全部候选动作；
2. 经真实 reducer 生成后继；
3. 计算每个后继 canonical key；
4. 至少两个不同 key 才计为一次实质候选分支。

只比较按钮数量不够，因为两个按钮可能生成完全相同的规则状态。

`place` 状态则要求至少两个合法 board index，且测试记录黄金路径中出现这种状态的
次数。

## 本项目实测

在 10,000 个访问状态的严格测试 Gate 下：

| 关卡 | 访问状态 | 黄金动作 | 完整回合 | 实质候选分支 | 多落点分支 |
|---|---:|---:|---:|---:|---:|
| `first-page` | 4161 | 28 | 8 | 5 | 8 |
| `crossed-notes` | 4161 | 28 | 8 | 5 | 8 |
| `album-night` | 4163 | 28 | 8 | 5 | 8 |

重复求解得到逐动作与统计完全相同的结果。三条路径都让左右两席分别承担过整理者和
补页者，且不依赖重复章节。

## 边界

这些证据能证明：

- 固定数据可解；
- 规则与 witness 一致；
- 决策在状态层面有不同后果；
- 搜索规模受控。

它们不能证明：

- 真实玩家觉得选择有趣；
- 文案、视觉或教学易懂；
- 触屏、键盘和响应式可用；
- 关卡时长符合目标。

这些仍需后续 UI、浏览器和双人试玩 Gate。不要用 solver 通过代替完整体验验收。
