# 内部游标哨兵不能直接显示为公共序号

## 适用场景

固定长度的卡组、步骤、分页或队列使用零基游标，并允许游标等于集合长度表示
“已耗尽”时。

## 核心区别

同一个整数可能有两种语义：

- 内部游标：`0..length`，其中 `length` 是完成哨兵；
- 用户序号：`1..length`，不能出现 `length + 1`。

因此不能在所有阶段无条件显示：

```js
ordinal = cursor + 1;
```

安全投影是：

```js
ordinal = Math.min(cursor + 1, length);
```

或者让结束阶段不显示当前项。选择哪一种取决于产品合同，但必须在公共 view 层
明确决定，不能修改内部哨兵来迁就显示。

## 为什么保留内部哨兵

`cursor === length` 可以稳定表达：

- 全部项目都已经处理；
- 不存在下一项；
- 完成 action 不会再次读取数组；
- reducer 与重放日志保持单调。

若为了避免 `7 / 6` 而把游标改回 `length - 1`，会混淆“正在处理最后一项”和
“最后一项已经处理完”，容易产生重复提交。

## 测试方法

边界测试至少同时断言：

1. 处理中第一项显示 `1 / N`；
2. 处理中最后一项显示 `N / N`；
3. 完成哨兵阶段仍显示 `N / N`，或按合同不显示进度；
4. 从完成阶段进入复核、结果等后续阶段不会重新出现 `N + 1 / N`；
5. 内部游标仍为 `N`，证明修复只在投影层。

这个模式同样适用于：

- 队列消费；
- 分页结束态；
- 教程步骤；
- 多轮题卡；
- 文件分块处理进度。
