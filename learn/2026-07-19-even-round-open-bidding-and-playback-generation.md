# 有限公开升价的对称赛制：偶数先手、证明责任与播放 generation

## 适用范围

适用于两个人共用一台设备、先观察有限信息，再公开声明自己能完成多少并现场证明的玩法，例如顺序记忆、声音复现、路线复述、图形回忆和限量知识竞拍。

它不适用于需要抵抗开发者工具检查的秘密对抗；同页 JavaScript 只能提供面对面礼仪与阶段隔离，不是密码学安全边界。

## 关键结论

### 1. 先手公平要按整场次数证明

若第 `r` 轮先手为：

```text
opener(r) = r mod 2
```

并固定进行偶数 `R` 轮，则两人各先手 `R / 2` 次。“看起来轮流”还不够，终局路径也必须保持这个轮数合同。

四轮是轻量同机对抗的实用下限：每人各先手两次，能形成比分 4–0、3–1、2–2、1–3、0–4。2–2 应作为正式平局；若临时添加单轮加赛，加赛只有一个先手，刚刚证明的对称性会立即失效。

如果产品必须决出唯一胜者，可以采用另一套预先冻结的对称决胜规则，例如双方各完成一份同构挑战后比较共同指标。不要在平局发生后临时发明“再来一轮”。

### 2. 报价必须同时产生责任

公开升价不是装饰性的数字按钮。一次合法报价应原子地更新：

```text
bids += { playerIndex, amount }
currentBid = amount
highBidderIndex = playerIndex
activeBidderIndex = 1 - playerIndex
```

并满足：

- 开价范围有明确下限和上限；
- 新报价严格大于当前报价；
- 只有当前行动者能报价或退出；
- 首次报价前不能退出，否则先手可以无成本把证明责任推给对方；
- 报到理论上限时立即结束竞价，因为对方已经没有合法更高报价；
- 退出只结束竞价，不修改最高报价者。

竞价的价值来自“高报价换取证明风险”：证明成功，最高报价者得分；证明失败或主动认输，对方得分。若失败不产生代价，最优策略会退化为永远报上限。

UI 不应自己推导“哪些数字大概合法”。公开 view 直接给出 `allowedAmounts`、`canPass`、当前行动者和完整公开报价日志，页面只把权威合同渲染成按钮。

### 3. 序列随机要先冻结结构约束

“八件随机物品”如果完全独立抽样，可能只出现两三种物品，也可能出现相邻重复，记忆体验会从顺序辨认退化为重复噪声。更稳定的生成合同是：

1. 六种基础物品各放一次；
2. 从六种中无偏选择两个不同物品，各追加一次；
3. 用无偏整数驱动 Fisher–Yates 洗牌；
4. 若出现相邻相同，只与能同时保持两侧局部安全的位置交换；
5. 对大量 seed 验证每串恰有六种、两种各出现两次、无相邻重复。

seed 和四轮完整答案属于权威 state；观察阶段的公开 view 只给当前可见物件，竞价与证明阶段不返回答案。本轮结算后才公开本轮序列，终局摘要也不需要携带四轮答案。

### 4. 自动播放动作必须带 generation

浏览器 timeout 不能被视为可信的“当前动作”。暂停、失焦、隐藏、切轮或重开后，旧 timeout 仍可能迟到执行。只调用 `clearTimeout()` 不足以成为逻辑证明：回调可能已经进入任务队列，或未来重构漏清某一条路径。

权威状态应持有单调递增的 `playbackGeneration`：

```text
SHOW_REVEAL_ITEM  { generation }
HIDE_REVEAL_ITEM  { generation }
```

reducer 只接受与当前 generation 精确相等的动作。每次显示、隐藏、暂停、恢复、进入下一轮都会推进 generation，使旧回调天然失权。浏览器层仍应集中取消 timeout；generation 是第二道确定性门禁，不是取消清理的替代品。

手动展示也应推进同一 generation。这样自动与手动共享一套权威序列生命周期，差别只在“谁触发下一步”，而不是维护两套容易漂移的状态机。

### 5. 暂停意味着立即盖住，不是冻结画面

记忆玩法的暂停如果保留当前物品，会变成无限观察。无论用户主动暂停、窗口失焦还是页面隐藏，权威转换都应同时做到：

- `revealVisible = false`；
- 记录有限的 `pauseReason` 枚举；
- generation 递增；
- 取消现有计划；
- 返回页面后必须主动恢复，不自动补播。

手动模式恢复后可以重新显示同一件；自动模式恢复后重新安排同一件的展示。两者都不能偷偷跳过或提前进入竞价。

### 6. 公开投影比“前端别读取答案”更可靠

推荐数据流：

```text
权威 state（四轮答案、报价、证明）
        ↓ 按 phase 投影
公开 view（当前可见物件或当前公开动作）
        ↓ replaceChildren
阶段 DOM
```

前端只持有公开 view，不读取权威 state。每个阶段只让一个阶段对象非空：`reveal / bidding / proof / roundResult / match`。这能避免竞价按钮、可访问名称、`data-*` 或隐藏节点意外带出尚未公开的序列。

## 反例

- 三轮制轮流先手：一人先手两次，另一人一次。
- 四轮打平后“随便再来一轮”：把偶数轮证明破坏为奇数轮。
- 允许首位玩家直接退出：无成本转移证明责任。
- 报到上限后仍要求对方点一次“退出”：制造没有决策价值的额外动作与焦点状态。
- 证明失败不送对手分：永远报上限成为支配策略。
- 每格独立随机一种物品：类别覆盖、重复数量和相邻重复都不可控。
- 只在浏览器层清 timeout：迟到回调仍可能推进新轮。
- 暂停时继续显示当前物品：暂停成为作弊入口。
- UI 从完整 state 中“自觉不渲染”答案：这是约定，不是结构边界。

## 验证方法

- 表驱动覆盖 4–0、3–1、2–2、1–3、0–4，并断言双方各先手两次；
- 首次合法报价为完整范围，之后只剩严格更高值；
- 首报前退出、非行动者报价、等价/降价、上限后再报价均被拒绝；
- 报上限在同一 action 进入证明；
- 成功、首错、部分草稿认输都明确归属唯一得分者；
- 512 个以上 seed 覆盖序列结构约束；
- 自动 show/hide、暂停/恢复、切轮和旧 generation 都有 reducer 测试；
- reveal view 只公开当前可见一件，bidding/proof/match 不含未公开答案；
- action 日志、JSON 中间态和相同 seed 能重放到同一终态；
- 真实浏览器同时验证自动与手动展示、生命周期暂停、最高报价、四轮终局与重开。

## 本仓库实例

“这一串，我还记得”固定四轮，每轮八件、六种齐全且两种各重复一次；两人轮流开价 2–8，最高报价者证明前缀。逻辑层使用拒绝采样整数、Fisher–Yates、局部相邻修复、严格 action 字段、播放 generation、阶段公开 view 与可重放结果。
