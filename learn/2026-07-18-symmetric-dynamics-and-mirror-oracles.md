# 对称双人动力学：让 fixture、舍入和镜像 oracle 同时成立

## 适用范围

适用于左右两席共同控制一个连续对象的本地玩法，例如天平、跷跷板、共同搬运、双桨小船和两端拉绳。目标不是让两边数值恰好一样，而是证明“交换玩家与方向后，规则不会暗中偏向任何一边”。

## 关键结论

### 1. 对称性是整条数据链的性质

只把左右输入写成相反符号还不够。完整镜像至少要同时交换：

- 左右输入集合；
- 左右升力或位置；
- 倾角、滚珠位置和滚珠速度的符号；
- 关卡外力或坡势的符号；
- 检查点和完成进度中不应镜像的公共标量。

如果第一段坡势是 `+72`、镜像段却是 `-84`，即使 reducer 公式完全对称，整关也不是严格镜像。这样的关卡可以故意存在，但不能再声称“严格左右公平”，也不能拿深相等镜像测试作公平证明。

### 2. fixture 必须先冻结，再写 mirror oracle

镜像测试不是普通示例测试，而是一个变换关系：

```text
mirror(reduce(state, action))
=== reduce(mirror(state), mirror(action))
```

要让这条关系有意义，关卡 fixture 也必须满足同一变换。推荐顺序是：

1. 先列出哪些字段变号、哪些字段交换、哪些字段保持；
2. 冻结对称坡势、边界和阈值；
3. 用同一动作日志生成原始轨迹和镜像轨迹；
4. 对权威物理字段做深相等，而不是只比较最终输赢；
5. 另写一次真实可达日志，证明对称规则不是“公平但过不了关”。

### 3. 负数舍入要显式定义

JavaScript 的 `Math.round()` 在负半值上的行为不是许多人直觉中的“远离零”。若动力学在正负两侧直接使用它，边界 tick 可能产生单边一格差异。

对称状态机应使用明确的整数除法规则，例如先处理符号，再对绝对值取整：

```js
function roundDivSymmetric(numerator, denominator) {
  const sign = numerator < 0 ? -1 : 1;
  return sign * Math.floor((Math.abs(numerator) + denominator / 2) / denominator);
}
```

实际实现还应限定整数输入与正分母。测试必须包含 `+0.5`、`-0.5` 及其相邻值，不能只测一般正数。

### 4. 权威状态与视觉投影分开

权威层保存有界整数，例如升力 `0..1000`、倾角 `-300..300`、球位 `-6000..6000` 和固定 tick 进度。渲染层再派生角度、百分比与 SVG 位移。

这样有三点收益：

- 镜像测试比较整数状态，不受像素、浮点与浏览器布局影响；
- CSS/SVG 可以平滑或降动效，而不会改变成功判定；
- 重放日志只保存输入边沿与 tick，能够稳定复现检查点、掉落和完成。

## 反例

- 只测试“左右同时按住会完成”：它证明可达性，不证明交换左右后轨迹相同。
- 只比较最终阶段：两条轨迹可能一边更难、失败次数更多，最终仍都完成。
- 对称公式配非对称坡势，却把偏差解释成数值误差：这是 fixture 契约问题，不是容差问题。
- 用截图比较左右公平：视觉只能检查投影，不能证明 reducer 的更新顺序和舍入对称。
- 为了让镜像测试通过而放宽 epsilon：整数状态机应先排查符号、更新顺序、钳制与舍入，容差通常会掩盖真实偏向。

## 验证清单

- 正负边界、钳制和半值舍入完全成对；
- 左右输入交换后，升力字段交换，倾角/球位/速度变号；
- 三段或多段关卡 fixture 明确标注哪些互为镜像；
- 原轨迹与镜像轨迹逐 tick 比较权威字段；
- 同一日志重复播放得到深相等状态，动作对象不被修改；
- 真实输入日志能够经过所有检查点并完成；
- 视觉层只读取 view model，不把像素值写回 reducer。

## 本仓库实例

“稳稳地，和你一起向前”使用 `+84 / -84 / 0` 三段坡势、对称整数舍入和固定 20ms tick。实现前曾发现规格把镜像段写成 `+72 / -84`，这会让严格镜像声明失真；修复与复现见 [`../bugs/2026-07-18-steady-together-asymmetric-bias-mirror-contract.md`](../bugs/2026-07-18-steady-together-asymmetric-bias-mirror-contract.md)。最终逻辑测试同时覆盖逐字段镜像、确定性重放和真实完成日志。
