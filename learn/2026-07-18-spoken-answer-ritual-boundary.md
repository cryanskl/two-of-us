# 只口头作答的双人仪式：把安全感写进状态机

## 适用范围

适用于谈话卡、约会提问、回忆接龙、倾听练习和其他“设备只负责提示，两个人在现实中回答”的本地 HTML。

## 关键结论一：不采集答案比“采集后不上传”更强

如果作品不需要回看、匹配或计算，就不要创建输入框、录音、草稿对象或存储键。答案只在现实空间存在，页面状态只保存卡 ID、阶段、当前席与完成/跳过结果。

```text
页面拥有：卡片、轮到谁、完成几张
两个人拥有：真正的回答
仓库不拥有：回答文本、录音、关系画像
```

这样既减少隐私表面，也让“刷新即清空”成为结构事实，而不是删除逻辑是否正确的承诺。静态 Gate 应检查输入控件、媒体 API、存储 API、网络 API 和答案字段，而不只搜索 `fetch`。

## 关键结论二：跳过必须是正常状态转换

“可以跳过”如果只是说明文字，而按钮隐藏、变灰或触发警告，仍会形成披露压力。把跳过设计成与完成同级的 reducer 动作：

- 记录当前卡 ID 到 `skippedIds`；
- 不增加 `completedIds`；
- 不询问原因、不扣分、不显示失败；
- 与完成一样翻转下一张首发席；
- 牌库耗尽时用中性完成页结束。

跳过同样参与轮换很重要，否则一方可以通过连续跳过把“先说”的压力固定给另一方。

## 关键结论三：重开需要恢复配置身份，而不是复用终局轮换

当状态只保存会变化的 `firstSpeaker`，终局无法直接知道原始配置席。若每处理一张都会翻转，则：

```text
openingSpeaker = cursor 为偶数 ? current firstSpeaker : other(current firstSpeaker)
```

更复杂的玩法应直接在状态保留不可变 `openingSpeaker`；轻量状态可以用可证明的奇偶不变量反推。测试必须包含奇数次跳过/完成后重开，不能只测恰好六张的偶数路径。

## 关键结论四：阶段 DOM 仍然有价值

谈话题本身不是密码，但卡背阶段不应提前泄露，它决定两个人是否同时准备好。卡背 DOM 只渲染占位文案；翻卡后才把题目通过 `textContent` 放入 H2。回答永远不进入 DOM。

验证时同时检查：

- 静态 HTML 和 app 不预埋题目；
- accessibility snapshot 的卡背没有当前题；
- `data-*`、`aria-label` 与隐藏节点不泄露；
- 完成页没有答案摘要或关系评价。

## 关键结论五：平衡随机服务于体验，不伪装成公平竞赛

谈话卡没有输赢，随机只改变节奏。仍然可以使用注入式 `randomIndex` 和平衡计划，保证前六张覆盖当下、共同经历与未来，但安全随机源缺失时允许本地 PRNG 回退。文档应明确它不是密码学用途。

## 验证清单

- 完整走一张和完整走六张；
- 分别在第一席、第二席和收好阶段跳过；
- 先跳过奇数张再完成并重开；
- 24 张全跳过，确认安全结束；
- 320px 检查主动作 ≥ 48px、无横向溢出；
- 控制台无错误，请求列表只有本地资源；
- README 明确“不录音、不保存、回答不进入页面”。
