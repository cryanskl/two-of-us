# 几何玩法的生产动作重放：同时证明可达、无穿透与完成 Gate

## 适用范围

适用于本地可重放的连续或离散几何玩法，例如共同搬运、迷宫、载具、轨道竞速、抛体、推箱和带检查点的协作关卡。尤其适合“规则单测都对，但不知道真实操作能否通关”的场景。

## 关键结论

### 1. 可达性必须从公开动作开始证明

一段合格的 production-action replay 只能调用玩家和运行时真实会调用的公开动作，例如：

- 输入按下与松开；
- 固定数量的 `tick`；
- 页面生命周期已有的暂停或重开动作。

它不能直接写姿态、传送到检查点、关闭碰撞、调用内部求解函数或使用只在测试中存在的宽松阈值。否则测试证明的是“终态可以构造”，不是“作品可以玩通”。

### 2. 同一条重放要验证三层事实

只断言 `phase === "complete"` 太弱。几何关卡的黄金路径至少要同时证明：

1. **路径可达**：路线阶段按规定顺序推进，所有关键区域确实经过；
2. **过程安全**：每个被接受的姿态重新通过世界边界、障碍和形状相交 Gate；
3. **结算真实**：最终位置、朝向、双方松手和连续保持 tick 全部满足生产完成规则。

这样，一次重放既是关卡可达性证据，也是碰撞回归和完成 Gate 的端到端测试。

### 3. 输入日志应比逐 tick 快照更语义化

推荐把重复 tick 压缩成“公开动作 + 次数”，而不是保存几百份完整状态：

```js
[
  { type: "input-down", side: "left", inputId: "key:KeyD", direction: "east" },
  { type: "input-down", side: "right", inputId: "key:ArrowRight", direction: "east" },
  { type: "tick", count: 48 },
  { type: "input-up", side: "left", inputId: "key:KeyD" },
]
```

测试 runner 负责把 `count` 展开成生产 `tick`。这样日志仍只描述用户意图，物理结果由当前 reducer 重新计算；若动力学或碰撞顺序漂移，测试会诚实失败。

### 4. 固定点角度让跨环境重放更稳定

带旋转的长刚体若每帧依赖浮点三角函数，浏览器、Node.js 版本或舍入边界的微小差异可能累积成不同碰撞结果。可重放规则层可以采用：

- 有限角度索引；
- 提前冻结的整数正弦/余弦表；
- 整数投影和明确舍入；
- 固定微步移动顺序。

渲染层仍可把角度索引转换成 CSS/SVG 旋转，但不得把视觉浮点值写回权威状态。

### 5. 重放 fixture 也是产品合同

固定地图或动力学修改后，黄金路径失败不应立刻通过改日志来“追绿”。先判断哪一项合同有意改变：

- 玩法规则是否真的调整；
- 地图是否仍应可达；
- 输入速度是否超出人工操作范围；
- 检查点或终点 Gate 是否意外漂移；
- 新路径是否仍能由两位玩家理解和执行。

只有产品合同有意变化时才更新重放，并在规格或变更记录中解释原因。

## 反例

- 测试开局后直接把对象设到终点，再执行 12 个 tick：只证明终点 Gate，不证明地图可达。
- 只检查最终没有碰撞：对象可能曾穿墙，随后又走回安全区。
- 用内部 `moveSafely()` 直接给位移：绕过了公开输入合成、按键身份和松手生命周期。
- 把每个中间状态写成 fixture：动力学的任何合理重构都会制造大面积快照噪音，反而隐藏真正的合同。
- 关卡变难后只延长 tick：如果已经撞墙，更多 tick 不会证明路线仍可执行。

## 验证清单

- 重放只含公开 action，动作对象自身不会被 reducer 修改；
- 相同日志重复执行得到深相等终态；
- 每个接受姿态都重新经过世界边界与全部生产障碍；
- 路线阶段单调、关键转角按顺序到达；
- 碰撞序号、回退次数或失败事件符合预期；
- 完成态同时记录 tick、最终姿态、路线阶段、保持 tick 与完成 tick；
- 日志规模足够短，人工能审查每一段意图；
- 浏览器实玩再验证键盘/Pointer 能产生与重放同类的公开动作。

## 本仓库实例

“一起，把家搬进来”的重放固定为 150 条公开动作，展开后在 tick 634 到达 `(820, 160, 0)`，路线阶段为 2，碰撞序号为 0，并完成 12 tick 双松手保持。测试逐一验证每个接受姿态都通过六个障碍和世界边界 Gate；它没有传送、内部状态写入、测试专用入口或碰撞旁路。

这条证据同时保护了 S 形门厅可达性、双端八向合成、256 格整数角度、OBB/AABB 碰撞顺序和最终地毯结算。对应实现位于 [`../experiences/co-op/moving-home-together/logic.test.js`](../experiences/co-op/moving-home-together/logic.test.js)。
