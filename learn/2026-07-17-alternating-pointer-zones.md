# 交替手势：用区域状态压缩高频 Pointer 事件

“左右摇动九次”不应按 `pointermove` 次数计数。事件频率受设备、浏览器和移动速度影响，同一次拖动可能产生几十个事件；直接累计会让快设备瞬间完成，也无法定义什么叫一次有效摇动。

## 把连续坐标压缩成三个区域

以按下位置为原点，只保留 `left / center / right` 三个语义区域。例如阈值为 48px：

- `delta <= -48` 进入 left；
- `-48 < delta < 48` 位于 center；
- `delta >= 48` 进入 right。

渲染层可以把视觉位移限制在更大的 76px，但规则层只接收离散方向。这样既保留手感，又让状态机与像素、帧率和设备采样频率解耦。

## 有效次数由“与上次不同”定义

第一次进入任一侧都算一次，之后只有与上次已接受方向相反才推进。同一侧继续移动、停留或反复触发事件都保持同一状态引用。回到 center 只代表经过中线，不清空 `lastDirection`，否则“右 → 中 → 右”会被误计为两次。

进度由 `acceptedShakes / required` 派生，不另外维护百分比。这样 DOM 圆点、剩余次数、可访问标签和滤镜都共享同一权威计数，不会因动画中断产生多份状态。

## 多输入共享一个 Gate

鼠标、触屏和键盘最终都调用同一个 `acceptDirection(direction)`：

- Pointer Events 负责坐标、pointer capture 和拖拽视觉；
- `← / →` 只负责把按键映射为方向；
- reducer 唯一决定同向是否无效、何时完成。

不要让键盘拥有一套独立计数逻辑。这样自动测试只需完整证明 reducer，再用浏览器分别证明两种输入确实到达同一 Gate。

## 取消路径必须归零视觉临时态

`pointerup`、`pointercancel`、`lostpointercapture`、窗口失焦和页面隐藏都应清除拖拽对象、抓取样式与 CSS 位移。规则进度可以保留，临时手势却不能跨越一次失焦继续存在，否则下一次触摸会继承旧 pointer 或让相纸卡在侧边。

这套模型适用于摇卡显影、左右擦拭、机械拉杆、往复充能和任何“连续动作被计为有限次交替”的本地网页交互。
