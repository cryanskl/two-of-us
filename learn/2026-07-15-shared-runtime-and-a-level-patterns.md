# A 级直开与 C 级运行时如何共用一个仓库

## 1. 门户采用双轨目录

根 `index.html` 内置一份最小作品目录，因此从 `file://` 双击时不依赖 `fetch()`；通过本地服务打开时，再从 `/api/catalog` 读取同一批作品并展示局域网二维码。这样不会为了 C 级能力破坏 A 级直开承诺。

## 2. 依赖统一，但不向轻作品扩散

Socket.IO 和 qrcode 只属于根运行时。回忆信、热座你画我猜和反应力对决保持普通 HTML/CSS/JS，整个作品目录可以单独复制。统一依赖的目标是减少安装入口，而不是让每个页面都变成工程化应用。

## 3. 热座玩法要清除秘密，而不只是隐藏

你画我猜交接设备时，进入画布前把秘密题目的 `textContent` 清空。只加 `display: none` 仍会把答案留在 DOM、辅助技术或调试工具里。这个模式也适用于真心话题卡、身份牌和双人密码谜题。

## 4. 双人反应游戏需要显式状态机

`idle → waiting → go → round-end → match-end` 把抢跑、正常按键、无人按下和重开分别约束在合法状态。键盘和触控最终都调用同一个 `press(player)`，避免两套判定产生不同比分。

## 5. 来源声明是自动验收项

`npm run verify` 会检查 catalog 入口、本地资源和每个 README 的“借鉴与来源声明”。把来源要求做成可执行 Gate，新增作品时就不会只依赖人工记忆。
