# 校验派生快照：字段自洽之外还要核对行动预算

## 两种一致性

一个派生快照可能同时满足：

- 坐标都在棋盘内；
- 库存范围合法；
- 障碍数量等于已消耗库存；
- 距离、合法行动和终局都能从当前棋盘重算；

但仍不可能由声明长度的历史产生。例如 `ply=0` 的快照不能已经用掉资源，也不能
让棋子离开起点。

因此快照校验至少有两层：

1. **横向一致性**：同一时刻的字段彼此吻合；
2. **纵向可达性**：声明的历史长度提供了足够行动预算形成当前字段。

只做第一层会接受“静态上合理、时间线上不可能”的状态。

## 交替回合的预算公式

若玩家严格交替、玩家 0 先手，则长度为 `ply` 的前缀中：

```text
turns[0] = ceil(ply / 2)
turns[1] = floor(ply / 2)
```

对每位玩家：

```text
resourceActions = startingResource - remainingResource
movementActions = turns[player] - resourceActions
```

必要条件包括：

- `resourceActions >= 0`；
- `resourceActions <= turns[player]`；
- `movementActions >= minimumMoves(start, current)`。

在图移动游戏中，`minimumMoves` 应来自不高估真实最短步数的下界。六角格可使用
轴/立方坐标距离；一般图可使用忽略临时障碍的 BFS。下界大于预算时一定不可能，
下界小于预算时则只说明“尚未证明不可能”。

## 必要条件不替代 history

行动预算验证通常不是充分证明：

- 棋子可能绕路或往返；
- 障碍可能在棋子经过后才放下；
- 某些动作会改变多个字段；
- 当前棋盘未必保留完整因果信息。

因此最可靠的权威状态仍应由事件 history replay 产生。预算校验适合用于：

- 接受派生 snapshot 的只读 helper；
- 网络或 worker 边界的快速 fail closed；
- 缺少完整 history 时排除明显伪造；
- 在昂贵重放前做便宜的必要条件过滤。

不要把必要下界写成“证明快照真实”，也不要用它替代严格事件序列。

## 建议测试

对任何公开派生快照 API，至少固定：

- `ply=0` 但资源已消耗；
- `ply=0` 但位置离开起点；
- 某玩家消耗次数超过其按奇偶获得的行动数；
- 最短移动距离比剩余移动预算多 1；
- 恰好等于预算的合法边界；
- 玩家互换、先手变化后的预算镜像。

这些反例应从真实合法快照复制后只修改最少字段，避免测试本身因无关 schema 错误
提前被拒绝。
