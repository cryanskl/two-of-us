# 结构化 WASM 绑定比解析示例输出更稳定

## 场景

whisper.cpp `v1.8.6` 的官方浏览器示例可以加载模型并启动转写，但示例绑定通过后台线程把分段文本和时间打印到控制台，调用方只能收到“任务已启动”的整数返回值。作品需要在推理结束后可靠地取得可编辑文本、分段时间和耗时。

## 做法

- 固定上游版本与 Emscripten 工具链，先构建官方目标确认基础环境成立；
- 不解析 `print` / `printErr` 文本，而是写一个只依赖 whisper.cpp 公共 C API 的薄绑定；
- 把同步 `whisper_full` 放进应用级 Worker，UI 主线程不阻塞；
- 绑定直接返回普通 JavaScript 对象：`ok/code/message/text/segments/inferenceMs`；
- 模型上下文在 Worker 生命周期内复用，`dispose` 显式释放；
- 对 12 秒样本上限、语言和线程数在 WASM 边界再次校验，不能只信任页面状态；
- 把 JS/WASM 的字节数、SHA-256、源码哈希和工具链 revision 写进机器可读构建记录。

## 可复用结论

上游 demo 适合验证能力，不一定适合作为产品协议。将“UI 看到的日志”当 API 会把文案、线程时序和错误格式都变成隐式依赖；一个很薄的结构化绑定通常更容易测试、升级、记录来源并保护隐私边界。
