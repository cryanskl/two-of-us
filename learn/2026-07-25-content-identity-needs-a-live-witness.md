# 内容身份不仅需要启动快照，还需要存活证明

deterministic hash 解决了“两个根目录内容是否相同”，但运行时复用还多一层时间问题：启动后，磁盘内容可能变化。

如果服务端永远返回启动时摘要，静态文件发生变化后，摘要与真实响应字节会分离；如果服务端直接把摘要更新成当前磁盘值，已经加载到内存中的运行时代码又可能与新摘要分离。

因此可复用身份应采用“启动快照 + live witness”：

```text
启动 identity == 当前重新计算 identity
  -> 可以继续声明启动 identity

启动 identity != 当前 identity
读取失败或无法证明
  -> 返回不可复用，不杀进程
```

这个规则有三个好处：

- 已存在的会话不会因工作目录被编辑而被强制结束；
- 新 launcher 不会复用身份已经漂移的进程；
- dirty、无 Git 分发目录和跨 checkout 继续遵循同一套实际字节规则。

这里的关键不是“总能给出一个 hash”，而是只在仍能证明进程与内容对应时给出可复用 hash。无法证明时，`null` 比一个看似合法但已经陈旧的摘要更安全。

本沉淀来自本仓库修复过程的独立分析，没有借鉴或复制其他开源项目代码。
