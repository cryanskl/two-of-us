# 混合键盘 / Pointer 游戏不要把“按钮获焦”当成全键盘禁区

## 可迁移结论

同屏游戏常允许一方触控、另一方键盘，或同一玩家在两种入口间切换。原生按钮被
鼠标 / 触控点击后通常会保留焦点；若输入层把“按钮获焦”与“正在编辑文本”合并成
同一个全键盘阻断条件，后续移动、转向和动作键就会被意外锁住。

## 推荐分层

1. 文本输入、文本域、下拉框和 `contenteditable`：
   阻止全部玩法键，避免破坏编辑。
2. 原生按钮：
   只阻止会激活按钮、同时又映射到玩法的冲突键，常见是 `Enter` 或空格。
3. 其他玩法键：
   即使按钮保留焦点，也继续进入 held-source 集合。
4. 全局安全键：
   `Escape` 暂停、`P` 暂停 / 恢复等应在焦点过滤前处理。
5. `keyup`：
   不应因当前焦点变化而拒绝释放，否则会留下卡键。

## 验收序列

不要只分别测试“键盘可用”和“触控可用”。至少增加：

```text
触控按钮 pointerdown/up
-> 按钮仍获焦
-> 另一玩法键 keydown/up
-> 对应输入生效
-> Enter 不误触右方动作
-> blur / hidden 后全部来源归零
```

这类测试能覆盖单输入模式用例看不到的焦点残留问题。
