# 手势门控的共享短音播放器

## 适用范围

多个纯静态 HTML 体验都要用 Web Audio 合成短音，但各自拥有不同频率表、节拍队列与声音开关。

## 核心结论

共享层只应拥有浏览器音频资源，不应拥有玩法语义：

```text
用户点击或按键
  → ensureReady() 创建 / 恢复 AudioContext
  → 作品自己的计时器决定何时播放
  → playTone() 创建 oscillator + gain
  → ended 断开本次节点
  → page unload 时 close() 释放 context
```

- `ensureReady()` 和 `playTone()` 分离，才能让用户手势满足自动播放策略，同时允许后续计时器同步播放；
- 共享 API 接收单个音的频率、波形、时长、淡入和音量，但不保存作品的谱面或播放队列；
- `playTone()` 在上下文未运行或参数非法时返回 `false`，视觉玩法仍应完整可用；
- 每个 oscillator 的 `ended` 是短命节点的释放边界，页面卸载是长命 AudioContext 的释放边界；
- 第三个消费者出现时再抽共享层，可以用真实重复代码确定最小接口，避免提前设计万能音频引擎。

这套边界让作品保留自己的声音个性，也能统一处理兼容、恢复失败和资源清理。
