# 密封联合结算：公开库存延迟、私密占用与策略穷举

适用范围：两个人轮流在同一设备上秘密选择有限资源，收齐两份选择后才共同揭晓并
结算的本地 HTML，例如同时出牌、暗选行动、密封竞价和预测对抗。

## 核心结论

### 1. “已经选择”和“已经公开消耗”是两本账

第一位确认秘密牌后，权威状态需要记住这张牌，但公开库存不能立刻减少。否则第二位
只需比较交接前后的公开数量，就能知道第一位选了哪一类。

更稳的状态分层是：

```text
committed hand  ──公开──> 双方最近一次揭晓后的库存
sealed choices  ──私密──> 本轮已确认、尚未揭晓的选择
draft choice    ──私密──> 当前席位尚未确认的界面草稿
```

- 确认第一份选择：只写 `sealed choices`，公开 `committed hand` 不变；
- 确认第二份选择：仍不公开牌种，只说明“两份已封存”；
- 共同揭晓：从同一个回合起点验证两张牌，原子扣减库存、计算得分、追加公开历史，
  然后清空 `sealed choices`；
- 离开选择阶段：直接删除 `draft choice` 及选牌 DOM。

这样既不会通过库存泄密，也不会把秘密选择误当成已经公开的事实。

### 2. 可用性校验必须同时看公开库存和本轮私密占用

延迟公开扣减不代表可以忽略占用。规则层处理确认动作时，应核对：

1. 当前席位是否正确；
2. 该席位是否还没有封牌；
3. 选择类型是否属于固定集合；
4. 该类型在回合起点库存中是否至少有一张；
5. 当前状态、动作和 revision 是否仍是同一份合法快照。

如果一个席位能在同轮重复确认，或确认后能改牌，延迟账本就会变成重复消费入口。
无效动作应保持原 state 引用；共同揭晓只接受两席都已封存的完整回合。

### 3. 联合结算不能依赖谁先操作

热座顺序只决定谁先拿到设备，不应改变得分公式。结算函数应接收同一个回合起点和
两份选择，一次性生成：

- 双方本轮得分；
- 双方揭晓后库存；
- 本轮公开说明；
- 是否达到终局。

不要“先结算玩家甲，再让玩家乙读取更新后的状态”。这会让先后顺序进入规则，
尤其在阻挡、争夺共享奖励或同时达标时产生偏差。

每轮轮换第一位操作者，可以减少交接体验上的固定先手感；真正的公平性仍应由联合
结算和镜像测试证明。

### 4. 有重复牌时，策略穷举要数行动序列，不是给实体牌编号

两张“阳光”在规则上不可区分。若把它们编号为 `sun-1 / sun-2` 再排列，会把同一
策略重复计算，扭曲胜率和“不败策略”结论。

正确的枚举对象是每轮牌种序列，并在生成下一步时只遍历当前计数大于零的类型：

```text
hand = { sun: 2, water: 2, pest: 2 }
next actions = keys whose count > 0
choose one type -> decrement its count -> recurse
```

对双方策略笛卡尔积、固定季节序列和镜像席位进行穷举后，至少核对：

- 交换两位玩家后，胜负计数严格镜像；
- 不存在某一固定行动序列对所有对手都不败；
- 每条序列恰好消费初始多重集合；
- 同轮同时达到目标时进入平局，而不是按操作顺序选赢家。

穷举测试是独立 Oracle，不应复用被测 reducer 来生成预期结果。

### 5. 公开投影和阶段 DOM 是账本边界的最后一公里

规则层不泄密还不够，UI 也不能直接读取权威 state。界面只消费公开 view，私密选择
阶段额外消费当前席位专用 view；确认或遮屏前先清空本地草稿并重建阶段 DOM。

`hidden`、`display:none`、`aria-hidden` 和改成牌背都不能证明秘密不存在。浏览器
验收应在第一位确认后、两位待揭晓时分别断言：

- 选牌按钮、已按下状态和揭晓牌节点数量为 0；
- 待揭晓页只有中性牌背，不带牌种 `aria-label` 或 `data-*`；
- `Escape`、`blur`、`pagehide`、页面隐藏后回到显式交接页；
- 恢复可见或重新聚焦不会自动展开秘密。

同设备热座仍只是正常传递设备时的视觉边界，不是密码学加密；需要抵御主动检查时
应换成双设备可信裁判或提交—揭晓协议。

## 反例

- 第一位确认后立刻把公开“阳光 2”改成“阳光 1”；
- 只延迟 UI 数字，却让公开 view 返回已扣减库存；
- 两份选择按操作顺序逐个结算，共享阻挡先到先得；
- 给重复牌编号后把实体排列数当作策略数；
- 选牌面板只做 `display:none`，秘密仍留在 DOM 和可访问树；
- 窗口重新聚焦就自动恢复上一位的选择页；
- 只跑几个示例局面就声称不存在固定优势策略。

## 验证清单

- 第一位封牌前后，所有公开字段深相等，仅公开流程计数变化；
- 第二位不能从公开库存、历史、播报、URL、DOM 或存储推断第一张牌；
- 揭晓时两张牌同时扣减，库存不为负且历史只追加一次；
- 六轮第一操作者严格交替，联合结算交换席位后结果镜像；
- 按多重集合枚举全部策略，记录 fixture 总数与胜负分布；
- 封牌、待揭晓、失焦和页面隐藏均有真实浏览器 DOM 断言；
- README 明确普通热座与主动攻击者的边界。
