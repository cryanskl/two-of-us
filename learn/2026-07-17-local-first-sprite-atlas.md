# 本地优先网格游戏的生成式图集管线

## 为什么用图集

小型网格游戏如果把每个玩家、门、压板和出口拆成独立图片，会增加资源清单、加载请求和风格漂移。一个严格对齐的图集能把所有对象锁定在同一材质、光照和镜头下；A 级 `file://` 页面只请求一个相对 PNG。

本次图集为 1448×1086，恰好是 4×3 个 362px 方格。CSS 使用 `background-size: 400% 300%`，列位置为 `0 / 33.333 / 66.667 / 100%`，行位置为 `0 / 50 / 100%`。状态切换只改变 background-position，不替换 URL。

## 生成 brief 的关键约束

- 明确行列数和每个单元的语义顺序；
- 所有对象采用同一镜头、材质、光照和相对尺度；
- 每件对象完整包含在单元内，单元之间不能重叠；
- 背景使用对象中不会出现的单一色，并禁止阴影、地面和反射污染背景；
- HUD、文字、碰撞盒和规则不进入图片，继续由代码原生实现。

生成后必须验证实际像素尺寸能被行列整除；如果不能整除，不应靠模糊 background-position 猜测裁切。

## 去背景不是运行依赖

绿色源图是设计输入，透明 PNG 是构建完成的运行资产。去背景工具只在制作时执行，不能把 Pillow 或图像模型加入普通用户的 setup。若系统环境缺库，可用临时 `uv run --with pillow`，但要记录工具版本边界和最终哈希。

透明通道的验证至少包括：尺寸、RGBA/alpha 存在、透明像素数量、半透明边缘数量和实际图片查看。只看到“命令退出 0”不足以证明玻璃边缘、内部孔洞或绿色残边正确。

## 逻辑与视觉分离

图集只负责投影视觉，关卡仍用字符网格表达；墙、出生点、出口、压力板与门的语义不依赖图块像素。测试可以完全不加载 PNG，BFS 也只遍历纯状态。这样视觉可迭代，碰撞和可解性仍保持确定。
