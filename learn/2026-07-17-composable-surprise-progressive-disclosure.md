# 可组合惊喜：先约束笛卡尔积，再做逐步揭晓

把惊喜拆成“时间、地点、彩蛋”三组，每组各三个候选，会产生 `3 × 3 × 3 = 27` 张可能车票。界面只展示九条配置，看起来很小；产品真正承诺的却是 27 种最终组合都自然、可执行。

## 因子化配置只适合任意组合都成立

三组独立候选适合这样的内容：

- 时间不依赖某个特定地点的营业时段；
- 地点不要求某个唯一出发时间；
- 彩蛋可以附着在任何时间与地点上。

如果存在“周五夜场只能配电影院”或“看日出必须配清晨”这类依赖，就不应继续用三组独立数组。更稳定的数据结构是三个或九个完整套餐，每个套餐预先保存时间、地点和彩蛋。不要在渲染层临时补互斥规则，那会让盲选结果难以解释，也会扩大测试状态空间。

## 配置错误要整份回退，不要拼成混合惊喜

准备者可能只写错一组数量或一个字段长度。逐字段回退会生成一张一半私人、一半默认的车票，既突兀又难定位。未来车票选择原子校验：整份结构全部合法才采用，否则完整回到深冻结默认配置。

这种策略适合礼物页、邀请函和故事页，因为内容之间通常有语气和人物一致性。它不一定适合普通设置面板；设置面板更常希望保留其他合法字段。

## 源码可见与页面不提前揭晓是两种承诺

A 级静态 HTML 无法对拥有本地文件的人保守密码学秘密，候选必然存在于 `config.js`。可以可靠做到的是：

- choosing 阶段 DOM 只含 A / B / C；
- 未揭晓值不进入隐藏节点、data 属性、title、CSS 变量或可访问名称；
- reducer 每次只接收当前被打出的一个值；
- 重新组合从 DOM 清除全部结果；
- README 明确源码可读边界，不夸大保密能力。

静态测试扫描 HTML 和运行源码，真实浏览器再检查正文、属性与可访问快照。两层证据比只看截图更可靠。

## 机械动画不能成为第二份状态机

打孔动画只有两个职责：给一次选择增加重量感，并在 520ms 内阻止重复输入。权威进度仍由 `choosing → punching → finishPunch` 控制；动画结束和超时兜底都调用同一个 Gate。

页面隐藏时应主动结算当前 punching，而不是留下一个依赖后台 timer 的半完成状态。重新开始和卸载则清掉旧 timer，避免上一局回调推进新局。

## 人类规范也可以是机器契约

仓库验证器要求 README 使用固定标题“借鉴与来源声明”。标题不仅帮助阅读，也让工具能稳定发现每个作品的来源边界。扩展仓库时应复用模板里的固定标记，不要仅凭自然语言“意思差不多”。

这套模式适用于盲选约会券、幸运饼干、三层礼盒、隐藏菜谱、旅行抽签和任何“准备者定义安全边界、体验者在边界内自由选择”的本地惊喜。
