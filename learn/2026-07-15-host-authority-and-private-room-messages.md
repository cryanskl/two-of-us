# 主机权威与房间私密消息

## 适用场景

局域网游戏同时包含公开状态、公开动作与隐藏信息，例如你画我猜的题目、身份牌、秘密选择和只交给裁判的答案。

## 三条消息路径

1. **公开权威状态**：主机广播阶段、回合、得分、当前角色和单调递增的 `version`。其他端只接受当前主机发送、且版本更新的状态。
2. **公开高频动作**：画家广播归一化笔迹。接收端同时核对发送者是不是当前画家、动作版本是不是当前回合，再决定是否绘制。
3. **私密定向消息**：题目由主机只发给画家，猜测只发给主机。服务端必须验证发送者和目标属于同一房间，并用真实 socket 身份重建消息，不能相信客户端自报的 `senderId`。

这三类数据不应为了少写几个事件而合成一个广播载荷。只要答案曾进入公开状态，即使页面没有渲染，也能从开发者工具或事件监听中读到。

隐藏字段没有进入广播，不等于猜词端无法推断答案。如果两端都能读取静态题库，而且主机每局固定取前几项，答案仍然等价泄露。主机应在创建权威状态时随机抽样；测试可注入固定随机函数，避免把随机性变成不稳定测试。

## Canvas 跨设备同步

不要持续发送截图。把指针轨迹拆成 `{ x1, y1, x2, y2 }`，四个坐标都相对画布宽高归一化到 0–1。接收端按自己的 Canvas 像素尺寸重绘，同一笔迹就能适配手机与电脑的不同纵横尺寸。

Canvas 尺寸变化时保留线段数组并完整重绘；像素缓冲区按设备像素比放大，坐标仍保持归一化。这样既避免模糊，也不会把特定设备尺寸写进网络协议。

回合版本变化时还要清理猜词输入框、错误提示等客户端临时状态。它们不属于权威比赛状态，却可能在角色下一次轮换回来时重新出现。

## 断线边界

主机保存答案和截止时间，因此主机断开后不能把剩余成员直接提升为“无损续局”的新主机。安全的最小策略是：角色或成员集合改变时清空答案、计时器、画布和公开状态，回到等待两人到齐。

若以后需要断线续局，应把完整权威状态移到服务端，并设计重连令牌、隐藏字段的按角色投影与状态持久化；这已经是另一档复杂度。

## 确定性回合制房间

四子棋这类没有隐藏信息的回合制游戏，不需要为每种动作增加服务端存储，但仍应把其中一端明确为权威主机：

1. 非主机只向主机发送带当前 `version` 的动作意图；
2. 主机核对真实 `senderId`、成员集合、当前回合、动作参数与版本；
3. 只有 reducer 产生新对象时才广播完整状态；
4. 其他端只接受当前主机发送且版本严格递增的完整状态。

完整状态广播比广播“第几列被点击”稍大，但 7×6 棋盘只有 42 格，收益是丢失中间事件后仍可在下一版本自愈。安全关键的 sender、room、host 与 member set 组合判断应抽成纯协议函数测试，真实 Chrome 双端/三端验证则覆盖 Socket.IO 重建身份、第三人退出和主机迁移的实际链路。

动作权限与棋盘可读性要分开：非当前玩家不能落子，不代表不需要理解局势。视觉棋格可从无障碍树隐藏以减少 42 个停靠点，但必须提供每列棋子顺序和一个始终可聚焦的完整棋盘摘要。
