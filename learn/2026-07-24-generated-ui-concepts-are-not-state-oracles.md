# 生成式 UI 概念是视觉证据，不是状态 Oracle

## 适用范围

适用于用生成图片探索多阶段网页、游戏、热座秘密、合作记录、离散棋盘或可访问
降级状态的视觉系统。

## 核心结论

生成图适合回答“它看起来是否属于同一个世界”“层级和密度是否成立”，不适合
回答“这个 phase 合法吗”“记录是否恰好六条”“DOM 顺序是否正确”。风格引用链
与业务真值链必须分开：

- 风格引用链：颜色、材质、构图、字体性格、组件外观；
- 业务真值链：reducer/public view、冻结文案、权限、基数、顺序、隐私和降级。

后者必须由规格、测试和浏览器 DOM 证明。

## 五类状态合同

每张完整状态图至少明确：

1. **阶段**：当前 phase、允许出现的主动作、不能提前出现的未来内容；
2. **权限**：哪些控件 enabled/disabled/pressed，谁可以操作；
3. **基数与顺序**：按钮、记录、格子、步骤的数量、字段、排序和求和；
4. **隐私**：未来答案、结语或另一席秘密必须不存在，而不是 blur/遮罩；
5. **降级语义**：reduced-motion、forced-colors、图片阻断和 no-JS 各保留什么。

## 推荐流程

1. 先冻结状态规格，再写视觉简报；
2. 用第一张合格图作材质锚点，但后续每张仍完整重述状态合同；
3. 把“不要什么”写到可测试层，例如“每席恰好四键”，不要只写“简洁控制”；
4. 所有候选原尺寸复核，记录淘汰稿和原因；
5. 生产实现从 reducer/public view 渲染 code-native DOM，概念图只进入 docs；
6. 浏览器 fidelity 对比同时检查概念和 DOM，但规则冲突时规格永远优先。

## 反例

- 看到画风一致，就默认姿势与当前状态一致；
- 看到六个相似条目，就默认每条字段与次数正确；
- 从完整截图裁按钮、文字或键帽进入运行时；
- OCR 生成图文案后写进代码；
- 用高对比概念图代替真实 `forced-colors` 浏览器验证。

## 验证方法

建立逐图台账，至少记录原生尺寸、SHA-256、输入引用、状态 ID、淘汰原因和运行时
排除范围。进入实现后再用测试验证状态投影，用浏览器验证 DOM 顺序、控件权限、
焦点、响应式与系统降级；两组证据不能相互替代。
