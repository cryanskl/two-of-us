# 随机结果先于动画

## 适用范围

适用于转盘、抽签、开箱、翻牌和任何“动画结束后揭晓随机结果”的本地互动。

## 稳定模型

先由随机源产生权威索引，再从索引计算动画终点。动画只负责表现，结束时直接显示已经选定的项目；不要读取 CSS transform、当前帧、像素颜色或计时误差反推结果。

这种拆分带来三个好处：

- 公平性可以在无 DOM 的纯函数里测试；
- `prefers-reduced-motion` 可缩短或取消动画而不改变结果；
- 页面卡顿、后台降帧或 transition 事件差异不会选出另一项。

用 32 位无符号整数除以 `2^32` 得到 `[0, 1)`，再映射到候选索引。每次抽取应独立；若产品没有明确说明，不要默认加入防重复或权重，因为它们会改变“每项机会一样”的含义。

## 角度与语义

固定指针时，目标旋转角应让中奖扇区中心对齐指针，而不是只让扇区边界对齐。累计角度可以持续增加整圈以保持正向旋转，但最终模 360 的角度只由中奖索引决定。

图形标签不应成为唯一候选来源。SVG 或 Canvas 负责视觉，真实列表负责完整文字与辅助技术，结果区用 `aria-live` 宣布；三者都从同一份清洗后的配置生成。

## 验证

- 给随机纯函数注入 0、区间边界和接近 1 的值；
- 检查所有索引的目标角都把扇区中心对齐指针；
- 正常动画与 reduced-motion 使用同一结果路径；
- 旋转中重复触发不会二次结算，结束后可再次触发；
- 捕获 Network 与控制台，确认随机和动画不依赖公网库。
