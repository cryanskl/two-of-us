# 双人网页游戏的首屏高度预算

桌面和手机游戏不能只验证“没有横向溢出”。若核心按钮落在折叠线下，用户点开后先看到的是展示页，而不是可玩的界面。

## 先把垂直空间当成预算

按实际顺序记录标题、连接状态、房间码、比分、主舞台、动作区和反馈文案的累计高度。桌面浏览器窗口标称 900px 时，扣除浏览器栏后内容区可能只有约 830px；设计稿能装进 900px 不代表实现首屏也能装下。

调整时优先压缩装饰性尺寸和重复空白：封印、插画、标题上下距和分隔区间距。不要先缩小核心触控目标、正文或状态反馈。本次密封猜拳在 390px 宽度下仍让三个出拳按钮保持约 117×116px。

## 用布局数值而不是截图裁切验收

窄截图不等于响应式页面。应让 Chrome 真正进入目标设备宽度，再同时检查：

- `innerWidth === document.documentElement.scrollWidth`，证明没有横向溢出；
- `scrollHeight` 与目标首屏高度的关系，证明核心流程是否需要额外滚动；
- 主要按钮的 `getBoundingClientRect()`，证明触控目标没有为适配而缩水；
- 首屏截图，确认层级、换行和折叠线位置与数值一致。

密封猜拳最终在 Chrome 的 390×844 设备模拟中得到 `innerWidth = scrollWidth = 390`、`scrollHeight = 844`，三个选择按钮高 116px，提交按钮完整可见。

## 适用范围

这套检查适用于同屏游戏、双设备控制器、问答卡和需要快速开始的惊喜页。长文章和内容型页面不必追求一屏完成，但首个主要动作仍应有明确的折叠线预算。
