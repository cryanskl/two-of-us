# 密封猜拳

两台设备加入同一个本地房间，各自选择石头、剪刀或布。第一份提交只会被本机 Node 裁判保存；两人都提交后才向本轮两位参与者同时揭晓。平局不加分，先得 2 分者赢下比赛。

## 启动与玩法

- 等级：C（本地服务 + 局域网双设备）
- 玩家：2 人对抗
- 公网依赖：无
- 首次使用：双击仓库根目录的 `setup.command` 或 `setup.bat`
- 此后使用：直接双击本目录的 `start.command` 或 `start.bat`；也可从根目录统一门户打开

玩家一创建房间并把五位房间码告诉玩家二。两台设备应连接同一个可信 Wi-Fi。两人到齐后由主机开始对局；每轮选择并密封出拳，双方都提交后同时揭晓。平局继续下一轮，先得 2 分后可以重新开始。

## 信任、隐私与断线边界

- 这是“**玩家浏览器之间密封、信任本机 Node 裁判**”的协议，不是端到端加密，也不是密码学 commit–reveal；运行本地服务的 Node 进程能够读取两人的选择。
- 未揭晓选择只通过 `room:sealed-submit` 交给本机裁判，不进入公开房间状态，也不由浏览器自报身份。
- 第一份提交的响应只说明仍在等待，不包含任何一方的选择；收齐后，裁判只把完整结果定向发送给本轮冻结的两位参与者。
- 已揭晓的双方选择与比分状态也由主机通过 `room:direct` 只定向给另一位参与者，不向房间第三人广播。
- 非主机收到比分后，会用自己刚收到的密封结果重新计算并校验；版本、回合、成员或比分不一致的状态不会被采用。
- 第三位加入者会自动退出。任一成员离开、成员被替换、主机迁移或连接断开时，尚未揭晓的选择和当前比赛都会清空，不做断线续局。
- 房间只用于用户自己控制的可信局域网，不应暴露到公网；选择和比分不写入磁盘、历史记录或日志。

- **[Socket.IO](https://github.com/socketio/socket.io) 4.8.1（MIT）**：作为共享本地运行时的直接依赖，本作品只通过其公开 API 使用连接、房间、acknowledgment 与定向 socket 投递能力；没有复制或改写其示例源码、文档、视觉与素材。
