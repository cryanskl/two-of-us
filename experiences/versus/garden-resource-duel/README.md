# 这一朵，我先养开

两个人共用一台设备的本地热座卡牌对抗。每轮先看共同季节，再轮流遮屏藏一张有限
手牌；两张牌一起揭晓，匹配季节就长花瓣，虫害只会挡住对方这一轮。

## 直接打开

双击 `index.html` 即可运行。页面使用经典脚本和相对路径，不需要安装、构建、服务
器、账号、权限或联网，也不会读取仓库外的共享文件。

1. 每人有 2 张阳光、2 张雨露和 2 张虫害；揭晓后实际使用的牌会消耗。
2. 六轮公共季节恰有 3 次阳光需求和 3 次雨露需求，当前轮公开，未来顺序隐藏。
3. 阳光或雨露匹配当前需求时，获得本轮的 `1 / 1 / 2 / 2 / 3 / 3` 片花瓣。
4. 虫害能挡住对方本轮本来能获得的花瓣，自己不得分，也不会扣掉旧花瓣。
5. 先达到 5 片花瓣者开花；同轮达到则平局。六轮后按花瓣数决定结果，同分仍平局。

每轮第一位藏牌者交替，但两份选择总是从同一个回合起点联合结算，输入顺序不构成
得分优势。

## 键盘、遮屏与降级

- `Tab`、`Shift+Tab`、`Enter`、`Space` 使用原生按钮完成整局；
- 秘密选择时可按 `1 / 2 / 3` 选择当前显示的第 1 / 2 / 3 张可用牌；
- 秘密选择时按 `Escape` 会丢弃未确认草稿并回到交接页；
- 窗口失焦、页面隐藏或离开页面时也会自动遮屏，恢复后必须重新明确接管；
- 页面没有倒计时、拖拽、抢按或自动揭晓；
- 320px 窄屏、200% 缩放、减少动态和强制颜色模式下仍保留文字规则、按钮、精确
  花瓣数与公开历史。

确认一张牌后，选择列表和本地草稿会立即从当前页面节点中移除。公开状态消息只播
报交接、共同揭晓和结果，不播报秘密草稿或已封存牌值。

## 个性化

可在 `config.js` 中安全修改标题、副标题、规则简介、两位玩家的显示名和默认结语。
`composeResultNote(summary)` 只接收公开终局摘要，可返回一段纯文本专属结语。

不要把用户输入解释成 HTML，也不要在配置中提交真实姓名、纪念日或私人消息。

## 正常热座隐私边界

未揭晓选择只保存在当前页面的 JavaScript 内存中，不写入 DOM、URL、浏览器存储、
剪贴板或网络。第一位确认后不会提前扣减公开手牌，因此第二位不能通过库存变化推断
牌种；两位确认后仍需主动点击“我们一起揭晓”。

这是两个人正常传递同一设备时的视觉遮挡，不是密码学加密。主动打开开发者工具、
检查进程内存或修改页面脚本的人，仍可能看到或改变内部状态。需要抵御主动检查时，
应采用带可信提交协议的双设备版本，而不是依赖本页。

刷新或关闭页面会清空整局，不提供存档、恢复、统计或导出。
