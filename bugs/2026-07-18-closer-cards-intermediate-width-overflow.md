# 靠近一点：861–980px 仍使用双列导致中间宽度溢出

- 状态：`fixed`
- 日期：2026-07-18
- 影响作品：靠近一点响应式布局
- 发现版本 / commit：`d33f18d`

## 环境

- macOS；headed Chrome；
- localhost 与 A 级 `file://` 入口；
- 900px 左右的窄桌面或横屏平板视口。

## 复现步骤

1. 把视口宽度设为 900px；
2. 打开第一张问题卡；
3. 比较文档 `scrollWidth` 与 `clientWidth`，并观察左轨和纸卡。

## 预期结果

中间宽度应切成移动布局，文档没有横向滚动，席位轨、纸卡和动作都能完整到达。

## 实际结果

修复前 860px 以上仍强制使用双列。两列最小宽度 238px + 620px，再叠加 gap 与页面边距，900px 附近无法容纳。

## 根因

响应式断点只参考常见手机宽度，没有把桌面网格的最小列宽、间距和外边距纳入几何预算。

## 解决方案

把移动布局切换点提前到 980px；981px 才启用双列。目录 Gate 固定检查该断点，防止后续样式回退。

## 回归验证

- [x] 320、390、900、980px 均满足 `scrollWidth = clientWidth`；
- [x] 981px 双列布局满足 `scrollWidth = clientWidth`；
- [x] 320px 主按钮 60px、次按钮 48px；
- [x] 整仓测试 390 / 390，控制台 0 error / 0 warning。
