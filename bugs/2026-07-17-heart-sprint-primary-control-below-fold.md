# 心跳冲刺：常见桌面与手机首屏看不到完整主控制

## 状态

已修复，2026-07-17。

## 复现条件

1. 从本地运行时进入一场双人比赛；
2. 在 Chrome 1269×774 内容区保持页面顶部，首稿的主控制按钮落在折叠线以下；
3. 在 390×844 设备指标下重复，按钮底部约为 902px，必须滚动才能完整点击。

## 原因

首稿分别实现了顶栏、比分、两条赛道、状态区和主控制，却只按页面宽度切换布局。各区的最小高度、上下间距和赛道负边距叠加后超过实际内容区；1586×992 的冻结概念能容纳这些元素，不代表常见桌面浏览器扣除工具栏后的 774px 内容区也能容纳。

## 解决方案

- 为宽度至少 641px、内容区高度不超过 850px 的短桌面增加高度预算，压缩顶栏、比分、赛道和状态间距；
- 在 390px 移动布局中进一步压缩元数据和赛道之间的重复空白；
- 不通过隐藏状态、缩小文案或把主按钮降为小按钮来适配；桌面主控制仍高 104px，390px 下仍为 132px；
- 320×700 允许纵向滚动，但保持无横向溢出、房间码可见和按钮高度 122px。

## 回归验证

- [x] 1269×774 得到 `scrollHeight = 774`，主控制完整位于首屏
- [x] 390×844 得到 `scrollWidth = innerWidth = 390`、`scrollHeight = 844`
- [x] 390px 主控制约 358×132px，底部约为 760px
- [x] 320×700 无横向溢出，允许纵向滚动到约 797px
- [x] reduced-motion 下点击仍能推进权威进度
- [x] 双端控制台无 warning 或 error
