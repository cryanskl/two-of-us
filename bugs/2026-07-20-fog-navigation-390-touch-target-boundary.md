# 雾里，跟着你走：390px 包含断点把方向键降到 52px

- 日期：2026-07-20
- 阶段：390×844 与 320×700 浏览器响应式验收
- 影响：390px 常见手机宽度未满足规格冻结的 56px 方向键门槛
- 状态：已修复并重新测量控件与首屏布局

## 复现

1. 以 390×844 视口打开 `experiences/co-op/fog-navigation/index.html`；
2. 进入驾驶阶段，读取四个 `.direction-button` 的 `getBoundingClientRect()`；
3. 按钮宽高均为 52px，而 390px 规格要求 56px。

## 根因

极窄屏降级规则原为 `@media (max-width: 390px)`。`max-width` 是包含边界，恰好 390px 的视口也会命中，于是基础移动端的 56px 被提前覆写为 52px。样式意图中的“低于 390px”和 CSS 实际表达的“小于等于 390px”不一致。

## 修复

- 把极窄屏规则收紧为 `@media (max-width: 359px)`；
- 390×844 保持 56×56px，320×700 在空间受限时使用 52×52px；
- 两个视口都重新检查完整 5×5 雾窗、方向控制首屏可见性与 `scrollWidth === innerWidth`；
- 浏览器控制台保持零 warning/error。

## 可复用结论

响应式门槛应写成可测试的区间，而不是凭设备名称推断。若一个冻结验收点正好位于媒体查询边界，必须读取最终几何；`max-width: N` 包含 N，本意为“小于 N”时应选择明确的下一个整数边界或改写区间。
