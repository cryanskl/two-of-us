# Bugs / Learn 公开发布检查清单

`bugs/` 和 `learn/` 是项目的公共工程知识库。公开的目标是让读者能够理解问题、复现结论并验证修复，而不是完整暴露开发机器、临时环境或排查聊天记录。

## 可以直接公开

- 已修复并完成回归验证的产品、交互、可访问性和兼容性缺陷；
- 有明确适用范围、反例和验证方法的稳定工程结论；
- 对用户有帮助的已知限制，以及写清理由和替代方案的 `wont-fix`；
- 为理解根因所必需的工具或平台信息，但应使用通用名称和可移植命令。

## 需要延迟或限制公开

- 尚未修复、可能被用于绕过隐私边界、破坏数据或影响其他用户的问题；
- 包含私人照片、聊天、账号、未发布素材或第三方受限内容的证据；
- 凭据、令牌、Cookie、私钥、精确内网地址、个人用户名和机器目录结构；
- 只有临时执行噪音、没有可复用结论的工具故障或排查流水。

安全或隐私问题应先私下记录最小复现，完成修复、负向测试和影响复核后，再公开经过脱敏的根因与验证方法。

## 脱敏约定

公共文档统一使用以下占位符：

| 占位符 | 含义 |
| --- | --- |
| `<repo-root>` | 当前仓库根目录 |
| `<worktree-root>` | 当前隔离 worktree 根目录 |
| `<tool-runtime>` | 工具提供的解释器或运行时 |
| `<skill-root>` | 可选开发工具或 skill 的安装目录 |
| `<temporary-host>` | 仅在一次验证中有效的主机或 IP |

占位符应保留命令和错误的解释力。例如将个人 worktree 下的 `catalog.json` 写成 `<worktree-root>/catalog.json`，不要直接删掉与根因有关的文件名。

## 提交前检查

1. 确认状态、影响范围和日期准确；
2. 确认“根因”不是未经验证的推测；
3. 确认修复记录包含原始复现和相关自动检查；
4. 搜索绝对用户路径、凭据模式、临时 IP 和私人内容；
5. 检查引用、截图、第三方代码和素材是否允许公开；
6. 确认 `bugs/README.md` 或 `learn/README.md` 的索引已同步。
