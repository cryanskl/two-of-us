# 在雾上，写给你：移动完成态重开按钮被信件滚动区裁切

- 状态：`fixed`
- 日期：2026-07-19
- 影响作品：在雾上，写给你
- 发现版本 / commit：前端实现的提交前候选；修复随 `312b18c feat: build fog window letter experience` 进入

## 环境

- 操作系统：macOS
- 浏览器与版本：Codex in-app Chromium，390×844 与 320×700
- 启动等级与入口：A 级作品，经本地仓库服务加载同一静态入口

## 复现步骤

1. 在 390×844 打开作品并选择“直接打开”。
2. 读取重开按钮的 `getBoundingClientRect()`，再查看真实视口截图。
3. 对照按钮与 `.completion-letter` 的裁剪边界。

## 预期结果

完成标题、正文首段、署名与“再写一次”都在移动首屏内真实可读可点。

## 实际结果

按钮报告 `top=418 / bottom=466`，看似处于 844px 视口内；但信件容器底部只有 425px 且 `overflow:auto`，按钮实际只露出顶部约 7px，文字完全不可见。

## 根因

验收只比较按钮与 viewport，没有把裁剪祖先的可视区域纳入判断。移动雾窗固定为 280px，完成信的内容高度超过其 88% 上限。

## 解决方案

只在移动 `complete` 阶段把雾窗高度调整为 `clamp(320px, 100svh - 330px, 390px)`。进行中书写面仍为 280px；完成阶段已无 Pointer 规则输入，resize 只从 view 重绘。

- [x] 320×700：重开按钮完整可见且文档无横向溢出
- [x] 完成标题仍获得焦点，重开后完成 DOM 被删除
- [x] 浏览器截图与几何/裁剪边界同时核对
