# 爱心投石器：检测顺序把较晚城堡接触判在较早触地之前

- 状态：`fixed`
- 日期：2026-07-24
- 影响作品：`heart-catapult` 调研与后续确定性物理合同
- 发现版本 / commit：调研批次提交前候选

## 环境

- 操作系统：macOS
- 载体：`docs/247-heart-catapult-research.md` 提交前审稿
- 启动等级：计划中的 A 级 `file://`
- 影响范围：同一固定 tick 内可能同时包含目标、地面或世界出口候选事件的连续碰撞

## 复现步骤

1. 采用初稿规定的 tick 顺序：“先对整段检查城堡 AABB，命中优先；再检查地面”；
2. 构造一条同时经过地面阈值与按爱心半径扩张后城堡 AABB 的运动线段；
3. 让地面首次接触参数为 `groundT = 1 / 2`；
4. 让城堡首次接触参数为 `castleT = 4 / 5`；
5. 按初稿检测顺序处理该 tick。

## 预期结果

`1 / 2 < 4 / 5`，爱心应先触地。若这是第一次触地，应落到精确接触点、反射竖直
速度并结束当前 tick；下一 tick 再从反射后的状态继续。不能命中位于未反射原线段
后半段上的城堡。

## 实际结果

初稿先对整条候选线段检查城堡，只要后半段与目标相交便立即返回 hit；较早发生的
地面接触没有机会参与裁决。

“同 tick 同时接触时城堡优先”也无法修正这个问题，因为初稿没有分别计算两个接触
参数，更无法判断它们是严格先后还是完全相等。

## 根因

文档混淆了：

- **时间优先级**：候选事件中最小接触参数 `t` 先发生；
- **相等时 tie-break**：只有两个最小 `t` 完全相等时，才用城堡、地面、出界的
  固定优先级；
- **代码检测顺序**：先写哪个 `if`。

若直接把代码检测顺序当作事件优先级，同一规格可以产生两套不同轨迹；圆形弹体对
半径扩张目标 AABB 时，靠近地面的目标尤其容易触发该歧义。

## 解决方案

- 分别求城堡、地面和世界出口的最早候选 `t`；
- 城堡使用“圆心线段对按爱心半径扩张后的目标 AABB”；
- 地面使用圆心对 `GROUND_Y - HEART_RADIUS` 的穿越；
- `t` 保持规范化的精确有理数，以安全整数交叉乘比较，不转换为浮点；
- 先处理严格最小的 `t`，仅在完全相等时使用“城堡、地面、出界”优先级；
- 第一次触地落到精确接触点、反射后结束本 tick，不消费剩余线段；
- 下一 tick 从接触点和反射速度继续；
- 分子、分母和交叉乘积全部纳入 `Number.MAX_SAFE_INTEGER` headroom 证明。
