# 和你一样：历史回合编号可复用并永久等待

## 状态

已修复，2026-07-17。

## 复现条件

1. 第一题使用 `round-1` 完成揭晓；
2. 第二题使用 `round-2` 完成揭晓；
3. 第三题再次使用 `round-1`，双方提交答案。

## 预期结果

状态机拒绝任何已经完成的历史回合编号。

## 实际结果

首稿只检查新编号不等于“当前”编号，因此 `round-1 → round-2 → round-1` 可以推进。服务端密封 registry 对完成过的 `round-1` 只返回 `replayed` acknowledgment，不会再次广播结果；前端把它当作成功提交，双方随后永久等待。

## 根因

前端状态没有保存历史编号，而任意字符串 `roundId` 又无法从当前公开状态判断是否属于当前题。服务端 tombstone 的幂等保护与客户端过宽的编号规则组合后，产生了合法 ack 但永远没有新结果的状态。

## 解决方案

让 `roundId` 由 `quizId + questionIndex` 确定性推导，并在创建、下一题、重开和公开状态验证中核对绑定关系。这样不增加公开状态字段，也能从当前题唯一判断编号是否正确；新局使用新 `quizId`，不会与旧 tombstone 碰撞。
