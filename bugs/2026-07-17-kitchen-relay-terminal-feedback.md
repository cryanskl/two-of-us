# 双人小馆：第三次洒落的普通事件覆盖失败反馈

- 状态：`fixed`
- 日期：2026-07-17
- 影响作品：双人小馆失败终局与重新开始播报
- 发现版本 / commit：实现提交前工作区

## 环境

- macOS 26.5.2；headed Chromium 150.0.7871.125；
- 连续三次在正确滑槽接到错误食材。

## 复现步骤

1. 累计两次洒落；
2. 第三次接取错误食材；
3. 比较状态、可见事件条与 `aria-live`；再点击“重新开门”。

## 预期结果

状态进入 failed，可见与可访问反馈都说明“三次洒落到了”；重新开始后旧终局播报被清除。

## 实际结果

状态和焦点正确，但第三次接取携带 `ingredientId`，渲染器优先调用普通事件文案，显示“下一样继续配合”；重开 intro 后 live region 还残留上一局失败文案。

## 根因

渲染优先级按“是否有食材事件”判断，没有先判断终局；live region 也只在有新事件时写入，没有在无事件阶段清空旧内容。

## 解决方案

文案顺序固定为 success / failed / order-clear / 普通接取事件；每次 render 都同步设置或清空 live region，不让上一阶段继续拥有播报节点。

## 回归验证

- [x] 三次洒落后可见文案与 live region 都为明确失败反馈；
- [x] failed 的“重新开门”获得焦点；
- [x] 重回 intro 后 live region 不保留失败文案；
- [x] 成功终局和普通 correct / wrong / missed 文案不受影响。
