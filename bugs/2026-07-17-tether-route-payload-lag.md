# 同心牵引：验证轨迹忽略吊坠滞后而卡在第二幕

## 状态

已修复，2026-07-17。

## 复现条件

1. 运行第二幕首版确定性输入轨迹；
2. 两枚线轴到达上方通路后立即转为向下；
3. 观察吊坠尚落后约 94px 时的针脚与中央软垫位置。

## 预期结果

用于证明关卡可解的轨迹应只通过生产 `stepGame()` 完成第二幕，且不借助危险区重置。

## 实际结果

线轴过早下降，吊坠仍在上方针脚附近；一枚线轴随后被中央软垫挡住，轨迹停在 waypoint 1，关卡保持 `playing`。下游状态机测试继续使用这条未完成轨迹，又表现为完成/重玩状态和 `resetCount` 断言不一致。

## 根因

连续弹性系统中，控制端到达 waypoint 不代表共享载荷已经通过同一位置。首版验证控制器只观察线轴，没有给吊坠的惯性和丝带相位差留下收束阶段。

## 解决方案

第二幕轨迹改成两个明确阶段：先让两枚线轴保持上方路线，直到吊坠完整越过针脚和软垫；再一起下降并收束。测试同时要求完成轨迹 `resetCount === 0`，避免把“碰危险后回起点”误当作通关路径的一部分。

## 回归验证

- [x] 第二幕通过生产 reducer 进入 `level-complete`
- [x] 三幕轨迹都不触发危险重置
- [x] 至少一幕包含双方同一步向不同方向输入
- [x] 重开与最终重玩清零步数和重置次数
