# 运行时相邻端口测试偶发冲突

## 现象

全量测试偶发失败，错误为：

```text
端口 62917 到 62918 均被占用。
```

单独重跑 `shared/runtime/server.test.js` 通常可以通过。

## 原因

测试先让占位服务器监听一个系统分配的临时端口，再断言运行时一定选择紧邻的下一个端口。操作系统只保证第一个临时端口已分配，并不保证 `端口 + 1` 空闲；并行测试或本机其他进程可以合法占用它。

运行时按顺序寻找可用端口的实现没有故障，偶发失败来自测试把“相邻端口空闲”当成了环境契约。

## 解决

- 保留第一个端口必定被占用的真实网络测试。
- 将搜索窗口从 2 个端口扩到 32 个端口。
- 断言结果位于搜索窗口内且不等于被占用端口，不再要求必须是 `端口 + 1`。
- 避开过高的临时端口，确保完整测试窗口不会越过合法端口上限。

## 验证

- 连续重复运行定向测试。
- 运行 `npm test`。
- 运行 `npm run verify`。
