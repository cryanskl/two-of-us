# 这一弹，拐弯见你：同刻发射的弹体 ID 破坏镜像重放

- 状态：`fixed`
- 日期：2026-07-25
- 影响作品：`ricochet-tank-duel`
- 发现版本 / commit：`b9bddfe`
- 失败测试提交：`6b4c3c4`
- 修复提交：`66e3575`

## 环境

- 操作系统：macOS
- 运行时：Node.js 22，纯 CommonJS 核心测试
- 入口：`js/simulation.js` 的重放、哈希和镜像变换

## 复现步骤

1. 创建 `START + 180 STEP` 的固定日志，使状态进入 `playing`。
2. 再追加双方都带 `FIRE_EDGE` 的同一个 `STEP`。
3. 分别重放原日志与逐项 `mirrorAction` 后的日志。
4. 将镜像日志结果用 `mirrorState` 反镜像，再比较规范状态和哈希。

## 预期结果

原日志与镜像日志在反镜像后应得到完全相同的规范状态和哈希。弹体 ID 属于逻辑
字段，不能因为固定从左席开始遍历就改变物理对象的身份。

## 实际结果

双方同刻发射时，原重放固定把 `id=1` 分给左方、`id=2` 分给右方；镜像状态只交换
owner 和坐标而保留 ID。因此反镜像结果中两个 ID 绑定到了相反弹体，规范状态和
FNV-1a 哈希同时分叉。旧测试只证明 `mirrorState(mirrorState(state)) === state`，
没有证明 reducer 与镜像变换可交换。

## 根因

全局单调 ID 按玩家遍历顺序逐个分配。这个顺序以“左席优先”为坐标约定，不具备
镜像对称性；给定同刻的两个对称创建事件，无法在保留原分配方式的同时让稳定 ID
也满足镜像等价。

## 解决方案

- 每个发生成功发射的 tick 预留一对 ID；
- 奇数 ID 固定属于左席，偶数 ID 固定属于右席；
- 即使只有一方成功发射，也将下一批基址推进 2；
- 镜像状态和带 bulletId 的语义事件同步翻转 ID 奇偶；
- validator 要求 ID 与 owner 席位匹配、`nextBulletId` 为奇数批次基址；
- ID 空间接近安全整数上限时拒绝继续分配，保证合法状态仍可安全推进。
