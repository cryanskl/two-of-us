# 这一颗我先到：终局标题与正文重复显示两次

- 状态：`fixed`
- 日期：2026-07-18
- 影响作品：这一颗我先到
- 发现版本 / commit：`db1700d`

## 环境

- macOS；Playwright CLI headed Chromium；
- 入口：`http://127.0.0.1:4175/experiences/versus/orbit-star-race/index.html`；
- 视口：1504×1046；通过生产按钮完成 5–1 对局。

## 复现步骤

1. 点击“开始抢星”；
2. 只通过四个公开升降轨按钮完成至少五次捕获；
3. 进入 `finished` 后查看左侧动态状态和操作区。

## 预期结果

终局标题与正文只有一个权威显示位置，另有一个“再绕一圈”主动作；结果焦点落到唯一标题。

## 实际结果

`getViewModel()` 的终局状态已经把默认结果写入动态状态区，`renderAction()` 又创建第二套标题和正文。截图和可访问树里都出现两次“朱方抢先一步”；删除第二套可见节点后，终局 `aria-live` 播报又会与主动聚焦的结果标题重复。

## 根因

状态区和操作区同时承担了结果文案所有权；custom formatter 又只在第二套结果节点执行，导致简单删除任一节点都会丢失定制文案或焦点契约。同时，终局既更新 live region 又主动聚焦标题，存在双重播报路径。

## 解决方案

终局时先通过 `resolveResultCopy(state, config)` 得到唯一文案并写入既有 `#status-title / #status-body`；操作区只生成“再绕一圈”按钮。结果焦点改落到 `#status-title`，并在该终局转换中清空 live region，避免同一结果被重复播报。比分、星盘和按钮继续分别由原组件负责。

## 回归验证

- [x] 生产 5–1 终局只出现一次标题与正文；
- [x] `#status-title` 获得焦点，live region 不再重复播报；
- [x] 四个轨道按钮禁用且“再绕一圈”唯一可用；
- [x] 重开后比分、claim 与起点归零。
