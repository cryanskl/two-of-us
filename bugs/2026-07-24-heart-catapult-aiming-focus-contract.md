# 爱心投石器：aiming 初始焦点出现两套互斥合同

- 状态：`fixed`
- 日期：2026-07-24
- 影响作品：`heart-catapult`
- 发现版本 / commit：`docs/252-heart-catapult-design.md` 提交前候选

## 环境

- 操作系统：macOS
- 浏览器与版本：设计合同审查阶段，尚未进入生产浏览器实现
- 启动等级与入口：A；问题位于视觉设计文档

## 复现步骤

1. 打开设计候选中的 `aiming` 阶段；
2. 读取该阶段末尾的焦点要求，观察其要求接管后直接聚焦角度 range；
3. 再读取“焦点、输入与播报”章节；
4. 观察全局合同要求每次 phase 转换先聚焦新阶段标题。

## 预期结果

每个 authority phase 只有一个可判定的初始焦点。进入 `aiming` 时应先聚焦阶段
`h2`，让用户得知当前席位与秘密瞄准上下文；自然 Tab 的下一站才是角度 range。

## 实际结果

初稿同时规定“直接聚焦角度 range”和“先聚焦阶段标题”，实现者无法同时满足，
浏览器测试也无法定义唯一断言。

## 根因

阶段局部描述从“最快开始操作”出发，全局无障碍描述从“先宣告新上下文”出发；
两者在合并时没有通过逐阶段焦点矩阵校验。

## 解决方案

- 把 `aiming` 局部合同统一为先聚焦阶段 `h2`；
- 明确自然 Tab 的下一站是角度 range；
- 保留锁定后立即销毁草稿控件并进入 handoff 的要求；
- 最终审查逐项比较阶段局部焦点与全局焦点规则。
