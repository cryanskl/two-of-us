# 这一弹，拐弯见你：伪造弹体可跨 tick 重叠对手并凭空计分

- 状态：`fixed`
- 日期：2026-07-25
- 影响作品：`ricochet-tank-duel`
- 发现版本 / commit：`5077976`
- 失败测试提交：`7b56433`
- 修复提交：`bf47e10`

## 环境

- 操作系统：macOS
- 运行时：Node.js 22，纯 CommonJS 核心测试
- 入口：`validateState` 与下一次 `simulatePlayingTick`

## 复现步骤

1. 构造 exact-key `playing` state。
2. 放入 owner 为左方、位置等于右方车体中心、速度与 ID 均合法的弹体。
3. 调用 `validateState`，再推进一个空输入 tick。

## 预期结果

弹体与对手达到接触距离时，连续碰撞循环会在当前 tick 立即销毁弹体并记录命中；
因此任何被持久化到 tick 边界的合法 state 都不得保留“弹体与对手相交”的组合。

## 实际结果

validator 只检查弹体对墙体的重叠，没有检查弹体对对手车体的重叠。伪造状态通过
后，下一 tick 把“初始重叠”解释成即时命中，使攻击者能注入一分。

## 根因

几何层正确把初始重叠视为不变量错误，但模拟层为了防御内部误差会将该错误转换为
命中。state 边界没有先排除 reducer 永远不会生成的跨 tick 对手重叠，导致防御
分支也能被外部伪造状态触发。

## 解决方案

在 tanks 和 bullets 都完成规范化后，validator 对每枚弹体与其对手执行精确整数
距离检查；距离小于等于两者半径之和即拒绝。自己的弹体仍可穿过己方车体，保持
“不自伤”规则不变。
