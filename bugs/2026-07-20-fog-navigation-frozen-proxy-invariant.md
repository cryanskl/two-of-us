# 雾里，跟着你走：冻结 Proxy 违反属性描述符不变量

- 日期：2026-07-20
- 阶段：完成结语配置的只读摘要实现与单测
- 影响：自定义 `composeCompletionNote` 读取受保护摘要时可能抛出 `TypeError`，错误回退掩盖了合法配置
- 状态：已修复并增加恶意读取/写入回归测试

## 复现

1. 把完成摘要包装为带读取类陷阱的 Proxy；
2. 冻结 Proxy 的目标对象，使目标属性变成不可配置；
3. 自定义完成结语读取 `summary.seats` 或嵌套轮次；
4. JavaScript 引擎因代理报告的描述符与冻结目标不兼容而抛出不变量 `TypeError`。

## 根因

Proxy 不能虚构与目标对象不可配置属性相冲突的结果。目标被冻结后，读取/描述符相关陷阱仍试图返回重新包装的值或不一致描述，违反 ECMAScript Proxy invariants。问题不是业务数据不合法，而是“冻结目标”和“动态代理读取”两套只读手段叠加后互相冲突。

## 修复

- 先把摘要递归复制到完全断开的普通数组/对象；
- 嵌套值在落入目标前就递归替换为对应 guard，不再在属性读取时动态换值；
- Proxy 只保留 `set`、`deleteProperty`、`defineProperty` 与 `setPrototypeOf` 四类写操作拒绝陷阱；
- 填充完成后冻结真实 target，使 Proxy 的默认读取与目标描述符完全一致；
- 单测覆盖深冻结、引用隔离、嵌套写入失败、抛错 composer，以及 `seats` 为恶意 getter 时的安全默认结语。

## 可复用结论

对传给不可信回调的只读快照，最稳妥的顺序是“先断开复制并递归包裹，再冻结真实目标，最后只拦截写操作”。一旦目标含不可配置属性，任何 `getOwnPropertyDescriptor` 或动态换值陷阱都必须逐条证明符合 Proxy 不变量，否则合法读取也会失败。
