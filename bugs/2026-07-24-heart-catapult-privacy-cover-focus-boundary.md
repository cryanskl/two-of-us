# 爱心投石器：隐私遮罩只盖住画面但没有闭合焦点边界

- 状态：`fixed`
- 日期：2026-07-24
- 影响作品：`heart-catapult`
- 发现版本 / commit：`04d903f` 提交前候选

## 环境

- 操作系统：macOS
- 浏览器与版本：Chrome MCP 当前连接版本
- 启动等级与入口：A；`experiences/versus/heart-catapult/index.html`

## 复现步骤

1. 第二位玩家进入秘密瞄准，修改角度与力度但不锁定；
2. 按 Escape，或让页面进入隐藏、失焦状态；
3. 用 Tab、读屏可访问树和页面恢复事件检查遮罩后的焦点与背景；
4. 恢复游戏并再次查看瞄准控件。

## 预期结果

遮罩出现时销毁未锁定草稿、停止飞行动画、让游戏背景不可聚焦且退出可访问树，并
把焦点放到遮罩标题；页面重新可见时焦点仍在隐私区，只有明确继续后才返回当前
阶段标题。

## 实际结果

候选实现只有视觉遮罩。背景内容仍可能被 Tab 或读屏访问；页面从隐藏回到可见时
焦点可能落在 `body`；未锁定的秘密草稿也可能留在控件中。

## 根因

隐私遮罩最初被当成展示层浮层，没有建模为独立的生命周期状态，因此没有同时统筹
草稿清理、动画取消、`inert`、`aria-hidden` 和恢复焦点。

## 解决方案

- 激活遮罩时清空本地 aiming 草稿并取消当前播放；
- 对游戏根节点同步设置 `inert` 与 `aria-hidden`；
- 遮罩标题设为程序化焦点目标，恢复可见时补偿浏览器丢失的焦点；
- 继续按钮只关闭遮罩，然后把焦点交还当前权威阶段标题。

## 回归验证

- [x] Chrome 中 Escape、窗口失焦和页面可见性路径均进入遮罩
- [x] 遮罩期间背景为 `inert` 且 `aria-hidden="true"`
- [x] 页面恢复可见后焦点保持在隐私标题或唯一继续动作
- [x] 继续后第二位玩家的未锁定草稿恢复默认值
- [x] 最终只读复审确认无剩余 P0/P1/P2
