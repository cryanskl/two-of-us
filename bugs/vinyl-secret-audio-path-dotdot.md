# vinyl-secret 音频文件名错误接受连续点

- 日期：2026-07-25
- 项目：`vinyl-secret`
- 阶段：纯逻辑内核实现

## 环境

- Node.js：项目当前 Node 运行时
- 分支：`codex/exp-vinyl-secret-core`
- 受影响提交：`2047303`

## 复现

把一条有效配置的 `audioSrc` 改成：

```text
./assets/private-audio/a..b.mp3
```

再调用 `sanitizeConfig(candidate)`。修复前该配置被接受，返回的轨道仍保留上述路径。

## 预期与实际

- 预期：规格明确拒绝任何包含 `..` 的音频路径，整份配置应原子回退到默认配置；
- 实际：文件名字字符白名单包含 `.`，原正则也允许连续两个点，因此 sanitizer 接受了它。

## 影响

目录前缀、额外斜杠和反斜杠仍被白名单拒绝，所以这不是已证实的目录穿越。实际影响是配置校验与冻结规格不一致，会让后续 UI 接收到本应拒绝的音频元数据。

## 根因

实现只用一条正则同时约束目录、文件名和扩展名，却没有为“文件名不得出现连续 `..`”增加独立语义检查。

## 修复

在正则校验前增加 `audioSrc.includes("..")` 拒绝条件；任何命中都让整份配置回退。

## 回归

- 最小复现应从 `accepted: true` 变为默认回退；
- 正式 `logic.test.js` 将覆盖 `a..b.mp3`、路径段 `../` 与其他白名单反例；
- 运行项目测试、`npm test`、`npm run verify` 与 `git diff --check`。
