# Dual Maze Race 桌面低高度下控制区被首屏裁切

- 日期：2026-07-26
- 项目：`dual-maze-race`
- 环境：Google Chrome，约 1728×906 CSS px，localhost 静态入口
- 状态：已修复

## 复现

1. 打开 `experiences/versus/dual-maze-race/index.html`；
2. 完成输入检查并进入 racing；
3. 保持桌面宽屏，但把可用高度控制在约 900px；
4. 查看两块棋盘下方的方向控制。

## 预期与实际

预期是 1440×900 级别的桌面视口同时看到比赛信息轨、两块完整迷宫、两组方向控制和
暂停入口。

实际首轮 CSS 只按宽度断点缩放。棋盘保持 560px，页面截图只露出两组“向上”按钮，
其余控制落到首屏之外。

## 根因

双盘竞技页的垂直预算同时包含标题、信息轨、玩家标题、正方形棋盘和 3×3 控制区。
仅用 `max-width` 响应式不能覆盖“很宽但不高”的桌面窗口；棋盘上限没有关联
`100vh`，导致它独占了过多高度。

## 修复

在 `min-width: 901px` 且 `max-height: 1100px` 时：

- 压缩标题和局部留白；
- 隐藏不影响规则的棋盘位置辅助行；
- 把棋盘宽度限制为 `min(100%, calc(100vh - 450px), 520px)`；
- 比赛阶段隐藏重复的底部本地说明，保留 live status；
- 方向按钮保持 52px，不通过缩小触控目标换空间。

## 回归

- 项目 core + UI contract：31/31；
- Chrome 1536×1024 与约 1728×906：双盘等宽，八个方向按钮与共享暂停完整进入首屏；
- 触控目标仍不小于 52px；
- 390/320 的独立宽度策略不受该桌面 media query 影响。
