# 软软相扑：生产背景与 DOM 场地形成双重竞技场

- 状态：`fixed`
- 日期：2026-07-19
- 影响作品：软软相扑
- 发现版本 / commit：前端提交前候选

## 环境

- 操作系统：macOS
- 浏览器与版本：Codex 内置 Chromium，1280×720
- 启动等级与入口：A 级，本地静态服务器的 `experiences/versus/soft-sumo/index.html`

## 复现步骤

1. 让 `arena-background.webp` 成功加载。
2. 打开 intro 或 playing，并截取首屏。
3. 比较生产图的大编织圆垫、`.arena-frame` CSS 圆场和实际 token 移动范围。

## 预期结果

页面只显示一个可理解为有效边界的大圆场；黄铜逻辑环、token 坐标和编织材质位于同一几何范围。

## 实际结果

初版把含完整大圆垫的生产图铺满 `.page-shell`，同时 `.arena-frame` 又在中央画一个小圆场。截图呈现圆场套圆场，棋子只在内圈活动，玩家无法判断大圆垫还是小圆环决定出圈。

## 根因

生产图本身已经包含场地几何，但 CSS 把它误当成纯地毯背景；实现没有在首次真实截图时核对素材语义与 DOM 几何是否重合。

## 解决方案

页面外层恢复深色 CSS 地毯；仅在 `.arena-frame` 成功加载态使用生产图，按约 177% 宽度居中裁切，使源图中央圆垫填满单一正方形场地。CSS radial 保留为加载失败回退，逻辑 `arena-ring` 继续覆盖同一边界。intro/赛果卡移到场地下部，避免遮住中线出生棋子。

- [x] intro 两枚出生棋子可见
- [x] 390×844 与 320×700 圆场完整且不横向溢出
- [x] 图片加载失败仍有 CSS radial 圆场声明
- [x] forced-colors 明确移除生产图
