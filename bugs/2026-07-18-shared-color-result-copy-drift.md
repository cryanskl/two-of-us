# 把颜色调到一起：合册结语随移动步数偏离冻结文案

- 状态：`fixed`
- 日期：2026-07-18
- 影响作品：把颜色调到一起
- 发现版本 / commit：`5f78ed0`

## 环境

- Node.js 18+ 纯逻辑测试；
- `experiences/co-op/shared-color-studio/config.js`；
- 五轮全部成功后的 `complete` 阶段。

## 复现步骤

1. 调用初版 `composeStudioResult()`；
2. 传入五张完成记录以及非零的色相/明度移动数；
3. 对照实现规格与视觉概念冻结的合册结语。

## 预期结果

默认始终返回：“你转过色相，我照亮明暗。最后留下的是我们一起调出的颜色。”

## 实际结果

初版根据移动步数返回“最后一张用了 N 步”，没有使用冻结文案；零步分支又返回另一句默认文案。同一个完成结果会因操作路径不同而改变结语。

## 根因

实现时把 `moves` 当成可用于丰富结果的统计信息，但规格只把它用于规则观察和测试，没有授权把移动数带入终局。原测试只断言结果包含“五张”，范围过宽，没能保护精确文案。

## 解决方案

- 删除默认结语对 `moves` 的依赖；
- 五张完成时返回规格冻结的精确字符串；
- 不足五张时保留安全的进度回退；
- 把测试从模糊正则改为精确相等；
- 继续保留 `composeStudioResult(view)` 作为用户可编辑的单一定制点。
