## 环境

## 复现步骤

1. 选择手动展示并看完八件旧物。
2. 首位玩家直接报价 8，进入证明阶段。
3. 查看六个旧物选择按钮及其 `.item-sprite` 计算尺寸。

## 预期结果

每个按钮显示对应旧物图片，六件物品分别命中 3×2 图集的六个格位。

## 实际结果

按钮只显示编号与名称，图片区域为空。首个 `.item-sprite` 的计算尺寸为 `0×0`；六件物品的背景位置也都停在默认 `0% 0%`。

## 根因

有两个相互独立的 CSS 合同错误：

1. `.item-button .item-sprite` 在 `grid-template-columns: auto ...` 中使用 `width: min(100%, 104px)`，百分比宽度依赖尚未确定的 `auto` 列，而列的 intrinsic size 又依赖子元素，最终循环计算为零；
2. 渲染函数把 `item-sprite` 与 `item-ticket` 等类放在同一个节点，CSS 却写成 `.item-ticket .item-sprite` 的祖先选择器，因此背景格位规则从不匹配。

## 解决方案

- 按钮内精灵改为确定的 `width: 104px; max-width: 100%`，响应式断点继续给出 72px / 68px / 60px 的明确宽度；
- 图集定位改为 `.item-sprite.item-ticket` 等同节点复合选择器；
- 保留编号、名称和轮廓占位，使图片失败时仍可完成证明。
