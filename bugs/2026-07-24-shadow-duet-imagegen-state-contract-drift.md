# 把影子，跳成我们：ImageGen 把风格引用误当成状态与重复结构真值

- 状态：`fixed`
- 日期：2026-07-24

## 现象

`shadow-duet` 的 16 态视觉概念生成中出现了三类可重复偏差：

1. S5 首稿把冻结的“左右均展开”改成了伸手/弓步，风格连续但业务状态错误；
2. S10 两次首稿为完成页发明标题，并省略每条记录中的“共同完成”；
3. S11 首稿在左右席各复制了两套键位，变成每席八个按钮。

最终 S10 虽保留了六条完整记录，但视觉上把共同摘要排在记录之前；该顺序只作为
概念排版参考，不能进入生产 DOM。

## 原因

参考图能稳定纸幕、色彩、字体性格和组件材质，却不是状态机输入。生成模型倾向于：

- 把相邻状态的姿势当成可自由改写的插画动作；
- 把重复记录压缩成视觉节奏，而不是逐字段保持业务基数；
- 把左右对称理解为复制完整控件组；
- 为“完成感”重组信息顺序或补充看似合理的标题。

因此“使用上一张图保持一致”不能代替精确阶段合同。

## 处置

- 每张图只承载一个冻结状态，prompt 重复声明 phase、允许内容、禁止未来内容；
- 对姿势、按钮数、记录数和尝试次数写出精确基数，而不是只写“完整”；
- 每个候选都用原始分辨率检查，不凭缩略图验收；
- S5、S10、S11 的不合格稿不复制进仓库，只在生成台账登记原因；
- 生产代码逐字使用 172/204 的 DOM 顺序和文案，不 OCR、不裁切、不读取概念 PNG。

## 验证

- `docs/assets/shadow-duet/` 最终包含 S1–S16 共 16 张候选；
- S5 为左右独立“展开”，S11 每席严格四键；
- S10 六条记录都含幕标题、`共同完成` 与尝试次数；
- 16 张图均以 `view_image(detail="original")` 复核；
- 文件尺寸与 SHA-256 固定在 `docs/assets/shadow-duet/GENERATION.md`。

## 防回归

以后生成多状态 UI 时，把下列字段纳入独立验收：

- phase 与此阶段唯一主动作；
- 谁可以操作、谁必须 disabled；
- 重复项的数量、字段、顺序与求和；
- 未来私密内容是否缺席而非仅被遮住；
- no-JS、图片失败和 forced-colors 是否保留必要语义。
