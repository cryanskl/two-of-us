# 双人小馆：营业态超出概念原生桌面高度

- 状态：`fixed`
- 日期：2026-07-17
- 影响作品：双人小馆 1504×1046 桌面首屏
- 发现版本 / commit：实现提交前工作区

## 环境

- macOS 26.5.2；headed Chromium 150.0.7871.125；
- 视口：1504×1046。

## 复现步骤

1. 在 1504×1046 打开 intro；
2. 点击“开门营业”进入包含三格配方的 service；
3. 比较 `documentElement.scrollHeight` 与 `innerHeight`。

## 预期结果

概念原生桌面尺寸内同时看见订单、三条滑槽、双方控制台和本地隐私页脚。

## 实际结果

初版 intro 高 1075px，首次压缩后仍为 1049px；service 因配方和控制台内容扩展到 1077px，页脚被裁切。

## 根因

只给静态区块分配最小高度，没有把状态内容引起的内在高度增长纳入首屏预算。intro 通过不代表信息更密的 service 也通过。

## 解决方案

分别压缩开场网格、订单内边距、配方格、食材按钮和控制键间距，同时保留按钮最小边长；最终 intro 与 service 均为 `scrollHeight = innerHeight = 1046`。

## 回归验证

- [x] 1504×1046 intro 与 service 无纵向、横向溢出；
- [x] 所有桌面可用按钮最小边长不低于 54px；
- [x] 390×844 与 320×760 仍自然滚动且无横向溢出。
