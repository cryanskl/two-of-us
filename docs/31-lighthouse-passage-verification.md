## 2. A 级直开边界

入口只加载相对 `styles.css`、`levels.js`、`logic.js`、`app.js`、本地背景和本地图集，脚本均为经典脚本。作品不依赖 setup/start、Node 服务、Pillow、Matter.js、CDN、远程字体、账号或公网；图像生成和去除图集背景只发生在开发期，不进入运行链路。

本轮 Chrome 控制接口的 URL 安全策略拒绝访问 `file://`，并明确禁止通过其他浏览器接口或 CDP 绕过；因此不能把“自动浏览器实际打开 file URL”列为通过项。真实交互与视觉改在仓库本地 `http://127.0.0.1:4175` 静态服务上验证，A 级直开能力由经典脚本加载顺序、全部相对资源、禁用网络/存储 API 扫描、Node 加载和目录完整性共同证明。这个限制属于验收工具边界，不改变作品代码或启动等级。

## 3. Chrome 真实交互

使用真实 Chrome 页面完成以下流程：

1. ready 页只有一个“点亮海面”主操作；点击后进入 playing，角色控制、暂停和重来启用；
2. 连续发送灯塔 `D` 与小船 `↑` 键，灯塔角度从 `-180°` 变化为 `-179°`，证明页面接入真实键盘事件；完整航行与三幕状态转换由同一生产 reducer 测试覆盖；
3. 点击“暂停”后角色控制禁用，主操作变为“继续领航”；继续后恢复 playing；
4. “玩法”对话框唯一打开，标题为“怎样一起领航”，由“关闭玩法说明”关闭且不改变暂停状态；
5. 点击“重来”恢复第一幕初始规则状态；
6. 1586×992、390×844 与 320×700 三个视口均无横向溢出；
7. 浏览器 warning/error 为 0。

浏览器交互用于验证真实 DOM、事件、Canvas 和响应式外壳；三幕可解、联合输入、角色必要性与所有完成 Gate 由生产 reducer 的确定性轨迹验证，不在页面上下文注入或伪造规则状态。

## 4. 响应式与触控

| 视口 | 结果 |
| --- | --- |
| 1586×992 桌面 | `scrollWidth = innerWidth = 1586`；Canvas 约 1544×546，完整控制台位于 937px 以内 |
| 390×844 触屏 | `scrollWidth = innerWidth = 390`，页面高度 855px；Canvas、航标、并排灯塔/船舵与工具条保持完整，无横向滚动 |
| 320×700 窄屏 | `scrollWidth = innerWidth = 320`，页面纵向高度 982px；两套角色控制纵向排列，所有可见按钮均至少 44×44px |

390px 继续保留两人并排控制，页面只比视口高 11px；320px 不缩小触控目标，而是让灯塔与船舵纵向排列。这里优先保证两个人能准确长按和同时操作，不为了伪造“零滚动”把按键压成装饰。

## 5. 视觉忠实度

最终桌面与 390×844 ready 截图分别和 [`docs/assets/lighthouse-passage/`](./assets/lighthouse-passage/) 的冻结概念图在同一次本地图片检查中对照：

1. **文案**：作品名、幕数、“你照亮前路，我把船开回家”、航标与点亮主操作保持冻结语义；
2. **布局**：桌面保留左标题/中间任务/右幕数、单一大海图与四段控制台；移动端依次为标题、海图、航标、双角色面板和工具条；
3. **排版**：标题采用系统宋体栈，状态与控制使用清晰正文，键位与角度使用独立标签；
4. **色彩**：午夜靛蓝海图、暖羊皮纸、旧黄铜、氧化青控制面与规格 token 一致；
5. **资产**：运行页只加载一张本地海图背景和一张透明图集；光束、路径提示、状态明暗与船迹由规则实时绘制；
6. **角色识别**：灯塔使用圆形罗盘与 A/D，小船使用四向船舵，两套控制在桌面和 390px 都能一眼区分；
7. **容器**：细黄铜外框把标题、海图和控制台连成一台航海仪器，没有拆成普通白色卡片；
8. **响应式**：390px 与概念一样保留并排双控，320px 的纵排是为保持触控尺寸而做的明确断点。

有意差异是概念图使用更高、更写实的海图和静态强光束，生产页把海图压到首屏可操作高度，并让光束严格服从 ready/playing 规则状态；海图装饰也减少，以免与可碰撞暗礁和必要航标混淆。这些差异服务于可玩性和状态真实性，不是遗漏核心视觉方向。

## 7. 借鉴、缺陷与沉淀

作品 README 固定声明 WHATWG Canvas 2D 标准，以及 Matter.js、rot.js、boardgame.io、trylock/visibility 的技术比较边界；这些第三方库的代码、运行时与素材均未进入本作品。`seaworthy` 的 MIT 代码和 CC BY-NC 音乐也作为排除项分别声明，避免把代码许可误用于音乐。

开发中复现并修复了[暗礁圆心合法但圆周越界](../bugs/2026-07-17-lighthouse-reef-radius-out-of-bounds.md)；可复用结论沉淀在[非对称同屏合作：让规则 Gate 证明双方都不可替代](../learn/2026-07-17-asymmetric-navigation-state-boundary.md)。
