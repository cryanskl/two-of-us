# A 级「未来车票」惊喜体验规格

## 1. Brainstorm 结论

本批实现一款可预先准备、打开即可玩的单设备惊喜：准备者在本地 `config.js` 写好三组都可接受的约会候选，收礼者看不到具体内容，只能在每一组的 A / B / C 三个孔位中选择一个，再按下复古打孔机。每打一孔，车票才揭晓“什么时候出发”“去哪里”“随行彩蛋”中的一项；三孔完成后签发一张完整未来车票。

| 方案 | 价值 | 风险与成本 | 本批决定 |
| --- | --- | --- | --- |
| 打开页面直接展示完整约会计划 | 最简单 | 缺少互动与揭晓节奏 | 不采用 |
| 三个步骤各从公开选项中选择 | 收礼者有控制感 | 更像规划工具，不像惊喜 | 不采用 |
| 三个步骤各盲选 A / B / C，打孔后才揭晓 | 同时保留选择感和惊喜 | 需要约束任意组合都成立 | 采用 |
| 随机抽取一个完整预设套餐 | 组合总是连贯 | 玩家只是按按钮，没有自己的选择 | 不采用 |
| 为每个字段提供任意数量候选 | 配置自由 | 版式、键盘与移动端难以稳定 | 不采用；每组固定三个候选 |
| 最后自动下载或打印票据 | 有纪念品感 | 引入权限、文件和打印差异 | 首版不做 |
| 保存上次结果 | 便于回看 | 违背刷新即清空的轻惊喜边界 | 不做 |

作品名为「未来车票」，目录 ID 为 `future-ticket`，主分类为单人惊喜，等级 A。它补齐“准备者定义可行边界、收礼者盲选组合、机械动作逐步揭晓”的互动模型，不新增第三方运行依赖。

## 2. 受众、唯一任务与语气

- **准备者**：愿意花 2–5 分钟替换九条本地文案，再把整个目录或入口交给伴侣；
- **体验者**：打开页面后，通过三次盲选和打孔拿到一张可执行的未来约会票；
- **唯一任务**：依次在三个孔位中选择并打孔，完成车票；
- **语气**：真诚、笃定、有一点老式旅行仪式感；不使用“命中注定”“永远”等过度承诺；
- **首局理解目标**：15 秒内知道“选一个孔位，打下去才会揭晓内容”。

## 3. 严格最小范围

只实现：

- 一张包含三个字段的未来车票；
- 三个固定步骤：什么时候出发、去哪里、随行彩蛋；
- 每步固定 A / B / C 三个闭合孔位；
- 选择、打孔、短机械动画、单项揭晓与自动进入下一孔；
- 三孔完成后的签发结果与重新组合；
- 可编辑 `config.js` 与稳定校验/回退；
- 鼠标、触控与键盘 `1 / 2 / 3 + Enter`；
- 生成式黄铜打孔机资产、代码原生车票和控件。

明确不做昵称编辑器、公开选项预览、套餐依赖、日期选择器、倒计时、提醒、日历写入、打印、下载、分享、二维码、历史、持久化、音频、震动、联网或双设备同步。

## 4. 内容模型与可组合约束

### 4.1 配置结构

`config.js` 暴露经典脚本全局 `window.FUTURE_TICKET_CONFIG`：

```js
{
  passenger: "给最想同行的你",
  issuer: "由我全程负责",
  finalNote: "出发那天，记得把我也带上。",
  serial: "A 02 240624",
  groups: [
    {
      id: "when",
      label: "什么时候出发",
      prompt: "第一孔 · 什么时候出发？",
      options: ["周五下班后", "周六午后", "一个不设闹钟的早晨"]
    },
    {
      id: "where",
      label: "去哪里",
      prompt: "第二孔 · 想把方向交给哪一格？",
      options: ["去看晚霞", "去吃一顿热汤", "去没有走过的街区"]
    },
    {
      id: "bonus",
      label: "随行彩蛋",
      prompt: "第三孔 · 再带上一点什么？",
      options: ["我负责路线", "你负责选歌", "留一小时给未知"]
    }
  ]
}
```

配置校验规则：

- `passenger`、`issuer`、`finalNote` 为 1–36 个 Unicode 字符；
- `serial` 为 1–18 个可见字符；
- `groups` 必须恰好三组，ID 依次为 `when / where / bonus`；
- 每组必须有非空 `label`、`prompt` 和恰好三个非空 `options`；
- label 最长 12 字符、prompt 最长 30 字符、每个选项最长 28 字符；
- HTML 标签只作为普通文本，不通过 `innerHTML` 注入；
- 配置任一结构错误时整份回退到内置默认值，不混用半份用户配置。

准备者必须确保三组候选任意交叉组合都可执行。例如时间组选“周五下班后”，地点组选“去看晚霞”，彩蛋组选“你负责选歌”仍然成立。首版不实现跨组依赖或互斥规则。

### 4.2 默认即玩

默认九条文案必须组成 27 种都自然的组合。没有修改 `config.js` 时也能完整体验；配置说明只放在 README，不把首次打开变成编辑器。

## 5. 状态机

```text
intro
  └─ START → choosing(step=0)

choosing
  ├─ SELECT(index 0..2) → choosing(selection=index)
  └─ PUNCH(selected option) → punching(revealed current field)

punching
  └─ FINISH_PUNCH
       ├─ step < 2 → choosing(step+1, selection=null)
       └─ step = 2 → complete

complete
  └─ RESTART → intro
```

权威状态字段：

```text
phase: intro | choosing | punching | complete
step: 0 | 1 | 2
selection: null | 0 | 1 | 2
reveals: [string|null, string|null, string|null]
revision: non-negative integer
```

约束：

- `START` 只从 intro 生效；
- `SELECT` 只在 choosing 接受 0–2；重复选择只改变当前孔位，不揭晓内容；
- `PUNCH` 必须同时满足 choosing、已选择、传入候选为当前配置中对应文本；
- `PUNCH` 只写入当前 `reveals[step]` 并进入 punching，重复事件无效；
- `FINISH_PUNCH` 是进入下一步或 complete 的唯一 Gate；
- 任何非法阶段或畸形状态回到冻结的初始状态，不能抛异常；
- 所有返回状态与 `reveals` 数组深冻结，不修改调用方对象。

浏览器动画只消费 punching 阶段。`animationend` 或 520ms 兜底触发一次 `FINISH_PUNCH`；重新开始、页面隐藏和卸载都取消旧计时器，防止上一孔的回调推进新局。

## 6. 隐藏信息边界

这不是密码学保密：候选仍存在本地 `config.js`，会查看源码的人可以读到。产品承诺只覆盖正常交接与页面浏览：

- choosing 阶段 DOM 只出现“孔位 A / B / C”，不出现当前组三个候选；
- 未揭晓字段只写“尚未打孔”，不把值放在隐藏节点、`aria-label`、title、data 属性或 CSS 变量；
- 只有当前打孔完成的单个文本进入 DOM；
- 页面不记录选择历史、未选候选或配置内容到日志；
- 重新组合回到 intro 并从 DOM 清除全部已揭晓内容。

catalog 静态测试检查入口没有 Module、远程资源、网络 API、持久化 API、Service Worker，以及没有在 HTML 中硬编码默认九条隐藏候选。

## 7. 键盘、触控与可访问性

- 三个孔位使用原生按钮，并由 `role="radiogroup"` / `role="radio"` 或等价原生语义表达单选；
- `1 / 2 / 3` 选择 A / B / C，`Enter` 只在已有选择时打孔；
- `event.repeat` 被忽略，单次长按不能连续穿过多个步骤；
- choosing 期间打孔按钮未选择时 disabled；punching 期间全部输入 disabled；
- 触控目标最小 48×48px，320px 下孔位改为单列但不压缩高度；
- 阶段提示使用 `aria-live="polite"`，打孔结果只播报一次；
- 颜色不是唯一状态：选中孔位同时使用实心孔、边框和 `aria-checked`；
- `prefers-reduced-motion` 下取消手柄位移与票据抖动，仍立即完成状态推进。

## 8. 视觉设计系统

视觉概念稿：[桌面与移动端铁路票据构图](assets/future-ticket/concept.png)，原生尺寸 1536×1024。概念稿是构图、色彩、打孔机材质与控件层级基准；运行页所有中文、序列号、状态和按钮均为 HTML/CSS 原生文字。

### 8.1 方向

**1960 年代大陆铁路票据 + 黑铁黄铜打孔机**。不使用爱心、粉色、照片拼贴或 SaaS 卡片。背景是温暖但不发黄的真纸色；页面保持开放式不对称构图，而不是把每块内容装进圆角卡片。

### 8.2 固定令牌

| 角色 | 值 |
| --- | --- |
| 纸张背景 | `#f3ecdc` |
| 票面纸 | `#e7d5b0` |
| 森林绿墨 | `#173b2a` |
| 朱红强调 | `#c94832` |
| 褪色钴蓝 | `#315d82` |
| 黑铁 | `#27251f` |
| 黄铜 | `#9b7133` |

不使用 CSS 渐变。纸张层次通过纯色、细边、虚线、轻微纹理资产和阴影完成。

### 8.3 版式与组件

- 桌面首屏：左侧约 68% 为标题、横向车票、问题与三孔控制；右侧约 32% 为贯穿上下的打孔机；
- 移动端：标题 → 横向缩放车票 → 当前问题 → 单列孔位 → 主动作；打孔机缩为票旁/票后局部装饰，不抢占操作高度；
- 标题使用粗窄中文系统黑体，`clamp(3rem, 7vw, 6.5rem)`；
- 正文与控件使用清晰宋体/系统衬线回退，序列号使用等宽字体；
- 车票为一个有缺口角的扁平大框，三字段由虚线分隔；
- 孔位按钮为直角细框，选中态是朱红实心孔；
- 唯一主动作是朱红矩形按钮“打下这一孔”或 intro 的“开始打孔”；
- 打孔机使用单张透明 PNG，手柄通过 CSS transform 小幅下压，不把机械图做成按钮。

## 9. 首屏文案锁

允许出现在 intro/choosing 首屏的固定文案：

- `← Two of Us`
- `未来车票`
- `这张票，通往我们还没去过的一天。`
- `什么时候出发` / `去哪里` / `随行彩蛋`
- `尚未打孔`
- 当前配置中的 prompt
- `孔位 A` / `孔位 B` / `孔位 C`
- `开始打孔` / `打下这一孔`
- `所有内容只留在这台设备上`

完成态允许：`车票已签发`、配置中的 passenger / issuer / finalNote、三个揭晓结果、`重新组合`。不额外添加 eyebrow、badge、玩法说明卡、统计或第二 CTA。

## 10. 文件结构与纯逻辑接口

```text
experiences/surprises/future-ticket/
├── index.html
├── styles.css
├── config.js
├── logic.js
├── app.js
├── logic.test.js
├── README.md
└── assets/
    ├── ticket-punch.png
    └── ATTRIBUTION.md
```

`logic.js` 使用 IIFE 暴露 `window.FUTURE_TICKET_LOGIC`，同时可由 Node `vm` 加载。最小接口：

```text
DEFAULT_CONFIG
sanitizeConfig(input)
createInitialState()
selectHole(state, index)
punch(state, option)
finishPunch(state)
restart(state)
```

`app.js` 负责配置校验、DOM 派生、键盘、动画计时器与焦点，不持有第二份权威玩法状态。

## 11. 本地优先与借鉴声明

- 不使用 fetch、XHR、WebSocket、CDN、远程字体、localStorage、sessionStorage、IndexedDB、Cache API、Service Worker、账号、统计或遥测；
- 配置、选择与结果只存在当前页面和本地文件，刷新即清空；
- 不读取照片、麦克风、摄像头、剪贴板、位置或日历；
- S18“未来车票打孔”来自本仓库原创创意池；本批不查阅、复制、改写或引入任何开源项目代码、视觉、字体、音效或素材；
- 视觉概念与打孔机资产由 OpenAI ImageGen 根据本规格生成，并在资产目录声明；
- 若未来参考开源项目，必须记录固定 URL、commit、许可证、借鉴内容和未复制边界。

## 12. 验收 Gate

### 12.1 自动检查

- 配置合法值保留，非法结构整份回退且默认值深冻结；
- 初始状态、三个阶段、选择切换与重复事件；
- 未选择不能打孔，打孔只揭晓当前一项；
- `FINISH_PUNCH` 依次推进，第三孔唯一进入 complete；
- restart 清空三个 reveal，畸形输入安全；
- catalog 入口、A 级直接打开与隐私静态边界；
- `node --check`、目标测试、`npm test`、`npm run verify` 和 `git diff --check` 通过。

### 12.2 Chrome 实玩

1. 从根门户找到“未来车票”并打开；
2. intro 三字段都为“尚未打孔”，开始按钮唯一可用；
3. 第一孔验证未选择时不能打孔，键盘 `2 + Enter` 揭晓 B；
4. 第二孔用触控/点击选择 A 并打孔，第三孔选择 C；
5. 每一步的未选候选均不出现在 DOM，可见字段依次从 0 增至 3；
6. 完成页展示完整组合、准备者文案与重新组合；
7. 重新组合清空 DOM 已揭晓值并回到 intro；
8. 页面日志无 error/warning，Network 无公网资源。

### 12.3 响应式与视觉

- 验证 1536×1024 概念原生视口、1269×774、390×844、320×700；
- 所有视口 `scrollWidth === innerWidth`；
- 首屏能看到完整车票、当前问题、三孔与主动作，320px 可纵向滚动但核心按钮不被裁切；
- 触控目标不低于 48px；
- 用 `view_image` 同次比较概念稿和最终浏览器截图；
- 忠实度账本至少核对标题层级、票面结构、色板、打孔机资产、孔位选中态、主动作、移动端重排和文案差异。
