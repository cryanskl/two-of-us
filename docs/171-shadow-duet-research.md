# A 级“把影子，跳成我们”定向调研

调研日期：2026-07-21

对应创意：`C19 影子双人舞`

建议目录：`experiences/co-op/shadow-duet/`

建议等级：A（单设备同屏、`file://` 直开、无第三方运行依赖）

## 1. 调研结论

C19 适合实现成一座背光纸幕小剧场：左席和右席各掌握四个剪影姿势，先读懂公开的双人目标，再在同一个定格窗里保持正确组合，让六幅“影子合照”依次留在幕布上。

正式方向采用 **四姿势词汇 + 固定整数 tick + 双席共同定格**：

- 左席使用 `W / A / S / D`，右席使用方向键；触屏端各有四个原生姿势按钮；
- 双方都拥有“举高、向内、低身、展开”四种抽象姿势，但镜像朝向不同；
- 每幕公开一个目标姿势对，不要求猜谱面，也不隐藏答案；
- 规则以 30Hz 整数 tick 推进，准备区可自由换姿势，只有定格窗参与判定；
- 正确姿势对在定格窗中连续保持 6 tick 才完成一幕；姿势错误或有人松手会把稳定计数清零；
- 窗口结束仍未稳定成形，只重试当前幕，已经完成的影子合照不丢失；
- 六幕完成后只总结共同尝试和六个造型，不计分、不评级、不比较个人准确度。

它与仓库现有作品有清晰边界：`four-hands-harmony` 的核心是两键在 200ms 内会合并保持；`together-zipper` 是每颗齿各提交一次离散拉动；`same-pace-star` 是四拍交接。C19 的核心则是双方从多姿势词汇中持续选择，目标由“左右姿势组合”定义，节拍只负责共同定格。

## 3. Brainstorm：四个方向与取舍

### 方向 A：摄像头识别真人姿势

两个人站在摄像头前，由姿态模型判断是否组成目标造型。它最贴近“跳舞”，但会引入相机权限、隐私说明、模型与 WASM 资产、多人骨架归属、设备性能和本地文件加载差异。

**结论：不采用。** MediaPipe 只作为技术边界研究，不进入实现；本作不请求相机、麦克风或传感器。

### 方向 B：自由拖动关节拼剪影

双方分别拖动头、手和脚的控制点，逼近目标轮廓。它能产生丰富姿势，却会把规则变成连续几何误差和拖拽精度题；手机多点触控也难以同时操作多个关节。

**结论：不采用。** 关节动画可以作为未来纯表现增强，不承担胜利条件。

### 方向 C：跟音乐按固定谱面

四个姿势像四轨音游一样随音乐落下，双方在判定线按键。这与 Bemuse、osu! 一类节奏游戏的输入模型接近，也会引入音频版权、自动播放、设备延迟和分数倾向，并与本仓库现有同步节奏作品重复。

**结论：不采用。** 不打包歌曲、谱面、音效、连击、生命或排行榜。

### 方向 D：公开目标的双人定格舞

每幕先展示目标姿势对，双方在纸幕上自由试动作；公共拍灯进入定格窗后，正确组合需要连续稳定一小段时间。失败只重演当前幕，成功会留下共同合照。

**结论：采用，进入规格冻结。**

## 4. 冻结姿势词汇与六幕路线

姿势是规则 ID，不依赖图片像素、骨架坐标或 CSS 类名。

| 姿势 ID | 中文动作 | 左席键 | 右席键 | 轮廓意图 |
| --- | --- | --- | --- | --- |
| `high` | 举高 | `W` | `↑` | 一只手向纸幕上缘伸出 |
| `wide` | 展开 | `A` | `→` | 身体向外侧展开 |
| `low` | 低身 | `S` | `↓` | 屈膝或俯身形成低轮廓 |
| `near` | 向内 | `D` | `←` | 手臂向两人之间伸出 |

六幕全部公开目标名、左右姿势和剪影预览：

| 幕 | 目标名 | 左席 | 右席 | 组合轮廓 |
| ---: | --- | --- | --- | --- |
| 1 | 开幕·展翼 | `wide` | `wide` | 两道影子向外打开 |
| 2 | 屋檐·相接 | `near` | `near` | 中间合成一座小屋檐 |
| 3 | 月钩·左起 | `high` | `low` | 一高一低形成左向弧线 |
| 4 | 月钩·右起 | `low` | `high` | 上一幕的镜像回应 |
| 5 | 窗边·递手 | `wide` | `near` | 一边撑开、一边递近 |
| 6 | 谢幕·换手 | `near` | `wide` | 交换上一幕的职责 |

每席在完整路线中都使用 `wide` 两次、`near` 两次、`high` 一次、`low` 一次。六个目标对互不重复，且每个目标都要求左右席同时为非空姿势。

## 5. 固定节拍与最后一 tick 边界

每幕从 `tick = 0` 开始，以 30Hz 规则时钟推进：

| 区间 | tick | 接受姿势输入 | 参与成功判定 |
| --- | --- | --- | --- |
| 熟悉目标 | `0…23` | 是 | 否 |
| 拍灯靠近 | `24…47` | 是 | 否 |
| 定格窗 | `48…61` | 是 | 是 |
| 结算 | 推进到 `62` | 否 | 若仍未成功则失败 |

定格窗是闭区间 `[48, 61]`。在每次单 tick 推进后，用该 tick 对应的当前姿势对结算：

1. 两席姿势都与目标相同，`stableTicks += 1`；
2. 任一席为空或姿势不符，`stableTicks = 0`；
3. `stableTicks === 6` 时立即原子完成该幕；
4. 若推进后即将越过 61 且仍不足 6，进入 `missed`；
5. 因此最晚可从 tick 56 开始连续正确，并在 tick 61 完成；tick 57 才开始则必然不足。

应用层可用 `requestAnimationFrame` 累积真实时间，但每帧最多提交 5 个 `STEP` tick；页面隐藏、失焦或离开时清空所有持有输入并暂停，恢复后回到当前幕的说明态，不补算后台时间，也不记一次失败。

## 6. 持有栈与输入语义

键盘允许同一席换姿势时短暂按住两个物理键。为了避免“松开旧键误清除新姿势”，规则层为每席维护一个去重的持有顺序：

- `PRESS(seat, pose)` 把尚未持有的姿势追加到末尾，重复按下是 no-op；
- 当前姿势始终是该席持有顺序的最后一项；
- `RELEASE(seat, pose)` 只移除对应姿势；如果它原本是当前姿势，则回退到仍持有的最后一个姿势；
- 非法席位、非法姿势、另一席试图代按、超长数组、继承属性和键盘 repeat 都不能改变状态；
- `RELEASE_ALL`、blur、`visibilitychange`、`pagehide` 和触控 `pointercancel / lostpointercapture` 必须把两席持有清空。

触屏按钮用 `pointerdown` 提交 `PRESS`，对应 `pointerup / pointercancel / lostpointercapture` 提交 `RELEASE`。按钮使用稳定存在的原生 `button`，每个席位只允许一个 pointer 同时占用一个姿势按钮；规则判定仍以 reducer 状态为权威。

## 7. 合作必要性与确定性证明

对任一幕：

1. 成功谓词要求 `left.activePose === target.left` 且 `right.activePose === target.right`；
2. 左席动作只能修改左席持有栈，右席动作只能修改右席持有栈；
3. 任一席始终为空时，`stableTicks` 每 tick 都被清零；
4. 单个 action 最多改变一个席位，不能伪造另一席姿势；
5. 完成态要求六幕记录均存在，所以规则层可证明两种席位权限都不可缺少。

同一台设备无法证明物理上确有两个人；一个人理论上可以同时操作两组按键。README 必须把这写成同机信任边界，不引入摄像头、账号或身份识别来“证明情侣”。

对确定性：初始状态、固定关卡和 action 序列完全决定结果；规则不读取 `Date`、随机数、音频时钟、DOM、图片尺寸、网络、存储或动画位置。完整 action 日志可在 Node 中重放为相同公共视图。

## 8. 状态机与实现草案

建议七阶段：

1. `intro`：题名、四姿势和双席控制说明；
2. `scene-intro`：公开当前幕目标与两席姿势；
3. `dancing`：接受 `PRESS / RELEASE / STEP`；
4. `pose-result`：成功定格，合照写入共同记录；
5. `missed`：窗口结束未成形，说明当前两席状态并准备重演；
6. `act-result`：六幕合照排成纸片，汇总共同尝试；
7. `complete`：配置结语与重新开始。

候选动作：`START`、`BEGIN_SCENE`、`PRESS { seat, pose }`、`RELEASE { seat, pose }`、`STEP { ticks }`、`SUSPEND`、`RETRY_SCENE`、`NEXT_SCENE`、`FINISH`、`RESTART`。

规则层建议导出 `SCENES` 的冻结安全副本、`createInitialState()`、`reduce()`、`getPublicView()` 和必要的输入/重放辅助函数。页面不得复制目标姿势、tick 窗口、当前幕、成功谓词、尝试计数或完成摘要。

## 9. 本地实现与依赖边界

- 经典脚本顺序 `logic.js → config.js → app.js`，CommonJS/浏览器双出口；
- 纯 HTML、CSS、SVG/PNG/WebP 与原生 DOM，不引入 PixiJS、音频引擎、姿态模型或第三方包；

## 11. 浏览器标准与可访问性

- 物理键位依据 W3C [KeyboardEvent code values](https://www.w3.org/TR/uievents-code/)，使用 `KeyW / KeyA / KeyS / KeyD` 与 `ArrowUp / ArrowRight / ArrowDown / ArrowLeft`，不依赖字符布局；
- 触摸与触控笔依据 W3C [Pointer Events](https://www.w3.org/TR/pointerevents3/)，显式处理 capture、cancel 和丢失 capture；
- 后台暂停依据 W3C [Page Visibility](https://www.w3.org/TR/page-visibility-2/)，恢复后不追赶丢失 tick；
- 语义、焦点、44×44px 命中盒、非颜色信息和降动效以 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 为验收基线；
- 当前两席姿势、定格窗、成功、失败、换幕和完成都要有文本状态；live region 不逐 tick 播报；
- 动态剪影对读屏隐藏，等价目标、当前姿势和六幕记录使用普通文本与列表表达。

## 12. 视觉方向与 ImageGen 边界

视觉采用“午夜背光纸幕剧场”，避免通用霓虹音游 HUD：

- 温暖琥珀背光、靛蓝幕边、粉灰纸纹、少量胶片齿孔与手写场记标签；
- 舞台中央是唯一主视觉，两道深墨剪影严格左右分区，中间保留组合轮廓；
- 定格窗用舞台横向拍灯和文字倒拍共同表示，不只依靠颜色或移动；
- ImageGen 先产出桌面进行态、移动触控态和完成态概念，再生成无字背光舞台背景与八姿势剪影图集；
- 生成资产不得包含文字、键帽、按钮、分数、品牌或规则答案；所有交互和文本由代码原生实现；
- 若图集轮廓不够一致，运行时必须保留原创 CSS 几何占位，不能让图片成为唯一可读规则。

响应式 Gate：

| 视口 | Gate |
| --- | --- |
| 1504×1046 | 无横纵滚动；标题、目标、完整舞台、两席控制和主动作同屏 |
| 1280×800 | 无横向滚动；舞台不低于 500px 宽，目标与两席当前姿势不折叠隐藏 |

## 13. 风险与进入规格的 Gate

| 风险 | 规格前冻结处理 |
| --- | --- |
| 与现有同步节奏作品重复 | 核心判定冻结为四姿势组合；不加入纯时差分数、和弦、逐齿点击或四拍交接 |
| 一开始就按对并一直不动，舞感太弱 | 六幕目标交替覆盖四姿势，场间必须释放；幕内允许提前准备，避免用反应速度惩罚亲密合作 |
| 多键换姿势出现 stuck key | reducer 维护去重持有顺序；blur/hidden/pagehide/pointercancel 全清空并暂停 |
| 最后一 tick 因调用顺序歧义 | 定格窗冻结为 `[48,61]`，逐 tick 先取当前姿势再累计；最晚 56 起连续六 tick 成功 |
| 剪影图片损坏后无法辨认 | CSS 占位轮廓 + 姿势中文 + 物理键文本持续存在，资产阻断仍能完整完成 |
| 一个人操作两席 | 明示同机信任边界；规则只证明双席权限，不请求摄像头或账号 |
| ImageGen 图集风格/方向不一致 | 用同一提示一次生成八格、固定左右朝向；逐格视觉复核，必要时重新生成，不用第三方人物参考图 |
