# 「这一弹，拐弯见你」功能与技术规格

> ID：`ricochet-tank-duel`  
> 等级 / 分类：A / 对战  
> 运行方式：本地直接打开  
> 状态：实现前冻结规格

## 1. 产品目标

做一个两人共用同一设备的实时折射对战小游戏：

- 两辆原创抽象“折光车”分别在左右活动区移动；
- 车头决定发射方向；
- 光点可在外边界和内部墙面折射；
- 场上可同时存在多枚光点；
- 双方同一逻辑刻命中时原子计分；
- 先到 3 分者胜，90 秒到时按比分结算；
- 无安装、无服务、无网络即可从 `file://` 打开。

成功标准不是拟真，而是：

1. 玩家能理解和学习折射路线；
2. 相同输入必然得到相同结果；
3. 左右玩家不受更新顺序偏置；
4. 资源与运行时有硬上限；
5. 键盘和触屏都能完成同一套操作；
6. 视觉和命中反馈不依赖第三方素材。

## 2. 非目标

第一版不包含：

- 单人 AI；
- 联机；
- 车体互撞、推动或伤害；
- 自伤；
- 弹体互撞；
- 生命值；
- 道具和不同武器；
- 随机地图；
- 地图选择或编辑；
- 皮肤、成长和账号；
- 音频文件；
- 粒子爆炸；
- 完整弹道预测线；
- 排行榜或持久化成绩。

## 4. 逻辑单位

### 4.1 世界

- 逻辑宽度：`WORLD_W = 960`；
- 逻辑高度：`WORLD_H = 600`；
- 固定步长：`TICK_HZ = 60`；
- 一个 tick 表示 `1/60` 秒，但规则内部不保存浮点秒；
- 定点比例：`FP_SCALE = 1024`；
- 所有位置、半径和每 tick 位移转换为定点整数。

Canvas CSS 尺寸可以响应式变化，但 `canvas.width / height` 与设备像素适配不得改变逻辑世界。

### 4.2 方向

- 使用 32 个离散方向，编号 `0..31`；
- `0` 表示向右；
- 编号按顺时针递增；
- 方向向量来自源码冻结的 Q10 整数查找表；
- 运行时不得调用 `Math.sin()` / `Math.cos()` 生成规则向量；
- 左转每 tick 减 1 个方向档，右转每 tick 加 1 个方向档；
- 同时按左转和右转时互相抵消。

文本投影把 32 档映射到八方位：

- 东；
- 东南；
- 南；
- 西南；
- 西；
- 西北；
- 北；
- 东北。

### 4.3 安全整数

实现必须证明所有运行时乘积保持在 `Number.MAX_SAFE_INTEGER` 内。几何比较使用整数分子 / 分母和交叉相乘；测试 oracle 可用 `BigInt`。

任何超出预期范围的状态：

- 在开发 / 测试中抛出错误；
- 在生产中暂停比赛并显示“状态异常，请重新开始”；
- 不静默夹断为另一个合法状态。

## 5. 固定地图

### 5.1 可运动世界

外边界内缘：

```text
left   = 24
right  = 936
top    = 24
bottom = 576
```

弹体在此矩形内反射。车体中心还必须考虑自身半径。

### 5.2 玩家活动区

车体中心范围：

```text
left zone:
  x = 48..432
  y = 48..552

right zone:
  x = 528..912
  y = 48..552
```

车体不能越过活动区边界；弹体不受左右活动区限制。

### 5.3 内部墙

墙体采用闭合轴对齐矩形，ID 与坐标冻结：

| ID | x1 | y1 | x2 | y2 | 说明 |
|---|---:|---:|---:|---:|---|
| `wall-left-shield` | 300 | 210 | 340 | 390 | 左盾墙 |
| `wall-right-shield` | 620 | 210 | 660 | 390 | 右盾墙 |
| `wall-center-top` | 456 | 72 | 504 | 222 | 中央上墙 |
| `wall-center-bottom` | 456 | 378 | 504 | 528 | 中央下墙 |

墙体镜像变换：

```text
mirrorX(x) = WORLD_W - x
```

对矩形 `[x1, x2]`，镜像为 `[WORLD_W - x2, WORLD_W - x1]`。

中央墙映射到自身；左右盾墙互相映射。

### 5.4 出生点

```text
left:
  center = (150, 300)
  heading = 0       // 向右

right:
  center = (810, 300)
  heading = 16      // 向左
```

出生点在盾墙后方。中央窗口允许经过走位后直射，但开局静止直射会被盾墙遮挡。

### 5.5 地图验收

实现必须用测试确认：

- 每个墙体镜像后都能在墙表中找到；
- 出生点、朝向和活动区严格镜像；
- 出生车体不与墙体或边界重叠；
- 所有通道宽度大于弹体直径；
- 至少各有一条成对的单折与双折 golden shot；
- 镜像 golden shot 的命中 tick 与反射数一致。

如果实际可玩验证发现中央窗口形成压倒性直射优势，可以调整地图，但必须先更新本 spec 并单独提交，不得在实现里偷偷偏移坐标。

## 6. 车辆规则

### 6.1 常量

```text
TANK_RADIUS = 18
TANK_FORWARD_SPEED_FP = 3 * FP_SCALE
TANK_REVERSE_SPEED_FP = 2 * FP_SCALE
TANK_TURN_STEPS_PER_TICK = 1
```

每 tick 最大前进 3 逻辑单位、后退 2 逻辑单位。

### 6.2 输入到运动

每个 tick：

1. 读取冻结的输入位掩码；
2. 先处理转向；
3. 再根据更新后的朝向计算平移；
4. 同时按前进与后退时平移为 0；
5. 平移使用圆对扩张 AABB 的扫掠检测；
6. 碰墙后将剩余位移投影到切向，最多滑墙 2 次；
7. 达到滑墙次数上限则丢弃剩余位移；
8. 车体不能进入另一方活动区；
9. 两辆车体互不碰撞，因为活动区不重叠。

车辆没有惯性。松开按键后立即停止。这既降低同键盘学习成本，也让重放状态更紧凑。

### 6.3 发射点

弹体从车体前方生成：

```text
spawnDistance = TANK_RADIUS + BULLET_RADIUS + 4
spawn = tankCenter + headingVector * spawnDistance
```

发射前必须验证生成位置：

- 在世界边界内；
- 不在墙体扩张区域内；
- 不与目标车体重叠。

若无效，本次发射不产生弹体，也不消耗冷却；UI 显示“车头贴墙，无法发射”。这一结果必须由逻辑状态计算，不能只靠视觉猜测。

## 7. 弹体规则

### 7.1 常量

```text
BULLET_RADIUS = 5
BULLET_SPEED_FP = 9 * FP_SCALE
FIRE_COOLDOWN_TICKS = 24
MAX_BULLETS_PER_PLAYER = 2
BULLET_LIFETIME_TICKS = 360
MAX_REFLECTIONS = 3
MAX_CONTACTS_PER_TICK = 4
```

### 7.2 生成

每个玩家的发射输入是边沿事件：

- 只有 `up -> down` 才尝试发射；
- `KeyboardEvent.repeat` 不产生额外边沿；
- 冷却为 0；
- 该玩家存活弹体少于 2；
- 发射点有效；
- 当前阶段为 `playing`；
- 当前 tick 尚未为该玩家创建弹体。

满足条件时：

- 分配单调递增的弹体 ID；
- 保存所有者；
- 保存位置和 Q10 速度；
- `ageTicks = 0`；
- `reflectionCount = 0`。

发射顺序不影响物理：左右发射请求先收集，再按玩家稳定 ID 创建。

### 7.3 寿命

- 每完成一个活跃 tick，`ageTicks += 1`；
- 当 `ageTicks >= 360` 时，在该 tick 事件处理结束后销毁；
- 暂停和倒计时不增加寿命；
- 回合重置清空全部弹体。

### 7.4 反射

轴对齐墙面反射：

- 命中竖直法向：`vx = -vx`；
- 命中水平法向：`vy = -vy`；
- 同时命中两个垂直法向：两个分量都翻转；
- 一个拐角事件只增加 1 次 `reflectionCount`；
- 第 1–3 次反射继续飞行；
- 将要发生第 4 次反射时直接销毁，原因 `reflection-cap`；
- 反射不损失速度。

反射后不能人为向外“推一个 epsilon”。应通过精确接触面 ID、剩余时间和进入方向过滤，避免重复处理零时间接触。

### 7.5 命中

- 弹体只可命中对方车体；
- 不命中发射者；
- 一枚弹体命中后立即标记销毁；
- 同一目标在一个 tick 内被多枚弹体命中，只计 1 分；
- 弹体之间互相穿过；
- 命中优先于同一时刻的墙面反射；
- 命中事件加入全局 `hitSet`，不能立刻重置回合。

## 8. 连续碰撞

### 8.1 时间区间

每个弹体 tick 的剩余时间表示为有理区间 `[0, 1]`。算法反复：

1. 从当前位置和剩余位移求所有候选接触；
2. 选择最早有效 TOI；
3. 推进到 TOI；
4. 收集与该 TOI 相等的全部事件；
5. 按并列规则处理；
6. 用剩余时间继续；
7. 无接触则走完整段；
8. 接触数达到 4 则销毁为 `contact-cap`。

不得先移动整段再做穿入修正。

### 8.2 弹体对墙

将墙体 AABB 向外扩张 `BULLET_RADIUS`，再做移动点对 AABB 的 slab sweep。

候选必须返回：

- TOI 分子 / 分母；
- 表面 ID；
- 法向；
- 接触类型；
- 是否为进入接触。

世界外边界使用等价的内缩矩形处理，并分配固定 surface ID：

```text
boundary-left
boundary-right
boundary-top
boundary-bottom
```

### 8.3 弹体对移动车体

车辆和弹体在同一 tick 都会移动。命中检测必须使用相对运动：

```text
relativeStart = bulletStart - tankStart
relativeDelta = bulletDelta - tankDelta
combinedRadius = BULLET_RADIUS + TANK_RADIUS
```

求移动点与原点圆的首次接触。车辆本 tick 的实际扫掠路径由车辆移动阶段确定并冻结，再用于弹体检测。

如果第一版实现不能正确支持车辆滑墙后的分段轨迹，则车辆运动必须输出最多 3 个带时间区间的线性段；弹体逐段与车辆相对扫掠。禁止把复杂车辆轨迹简化为只检测终点圆。

### 8.4 TOI 并列

两个 TOI 相等的定义必须是有理数交叉相乘相等，不能用浮点 epsilon。

同一最早 TOI 的事件优先级：

1. 对方车体命中；
2. 边界 / 墙面反射；
3. 其他安全销毁。

如果多个墙面并列：

- 合并不同轴法向；
- 同轴重复法向只处理一次；
- 按 surface ID 排序只用于稳定日志，不改变合并结果。

如果目标命中与墙面并列：

- 记为命中；
- 不再反射；
- 弹体销毁。

### 8.5 车体滑墙

车辆使用圆扫掠：

- 对墙体和活动区边界做扩张 / 内缩；
- 找最早接触；
- 推进至接触；
- 去掉剩余位移中指向法向的分量；
- 使用剩余切向位移继续；
- 最多 2 次接触；
- 车辆位置始终不得穿入。

初始状态若已重叠属于不变量破坏，不使用“推出墙体”作为日常修复。

## 9. tick 顺序

每个 `STEP(state, inputFrame)` 必须严格按以下顺序：

1. 若阶段不是 `playing`，只推进对应阶段计时；
2. 冻结双方输入位掩码和发射边沿；
3. 同时计算两车意图；
4. 分别求两车实际分段路径；
5. 提交两车最终状态；
6. 收集双方合法发射请求；
7. 按稳定玩家 ID 创建弹体；
8. 对 tick 开始时已有及本 tick 新建弹体求连续事件；
9. 收集全局 `hitSet`；
10. 统一增加弹体年龄并执行销毁；
11. 统一减少冷却；
12. 若 `hitSet` 非空，原子更新比分并进入回合结算；
13. 否则增加整局活跃 tick；
14. 检查 90 秒上限；
15. 生成低频语义事件；
16. 计算调试状态哈希。

左右玩家不能通过循环先后改变对方结果。遍历可以稳定排序，但提交必须批量发生。

## 10. 阶段状态机

```text
instructions
  -> countdown
  -> playing
  -> round-result
  -> countdown
  -> playing
  -> match-result

任意活跃阶段
  -> paused
  -> countdown

match-result
  -> countdown (重新开始)
```

### 10.1 `instructions`

- 显示三条规则与控件；
- 不推进逻辑；
- “开始”后进入 180 tick 等价的视觉倒计时，但倒计时由独立固定 tick 计数。

### 10.2 `countdown`

- 180 tick；
- 两车和弹体静止；
- held inputs 被持续清空；
- 结束时进入 `playing`；
- 发射边沿必须在进入 `playing` 后重新按下。

### 10.3 `playing`

- 推进车辆、弹体、冷却和活跃时间；
- 可暂停；
- 可产生计分。

### 10.4 `round-result`

- 持续 90 tick；
- 展示“左方命中”“右方命中”或“双双命中”；
- 所有弹体已清空；
- 之后若达到比赛结束条件则进入 `match-result`，否则重置车辆并进入 `countdown`。

### 10.5 `paused`

- 不推进任何玩法 tick；
- 清空 held inputs、发射边沿和渲染累加器；
- 显示暂停原因；
- 只有显式点击 / 按键恢复；
- 恢复后进入完整 `countdown`，不直接回到 `playing`。

### 10.6 `match-result`

- 停止玩法；
- 展示比分、胜者或平局；
- 提供“再来一局”和“查看规则”；
- 不自动重开。

## 11. 比分和比赛结束

### 11.1 命中计分

```text
if left tank in hitSet:
  rightScore += 1

if right tank in hitSet:
  leftScore += 1
```

一个目标同 tick 多次命中只加入集合一次。

### 11.2 三分制

- 目标分：3；
- 一方达到 3、另一方未达到 3：该方胜；
- 双方同一 tick 都达到 3：平局；
- 不进行加赛。

### 11.3 时间上限

- `MATCH_ACTIVE_TICKS = 5400`；
- 只在 `playing` 增加；
- 倒计时、回合结果和暂停不计入；
- 达到上限时先完成当前 tick 的命中结算；
- 高分者胜；
- 同分平局。

## 12. 输入契约

### 12.1 输入位

每位玩家的位掩码：

```text
FORWARD = 1 << 0
REVERSE = 1 << 1
TURN_LEFT = 1 << 2
TURN_RIGHT = 1 << 3
FIRE_HELD = 1 << 4
FIRE_EDGE = 1 << 5
```

`FIRE_EDGE` 在采样后立即消费，不跨 tick 保留。

### 12.2 键盘映射

| 玩家 | 前进 | 后退 | 左转 | 右转 | 发射 |
|---|---|---|---|---|---|
| 左方 | W | S | A | D | F |
| 右方 | ↑ | ↓ | ← | → | Enter |

其他：

- `P`：暂停 / 请求恢复；
- `Escape`：只暂停，不直接恢复；
- 仅在比赛组件有交互上下文时阻止相关按键默认行为；
- 不拦截 Tab；
- `repeat` 不产生发射边沿；
- 输入字段 / 按钮聚焦时不把 Enter 误当作右方发射。

### 12.3 Pointer Events

每个控制按钮：

- 在 `pointerdown` 时记录 `pointerId` 与动作；
- 调用 pointer capture；
- `pointerup` 释放动作；
- `pointercancel` 释放动作；
- `lostpointercapture` 释放动作；
- 同一动作可由键盘和指针同时持有，内部使用来源集合；
- 只有所有来源都释放时才清掉 held bit；
- 每个 `pointerId` 同时只绑定一个动作；
- 页面失焦、隐藏、暂停、重开时清空全部来源。

### 12.4 并发输入

逻辑支持两位玩家同时：

- 各自转向；
- 各自移动；
- 各自发射；
- 触屏多指。

文档应提示部分消费级键盘存在按键矩阵冲突，触屏按钮是等价入口。不能把硬件 ghosting 误判为游戏逻辑错误。

## 13. 调度与暂停

### 13.1 渲染循环

`requestAnimationFrame` 只做：

1. 读取单调时间戳；
2. 计算与上一帧的调度间隔；
3. 向累加器加入经过时间；
4. 在上限内调用固定 `STEP`；
5. 绘制当前或插值状态。

逻辑层不得读取：

- `Date.now()`；
- `performance.now()`；
- rAF 时间戳；
- 帧率；
- CSS 像素尺寸。

### 13.2 防追赶

```text
MAX_FRAME_GAP_MS = 250
MAX_STEPS_PER_FRAME = 5
```

- 帧间隔大于 250 ms：进入暂停；
- 一帧需要超过 5 次补算：进入暂停；
- 进入暂停时丢弃累加器；
- 不以截断 `dt` 的方式继续比赛；
- 恢复必须经过倒计时。

### 13.3 自动暂停来源

- `document.visibilityState === "hidden"`；
- `window.blur`；
- 长帧；
- 检测到逻辑不变量破坏；
- 浏览器失去 Pointer capture 时仅清对应输入，不必单独暂停；
- 页面 resize 不暂停，除非 Canvas 尺寸暂时为 0。

## 14. 渲染规格

### 14.1 层级

从后到前：

1. 背景；
2. 活动区轻微色块；
3. 墙体；
4. 反射接触刻痕；
5. 弹体；
6. 折光车；
7. 方向楔；
8. 回合状态覆盖；
9. 调试层（默认关闭）。

### 14.2 阵营编码

不能只靠颜色：

- 左方：珊瑚橙 + 实心方向楔 + “左”标签；
- 右方：湖蓝 + 条纹方向楔 + “右”标签；
- 弹体带所属形状刻线；
- 比分卡明确写文字。

### 14.3 插值

- 插值只影响视觉；
- 逻辑状态和碰撞不读取插值结果；
- reduced-motion 下关闭插值；
- 回合结算前立即渲染最终命中状态；
- 不做慢动作。

### 14.4 命中反馈

- 目标轮廓短暂切换为高对比静态样式；
- 接触点显示不超过 90 tick 的小型裂光标记；
- 比分文本同步更新；
- 不震屏；
- 不播放外部爆炸动画。

## 15. 页面结构

页面至少包含：

- `<main>`；
- 标题和一句玩法说明；
- 比分 / 时间区；
- Canvas 舞台；
- Canvas 对应文字说明；
- 左右状态卡；
- 左右触屏控制组；
- 暂停、规则、重开按钮；
- 规则对话区域；
- 低频 `role="status"`；
- 无脚本提示。

原生按钮必须：

- 可 Tab；
- 有可见焦点；
- 至少 44×44 CSS px；
- disabled 状态仍有文字解释；
- 不用仅图标表达动作。

## 16. 文本状态投影

### 16.1 每方字段

每方状态卡显示：

- 名称；
- 比分；
- 八方位朝向；
- 粗粒度位置；
- 存活弹体数；
- 冷却：“可发射”或剩余分段；
- 最近威胁方向；
- 最近威胁距离等级。

位置将活动区划分为 3 列 × 3 行，文本例如“左区 / 中列 / 上行”。

### 16.2 威胁计算

只考虑对方弹体：

- 按当前欧氏距离选择最近一枚；
- 方向按相对向量映射到八方位；
- 距离分为近 / 中 / 远；
- 不预测折射后的未来路径；
- 没有对方弹体时显示“暂无来弹”。

这是视觉补充，不参与游戏逻辑。

### 16.3 live region

只播报：

- “三、二、一、开始”；
- 暂停原因；
- 恢复；
- 左方命中；
- 右方命中；
- 双双命中；
- 最终比分与结果。

不播报每 tick 的位置、朝向、冷却或弹体距离。

## 17. reduced-motion

媒体查询为 `reduce` 时：

- 关闭尾迹；
- 关闭屏幕震动；
- 关闭闪白；
- 关闭缩放 / 滑动过渡；
- 关闭状态插值；
- 保留车体、弹体和折射的必要位置变化；
- 命中使用静态轮廓和文字；
- 逻辑哈希与普通模式完全相同。

测试必须用同一输入日志在普通和 reduced-motion 渲染模式下比较最终逻辑哈希。

## 18. 状态模型

最小逻辑状态：

```js
{
  version,
  phase,
  phaseTicksRemaining,
  activeMatchTicks,
  scores: [number, number],
  tanks: [
    {
      id,
      xFp,
      yFp,
      heading,
      cooldownTicks
    }
  ],
  bullets: [
    {
      id,
      ownerId,
      xFp,
      yFp,
      vxFp,
      vyFp,
      ageTicks,
      reflectionCount
    }
  ],
  nextBulletId,
  roundIndex,
  lastRoundResult,
  pauseReason,
  semanticEvents
}
```

逻辑状态不保存：

- DOM 节点；
- Canvas context；
- rAF ID；
- 当前真实时间；
- CSS 尺寸；
- PointerEvent；
- 装饰粒子；
- 文本格式化结果。

## 19. 状态哈希与重放

### 19.1 输入日志

每个活跃 tick 保存：

```js
{
  tick,
  leftMask,
  rightMask
}
```

阶段转换输入也要记录。自动暂停不是确定性玩法输入，重放工具应在纯逻辑环境中直接提供阶段命令。

### 19.2 规范化

哈希前：

- 数组按稳定 ID 排序；
- 只包含逻辑字段；
- 数字使用十进制整数；
- 不包含语义事件文案；
- 不包含对象键插入顺序偶然性。

### 19.3 镜像变换

镜像重放：

- 交换玩家；
- `x -> WORLD_W - x`；
- 方向 `h -> (16 - h + 32) % 32`；
- 交换左 / 右转输入；
- 保持前进 / 后退 / 发射；
- 墙面和出生点使用同一镜像规则。

原重放与镜像重放的规范化状态在反镜像后必须相等。

## 20. 测试规格

### 20.1 几何单元测试

### 20.4 同刻结算测试

## 21. 性能预算

硬上限：

- 2 辆车；
- 4 枚弹体；
- 4 块内部墙；
- 每弹每 tick 4 次接触；
- 每车每 tick 2 次滑墙接触；
- 不分配无限增长粒子；
- 反射刻痕使用固定长度环形缓冲区；
- 语义事件队列每 tick 清空。

目标：

- 低端移动设备逻辑计算稳定低于一个 60 Hz 帧预算；
- 调试模式可显示 tick 耗时，但不得进入规则；
- 长帧一律公平暂停，而不是降级物理质量。
