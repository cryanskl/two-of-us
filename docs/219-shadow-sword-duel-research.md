# 创意池 V19“影子剑术”定向调研：不是四选一猜拳

- 调研日期：2026-07-23
- 对应创意：[`40-idea-backlog.md`](./40-idea-backlog.md) 的创意池 V19“影子剑术”
- 稳定工作 ID：`shadow-sword-duel`
- 建议目录：`experiences/versus/shadow-sword-duel/`
- 建议启动等级：A（双击 `index.html`，无安装、服务、权限或公网）
- 本轮范围：研究、brainstorm、来源与许可证复核；不创建生产目录

## 1. 结论

V19 可以做，但不能把“攻、防、闪、蓄”写成一张固定四向克制表。那样无论换成
剑、魔法还是情侣表情，本质仍是一次性猜拳。

推荐进入规格的版本是一场最多九回合的热座密封决斗：

- 双方各有 3 点体力，初始 1 点气，气最多 2 点；
- `攻` 消耗 1 点气，能打断 `蓄`；普通攻会被 `防` 挡下，带先机的攻可以破防，
  `闪` 始终能够避开本回合攻击；
- `防` 只有真的挡住普通攻击时才获得先机，不能空防刷资源；
- `蓄` 只在本回合没有被击中时增加 1 点气；
- 双方选择完成后，页面仍不显示任何招式；两人一起按下“揭晓本回合”后，规则层
  才从同一个回合开始快照原子结算；
- 同回合双方都攻击时可以同时受伤，不能按玩家遍历顺序提前宣告胜者；
- 任一方体力归零时结束；九回合仍未分胜负，则先比体力、再比气，仍相同即平局。

它的核心不是“哪个图标克哪个图标”，而是：

```text
当前体力 / 气 / 先机
        ↓
本回合两份密封选择
        ↓
同一开始快照上的联合结算
        ↓
下一回合资源与可选动作改变
```

同样的“攻对防”，在攻击方是否拥有先机时会得到不同结果；零气时不能选择攻；
一次成功防守会影响未来回合，而不是只决定当下输赢。这三点共同建立与仓库已有
“密封猜拳”的实质差异。

## 5. Brainstorm：四个方向

| 方向 | 核心规则 | 结论 |
| --- | --- | --- |
| 固定四向克制 | `攻 > 蓄 > 闪 > 防 > 攻`，相邻获胜 | 排除；仍是一张静态猜拳表 |
| 实时键盘剑斗 | 左右移动、格挡、出剑、翻滚 | 暂缓；输入设备公平、碰撞、动画帧和触屏适配会把首版推向动作游戏 |
| 血量 + 气 | 攻耗气，防/闪/蓄决定伤害和回气 | 可行，但同一动作对在不同局面仍可能过于一致 |
| 血量 + 气 + 先机 | 成功防守取得先机；带先机的下一次攻可破防 | **采用**；资源让动作合法性与结算都依赖历史，又保持规则可口述 |

“先机”不是速度计时或隐藏随机暴击，而是一个公开布尔资源。双方在选招前都能
看见体力、气和先机，所以决策信息完整；只有当回合选择需要保密。

## 6. 建议冻结的最小规则

规格阶段应验证数值平衡，但不再更换机制骨架：

```text
PLAYER_COUNT = 2
START_HEALTH = 3
START_ENERGY = 1
MAX_ENERGY = 2
MAX_ROUNDS = 9
ATTACK_COST = 1
ACTIONS = attack / guard / dodge / charge
```

### 6.1 单项动作

| 动作 | 选择条件 | 本回合含义 |
| --- | --- | --- |
| 攻 | 气至少 1 | 先支付 1 气；普通攻可被防住，带先机的攻可破防；闪始终能避开 |
| 防 | 始终可选 | 只有挡住“不带先机的攻”才获得先机；空防没有收益 |
| 闪 | 始终可选 | 避开普通攻和先机攻；不获得气或先机 |
| 蓄 | 始终可选 | 若本回合没有受伤，结算后增加 1 气；上限仍为 2 |

攻击方选择 `攻` 时，无论命中、被防或被闪，都支付气并消耗已有先机。费用和
先机消耗不能等到看到对手动作后再决定。被先机攻破防不会清除防守者此前已有的
先机；先机只在其持有者本人选择 `攻` 时消耗，成功挡住普通攻击则把它设为 true。

### 6.2 联合结算

结算只读取回合开始快照 `before` 与双方已密封动作：

1. 先校验双方动作在 `before` 中都合法；
2. 同时计算两位攻击者的气和先机消耗；
3. 分别判断每一次攻击是命中、被防还是被闪；
4. 一次性应用双方伤害，因此允许双败；
5. 给成功挡住普通攻击者授予先机；
6. 给本回合未受伤的蓄力者增加气；
7. 生成不可变历史记录和下一回合状态；
8. 最后统一判断体力归零与九回合终局。

关键交互如下：

| 双方动作 | 从回合开始状态派生的结果 |
| --- | --- |
| 攻 / 攻 | 双方各支付气并同时受 1 伤；可能双败 |
| 普通攻 / 防 | 攻支付气但不造成伤害；防守方取得先机 |
| 先机攻 / 防 | 攻支付气并消耗先机，防守方受 1 伤且不得取得先机 |
| 任意攻 / 闪 | 攻支付气并消耗先机（若有），闪避方不受伤 |
| 任意攻 / 蓄 | 蓄力方受 1 伤且本回合不加气 |
| 无攻击 / 蓄 | 蓄力方增加 1 气，最多 2 |
| 防 / 防、闪 / 闪、防 / 闪 | 无资源或伤害变化 |

这不是完整的胜负矩阵。“蓄对防”没有谁立即获胜，“防对闪”也不计分；它们只
改变或保留未来局面。九回合上限负责让消极循环有限结束。

### 6.3 终局

- 任一方体力为 0、另一方仍大于 0：存活方获胜；
- 双方同回合体力均为 0：平局；
- 第 9 回合后双方仍存活：体力较高者胜；
- 体力相同：气较高者胜；
- 体力与气都相同：平局；
- 先机不参与最终 tie-break，避免一个布尔标记悄悄决定整场胜负。

## 7. 单设备密封流程

建议阶段：

```text
intro
→ choosing（本回合第一位）
→ handoff
→ choosing（本回合第二位）
→ ready-to-reveal
→ round-result
→ choosing / match-result
```

- 每回合第一位选择者交替，降低设备交接和记忆侧信道的固定优势；
- `choosing` 只为当前席位创建四个动作按钮，另一位的选择不进入 DOM；
- 当前席位确认后立即卸载动作区，进入只含中性文字的 `handoff`；
- 第二位确认后进入公共 `ready-to-reveal`，此时两份动作仍不进入 DOM、attribute、
  可访问名称、事件详情、URL 或 storage；
- 只有两人一起确认“揭晓本回合”后才结算并显示双方动作与结果；
- `round-result` 公开完整资源、结果原因和历史摘要，下一回合开始前再次遮屏；
- `restart` 清空秘密、历史和资源，回到与首次加载深相等的 `intro`。

单设备上两个动作是依次输入的，但它们组成一次联合行动。OpenSpiel 的概念文档
把 simultaneous transition 描述为 joint action，也指出同时行动游戏可以编码为
顺序回合；本作只借用这个抽象解释“顺序录入、联合结算”，不使用其代码或运行时。

热座遮屏只承诺正常使用流程中不提前渲染秘密，不能对同一设备上主动打开开发者
工具、断点或 JavaScript 内存检查的参与者提供密码学保密。若要抵御恶意参与者，
应升级为 C 级双设备 + 本机裁判，而不是在单页中伪装安全性。生产 README 必须
明确这条信任边界。

## 8. 权威状态、历史与公开投影

建议 state：

```text
phase
roundIndex
firstSeat
activeSeat
players[] = { health, energy, initiative }
sealedActions[] = action | null
history[] = {
  roundIndex,
  beforePlayers,
  actions,
  effects,
  afterPlayers
}
result
revision
```

历史是权威证据，不只是展示文案。规格与测试至少应要求：

- `resolveRound(before, actions)` 为纯函数；
- 从初始状态依次重放每条 `history[i].actions` 能重建当前玩家资源；
- view、历史和输入对象递归冻结，并与内部状态断开可变引用；
- 任何未知 action、错阶段 action、额外 getter、原型污染或不合法 `攻` 都不推进；
- `ready-to-reveal` 的公开 view 只能说“两位都已封招”，不能包含动作值；
- `round-result` 后才可把当回合动作投影到公开 view；
- 当前资源只存一份；若为性能缓存派生值，测试必须验证缓存与重放一致。

首版不复用 C 级 `shared/runtime/sealed-rounds`。它需要单设备遮屏，而不是两台
设备和可信本机裁判；强行接入会把 A 级作品变成服务依赖。未来若增加 C 级双设备
变体，可以复用协议思想，但应作为独立升级批次。

## 10. 无障碍与生命周期

- 四个动作都用带文字的原生 `<button>`，图标只能冗余表达；
- 零气时“攻”必须真实 `disabled`，并在附近文字解释“需要 1 点气”；
- 焦点顺序与视觉顺序一致；窄屏重排不改变 DOM 顺序；
- handoff 进入时焦点移动到交接标题，不能残留在已卸载的秘密按钮；
- ready-to-reveal 焦点移动到“揭晓本回合”，且读屏文本不泄露动作；
- round-result 用单一 `role=status` 概括伤害、气与先机变化，不依赖颜色或动画；
- 先机、气和体力都同时提供数字/文字，不只用剑气亮度、血条长度或光效；
- `prefers-reduced-motion: reduce` 下取消拔剑、闪避和翻牌位移动画；
- `visibilitychange`、`pagehide`、`blur` 不自动揭晓、不代选、不结算；
- 任何表现动画只消费已结算结果；动画结束事件不能成为规则推进条件。

这些边界按 W3C WCAG 2.2 的键盘、焦点、状态消息、目标尺寸和运动相关原则校准；
不复制规范原文或示例代码。

## 13. 风险与验证矩阵

| 风险 | 必须验证 |
| --- | --- |
| 退化成猜拳换皮 | 同一“攻/防”在有无先机时结果不同；零气不能攻；历史会改变未来合法动作 |
| 第二位从 DOM 偷看第一位 | handoff、第二次 choosing、ready-to-reveal 均不存在第一份动作值 |
| 顺序结算造成偏置 | 攻/攻与同时归零按同一 before 快照原子结算；交换玩家只交换结果身份 |
| 资源越界 | 任意序列下 `0 ≤ health ≤ 3`、`0 ≤ energy ≤ 2`、initiative 为布尔值 |
| 无气仍能攻击 | UI disabled 与 reducer 双重拒绝；伪造 action 不推进 revision |
| 历史和当前状态漂移 | 从初始状态重放历史得到与当前玩家资源深相等的状态 |
| 消极循环不结束 | 第九回合强制按体力、气、平局规则结束 |
| 先手/交接固定优势 | firstSeat 每回合交替；交换席位性质测试保持规则对称 |
| 动画驱动规则 | 关闭动画、后台切换或直接派发 reveal 仍得到完全相同结果 |
| restart 留下秘密 | 重开后 state/view/DOM 与首次加载深相等且 history 为空 |

定向逻辑测试至少覆盖：

1. 普通攻被防、先机攻破防、任意攻被闪、攻打断蓄；
2. 成功防守获得先机，空防不获得；
3. 攻击无论命中与否都支付气并消耗先机；
4. 未受伤蓄力加气、受伤蓄力不加、上限不溢出；
5. 双攻原子伤害、双败、单败和第九回合三类终局；
6. 两个相同 action pair 因 before 资源不同而得到不同结果；
7. 全阶段秘密投影与非法 action 门控；
8. 历史重放、输入不可变、输出递归冻结与玩家交换对称性。

## 14. 实现路线建议

如果规格复核仍成立，按独立提交推进：

1. **研究提交**：本文件与文档索引；
2. **规格提交**：冻结所有动作、阶段、DTO、终局、隐私和验收合同；
3. **计划提交**：拆出纯逻辑、UI/配置/来源、浏览器验收与记录；
4. **逻辑提交**：`logic.js` + 定向测试，不先画 UI；
5. **视觉确认提交**：三态概念与用户 Gate；
6. **页面提交**：A 级静态作品、catalog 接入、README/ATTRIBUTION；
7. **验收提交**：全仓测试、verify、Chrome `file://` 与 localhost 完整实玩，
   有复现问题写入 `bugs/`，可复用经验写入 `learn/`。

规格与逻辑阶段最值得验证的不是 CSS，而是下面这个性质：

```text
resolve(before, [actionA, actionB])
交换玩家身份
==
resolve(交换后的 before, [actionB, actionA])
再交换结果身份
```

如果这一性质不成立，说明规则或结算顺序藏有席位偏置。

## 15. Go / No-Go

**Go：进入规格。**

进入规格前无需新增依赖，也无需请求私人素材。规格必须进一步冻结：

- attack / guard / dodge / charge 的 schema 与非法字段策略；
- 先机获取、消耗和破防的精确先后顺序；
- 双方同时攻击、同时归零和第九回合 tie-break；
- firstSeat 交替、handoff cover 与每阶段公开 DTO；
- history 是权威事件还是快照，以及重放合同；
- 默认玩家名、结果原因文案、焦点目标和 reduced-motion 行为；
- A 级 file 直开、无网络监听器和 restart 深相等验收。

本调研不把“规则可写”算作“作品已完成”。只有规格、计划、纯逻辑、视觉确认、
生产页面、来源声明、整仓检查与真实浏览器完整实玩都通过后，创意池 V19 才能
标记为已实现。
