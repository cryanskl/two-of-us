# C 级“我们的地点”定向调研

- 日期：2026-07-25
- 工作 ID：`our-place-guess`
- 暂定中文名：`你记得，我们在哪里`
- 目标等级：C，本机服务 + 同一可信局域网内两台设备
- 本阶段范围：只确定可行性、原创边界、来源与风险；不写生产代码
- 结论：**有条件 Go**。不做 Posio 的本地复刻，改做“情侣自备地点卡 + 两人密封落点 + 合作结算”的原创玩法；离线底图只使用固定版本 Natural Earth 物理陆地数据。

## 1. 调研问题

本轮要回答六个问题：

1. 58 个已安装作品里是否已有同类机制；
2. “我们的地点”应归合作还是对抗；
3. 能否在不引入 Django、Redis、在线瓦片和公共服务器的情况下实现；
4. 现有 C 级房间运行时能否承担秘密提交、重连和主机迁移边界；
5. 世界底图的代码、数据和视觉资产分别拥有什么权利；
6. 经纬度、投影和移动端点按会不会让分数失去公平性。

### 2.3 重复性判定

以下三个直觉方案均判定为不进入生产：

- **“随机城市，谁点得近谁赢”**：与 Posio 的公开城市竞猜和距离排名过近；
- **“一人看目标，另一人猜地图”**：与 `lan-pictionary` 的秘密题目/猜答角色轮换同构；
- **“一人看全图，另一人只看局部图”**：与 `fog-navigation` 的核心信息差同构。

仍有明确增量的方向是：

- 题库不是全球城市知识，而是准备者写入的“我们共同经历过的地点”；
- 两个人在同一回合都拿到同一段回忆线索；
- 两个人都独立落点并密封提交；
- 两个落点同时揭晓；
- 以两人的**较差距离**作为共同成绩，强调“都记得”而不是一个人带飞；
- 结果页才显示目标、双方落点、距离与准备者结语。

它与现有密封问答共享基础协议，但输入域、空间计算、地图交互、共同计分和私人地点配置均为新能力。

## 3. 现有 C 级运行时可行性

### 3.1 已有能力

`shared/runtime` 当前已提供：

- 根目录统一依赖中的 Socket.IO 4.8.1；
- 监听 `0.0.0.0` 的本地服务、局域网地址和二维码；
- 五位房间码；
- `room:create`、`room:join`、`room:leave`；
- `room:action` 房间广播；
- `room:direct` 同房间成员定向消息；
- `room:sealed-submit` 两位冻结参与者的密封提交；
- 同一玩家相同重复提交幂等、改变内容的重复提交拒绝；
- 第三位成员容量拒绝；
- host 离开后把剩余成员提升为 host；
- 静态文件与本地 vendor 资源服务；
- 100 KB Socket.IO 消息上限。

新作不需要修改共享运行时，也不需要新增 npm 运行依赖。

### 3.2 必须由作品自己补足的语义

共享运行时只管理房间，不保存可恢复的比赛身份和历史。断线后重新连接会得到新的 socket ID。因此新作必须明确：

- 任何成员 ID 或 host 变化都清空正在进行的比赛；
- 不承诺刷新续局或断线续局；
- 被提升的新 host 不能继承旧 host 内存中的地点答案；
- 第三人收到容量错误后返回大厅，不能看到房间状态；
- 活跃轮次只接受冻结的两位参与者；
- 每轮每人只能提交一次，提交后不能拖动或覆盖落点；
- host 不能替另一位玩家提交；
- `room:action` 的状态只接受已知 host、同房间和严格递增版本。

### 3.3 消息大小与隐私

世界底图必须是本地静态资产，不通过房间消息发送。房间消息只携带：

- 卡片 ID、公开线索和回合序号；
- 玩家提交的经纬度；
- 回合/比赛的公开结果；
- 不超过约定长度的纯文本结语。

地点配置、完整卡组和未揭晓目标经纬度只存在 host 页面内存。共享层不会端到端加密消息，因此本作只面向可信局域网；不应宣传为安全通信工具，也不应暴露公网。

## 5. 离线地图数据核验

### 5.1 为什么不用在线瓦片

OpenStreetMap、Mapbox、Google Maps 或其他在线瓦片会带来：

- 首次或每次运行的公网依赖；
- token、服务条款和速率限制；
- 浏览器向第三方暴露 IP、时间和地图视口；
- 缓存与再分发权利边界；
- C 级本地直开无法离线验收。

本作只需要一个可点击的低细节世界轮廓，不需要道路、地点名、国家名、行政边界或卫星图。

### 5.2 采用 Natural Earth 物理陆地层

权威来源：

- 官方使用条款：<https://www.naturalearthdata.com/about/terms-of-use/>
- 官方仓库：<https://github.com/nvkelso/natural-earth-vector>
- 固定 tag：`v5.1.2`
- tag commit：`f1890d9f152c896d250a77557a5751a93d494776`
- 固定 GeoJSON：<https://raw.githubusercontent.com/nvkelso/natural-earth-vector/f1890d9f152c896d250a77557a5751a93d494776/geojson/ne_110m_land.geojson>
- 原始 GeoJSON SHA-256：`9e0729ee253ca7d7a5c4ae9395fb1902264c5377c52e224d13dd85010e2835d9`
- 原始大小：138,160 bytes
- 核验日期：2026-07-25

官方 `VERSION` 在该 commit 为 `5.1.2`。官方条款说明网站上的 Natural Earth 栅格和矢量地图数据均为 public domain，允许使用、修改和电子传播，不要求许可或署名。尽管署名不是强制条件，本仓库仍应显示 `Made with Natural Earth` 并保留固定版本、commit、原始哈希和转换记录。

### 5.3 为什么只用 land，不用国家边界

只使用 `ne_110m_land`：

- 足以显示大陆和主要岛屿；
- 没有国家名、城市名、国旗和题库；
- 不需要选择 de facto / de jure / POV 行政边界；
- 减少政治边界表达风险；
- 体积小，适合本地静态资源。

游戏仍需在文档中诚实说明：小比例尺数据经过概化，不适合导航、测量、主权判断或精确定位。

### 5.4 数据处理与可追溯性

生产阶段不得运行时加载 raw GitHub 或 Natural Earth 网站。建议：

1. 用固定 commit 的 GeoJSON 作为唯一输入；
2. 用仓库内确定性脚本提取 `geometry`，删除无关属性；
3. 保持经纬度 WGS84；
4. 输出本地静态 GeoJSON 或确定性的 SVG path；
5. 记录输入 URL、版本、commit、输入 SHA-256、转换命令和输出 SHA-256；
6. 运行页面只读取本地输出；
7. `ATTRIBUTION.md` 区分原始地图数据和本仓库生成的视觉表达。

官方网页当前的 110m Land 下载标签与其 ZIP 内嵌 `VERSION.txt` 存在版本显示不一致，因此不采用网页上的滚动下载地址作为构建输入。固定 Git commit、固定文件 URL和 SHA-256 能消除该漂移。

## 7. 经纬度、投影与公平性

### 7.1 存储与距离

- 配置和提交都用十进制度 `[longitude, latitude]`；
- 经度范围 `[-180, 180]`，纬度范围 `[-90, 90]`；
- 比较距离使用 haversine 大圆距离；
- 固定地球平均半径 `6371.0088 km`；
- 计算中保留浮点精度，展示时再舍入；
- 不使用屏幕像素距离计分，因为纬度变化会扭曲等经度间隔。

### 7.2 可视投影

首版可用等距圆柱投影显示世界轮廓：

```text
x = (longitude + 180) / 360
y = (90 - latitude) / 180
```

它便于稳定逆变换和离线渲染，但高纬区域视觉面积被拉伸。公平性不能靠“看起来一样远”，必须：

- 结果明确显示实际公里距离；
- 不使用屏幕像素作为分数；
- 默认地点卡限制在 `|latitude| <= 80`；
- 目标跨越 ±180° 时用最短经度差；
- 点击边界后钳制到合法经纬度；
- 测试赤道、高纬、反经线和相同点。

### 7.3 点击精度与分数

移动端手指无法可靠选择城市级精度。建议：

- 地图点按后生成大号可拖动 pin；
- pin 周围有放大镜/局部十字辅助；
- 同时提供方向键微调；
- 键盘每次移动固定角度，Shift 进行更细微调；
- 提交前显示“当前落点可继续调整”；
- 提交后冻结，不允许悄悄覆盖；
- 不把小于 25 km 的误差差异包装成有意义的排名。

合作成绩建议用两人误差中的较大值进入宽松等级，而不是比较胜负：

| 较差距离 | 共同等级 |
| --- | --- |
| `<= 50 km` | 像昨天才去过 |
| `<= 200 km` | 方向一直在 |
| `<= 800 km` | 记忆还认得回家的路 |
| `> 800 km` | 下次一起把它记得更清楚 |

阈值必须在实现前用真实移动端试玩校准；本表是调研建议，不在本阶段冻结。

## 8. 隐私与内容配置

“我们的地点”天然可能暴露住址、工作地点、旅行轨迹和关系信息。首版必须采取最小数据原则：

- 仓库只提供虚构示例，不提交真实姓名、住址、约会地点或照片；
- 准备者在本地复制 `config.example.js` 为忽略追踪的私人配置；
- 地点卡只需 ID、公开线索、目标经纬度和可选结语；
- 不需要地址、国家、城市、照片、EXIF 或 GPS 权限；
- 不调用地理定位 API；
- 不提供地址搜索和反向地理编码；
- 不写 localStorage、IndexedDB、Cookie、日志文件或云端；
- 页面刷新、成员变化、服务重启即清空比赛；
- 结果页不生成分享链接、截图或社交卡片；
- 局域网流量未端到端加密，只在可信 Wi-Fi 使用。

若未来需要本地照片，必须另开规格并沿用本地文件“不上传、不持久化、清理对象 URL”的边界；首版排除照片。

## 9. Go / No-Go Gate

### Go 条件

- 产品采用合作而不是最近者获胜；
- 默认内容是虚构示例，私人配置留在忽略追踪文件；
- 只使用 Natural Earth 物理 land 数据，不使用在线瓦片或行政边界；
- 固定上游 commit 与输入/输出哈希；
- 不修改共享运行时，不增加 npm 依赖；
- 密封提交、成员变化清局、第三人退出和 host 迁移均有测试；
- 距离基于 haversine，不基于屏幕像素；
- 触屏和键盘都能落点、调整和提交；
- Chrome 双端证明 Network 无公网请求。

### No-Go 条件

出现任一项即停止生产：

- 需求回退为 Posio 的城市/旗帜/最近者获胜复刻；
- 需要复制 Posio 源码、UI、题库或部署栈；
- 需要在线瓦片、公共服务器、账号或位置权限；
- 地图来源、版本或派生过程无法固定；
- 私人地点必须提交公开仓库才能运行；
- 双人密封落点无法与现有问答作品形成足够机制增量；
- 移动端无法在宽松阈值下形成可理解且可复现的距离结果。

## 10. 调研结论

**有条件 Go。**

技术上，现有 C 级本地房间、密封回合与静态资源服务足够，不需要 Django、Redis、Leaflet、在线瓦片或新依赖。权利上，Posio 的固定提交和 MIT 权利主体已核验，但本作只保留概念声明并执行零复制；Natural Earth v5.1.2 物理 land 数据可固定为 public-domain 离线输入。

产品上，Go 的前提是保留原创核心：两个人面对共同回忆，各自密封落点，以较差距离形成共同成绩。下一阶段 brainstorm 将比较具体回合结构，并决定最终名称、地点卡模型与是否允许回合内交流。
