## 2. Chrome 双端流程

使用 Chrome 扩展会话创建房主、访客、第三人和移动端标签页，真实连接本机 Socket.IO 服务完成以下流程：

1. 房主创建房间，第二位玩家用五位房间码加入；
2. 第三位玩家加入时稳定收到“房间人数已满。”，原两位玩家状态不受影响；
3. 第一位玩家密封答案后，另一端仍看不到答案，只看到等待状态；
4. 第二份答案到齐后，两端同时揭晓，并得到相同的题号、双方答案和同心数；
5. 连续完成八题，交替验证相同与不同答案，最终两端均显示 `4 / 8`；
6. 房主离开后，留下的玩家被提升为房主，旧题、答案、揭晓 class、ARIA 状态和结果文案全部清空；
7. 新成员加入后可以开始新局；
8. 房主、访客、第三人和移动端控制台均无 warning 或 error。

资源树中作品自身只加载本机页面与 `http://localhost:4173/socket.io/socket.io.js`。检查时出现的 `chrome-extension://.../cursor-chat.png` 由验收用 Chrome 扩展注入，不属于作品依赖；页面没有公网资源请求。

## 4. 视觉忠实度

实现以 [`compatibility-quiz-concept.png`](./assets/compatibility-quiz-concept.png) 为视觉基准，采用浏览器真实页面截图逐项对照：

1. **核心文案**：标题、`01 / 08` 进度、首题“周末突然空出一天，你更想？”和两个答案与概念稿一致；
2. **色彩**：暖纸底、深李子文字、莓果红选中态、浅腮红未选项对应设计令牌；
3. **字体层级**：标题与问题使用中文衬线回退，房间、进度、状态和控件使用系统无衬线；
4. **桌面构图**：保持开放页面、左右两人并置、中线与揭晓心线，没有引入卡片网格、玻璃拟态或装饰徽章；
5. **状态反馈**：选中答案为莓果红底白字，揭晓后双方答案同时出现；触屏 sticky hover 不再覆盖选中态；
6. **移动构图**：720px 以下纵向堆叠，作答时只保留“等待对方”状态，不提前展示对方候选；
7. **动效与可访问性**：交互时长保持在视觉规格范围，支持 `prefers-reduced-motion`，按钮含清晰焦点与文字/标记双重反馈。

首屏锁定文案没有增加眉题、类别、排名、分享或关系诊断。功能规格要求的“密封这个选择”确认按钮是相对概念稿唯一的有意增加：它保证点击答案和提交秘密是两个独立动作。移动端截图后又把已选择状态的辅助文案从“先选一个答案”定向修正为“准备好后，把这个答案密封。”；这是纯文案条件修正，不改变布局与视觉令牌。
