# 四符片名擂台：玩法 Brainstorm

> 前置调研：`docs/271-emoji-movie-duel-research.md`
> 候选：`emoji-movie-duel`
> 建议生产 ID：`four-symbol-film-duel`
> 建议产品名：**四符片名擂台**
> 目标：从多个可行方向中选择一个可离线、可公平对抗、可独立创作的首版

## 1. 一句话体验

两个人轮流面对由四枚 Emoji 组成的原创“电影谜面”，在四个虚构片名中选出最合理的答案；每个人都可以有限次点亮“聚光灯”排除一个错误答案，但本题得分会降低。

## 2. 产品承诺

这不是影视知识考试，也不是认 Logo 或背台词。

它承诺的是：

- 四个符号带来的快速联想；
- 原创片名带来的小型故事感；
- 是否使用提示的资源博弈；
- 双方题目不同但强度相近；
- 一台电脑直接打开、十分钟内完成；
- 不联网、不注册、不安装；
- 没看过任何特定电影也能公平参与。

## 3. 设计支柱

### 3.1 四符成句

每题恰好四枚符号。限制必须固定，否则“随便放很多 Emoji”会失去辨识度和设计张力。

四符不是逐字翻译，也不是固定码本。它们共同营造：

- 人物或主体；
- 行动；
- 场景；
- 情绪、转折或结局。

一张好题应该让玩家先形成一个微型故事，再从原创片名中选择最贴切的命名。

### 3.2 对称而不相同

双方不答同一题，避免后手记住答案；但双方题目来自成对设计：

- 难度相同；
- 类型相同；
- 片名长度接近；
- 干扰项强度接近；
- Emoji 熟悉度接近。

这是一种“结构对称”，不是机械复制。

### 3.3 提示有代价

“聚光灯”不是免费帮助，而是一个需要权衡的有限资源：

- 不使用：答对得 2 分；
- 使用：排除一个错误选项，答对得 1 分；
- 每人整局只有 2 次；
- 每题最多使用 1 次。

玩家既要判断当前题目，也要判断后面是否可能更难。

### 3.4 原创虚构影院

题库不是现实影视索引，而是仓库自己的“小小虚构影院”。片名、类型、线索和解释都可以形成统一气质，例如：

- 轻奇幻；
- 城市小事；
- 太空寓言；
- 动物冒险。

原创题库既是风险控制，也是产品的内容人格。

## 4. 探索过的玩法方向

### 4.1 方向 A：自由出题对抗

流程：

1. 玩家 A 输入答案；
2. A 从符号盘选四枚 Emoji；
3. 玩家 B 猜；
4. 交换角色。

优点：

- 创作感最强；
- 很适合熟悉彼此的情侣；
- 题目可以贴近共同回忆。

问题：

- 出题者可能故意给出难以理解的提示；
- 自由答案需要模糊匹配、别名或人工裁决；
- 输入真实片名会引入不可控内容；
- 移交设备时存在答案偷看；
- 与你画我猜类项目的“玩家生成提示”结构接近；
- 很难把得分解释为公平竞技结果。

结论：不作为首版排名玩法。未来可以做“默契自编场”，明确标为非排名、共同创作模式。

### 4.2 方向 B：真实电影竞猜

流程：

1. 展示四枚 Emoji；
2. 从四个真实片名中选择；
3. 按影视知识得分。

优点：

- 上手成本低；
- 天然有熟悉感；
- 内容传播性强。

问题：

- 需要逐题核查片名、系列标识和表达来源；
- 很容易依赖经典场景、人物或剧情梗；
- 会让没看过相关影片的人处于明显劣势；
- 第三方题库来源难追踪；
- 产品价值会退化为换皮四选一。

结论：不采用。

### 4.3 方向 C：原创虚构片名对抗

流程：

1. 系统从已配平题包中给当前玩家一题；
2. 玩家解读四枚 Emoji；
3. 可选使用一次聚光灯；
4. 从四个原创片名中提交答案；
5. 交给另一位玩家；
6. 8 回合后比较总分。

优点：

- 权利来源清晰；
- 不要求影视知识；
- 规则公平可复核；
- 能形成独特内容资产；
- 本地静态实现简单；
- 可以同时支持视觉和文字等价模式。

问题：

- 原创题库需要人工编写和盲测；
- 题目可能存在歧义；
- 配平需要数据字段和审查流程。

结论：**首版采用**。

### 4.4 方向 D：合作制片

流程：

- 两人共同用 Emoji 给虚构片名配线索；
- 系统根据规则检查是否达到四枚；
- 完成后生成“电影票根”。

优点：

- 很适合情侣共同创作；
- 没有胜负压力；
- 可作为惊喜留念。

问题：

- 自动判定线索好坏没有可靠标准；
- 和对抗候选目标不一致；
- 需要导出或保存能力才有完整价值；
- 可能与已有共同创作项目重叠。

结论：作为未来独立候选，不并入本项目。

## 5. 选定方案

### 5.1 核心循环

```text
开场
  → 输入或选择双方称呼
  → 选择文字等价模式
  → 随机/手动选择一个完整题包
  → 玩家 A 第 1 题
  → 交接
  → 玩家 B 第 1 题
  → 持续交替至各 4 题
  → 展示总分、每题结果与平局/胜者
  → 再玩一个未使用题包
```

### 5.2 每回合循环

```text
展示当前玩家与剩余聚光灯
  → 展示四符题面
  → 浏览四个片名
  → 可选：消耗聚光灯，排除一个预设错误项
  → 选择一个片名
  → 确认提交
  → 展示正确答案、简短原创解释与所得分数
  → 进入交接屏
```

### 5.3 为什么只允许一次作答

若允许多次猜测，玩家可以从四个选项中穷举，提示的价值也会崩塌。一次提交让：

- 选择具有明确后果；
- 聚光灯资源有意义；
- 计分无需复杂衰减；
- 一局时长稳定；
- 键盘和屏幕阅读器流程更简单。

## 6. 计分方案比较

### 6.1 方案一：3 / 2 分

- 直接答对 3 分；
- 使用提示答对 2 分。

优点是分数看起来更丰厚；缺点是提示代价较弱，常常值得无脑使用。

### 6.2 方案二：2 / 1 分

- 直接答对 2 分；
- 使用提示答对 1 分。

优点：

- 代价直观；
- 总分范围小，结算易懂；
- 直接解出一题等于提示解出两题；
- 每人最高 8 分，便于心算。

缺点是平局概率可能略高。

### 6.3 方案三：2 / 0 分

- 直接答对 2 分；
- 使用提示只保住答题记录，不得分。

代价太重，玩家会不愿使用核心机制。

### 6.4 选择

采用 **2 / 1 / 0**：

- 不提示答对：2 分；
- 提示后答对：1 分；
- 答错：0 分。

平局是有效结局，不再用速度、额外随机题或先手优势强行决胜。

## 7. 题包结构 Brainstorm

### 7.1 随机抽题

从 32 题独立随机抽 8 题，再交替分给双方。

问题：随机分配很难保证双方难度、类型和干扰项结构一致。不采用。

### 7.2 镜像同题

双方回答同一组题。

问题：单设备上后手已经看过答案，无法使用。不采用。

### 7.3 预配对题包

每个题包包含四组 A/B 配对：

| 回合对 | A 方卡 | B 方卡 | 难度 | 类型 |
|---|---|---|---:|---|
| 1 | P1-A | P1-B | 1 | 城市 |
| 2 | P2-A | P2-B | 1 | 动物 |
| 3 | P3-A | P3-B | 2 | 奇幻 |
| 4 | P4-A | P4-B | 3 | 太空 |

优点：

- 可人工检查；
- 可做盲测；
- 不会因随机抽题产生极端不均；
- 数据仍然简单；
- 题包之间可以有不同内容气质。

选择：**预配对题包**。

### 7.4 首版内容量

选定 4 个题包 × 每包 8 张卡 = 32 张卡。

理由：

- 支持至少四局不重复；
- 内容量足以验证题库机制；
- 仍能逐张做原创和歧义审查；
- 不需要生成器；
- 后续扩展可以只追加完整题包。

## 8. 符号盘与题面

### 8.1 闭合符号表

第一版不用全量 Unicode Emoji。应维护一个小型、经审核的 token 表：

```js
{
  id: "moon",
  glyph: "🌙",
  labelZh: "月亮",
  concepts: ["夜晚", "月光", "睡眠"],
  safe: true
}
```

`concepts` 只供内部内容审查使用，玩家界面只用 `glyph` 和 `labelZh`。

### 8.2 四符语法

不强制每张题都使用相同句法，但建议至少覆盖三种结构：

- 主体 → 行动 → 场景 → 情绪；
- 场景 → 物件 → 事件 → 结果；
- 两个对照主体 → 连接 → 转折。

题库审查时应避免：

- 四枚符号只是片名逐字替换；
- 一枚符号独自泄露答案；
- 必须依赖 Emoji 颜色或厂商细节；
- 只有作者自己知道的私人联想；
- 使用符号顺序与解释完全无关。

## 9. 聚光灯提示设计

### 9.1 被排除的选项

提示不应随机排除一个错误答案。随机会导致：

- 有时排除最弱干扰项，几乎没帮助；
- 有时排除最强干扰项，价值过高；
- 同一题重玩时结果不同；
- 盲测难以复现。

每张卡应预先标出一个“合理但非最强”的干扰项供聚光灯排除。内容审查同时确认该选择。

### 9.2 视觉语言

使用“聚光灯照亮线索”的隐喻：

- 按钮文字明确写“使用聚光灯：排除 1 项，本题最多 1 分”；
- 使用后，被排除项仍保留位置但不可选；
- 不仅靠降低透明度，显示“已排除”文本；
- 剩余数量立即更新；
- 不能撤销，点击前需要按钮文案充分说明代价，不再弹模态框。

### 9.3 资源数量

每人 2 枚最合适：

- 4 题中最多帮助一半；
- 需要做跨回合判断；
- 不会因为只给 1 枚而过分惜用；
- 不会因为给 4 枚而失去资源管理。

## 10. 文本等价模式

### 10.1 模式一：默认符号模式

- 视觉玩家只看到四枚 Emoji；
- 屏幕阅读器获得等价中文标签；
- 不显示内部解释；
- 题意仍来自四枚符号组合。

### 10.2 模式二：符号 + 文字

- 每枚 Emoji 下显示其中文标签；
- 两名玩家同局使用相同模式；
- 分数和题目不变；
- 开局后锁定，避免双方设置不同。

### 10.3 不采用纯文字替换

完全隐藏 Emoji、只展示四个名词虽然可玩，但会失去产品身份。视觉模式应保留 Emoji，文字作为等价辅助。

对于无法渲染的字形，可在 token 下方显示标签作为自然兜底，而不是下载远程图片。

## 11. 开场、交接与结算

### 11.1 开场

开场只收集必要信息：

- 玩家称呼，可留空并使用“玩家 A / 玩家 B”；
- 文字等价模式开关；
- 题包选择：“随机未玩题包”或四个明确题包。

不收集：

- 账号；
- 性别；
- 关系天数；
- 生日；
- 网络昵称；
- 真实影视偏好。

### 11.2 交接

交接屏显示：

- 下一位玩家称呼；
- 当前回合进度；
- 双方公开分数；
- “我准备好了”按钮。

不显示下一题的符号或选项。

### 11.3 结算

结算显示：

- 胜者或“默契平局”；
- 双方总分；
- 聚光灯使用次数；
- 每题的四符、正确片名、玩家选择、得分；
- 再玩一个题包；
- 返回开场。

不生成社交分享图，不上传成绩，不要求复制到剪贴板。

## 12. 视觉方向探索

### 12.1 方向 A：霓虹影院

- 深色背景；
- 洋红和蓝色霓虹；
- 大量发光和扫光。

优点：电影感直接。

缺点：容易俗套，发光影响阅读，Emoji 色彩与背景可能冲突。

### 12.2 方向 B：独立影院票根

- 暖米色纸张；
- 深红、墨黑、黄铜色；
- 票根、座位号、放映场次等轻量隐喻；
- 符号题面像“四格片头卡”。

优点：

- 有电影氛围但不依赖真实影视素材；
- 适合情侣和双人桌面游戏；
- 高对比度容易控制；
- 可用纯 CSS 完成。

缺点：需要避免装饰过多。

### 12.3 方向 C：电视游戏秀

- 高饱和色；
- 倒计时；
- 主持人文案；
- 大按钮和音效。

优点：竞技感强。

缺点：速度和噪音不是本项目核心，容易造成压力。

### 12.4 选择

采用 **独立影院票根**：

- 深酒红背景；
- 暖纸色主卡；
- 黑色或深棕正文；
- 黄铜色聚光灯；
- 每位玩家各有一种辅助色，但所有状态都有文字和图形；
- 动效只用于卡片入场和聚光灯，且支持减少动态效果。

## 13. 语气与文案

语气应像一间只为两人开场的小影院：

- 温暖；
- 简短；
- 有一点电影隐喻；
- 不油腻；
- 不把输赢上升为关系评价。

推荐：

- “本场放映：第 2 题”
- “四个符号，一部从未上映的电影”
- “聚光灯会排除一个错误片名，但本题最多得 1 分”
- “这一幕猜中了”
- “片尾平分，今晚没有配角”

避免：

- “更爱对方的人获胜”
- “默契失败”
- “你怎么连这都猜不到”
- “输家接受惩罚”
- 真实影院或流媒体品牌口吻。

## 14. 状态机草案

```text
SETUP
  → HANDOFF
  → QUESTION
  → CONFIRM
  → RESULT
  → HANDOFF
  → ...
  → SUMMARY
```

关键限制：

- `QUESTION` 只能选择一个尚未排除的选项；
- 未选择时不能进入 `CONFIRM`；
- `CONFIRM` 提交后不可返回；
- `RESULT` 只结算一次；
- 8 题完成后只能进入 `SUMMARY`；
- 刷新页面允许重新开始，不承诺恢复中局。

## 15. 第一版明确不做

- 真实电影题库；
- 公版电影题包；
- 玩家自由输入片名；
- 玩家自由选 Emoji 出题；
- 在线影视数据库；
- AI 自动生成题目；
- 多语言；
- 联机；
- 计时排名；
- 音效和背景音乐；
- 成绩分享图；
- 自定义题包编辑器；
- 本地导入导出；
- 连胜、成就和排行榜；
- 单人模式；
- 观众模式；
- 复杂动画。

这些不是永久否定，而是防止第一版偏离“公平原创四符对抗”。

## 17. 进入 Spec 的冻结项

下一阶段不再讨论以下选择：

- 不使用真实电影；
- 不让玩家自由出题；
- 不采用速度决胜；
- 使用 32 张原创卡；
- 使用 4 个完整配平题包；
- 每局 8 题、每人 4 题；
- 每人 2 枚聚光灯；
- 采用 2 / 1 / 0 计分；
- 允许平局；
- 使用系统 Unicode 字形，不打包平台 Emoji 图像；
- 第一版不引入第三方依赖。

Spec 需要把这些选择转成可验收的数据契约、交互规则、可访问性要求和 `file://` 约束。
