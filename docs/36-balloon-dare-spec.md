# A 级「气球胆量局」双人对抗规格

## 1. Brainstorm 结论

本批实现一款单设备轮流冒险的双人对抗：每位玩家面对一只隐藏爆点的气球，可以逐次打气，也可以随时“见好就收”把本轮积分存入总分。继续加压会让本轮收益按三角数增长，但一旦达到隐藏爆点，本轮所有待收积分归零。四个公平轮次、双方各玩四只气球后，总分高者获胜。

| 方案 | 价值 | 风险与成本 | 本批决定 |
| --- | --- | --- | --- |
| 双方轮流给同一只气球打 1–3 下 | 像传递定时炸弹，互动直接 | 隐藏阈值与先后手组合容易形成不可解释偏差 | 不采用 |
| 每位玩家拥有独立气球，随时打气或收手 | 决策清楚，风险由自己承担 | 随机爆点会产生运气差异 | 采用；双方获得相同数量、同分布的独立机会 |
| 先到目标分立即获胜 | 节奏快 | 先行动者可能少给对方一次追分机会 | 不采用 |
| 固定四轮、双方各完成一只气球 | 机会数相同，可以平局 | 共八个回合略长 | 采用，目标 2–4 分钟 |
| 每轮总是甲先 | 实现最简单 | 后行动者能看到前者分数，信息顺序不公平 | 不采用 |
| 四轮按甲→乙、乙→甲交替 | 双方各有两次先手和两次后手 | 需要确定性 turn schedule | 采用 |
| 每泵固定 1 分 | 风险回报容易理解 | 高风险没有足够诱惑 | 不采用 |
| 待收分使用三角数 `1, 3, 6, 10…` | 每多一泵的边际收益持续上升 | 需把收益表清楚展示 | 采用 |

作品名为「气球胆量局」，目录 ID 为 `balloon-dare`，主分类为双人对抗，等级 A。它补齐仓库当前没有的“push-your-luck / 主动止盈”状态模型，不新增第三方依赖。

## 2. 受众、唯一任务与语气

- **受众**：围在同一台电脑、平板或手机前，想玩一局轻量心理博弈的情侣或伴侣；
- **唯一任务**：每次选择继续打气或收下本轮积分，四轮后争取更高总分；
- **语气**：嘉年华式紧张但不嘲讽，爆掉写作“这一轮飞走了”，不评价胆量或性格；
- **首局理解目标**：进入页面后 20 秒内知道“多打一泵分更多，爆掉本轮归零”。

## 3. 严格最小范围

只实现：

- 珊瑚方与青绿方两位固定席位；
- 四个大轮、每轮双方各完成一个独立气球，共八个回合；
- 起手顺序固定为 `珊瑚→青绿 / 青绿→珊瑚 / 珊瑚→青绿 / 青绿→珊瑚`；
- 每只气球的爆点由本机安全随机生成，均匀分布在第 4–8 泵；
- 前三泵绝对安全；每次安全泵后的待收分依次为 `1 / 3 / 6 / 10 / 15 / 21 / 28`；
- “再打一泵”“见好就收”、回合交接、爆裂、本轮存分、总分与最终结果；
- 触控按钮与键盘 `↑ / ↓` 等价；
- 平局作为正式结果，可直接重赛。

明确不做昵称、难度设置、道具、生命、下注、惩罚、AI、排行榜、历史、本地存储、分享、音频、震动、联网房间或局域网同步。

## 4. 公平性与随机边界

### 4.1 固定机会与先后手

`TOTAL_TURNS = 8`，每两回合构成一个大轮。当前玩家只由 `turnIndex` 派生：

```text
turn 0: 珊瑚   turn 1: 青绿
turn 2: 青绿   turn 3: 珊瑚
turn 4: 珊瑚   turn 5: 青绿
turn 6: 青绿   turn 7: 珊瑚
```

因此双方都有四只气球、两次先于对方行动和两次后于对方行动。比赛不会因为某人先达到分数而提前结束；第八个回合完成后才比较总分。

### 4.2 爆点

- 浏览器层使用 `crypto.getRandomValues(new Uint32Array(1))`；不可用时显示稳定错误，不回退到 `Math.random`；
- `mapRandomToBurstPoint(value)` 对可接受的无符号 32 位整数取模映射到 `4..8`；由于 `2^32` 不能被 5 整除，唯一多出的最大值必须拒绝并重抽，不能用有偏的直接取模冒充等概率；
- 爆点只在玩家确认开始当前回合时传给纯逻辑；handoff DOM、按钮属性、CSS 变量、URL 与日志都不包含它；
- 同一回合重渲染、切换焦点或重复事件不能重新抽爆点；
- 随机性决定单回合运气，但双方从同一分布得到相同次数的独立样本。作品不宣称竞技级随机公平。

### 4.3 计分

安全完成第 `n` 泵后：

```text
pending = n × (n + 1) / 2
```

玩家选择收手时把 `pending` 一次性加入自己的总分；达到爆点时 `pending` 清零，总分不倒扣。前三泵必定安全，所以玩家始终有一个低风险可得分路径。

## 5. 状态机

```text
intro
  └─ START_MATCH → handoff
handoff
  └─ BEGIN_TURN(burstPoint) → pumping
pumping
  ├─ PUMP(nextPump < burstPoint) → pumping
  ├─ PUMP(nextPump = burstPoint) → burst
  └─ BANK(pumps > 0) → banked
burst / banked
  ├─ ADVANCE(turnIndex < 7) → handoff
  └─ ADVANCE(turnIndex = 7) → complete
complete
  └─ RESTART → intro
```

状态至少包含：

```text
phase, turnIndex, scores, pumps, pending, burstPoint, outcome
```

`scores` 与返回状态冻结，调用方不能在 reducer 外修改历史。当前玩家、当前大轮和先后手从 `turnIndex` 派生，不重复存储，避免换棒字段漂移。

### 5.1 输入 Gate

- `BEGIN_TURN` 只接受 handoff 与合法爆点；
- `PUMP` 只接受 pumping；一次物理动作只能增加一泵；
- 0 泵时不能 `BANK`，避免空操作跳过自己的气球；
- burst / banked 阶段不能继续泵或重复结算，必须明确推进；
- 第八回合 outcome 后才能 `ADVANCE` 到 complete；
- complete 比较两个总分，可得到珊瑚胜、青绿胜或平局；
- 非法阶段、未知动作、畸形分数、非法爆点和重复事件返回原引用或安全初始状态。

## 6. 纯逻辑接口

`logic.js` 采用经典脚本 factory，同时支持 `file://` 与 Node 测试：

```text
createDareState()
startMatch(state)
beginTurn(state, burstPoint)
pumpBalloon(state)
bankTurn(state)
advanceTurn(state)
restartMatch()
playerForTurn(turnIndex)
roundForTurn(turnIndex)
scoreForPumps(pumps)
mapRandomToBurstPoint(value)
```

至少测试：

- 初始状态、四轮八回合与先后手序列；
- 32 位随机数到 `4..8` 的首尾边界与均匀区间；
- 前三泵安全、三角数待收分；
- 达到爆点只清当前待收分，不倒扣总分；
- 0 泵不能收手，收手只结算一次；
- banked / burst 明确推进并清理私有爆点；
- 双方各四次机会后才完成；
- 珊瑚胜、青绿胜和平局；
- 未知事件、重复输入、畸形状态和调用方数组保持安全。

## 7. 浏览器编排与隐私

### 7.1 回合交接

handoff 只显示“第几轮、轮到哪一方、当前总分”和“接过设备”。当前玩家点击后才抽取一次爆点并进入 pumping。爆点不属于需要对另一位保密的私人内容，但它必须对两位玩家都不可见，否则风险决策失效。

### 7.2 动画不是状态权威

- 气球尺寸由 `pumps / 8` 派生 CSS 变量，只用于视觉；
- 每次 PUMP 先经 reducer 判定，再播放一次短促形变；
- burst 动画不能延迟或重复计分，phase 在动画前已经确定；
- `prefers-reduced-motion` 下取消弹跳、爆裂飞片和分数上浮，结果文字仍即时出现；
- 页面隐藏或失焦不改变回合，因为首版没有倒计时和后台计划器。

### 7.3 数据边界

- 不使用 fetch、XHR、WebSocket、CDN、远程字体、localStorage、sessionStorage、IndexedDB、Cache API、Service Worker、账号、统计或遥测；
- 爆点、进度与比分只在当前页面内存存在，刷新即清空；
- 不读取相册、麦克风、摄像头、剪贴板或传感器。

## 8. 视觉方向

方向是 **夜间嘉年华气球摊 + 老式机械打气计**，避免继续使用磁带、运动赛道、暖纸信件或夜航地图。

视觉概念稿：[桌面与移动端嘉年华构图](assets/balloon-dare/concept.png)。概念稿只用于确定构图、色彩与机械装置方向；运行页的中文标题、分数、按钮和状态提示全部由 HTML/CSS 原生排版，避免把生成图中的文字当成产品文案。

## 9. 响应式与可访问性

- 1269×774 首屏完整看到标题、双方比分、气球、待收分和两项决策；
- 390×844 保持决策按钮并排；320×700 可上下排列但每个至少 64px 高；
- 无横向溢出，安全区使用 `env(safe-area-inset-*)`；
- `↑ / ↓` 只在 pumping 阶段拦截，`event.repeat` 一律忽略；
- Tab、Enter 和 Space 保留原生按钮语义，同一动作不在 pointerdown 与 click 重复派发；
- 状态区 `aria-live="polite"` 只宣布回合结果，不逐帧播报气球尺寸；
- 压力表同时显示“已打 N 泵”和当前待收分，颜色不是唯一信息；
- 焦点环清晰，交接、结果和完成阶段的唯一主按钮自动获得焦点；
- JavaScript 不可用时显示明确说明。

## 12. Chrome 验收

- 从 intro 完成八个回合，覆盖收手、爆裂、珊瑚/青绿换棒和最终胜/平结果；
- 用受控爆点验证前三泵安全、第四至第八泵边界和重复输入 Gate；
- 0 泵时收手禁用，结果阶段两决策按钮禁用；
- DOM、按钮属性、CSS 变量和可访问名称不泄露爆点；
- 键盘 `↑ / ↓` 与触控按钮都能完成核心路径，系统 repeat 不重复打气；
- 1269×774、390×844 与 320×700 无横向溢出、核心决策不裁切；
- reduced motion 下规则反馈完整；
- 控制台无 error/warning，Network 无公网资源；
- 从根门户可以打开作品，返回链接正确。

## 13. 完成与提交标准

- 双方各有四次独立气球机会，先后手对称，四轮后才结算；
- 打气、止盈、爆裂、推进、平局和畸形输入有纯逻辑测试；
- A 级双击成立，无第三方依赖、公网请求和持久化；
- README 有明确独立实现与未来引用更新义务；
- `npm test`、`npm run verify`、语法检查和 `git diff --check` 通过；
- Chrome 桌面与移动核心路径通过；
- 新 bug 写入 `bugs/`，跨作品经验写入 `learn/`；
- 本规格与完整作品分别形成独立提交。
