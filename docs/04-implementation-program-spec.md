# Two of Us 持续建设规格

> 建立日期：2026-07-15 · 状态：执行中

## 1. 最终目标

把调研中法律与技术上可行的候选，逐批变成真正可交付的情侣互动体验。安装阶段允许统一下载依赖；安装完成后，用户不需要账号、命令行或公网连接，通过双击入口即可打开每个作品。

“能做”同时满足四个条件：

1. 许可证允许引入，或只借鉴玩法并由本仓库自行实现；
2. 核心体验可以在本机或同一局域网内完成；
3. 所需运行时、模型和素材可以明确安装、固定版本并合法分发；
4. 能提供可重复的启动、停止、测试和故障提示。

## 2. 法律与实现边界

- MIT、Apache-2.0、BSD、ISC 等项目可以优先评估引入，但仍要保留许可证与素材来源；
- GPL、AGPL、MPL 项目单独保留许可证边界，默认优先借鉴架构或玩法，避免无意扩大整个仓库的许可证义务；
- 未声明许可证的项目只记录机制，不复制代码、文案或素材；
- 只要参考过开源项目，不论是否复制代码，都必须在作品 README 写“借鉴与来源声明”，明确参考了什么、没有使用什么；
- 运行时许可证、模型权重许可证、素材许可证分别核验，不能互相替代；
- 商业音乐、真实照片、声音克隆样本与私人聊天默认留在用户本地配置，不提交到公开仓库。

## 3. 统一运行架构

```text
setup.command / setup.bat
        │
        ├── 安装并锁定共享依赖
        └── 检查本地运行时与可选能力包

start.command / start.bat
        │
        └── shared/runtime
              ├── 启动本地静态服务
              ├── 选择可用端口
              ├── 打开浏览器门户
              ├── C 级显示局域网地址与二维码
              └── D 级检查模型、权限、磁盘与硬件

experiences/<category>/<slug>/
        ├── experience.json
        ├── index.html
        ├── assets/
        └── start.command / start.bat（仅调用共享启动器）
```

### 共享依赖原则

- 根目录只有一份锁文件和安装入口；
- 浏览器依赖优先构建成固定版本的本地资源，不在游玩时访问 CDN；
- 网络房间默认使用共享的 Socket.IO/本地 HTTP 层；只有确实需要媒体直连时再引入 WebRTC；
- 模型和大型素材使用 manifest 记录来源、版本、哈希、大小与许可证，不在代码里隐式下载；
- 体验之间不直接引用彼此的私有文件，共享能力只能放进 `shared/`。

## 4. 启动契约

| 等级 | 用户动作 | 完成条件 |
| --- | --- | --- |
| A | 双击作品 `index.html` | 无安装、无服务、无外部请求 |
| B | 双击作品启动器 | 自动启动 localhost、打开正确页面、重复启动不会产生多个失控进程 |
| C | 双击主机启动器 | 主机页面显示二维码与短地址，第二台设备在同一局域网加入，退出后端口释放 |
| D | 双击作品启动器 | 缺少运行时/模型时给出可操作提示；准备完成后自动进入体验 |

根门户始终可以通过根 `start.command` / `start.bat` 打开，并显示每个作品的等级、人数、设备、安装状态与启动按钮。

## 5. 分批实现路线

### 第 0 批：研究与基础设施

- 完成第二轮 A–D 候选总报告与可行性矩阵；
- 建立 `bugs/`、`learn/` 的记录规范；
- 建立根依赖、共享运行时、跨平台安装/启动入口和作品 manifest；
- 把现有 Love Tree 纳入统一门户，但保留 A 级直接打开能力。

### 第 1 批：零重型依赖样板

- 单人惊喜：回忆相册或拆信封惊喜；
- 双人合作：热座你画我猜；
- 双人对抗：反应力对决；
- C 级样板：手机加入的同步按键或抢爱心游戏。

这一批先建立统一的配置、计时、交接遮挡、计分、重新开始和移动端输入组件。

### 第 2 批：可复用玩法族

- 惊喜：刮刮卡、约会转盘、未来信箱、360°回忆地点、音乐可视化；
- 合作：爱情地图、协作拼图、机关迷宫、语音暗号；
- 对抗：Pong、四子棋、海战棋、手机控制器竞速、你画我猜对抗版。

### 第 3 批：本地重型能力

- MediaPipe 手势/姿态；
- whisper.cpp 或 sherpa-onnx 本地语音；
- Transformers.js / ONNX Runtime Web 本地语义与图像能力；
- Three.js / Babylon.js 3D 回忆空间；
- 本地生成式图像或语言模型只在许可证、模型体积和硬件 Gate 通过后进入。

## 6. Bug 记录规则

每个实际发现并已复现的缺陷写入 `bugs/YYYY-MM-DD-<slug>.md`，至少包含：

- 影响的作品与版本；
- 环境和复现步骤；
- 预期与实际结果；
- 根因；
- 修复内容；
- 回归验证；
- 相关 commit。

尚未确认根因的问题可以标记 `investigating`，但不能把猜测写成结论。

## 7. Learn 沉淀规则

可跨两个以上作品复用，或能改变后续技术选择的知识写入 `learn/`。典型主题包括：

- `file://`、localhost、局域网 HTTPS 与浏览器权限；
- 一键启动器、端口与进程生命周期；
- Socket.IO 房间、断线重连和隐藏信息；
- WebRTC 信令、ICE 与本地网络边界；
- WASM、Web Worker、WebGPU 和模型缓存；
- 代码、模型、素材的许可证分层；
- 双人同屏、热座交接、手机控制器的交互模式。

## 8. 单批完成定义

一个作品只有同时满足以下条件才算完成：

1. 玩法从入口到结果完整可用；
2. 按声明的 A/B/C/D 路径直接打开；
3. 核心体验断开公网仍然可用；
4. README、来源、许可证、隐私与定制方式齐全；
5. 所有参考项目已经按“玩法 / 架构 / 代码 / 依赖 / 素材”分类写明借鉴声明；
6. 对应静态检查、测试或构建通过；
7. UI 使用真实浏览器验证；C 级使用第二设备或等价真实客户端验证；
8. 本批发现的 bug 已进入 `bugs/`，可复用知识已进入 `learn/`；
9. 形成作用域清晰的独立 commit。
