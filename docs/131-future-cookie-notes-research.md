# S10“幸运饼干未来签”定向调研：三枚以后，都是我们

调研日期：2026-07-19。

## 结论

S10 适合实现为 A 级单人惊喜作品“三枚以后，都是我们”，工作 ID 为 `future-cookie-notes`。推荐完全原创实现，不引入第三方运行时，不复制现成项目的代码、签语、图片、字体、视觉、文案或随机数据。

本作的核心不是“随机抽一句运势”，而是：收件人可以以任意顺序敲开三枚未来签，分别收好“什么时候”、“去哪里”和“一起做什么”三段私人约定；三段齐全后，再由收件人主动点击“把三个以后拼起来”，才展开完整邀请。

它满足创意池的五项进入条件：

1. 主分类唯一：一人准备，另一人打开的单人惊喜；
2. A 级可行：经典脚本、相对资源、无服务端、无账号、无公网；
3. 首次打开 30 秒内可理解：“敲开三枚，收好三段，最后拼成邀请”；
4. 去掉音乐、真实照片和随机后，核心仍完整；
5. 最小版本是一个入口、一种敲开机制、一个合成结尾。

## 为什么选择 S10

当前安装目录共 47 项：单人惊喜 15、双人合作 18、双人对抗 14。从数量看，惊喜与对抗都低于合作；从机制看，S10 又能补一个“多段内容无序收集 → 有序合成”的惊喜样板。

| 已有作品 | 已覆盖机制 | S10 的新增机制 |
| --- | --- | --- |
| 一层一层 | 线性多手势拆盒，只能按层序前进 | 三枚可任意顺序打开，重点是齐套收集与合成 |
| 未来车票 | 先盲选目的地，再揭晓一张完整计划 | 没有选项赢输；三段都是准备者真正想邀请的组成部分 |
| 慢慢打开的信 | 单封信从封闭到全文展开 | 先建立三个独立期待，最后才显示它们原来是同一封邀请 |
| 今晚做什么 | 随机挑选一个当下选项 | 不使用随机，结果是准备者写好的承诺，每次打开都一致 |

因此它不应实现为另一个轮盘或抽签器，也不应让随机数决定对方将收到哪一句话。

[WCAG 2.2 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) 明确指出，指针操作应有键盘等价，不应要求为一次按键设置特定时长。因此本作不用“必须长按 800ms 才能敲开”作为唯一路径，而是让原生按钮的 click / Enter / Space 完成同一动作。

[WCAG 2.2 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) 要求不移动焦点的重要变化可被辅助技术得知。本作只播报“已收好第 N 段”、“三段已齐”和“邀请已展开”，不逐帧播报碎屑或动画。[WCAG 2.2 Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) 对不必要的交互动画提供可关闭的方向；本作在降低动效下以即时状态替换保留全部规则。

## 推荐的原创交互

### 1. 三枚签的语义

三枚签的逻辑 ID 和作用固定，文案可在 `config.js` 修改：

| 顺序 | ID | 打开前只显示 | 默认约定的作用 |
| ---: | --- | --- | --- |
| 1 | `when` | 什么时候 | 给邀请一个温和、不强迫的时间边界 |
| 2 | `where` | 去哪里 | 给未来一个可想象的地点或场景 |
| 3 | `together` | 一起做什么 | 给对方一个可执行的共同动作 |

默认文案只作可运行样例，不引用签语库或现成句子。准备者可修改三段，不需改 HTML、CSS 或状态机。

### 2. 无序收集与有序合成

- 三枚饼干从开始就可聚焦，收件人可以任意顺序打开；
- 同一枚重复激活是幂等的，不增加计数，不替换文案；
- 打开后该枚成为静态签条，编号、标题和正文同时显示；
- 三枚全部打开后只进入 `ready`，不自动跳转；
- 只有用户激活“把三个以后拼起来”，才进入最终邀请；
- 最终文字按 `when → where → together` 的语义顺序组合，与饼干打开顺序无关。

这是本作最重要的规则：探索顺序由收件人决定，但邀请语义不被点击顺序破坏。

### 3. 阶段与秘密边界

权威状态可以保存三段配置，但 UI 只消费阶段 view：

- `collecting`：未打开项只有 ID、序号、公开标题和打开状态，没有私人正文；
- `ready`：三段正文已分别公开，但完整邀请和结语仍不进 DOM；
- `finale`：才暴露完整合成邀请、私人结语和重新打开入口。

直接打开的纯前端文件无法对会查看源码的人提供密码学隐藏。本作的承诺是“未到阶段不进可见 DOM”，而不是“源码中无法找到”。

## 确定性、重放与配置边界

- 不使用 `Math.random()`、Web Crypto、时间戳或本地存储；
- 同一配置和同一动作日志必须产生深相等终态；
- 动作只有 `OPEN_NOTE` 和 `ASSEMBLE`，可选 `RESTART` 仅在结尾生效；
- `OPEN_NOTE` 只接受三个固定 ID，拒绝多余字段、未知 ID、错阶段和重复打开；
- `ASSEMBLE` 只在三个 ID 均已打开时生效；
- 配置只接受有界纯文本，按 Unicode code point 限长，空白、异常 getter、非字符串和超长值逐字段回退；
- 动态文字只用 `textContent`，不进 `innerHTML`，不执行配置中的标记。

## 键盘、响应式与降级

- 三枚饼干均是原生 `<button>`，指针、Enter 和 Space 走同一个 click 路径；
- 打开一枚后，焦点落到下一枚未打开的饼干；三枚齐全后落到合成按钮；
- 不用悬停才显示的必要文字，不用双击、长按或摇晃作为唯一操作；
- 开启降低动效时，饼干碎开、纸签抽出和最终拼合改为即时状态替换；
- 强制颜色下用序号、文字、边框和图案区分未开、已开和已合成，不只靠金/红/绿；
- 320×700、390×844、768×1024和 1280×800 无水平滚动，主操作不被固定装饰遮挡；
- 中心背景或饼干图集加载失败时，仍能通过 CSS 轮廓、序号、标题和原生按钮完成全流程。

## 最小测试 Gate

### 逻辑

1. 初始三个 ID 都未打开，阶段为 `collecting`；
2. 任意顺序打开后，收集计数、打开集合和对应公开 view 精确；
3. 重复 ID、未知 ID、多余字段、错阶段和畸形 action 不推进；
4. 三枚齐全进入 `ready`，不自动进 `finale`；
5. 未齐全时 `ASSEMBLE` 无效，齐全后仅生效一次；
6. 六种打开排列得到同一最终语义顺序；
7. `collecting` 的未打开项不含私人正文，`ready` 不含最终结语，`finale` 才完整公开；
8. 同一配置 + action log、深克隆日志与 JSON 往返产生深相等终态；
9. 配置逐字段限长、空白/类型/异常回退、策略异常回退和输入不变；
10. 公共状态、view 与安全配置递归冻结且断开输入引用。

### 静态与浏览器

1. `file://` 经典脚本、相对资源、Network 0 和不读仓库共享依赖；
2. 按不同顺序打开三枚、收集进度、主动合成、结尾与重开；
3. 用指针、Tab / Enter / Space 分别完成一遍，焦点顺序不丢失；
4. 逐阶段扫描 DOM 文本、属性、注释和隐藏节点，未到阶段不含对应私人文字；
5. 320×700、390×844、768×1024、1280×800 无横向溢出、裁切和不可达主操作；
6. 原始动效、降低动效、强制颜色、背景失效和图集失效均不修改规则可达性；
7. 概念图与实际截图逐状态 `view_image` 对照，至少五项 fidelity ledger；
8. README 与 ATTRIBUTION 固定两个 MIT 研究项目、一个排除数据包、权利主体、版本、零复制、平台规范与 ImageGen 输入链。
