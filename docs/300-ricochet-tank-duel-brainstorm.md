# 「这一弹，拐弯见你」方案发散与收敛

> 候选 ID：`ricochet-tank-duel`
> 前置结论：`docs/299-ricochet-tank-duel-research.md` 判定为有条件 Go
> 本文目标：比较可行玩法骨架，冻结第一版方向，不进入生产实现

## 1. 设计命题

需要回答的不是“怎样做一款坦克游戏”，而是：

> 怎样在一个本地打开、同屏双人的轻 HTML 中，让两个人能读懂墙面折射、同时做决定，并且每次命中都有可复现的公平答案？

候选必须保护五个增量：

1. 实时移动；
2. 同刻输入；
3. 多枚在途弹体；
4. 多次墙面折射；
5. 同刻命中原子结算。

任何方案如果牺牲其中两项以上，就不再值得独立立项。

## 2. 三种玩法骨架

### 2.1 方案 A：自由混战场

两辆车可在整张地图自由移动，车体互相碰撞，子弹可多次折射。

优点：

- 接近玩家对“坦克对战”的直觉；
- 追逐、贴身绕后和抢占空间都可能发生；
- 单张地图的局面变化多。

问题：

- 车体碰撞、推挤、出生保护和贴脸射击会快速扩大规则；
- 双人共用小屏时容易在中央纠缠；
- 核心注意力从“规划折射”偏移到“贴身混战”；
- 与 `soft-sumo` 的连续接触对抗产生不必要的邻近感；
- 需要处理车体对车体的连续碰撞，显著增加确定性难度。

结论：**不选。** 它更像通用坦克游戏，折射不再是唯一主角。

### 2.2 方案 B：左右镜像折射场

两辆车分别在左右镜像活动区内移动。弹体可穿过中央通道、进入对方区域，并借外墙和内部墙体折射。车体不会互相接触。

优点：

- 保留实时走位与空间压力；
- 折射路线是主要进攻方式；
- 左右镜像便于验证公平；
- 去掉车体互撞，物理边界更清楚；
- 玩家在同一屏上容易快速识别自己的半场和控件；
- 与现有项目差异最清楚。

问题：

- 若中央通道过宽，直射会压过折射；
- 若墙太密，弹道不可读；
- 左右分区可能让玩家误以为不能越区射击；
- 固定地图需要精心布置可学习的单折和双折路线。

结论：**推荐。** 用地图和速度参数让直射可用但不占绝对优势。

### 2.3 方案 C：轮流布置、同时开火

双方先移动或选择方向，确认后同时发射，观看结果，再进入下一轮。

优点：

- 容易保证公平；
- 触屏输入更简单；
- 动画可读性强；
- 物理仍可包含多次折射。

问题：

- 失去实时躲避；
- 弹体通常只在一个短阶段存在；
- 很容易变成 `heart-catapult` 的同时揭晓版；
- 无法形成“场上已有弹体迫使你改线”的持续压力。

结论：**不选。** 虽然实现风险低，但增量不足。

## 3. 收敛方案

选择方案 B：**左右镜像折射场**。

一句话体验：

> 你能看见对方，却未必要朝对方开火；真正聪明的一弹，会从墙后拐弯来见你。

第一版目标不是拟真射击，而是形成三个清楚的快乐点：

1. **读线**：预判弹体碰墙后会从哪里出现；
2. **骗位**：用第一枚弹体迫使对方移动，再用第二枚封路；
3. **同刻反杀**：双方同一刻命中时都能得分，紧张但不吃更新顺序亏。

## 4. 核心循环

1. 3、2、1 倒计时；
2. 双方同时移动、旋转、观察已有弹体；
3. 玩家在冷却完成且未达弹体上限时发射；
4. 弹体穿越通道、碰墙折射或命中；
5. 本 tick 结束时原子结算命中集合；
6. 有命中则双方回到出生点、清空弹体，再次倒计时；
7. 先到 3 分者获胜；同刻都到 3 分则平局；
8. 90 秒到时按比分结算。

每个回合预计 8–25 秒，整局约 1–2 分钟。

## 5. 地图发散

### 5.1 迷宫型

大量窄通道，弹体会连续多次折射。

- 优点：折射频繁；
- 缺点：玩家难以预测，零时间拐角接触多，触屏上信息过载。

不选。

### 5.2 空旷型

只有外边界，没有内部墙。

- 优点：非常清楚；
- 缺点：直射占优，折射只是一种偶尔使用的花招。

不选。

### 5.3 镜像双盾型

每位玩家前方有一块纵向盾墙，中央上下各有一块短墙，留下中部和上下绕射通路。

- 直射存在，但需要主动对齐中央窗口；
- 盾墙能制造稳定的单折射进攻；
- 中央短墙与外边界能形成双折射路线；
- 墙数有限，玩家能逐步记住路线；
- 所有几何都可严格镜像。

推荐。

### 5.4 地图冻结方向

逻辑画布为 960×600：

- 世界安全边距：24；
- 左车活动区中心范围：`x = 48..432`；
- 右车活动区中心范围：`x = 528..912`；
- 车体半径：18；
- 左盾墙：`x = 300..340, y = 210..390`；
- 右盾墙：`x = 620..660, y = 210..390`；
- 中央上墙：`x = 456..504, y = 72..222`；
- 中央下墙：`x = 456..504, y = 378..528`。

这组坐标是 spec 的候选冻结值。实现前必须用可视化和 golden shots 验证：

- 出生点不存在开局直击；
- 中央窗口不会过强；
- 至少各有一条稳定单折和双折路线；
- 任何通道宽度均大于弹体直径加数值余量；
- 镜像测试严格成立。

## 6. 移动与瞄准发散

### 6.1 炮塔与车身分离

移动方向和瞄准方向独立，需要每方至少六个持续控制输入。

优点是策略多，缺点是同键盘操作过载、触屏需要两个摇杆，还会提升键盘冲突概率。

不选。

### 6.2 车身方向即发射方向

左右旋转车身，前进 / 后退，弹体沿车头发射。

优点：

- 每方四向加一个发射键即可；
- 方向状态容易用箭头呈现；
- 触屏可以用原生按钮；
- 玩家必须在“朝向进攻”和“朝向逃跑”之间权衡。

推荐。

### 6.3 八方向瞬时转向

按键直接切换八个朝向，没有旋转过程。

优点是输入确定，缺点是移动手感接近格点游戏，也让折射瞄准过于粗糙。

不选。保留连续转向，但逻辑使用有限整数角度表。

## 7. 弹体规则发散

### 7.1 无限寿命

弹体直到命中或离场才消失。

不选：边界会让弹体永不离场，局面和计算量失控。

### 7.2 单弹制

每位玩家场上只能有一枚弹体。

实现简单，但无法形成“第一弹逼位、第二弹封路”的特色，接近轮流投射物体验。

不选。

### 7.3 双弹、三反射、六秒寿命

每人最多 2 枚，冷却 24 tick，每枚最多 3 次反射、存活 360 tick。

优点：

- 场上最多 4 枚，玩家能读懂；
- 足以制造组合压力；
- 物理计算量有硬上限；
- 过时弹道会自行清理。

推荐。

### 7.4 自伤和弹体互撞

自伤能增加风险，弹体互撞能产生戏剧性。

不选：

- 会扩大同刻事件图；
- 使“谁得分”更难解释；
- 弹体互撞容易出现极短时间的连锁；
- 第一版重点是射线规划，不是模拟所有物理可能性。

## 8. 计分发散

### 8.1 一击决胜

节奏太短，偶然性过高，不选。

### 8.2 生命值

需要伤害、血条、无敌帧和连续受击规则，不选。

### 8.3 三分制小局

命中一次得 1 分，回合立即重置，先到 3 分。

推荐，原因：

- 每次命中意义明确；
- 失败者不会在残血状态持续受压；
- 回合重置自然清理复杂弹体状态；
- 三分足以让双方学习地图，又不拖长。

同刻双方命中必须双方都得分；同刻达到赛点则平局。90 秒上限防止消极躲避。

## 9. 视觉方向

### 9.1 不采用的方向

- 拟真坦克；
- 军事品牌和型号；
- 迷彩、阵营旗帜；
- 爆炸素材和火焰粒子；
- 第三方像素坦克素材；
- 仿制经典商业坦克游戏界面。

### 9.2 推荐方向：夜色折光桌游

视觉像一张两个人面对面玩的发光桌游：

- 深靛色背景；
- 左方珊瑚橙、右方湖蓝；
- 折光车由圆角胶囊、轮廓环和方向楔组成；
- 墙面为低饱和半透明“棱镜板”；
- 弹体是高对比小圆点，附短而克制的方向刻线；
- 不用持续发光模糊，以保持低端设备性能；
- 命中用静态裂光标记和文本，不使用爆炸。

公开文案使用“折光车”“光点”“命中”，不使用枪炮型号。

## 10. 反馈设计

### 10.1 必需反馈

- 开火冷却：按钮和状态文字同时变化；
- 达到弹体上限：按钮禁用并显示“场上已有 2 枚”；
- 反射：墙面接触点出现短暂静态刻痕；
- 命中：目标轮廓高亮、比分原子更新；
- 暂停：覆盖双方同样的信息；
- 同刻命中：明确显示“双双命中”；
- 物理安全销毁：正常玩家不显示技术原因，调试模式记录 `lifetime`、`reflection-cap` 或 `contact-cap`。

### 10.2 可选但第一版不做

- 音效；
- 手柄震动；
- 弹道预测线；
- 回放；
- 慢动作；
- 皮肤。

尤其不提供完整弹道预测线，因为它会把读线变成照线操作；新手教学可用三张静态示意图解释入射 / 反射。

## 11. 输入布局

### 11.1 键盘

- 左方：`W/S` 移动，`A/D` 转向，`F` 发射；
- 右方：`↑/↓` 移动，`←/→` 转向，`Enter` 发射；
- 暂停：页面按钮与 `P`。

采用 `F` 而不是空格，避免浏览器滚动和双方争用。

### 11.2 触屏

每侧底部提供：

- 前进；
- 后退；
- 左转；
- 右转；
- 发射。

不做虚拟摇杆。原生按钮更容易支持焦点、明确按下 / 释放、pointer capture 和多指取消。两侧控件使用各自阵营颜色、文字与图标三重区分。

### 11.3 小屏策略

- 比赛区域保持 16:10；
- 控制区在画布下方左右并排；
- 过窄时提示横屏，但不能锁死方向；
- 画布按 CSS 缩放，逻辑坐标不变；
- 触控按钮至少 44×44 CSS px；
- 文本状态置于画布上下，不覆盖运动区域。

## 12. 可访问性方案

### 12.1 可见文本投影

每侧都有紧凑状态卡：

> 蓝方：2 分；朝西北；右区第 2 行；1 枚在途；可发射；来弹在左下，距离中。

该状态不做逐帧朗读，只做视觉更新。live region 只播报：

- 倒计时；
- 开始 / 暂停 / 恢复；
- 某方命中；
- 双双命中；
- 最终结果。

### 12.2 reduced-motion

保留必要运动，移除：

- 尾迹；
- 屏幕震动；
- 闪白；
- 弹性缩放；
- 回合转场滑动。

可以关闭渲染插值，让位置按逻辑刻呈现；碰撞和计分不变。

### 12.3 诚实边界

实时空间对抗无法仅靠低频文本提供完全等价的非视觉竞技操作。第一版承诺的是：

- 控件可访问；
- 状态不只依赖颜色；
- 关键事件可读；
- 规则和结果可理解；
- 两人也可以通过口头协作共同玩。

不宣称完整屏幕阅读器等价。

## 13. 教学设计

首次开始前只展示三条：

1. 转动车头，光点从车头方向发出；
2. 光点碰墙会折射，最多反射 3 次；
3. 每人最多 2 枚在途，先命中 3 次获胜。

配一张由程序原语绘制的静态单折示意图。教程不自动播放动画，玩家可跳过。第二次打开不依赖持久化记忆，仍可通过“规则”按钮查看。

## 14. 风险与抉择

| 风险 | 设计抉择 |
|---|---|
| 直射压过折射 | 双盾墙遮挡出生区，中央窗口有限 |
| 地图太复杂 | 只用四块内部矩形墙 |
| 车体物理失控 | 左右活动区分离，无车体互撞 |
| 弹体数量失控 | 每人 2 枚、6 秒寿命、3 次反射 |
| 更新顺序偏置 | 双方输入与命中按 tick 原子处理 |
| 触屏卡键 | Pointer Events、capture、cancel 与 blur 清空 |
| reduced-motion 破坏公平 | 只减少装饰，不改变逻辑 |
| 题材过于军事 | 原创抽象折光车，无品牌 / 预制素材 |
| 与既有项目重叠 | 五项核心机制成为不可降级门槛 |

## 15. 第一版冻结项

brainstorm 阶段建议冻结：

- ID：`ricochet-tank-duel`；
- 标题：「这一弹，拐弯见你」；
- 等级 / 分类：A / 对战；
- 方案：左右镜像折射场；
- 固定 60 tick/s；
- 车身方向即发射方向；
- 每人最多 2 枚弹体；
- 冷却 24 tick；
- 弹体寿命 360 tick；
- 最多 3 次反射；
- 先到 3 分；
- 90 秒上限；
- 同刻双命中同时计分；
- 一张固定镜像地图；
- 键盘 + 原生触控按钮；
- 纯 Canvas / CSS 原语；
- 无外部依赖、素材、网络或服务。

## 16. 仍需在 spec 冻结

- 所有逻辑单位和整数范围；
- 车辆速度、转速与弹体速度；
- 精确出生点和朝向；
- 地图墙体坐标；
- 扫掠碰撞公式与事件并列优先级；
- 车体滑墙规则；
- 输入位掩码和阶段状态机；
- 暂停与长帧阈值；
- 文本投影字段与更新频率；
- 测试 oracle、状态哈希和镜像变换；
- 验收命令与 `file://` 检查。

## 17. 借鉴声明

本方案基于前置研究中的浏览器标准、连续碰撞论文和仓库内部重叠审计独立形成。没有采用任何外部开源游戏的代码、资产、地图、数值或规则实现。

若后续实现实际参考开源软件，必须先补齐固定 URL、commit / tag、许可证、版权和“借鉴 / 未复制”边界，再允许合入。
