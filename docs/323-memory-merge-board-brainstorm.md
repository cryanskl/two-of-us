# Memory Merge Board brainstorm

- 日期：2026-07-25
- 候选 ID：`memory-merge-board`
- 分类：`co-op`
- 等级目标：A
- 前置研究：`docs/322-memory-merge-board-research.md`
- 本阶段结论：选择方向 C，继续 **Conditional Go**

## 1. 问题定义

我们要做的不是把数字替换成情侣图标，而是寻找一个满足以下条件的本地双人体验：

- 双击 HTML 就能开始；
- 两个人在同一设备上都拥有真实决策；
- 共同操作一个持续变化的状态；
- 主题能自然引出轻量回忆交流；
- 不要求输入、保存或上传私人内容；
- 不与仓库现有 58 项及当前候选重复；
- 核心机制可以用原创代码与固定关卡完整验证。

本阶段采用“先发散，再按硬条件淘汰”的方式。视觉形式、故事包装和附加功能不能弥补核心角色结构不足。

## 2. 不可协商的硬条件

### 2.1 产品条件

1. 每个有效回合必须让两个人分别作出一个会改变后续局面的决定。
2. 双方职责必须定期交换，避免一人长期成为指挥者或机械执行者。
3. 回忆交流必须发生在共同成果节点，而不是强迫式问答。
4. “先留白”必须与回答具有相同的游戏后果。
5. 第一局应在 6–10 分钟完成。

### 2.2 本地条件

1. 运行时零第三方依赖。
2. `file://` 下完整可玩。
3. 零网络、零存储、零权限。
4. 不通过 `fetch()` 读取本地数据。
5. 刷新即复位，不留下私人信息。

### 2.3 独立性条件

1. 不使用数字、Score、Best、2048 目标或随机 2/4。
2. 不复制参考项目代码、函数结构、名称、CSS、布局或资产。
3. 不成为 `photo-slider-race` 的双人同屏版本。
4. 不成为 `seven-day-garden` 的另一套资源卡。
5. 不成为 `closer-cards` 外包了一层小游戏。
6. 不成为 `rhythm-relay` 的空间版序列复现。

## 3. 发散方向

## 3.1 方向 A：自动补充的回忆合并盘

### 核心

双方轮流选择滑动方向。有效移动后，系统自动从固定或伪随机序列生成一张回忆图标。合到最高级即胜利。

### 优点

- 规则最短；
- 实现范围小；
- 容易适配键盘与触摸；
- 状态搜索简单。

### 问题

- 第二位玩家只是隔回合接手同一动作，没有互补职责；
- 自动出生仍高度接近 2048 的回合结构；
- 即使换成回忆图标，也很容易被体验成主题换皮；
- 交流主题只能作为结算弹窗附着在玩法之外；
- 与“每个回合双方都要参与”的情侣合作目标不符。

### 结论

**No-Go。**

它是最低成本方向，但不能通过独立性与双人强度 Gate。

## 3.2 方向 B：双盘同步合成竞速

### 核心

双方各自拥有一块小棋盘，使用相同线索队列，在限定回合内率先合成指定章节。

### 优点

- 双方都有持续操作；
- 同种子带来公平比较；
- 可以形成短局；
- 规则可以确定性重放。

### 问题

- 本质是对抗而非合作；
- 与 `photo-slider-race` 的“双盘、同题、竞速”结构直接重叠；
- 视觉空间需要在窄屏并排两盘，移动端可用性差；
- 回忆主题被胜负压过；
- 目标分类会从 `co-op` 漂移到 `versus`。

### 结论

**No-Go。**

即使机械规则不同，产品结构也与已选候选过近。

## 3.3 方向 C：共享棋盘的“整理者 + 补页者”

### 核心

两人共享一块 4×3 回忆书架。每个有效回合分成两个连续动作：

1. 整理者选择一个方向，让整盘线索移动与合并。
2. 补页者从两张公开线索中选一张，并放到来向边缘的一个空位。

完整回合后双方交换职责。

相同主题、相同阶段的线索合并。最高阶段“章节”离开棋盘进入共同相册，触发一次可留白、不记录的口头分享。收齐三个不同主题章节即完成。

### 优点

- 两个人在每个有效回合都作出不同、相互依赖的决策；
- 自动随机生成被替换为伙伴选择；
- 章节离开棋盘改变长期空间经济，不复制无限增长结构；
- 固定公开队列支持讨论、规划、重放与求解；
- 共享胜负，不比较速度或个人得分；
- 回忆分享与成果节点自然结合；
- 4×3 棋盘比 4×4 数字盘更短、更适合 320px 窄屏。

### 问题

- “滑动后从边缘补页”的规则需要清晰教学；
- 两张候选与多个落点可能扩大状态空间；
- 若关卡设计不当，补页者可能只有一个显然选择；
- 若分享弹层频繁，会割裂棋盘节奏；
- 需要原子化处理滑动、合并、归档、分享、补页、换位六个阶段。

### 控制办法

- 第一关只引入一个主题和两个阶段，分三步教学；
- 两张候选只显示主题，初始都从“碎片”开始；
- 来向边缘仅显示合法空位按钮；
- 每关最多形成三个章节，分享次数固定且少；
- 每关用状态搜索确认至少一条解，并测量选择分支数；
- UI 呈现按状态机严格锁定当前合法动作。

### 结论

**Conditional Go，选中。**

这是唯一同时满足双人强度、独立性、可验证性和本地合同的方向。

## 3.4 方向 D：不使用棋盘的回忆线索树

### 核心

双方轮流从线索卡中选两张，合成为更高层的故事节点，最终形成一棵共同回忆树。

### 优点

- 与 2048 视觉距离最大；
- 叙事感强；
- 容易呈现已合成关系；
- 可完全离线。

### 问题

- 去掉空间压缩后，决策趋近普通卡牌配对；
- 与 `future-cookie-notes`、`flower-language-bouquet` 等“选择并组合内容”的候选更接近；
- 如果合并关系固定，会成为线性点击；
- 如果关系开放，则需要文本输入或主观判定；
- 难以让双方在一个回合里拥有互补职责。

### 结论

**No-Go。**

它适合作为未来独立概念，不适合作为本候选的落地方向。

## 4. 方向评分

评分 1–5，5 为最优。独立性和双人决策为硬门槛，不用总分掩盖单项失败。

| 方向 | 双方每回合都有决策 | 与现有项目独立 | 本地 A 级 | 可解性验证 | 亲密主题自然度 | 范围可控 | 结论 |
|---|---:|---:|---:|---:|---:|---:|---|
| A 自动补充合并盘 | 2 | 1 | 5 | 5 | 2 | 5 | No-Go |
| B 双盘同步竞速 | 4 | 1 | 4 | 4 | 2 | 3 | No-Go |
| C 整理者 + 补页者 | 5 | 4 | 5 | 4 | 5 | 3 | Conditional Go |
| D 回忆线索树 | 3 | 3 | 5 | 3 | 4 | 4 | No-Go |

方向 C 未获得无条件 Go，原因不是技术依赖，而是关卡与交互仍需证明：

- 补页者是否经常面对至少两个有意义的选择；
- 固定队列能否形成 6–10 分钟可解关卡；
- 章节分享是否会打断流程；
- 4×3 空间是否既不拥挤又不太容易。

## 5. 选中方向的体验主线

## 5.1 开场

页面先展示一句隐私承诺：

> 只说给身边的人听。这个页面不会录音、保存或上传你们的回答。

双方选择座位标签：

- 左边的人
- 右边的人

第一版不要求姓名输入。点击“翻开第一页”进入首关。

## 5.2 首个教学回合

初始棋盘只放少量线索，并高亮当前整理者。

1. 页面提示“先选一个方向，把相同线索靠在一起”。
2. 整理者可以点击四个方向按钮，也可以在棋盘上滑动或用方向键。
3. 移动完成后，页面提示“现在由另一位补一张线索”。
4. 补页者从两张公开候选中选择一张。
5. 来向边缘的合法空位出现 44×44px 以上的落点按钮。
6. 放下后，角色卡片交换位置，进入下一回合。

教学文本只解释当前一步，不在开场堆叠完整规则。

## 5.3 中段规划

双方可以共同讨论：

- 哪个方向能制造合并；
- 是否为某一主题腾出空间；
- 候选线索应该放在哪条线；
- 是否优先完成尚未归档的主题。

双方都看到：

- 当前棋盘；
- 两张候选线索；
- 队列剩余张数；
- 已完成章节；
- 当前角色；
- 当前关卡目标。

不存在隐藏信息、倒计时或个人积分。

## 5.4 章节完成

当最高阶段形成：

1. 逻辑先将章节从棋盘移入相册；
2. 合成动画结束后进入分享状态；
3. 页面显示与主题对应的原创提示；
4. 任一人选择“说好了，继续”或“这题先留白”；
5. 两个选择都进入补页阶段；
6. 不保存选择结果，也不显示完成率。

## 5.5 结局

收齐三个不同主题章节后：

- 停止接受棋盘输入；
- 共同相册展开；
- 显示三个主题与一段原创结语；
- 提供“同一关再整理一次”和“回到选关”；
- 不显示分数、步数排名或“谁贡献更多”。

若无合法滑动或固定队列耗尽：

- 显示“这一页暂时排不下了”；
- 提供“从本关开头再来”和“看看提示”；
- 不责备任何一方；
- 提示只给下一步方向，不直接自动代玩。

## 6. 核心规则候选

## 6.1 棋盘

- 4 列 × 3 行，共 12 格。
- 行列仅用于逻辑定位，不使用参考项目的视觉尺寸或样式。
- 一个格子为空，或包含一张线索。
- 线索使用原创符号、短标签、轮廓纹理三重编码。

## 6.2 主题与阶段

| 主题 | 原创符号方向 | 章节提示方向 |
|---|---|---|
| 地点 | 路标 / 小径 | 一次一起出发 |
| 味道 | 杯子 / 蒸汽 | 一种想到对方的味道 |
| 声音 | 两道声纹 | 一段一起听过的声音 |
| 照顾 | 缝线 / 小毯子 | 一次被对方照顾 |

阶段只显示文字与逐渐完整的图形：

1. 碎片
2. 片段
3. 故事
4. 章节

禁止在界面中显示 2、4、8、16 等数值映射。

## 6.3 一次滑动

一次滑动的纯逻辑规则：

1. 按所选方向逐行或逐列读取非空线索。
2. 从移动方向的远端开始比较相邻线索。
3. 主题和阶段都相同时合并为下一阶段。
4. 新生成线索本次不得再次合并。
5. 其余线索向所选方向压紧。
6. 若结果与输入完全相同，返回无效，不推进状态。
7. 若产生章节，将其加入待归档列表并清空对应格。

一个动作可能同时产生多个章节。分享提示按稳定的棋盘扫描顺序依次展示，全部处理后才进入补页阶段。

## 6.4 补页

- 仅在有效滑动后发生。
- 公开两张候选，均为“碎片”阶段。
- 补页者选择其中一张。
- 只能放在与移动方向相反的来向边缘空格。
- 被选候选从队列移除；未选候选保留，并补充下一张。
- 若产生章节后出现多个边缘空位，补页者任选其一。
- 若没有合法边缘空位，属于关卡或逻辑错误，测试必须阻止发布。

## 6.5 换位

完成补页后：

- 当前补页者成为下一回合整理者；
- 当前整理者成为下一回合补页者；
- 回合计数增加一；
- 焦点移动到新整理者的方向控制组标题或首个方向按钮。

无效滑动、分享确认和帮助操作都不触发换位。

## 7. 被明确排除的功能

第一版不做：

- 自定义姓名、纪念日或私人文案；
- 用户上传照片、录音或视频；
- 自动语音识别；
- 局域网、二维码加入或远程同步；
- 随机关卡、每日挑战或无限模式；
- 排行榜、计时、分数、连击或成就；
- 撤销历史；
- 保存进度；
- 关卡编辑器；
- AI 生成回忆题；
- 音乐与音效依赖；
- 粒子背景或复杂 3D 动画；
- 2048 风格数字皮肤；
- 双盘竞速或 PvP 模式。

这些不是“以后默认会加”的承诺，只是本轮明确不进入范围。

## 8. 视觉与语气方向

### 8.1 视觉隐喻

采用“摊开的旅行剪贴簿”而不是数字棋盘：

- 棋盘称为“这一页”；
- 格子像浅色纸槽，但不模仿 2048 的圆角方块矩阵；
- 线索像小纸签，有主题轮廓与纤细缝线；
- 已完成章节沿页面上方进入“共同相册”；
- 角色卡像两枚书签，回合后交换主次。

### 8.2 色彩

使用低饱和但高对比的原创色组，具体色值留给实现阶段独立确定。硬要求：

- 不采用参考项目奶油背景、棕色棋盘与数字色阶；
- 文字与背景满足 WCAG AA；
- 主题不能只靠色彩区分；
- 焦点环在所有主题上都清晰。

### 8.3 文案

语气应：

- 温和但不幼稚；
- 不假设婚姻、性别、共同居住或关系时长；
- 不评判回答质量；
- 不把失败归因给任何一方；
- 不使用“默契分”“灵魂伴侣指数”等评价。

## 9. 可访问交互方向

每个动作至少有两条路径：

| 动作 | 主路径 | 等价路径 |
|---|---|---|
| 选择滑动方向 | 棋盘滑动 | 四个方向按钮、方向键 |
| 选择候选 | 点击卡片 | Tab + Enter/Space |
| 选择落点 | 点击边缘空位 | Tab + Enter/Space |
| 继续分享 | 点击按钮 | Tab + Enter/Space |
| 重开 / 返回 | 点击按钮 | Tab + Enter/Space |

补充要求：

- 页面全局不禁用缩放；
- 只在棋盘手势区处理指针滑动；
- 小于阈值的移动不触发方向；
- 对角手势取绝对位移更大的轴；
- 指针取消、页面隐藏或失焦时清空手势状态；
- `prefers-reduced-motion` 下直接切换到最终位置；
- 状态变化由礼貌型 live region 宣布；
- 装饰图形隐藏于辅助技术；
- 320px 下不出现水平页面滚动。

## 11. 风险验证实验

spec 前必须能回答以下问题：

### 实验 1：补页者是否有真实决策

- 为每个固定关卡运行状态搜索。
- 统计可达的补页状态中，两个候选是否会导向不同后续状态。
- 统计存在两个以上合法边缘落点的比例。
- 若大多数回合只有单一实质选择，重新设计队列或棋盘。

### 实验 2：关卡是否可解

- 对固定初始状态和固定队列做广度优先或深度优先搜索。
- 状态键必须包含棋盘、候选、队列位置、已归档主题、角色与阶段。
- 每关至少保存一条黄金路径。
- 任何发布关卡都不能依赖随机好运。

### 实验 3：时长是否合适

- 以正常双人讨论速度试玩。
- 首关目标 4–6 分钟，正式关目标 6–10 分钟。
- 若分享弹层占用超过约三分之一时间，减少章节数或缩短提示。

### 实验 4：是否被理解为 2048 换皮

让不了解设计过程的试玩者回答：

- 两人的职责分别是什么？
- 为什么要讨论下一张线索放哪？
- 胜利目标是什么？
- 是否注意到分数或数字？

若回答仍集中在“轮流玩 2048”，则视觉或角色机制未建立，应 No-Go 或重构。

## 12. 选型决策

选择方向 C：“共享棋盘的整理者 + 补页者”。

继续进入 spec 的前提是把以下内容写成可测试合同：

1. 4×3 棋盘与四主题四阶段模型；
2. 一次且不连锁的合并；
3. 章节出板与三个不同主题胜利；
4. 滑动 → 归档分享 → 补页 → 换位的状态机；
5. 固定公开候选队列；
6. 无效动作不推进；
7. 零网络、零存储、零权限；
8. 全部滑动动作有按钮与键盘替代；
9. 固定关卡必须由搜索证明可解；
10. README 与 ATTRIBUTION 固定开源来源和未复制边界。

当前结论仍是 **Conditional Go**。Conditional 的唯一解除方式是通过 spec、状态搜索原型与浏览器 Gate，而不是增加更多包装或内容。
