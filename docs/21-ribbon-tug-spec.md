# A 级「心动拔河」同屏实时对抗规格

## 1. Brainstorm 结论

本批实现一款两个人围在同一台设备前玩的短局对抗：左侧玩家连续按 `A`，右侧玩家连续按 `L`，也可以点击各自的大触控区。每次完整按下产生一次拉力；双方的拉力在同一个固定步长中合并，先把织带结拉过自己一侧终点线的人赢下一局，先赢两局完成比赛。

| 方案 | 价值 | 风险与成本 | 本批决定 |
| --- | --- | --- | --- |
| 单次 `keydown` 直接改位置 | 实现最短 | 同一帧事件先后可能先判胜；系统 repeat 可刷分 | 不采用 |
| 按下/松开门控 + 脉冲队列 | 长按不刷分；键盘与触控规则一致 | 要清理失焦与取消事件 | 采用 |
| 固定步长集中结算 | 同帧双方输入可原子合并；刷新率不改变规则 | 需要 accumulator 与追帧上限 | 采用 |
| 每帧固定像素回中 | 视觉简单 | 60Hz 与 120Hz 的回中速度不同 | 不采用 |
| 按真实时间线性回中 | 可测试、刷新率无关、停止后局面重新拉近 | 需要定义暂停语义 | 采用 |
| 复杂绳索物理 / Matter.js | 摆动更真实 | 新增依赖、碰撞与移动端性能，不增加核心乐趣 | 不采用 |
| 一局定胜负 | 规则最轻 | 偶发误触决定整场 | 不采用 |
| 三局两胜 | 仍能在一分钟内完成，也允许翻盘 | 多一个局间状态 | 采用 |

作品名为「心动拔河」，目录 ID 为 `ribbon-tug`，主分类为双人对抗，等级 A。它补齐仓库此前缺少的“同机双方持续同时输入”模型；首版不抽取通用游戏循环，等 Pong 或第二款固定步长作品成为真实消费者后再评估共享层。

## 2. 题材、受众与唯一任务

- **题材**：两种代表色在一条织带两端较劲；不是写实运动场，也不是关系输赢测试。
- **受众**：坐在同一台电脑或平板前，想在 30 秒内开始一轮轻对抗的情侣或伴侣。
- **页面唯一任务**：让双方公平地连续输入，把中央织带结拉过自己一侧终点线。
- **语气**：短、直接、中性；胜负只描述本局，不使用“更爱”“更默契”或羞辱性惩罚。

## 3. 严格最小范围

只实现：

- `A` 与 `L` 两个键位；
- 左右两个大触控按钮，点击一次等于一次合法按键脉冲；
- 2.4 秒开局倒计时；
- 织带结位置、双方终点线、当前局分与比赛状态；
- 三局两胜、下一局、重新比赛；
- 主动暂停，以及页面失焦/隐藏时自动暂停并清空输入；
- 鼠标、单指触摸、键盘与屏幕阅读器的基本路径。

明确不做昵称配置、难度选择、连击倍数、蓄力、AI、道具、震动、音效、商业音乐、排行榜、历史、本地存储、账号、分享、公网房间或局域网同步。

## 4. 状态机

纯逻辑状态：

```text
idle
  └─ startRound → countdown
countdown
  ├─ advance(countdownMs <= 0) → playing
  └─ pause → paused
playing
  ├─ advance(abs(position) >= 1, 未到赛点) → round-end
  ├─ advance(abs(position) >= 1, 达到两胜) → match-end
  └─ pause / blur / hidden → paused
paused
  └─ resume → countdown（短倒计时后继续，保留位置和局分）
round-end
  └─ startRound → countdown（位置归中）
match-end
  └─ resetMatch → idle（位置、局分、局号全部归零）
```

状态至少包含：

```text
phase, position, leftScore, rightScore, roundNumber, countdownMs, lastWinner, pauseReason
```

`position` 规范为 `[-1, 1]`：负值偏左，正值偏右。只有 `playing` 接受拉力；倒计时、暂停、局间和终局收到的输入全部丢弃，不能延迟到下一阶段结算。

## 5. 固定步长与公平结算

浏览器层以 `requestAnimationFrame` 驱动，但规则层只接收固定 `1000 / 60 ms` 步长。每帧累加真实 elapsed，最多追赶 5 个逻辑步；超出部分丢弃，避免页面恢复后一次性补算数秒。

每个逻辑步按以下顺序处理：

1. 读取并清空本步的 `leftPulls` 与 `rightPulls`；
2. 每侧脉冲必须是 `0–6` 的整数，非法值归零，过量值截断；
3. 计算 `netPull = rightPulls - leftPulls`，一次性把净拉力施加到 `position`；
4. 若位置达到 `-1` 或 `1`，立即结算当前局，不再回中；
5. 未决胜时，按 elapsed 将位置以固定速率向 `0` 线性回中；
6. clamp 回 `[-1, 1]`，返回新不可变状态。

若一个动画帧需要追赶多个逻辑步，脉冲队列只在第一个待执行步被 drain 一次；后续追赶步使用零脉冲。不能把同一批按键重复施加到每个 catch-up step。

首版建议常量：每个净脉冲移动 `0.085`，回中速率为每秒 `0.08`。它们属于规则常量，不暴露为首屏设置。两侧同一步各拉一次时 `netPull = 0`，不会因为事件先到而让某一方先越线。

倒计时也由同一 `advanceMatch()` 消耗 elapsed，而不是另开多个 `setTimeout`；暂停时 accumulator、待处理脉冲和 held key 集合全部清空，恢复后先经过 1.2 秒保护倒计时。

## 6. 输入 Gate

键盘：

- `A` 只属于左侧，`L` 只属于右侧；大小写等价；
- `keydown` 只有在该键不在 held 集合且 `event.repeat === false` 时入队一次；
- 对应 `keyup` 后才允许下一次；
- `blur`、`visibilitychange(hidden)`、主动暂停和重置都清空 held 与脉冲队列；
- 不劫持无关按键；Space / Enter 继续服从当前聚焦的原生按钮。

触控与鼠标：

- 左右均使用原生 `<button>`，一次 `click` 入队一次；
- 不用定时器模拟长按连发，按住不产生额外拉力；
- 控制区至少 56px 高，左右各有独立色块、按键字母和“拉一下”文字，不能只靠颜色区分；
- 倒计时、暂停与局间禁用拉力按钮，避免视觉上可按但规则层丢弃。

## 7. 纯逻辑接口与测试边界

`logic.js` 使用仓库 A 级作品一致的全局 factory，可被经典脚本直接加载，也能由 Node 测试导入：

```text
createMatchState()
startRound(state, countdownMs?)
advanceMatch(state, { elapsedMs, leftPulls, rightPulls })
pauseMatch(state, reason)
resumeMatch(state)
resetMatch()
classifyPullKey({ key, repeat, isHeld })
```

`classifyPullKey()` 只把新的 A/L 按下分类为 `left` / `right`，对 repeat、held 或无关键返回 `null`；held 集合仍由浏览器层维护。所有函数拒绝畸形状态或输入时都返回稳定结果，不修改调用方对象。DOM、时间源、CSS 变量、声音和浏览器事件不能进入逻辑层。

至少测试：

- 初始状态、开局倒计时与非法阶段调用；
- 倒计时输入不泄漏到 playing；
- 左右脉冲方向正确，等量同帧输入无偏；
- 系统 repeat 由应用 Gate 只计一次；
- 60Hz、120Hz 和不同帧分组下相同输入时间线得到等价位置；
- 回中只依赖 elapsed；
- 左右越界各自赢局，比分只结算一次；
- 两胜进入 match-end，下一局与重开边界正确；
- 暂停保留位置/比分但清空输入，恢复倒计时不接受旧脉冲；
- 畸形 pulls、elapsed 与状态不会产生 `NaN` 或越界位置。

## 8. 视觉方向

本作品不沿用“和你一样”的暖纸衬线，也不复用“反应力对决”的黑底霓虹。方向是 **1960 年代双人运动海报 + 布料比赛器材**：大色块、短标题、粗体中文、没有卡片网格。

| 左侧钴蓝 | `#2352c8` |
| 右侧杏橙 | `#ff8468` |
| 深墨蓝 | `#111936` |
| 奶油黄 | `#fff0a8` |

### 8.3 唯一视觉签名

唯一记忆点是一条横跨双方色场的奶油色织带：两条缝线贯穿带身，中央布结随 `position` 水平移动；终点不是普通进度条刻度，而是两枚像裁缝定位针一样的竖向标记。胜局时只让获胜侧色块短促扩张一次，不增加彩纸、奖杯、粒子或额外徽章。

桌面与移动端都保留横向双方关系。窄屏不把两名玩家上下堆叠，否则会破坏“同时拉同一条带”的空间语义；320px 时缩短标题、局分和控制文案，仍保持左右按钮各至少 44px 宽、56px 高且无横向溢出。

## 9. 动效与可访问性

- 织带结位置由 CSS transform 更新；规则位置是权威值，不能从 transform 反推；
- 每次合法脉冲只触发对应色场 120ms 的压力反馈；胜局扩张不超过 320ms；
- `prefers-reduced-motion` 下取消压力反馈、织带弹性和胜局扩张，位置仍立即准确更新；
- 进度使用 `role="meter"`，暴露最小值、最大值和当前数值；
- 倒计时、暂停、局胜与赛果通过 `aria-live="polite"` 宣布，不逐次朗读每个脉冲；
- 键位说明在可见文字中出现，触控按钮使用完整可访问名称；
- 键盘焦点清晰，颜色不是玩家与状态的唯一识别方式；
- JavaScript 不可用时显示明确说明，不伪装成正在运行。

## 13. Chrome 验收

- 直接以 `file://` 打开，开局、倒计时、拉动、局胜、赛点、重开全部可见；
- 用受控键盘序列验证左/右胜局、双方同帧抵消、长按不刷分；
- 在 60Hz 默认路径与临时 120Hz 分帧模拟下复核等价逻辑结果；
- 主动暂停、切走标签、窗口失焦后位置不继续变化，恢复时旧输入不泄漏；
- 触控按钮连续点击可完成一整局，键盘 A/L 可完成另一整局；
- Tab、Enter 与 Space 能操作开局、暂停和触控按钮；
- 390×844、320×700 以及常见桌面宽度无横向溢出或按钮裁切；
- reduced motion 保留完整玩法，控制台无 warning/error，资源树无公网请求；
- 最终桌面与移动截图对照本规格的颜色、排版、左右色场、织带结和控制层级。

## 14. 完成标准

- 两个人可在同一设备通过 A/L 或左右触控区完成三局两胜；
- 长按、系统 repeat、同帧事件先后、刷新率差异和失焦都不会给任一方隐藏优势；
- 状态机、倒计时、回中、越界、比分、暂停与重开有纯逻辑测试；
- A 级直接双击成立，无第三方运行依赖和公网资源；
- 视觉拥有独立于现有作品的明确语言，320px 可用且 reduced motion 完整；
- README 包含准确的上游 commit、MIT 许可证与“仅借鉴机制、未复制代码/视觉/素材”声明；
- `npm test`、`npm run verify`、全仓 JavaScript 语法检查与 `git diff --check` 通过；
- 新发现的可复现缺陷写入 `bugs/`，跨作品经验写入 `learn/`；
- 规格和完整作品分别形成独立提交。
