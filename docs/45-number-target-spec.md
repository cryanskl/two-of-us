# A 级「数字凑靶」双人对抗规格

## 1. Brainstorm 结论

本批实现一款单设备、公开信息、轮流选牌的双人算术对抗：页面公开一个目标数和八张数字牌；双方经过“各拿第一个数字 → 各拿一个运算符 → 各拿第二个数字”三段蛇形选牌，组成 `左数 运算符 右数`。离目标更近的一方获得 1 分，三局后比较总分。

| 方案 | 价值 | 风险与成本 | 本批决定 |
| --- | --- | --- | --- |
| 每人独立抽牌后秘密出式 | 惊喜强、无法针对性卡牌 | 同机遮挡流程长，策略信息少 | 不采用 |
| 共享市场公开选牌 | 每一步都能计算、抢牌和阻断 | 后手可针对前手 | 采用；用蛇形阶段和轮换开局方平衡 |
| 任意长度算式与括号 | 数学空间大 | 首局难懂，解析与安全边界膨胀 | 不采用 |
| 固定“两数 + 一运算符” | 10 秒理解，结果可解释 | 解空间较小 | 采用；每局重新生成市场与目标 |
| 加减乘除 | 选择丰富 | 除法引入小数、除零和显示精度 | 首版只用加、减、乘 |
| 精确命中得 2 分 | 鼓励靶心 | 运气和先手牌差被放大 | 不采用；精确命中仍只得 1 分 |
| 等距时比较是否越过目标 | 可以强行分胜负 | 规则难记且偏好没有产品依据 | 不采用；等距正式平局，双方都不加分 |
| 三局两胜、提前结束 | 节奏短 | 可能让一方少玩一局 | 不采用；固定三局全部完成 |

作品名为「数字凑靶」，目录 ID 为 `number-target`，主分类为双人对抗，等级 A。它补齐现有 A 级对抗作品没有的“公开市场草拟 / deterministic arithmetic scoring”状态模型，不新增第三方运行依赖。

## 2. 受众、唯一任务与语气

- **受众**：围在同一台电脑、平板或手机前，愿意做一点心算但不想学复杂桌游的情侣或伴侣；
- **唯一任务**：轮流从共享市场拿牌，组成一个两数算式，让结果尽量接近目标；
- **语气**：像在纸上解一道轻松靶题，强调“差几格”而不是评价算术能力；
- **首局理解目标**：打开后 15 秒内知道“每人拿两张数字和一个符号，离目标最近得 1 分”。

## 3. 严格最小范围

只实现：

- 珊瑚方与蓝方两个固定席位；
- 固定三局，每局一个公开目标、八张唯一数字牌、三张唯一运算符牌；
- 每位玩家获得第一数字、运算符、第二数字各一张；
- 蛇形公开选牌、即时表达式占位、局结果、比分与最终结果；
- 鼠标、触控以及数字键 / `+ - *` 键盘选择；
- 精确命中、普通胜、等距平局与完整重赛；
- 生成式纸靶和方格纸背景，代码原生 HUD、牌面与算式。

明确不做昵称、难度、计时、心算输入框、括号、多步表达式、除法、小数、负数目标、道具、AI、题库编辑器、排行榜、历史、持久化、音效、震动、联网房间或双设备同步。

## 4. 每局材料与可达目标

### 4.1 数字市场

- 候选池固定为整数 `1..12`；
- 使用 Fisher–Yates 洗牌后取前八个，得到本局八张唯一数字牌；
- 双方共拿走四张，未选数字留在市场但不参与结算；
- 牌面公开，选中后从共享市场移除并进入对应玩家槽位。

### 4.2 运算符市场

固定为 `+ / - / *` 三张唯一牌；双方各拿一张，剩余一张不参与结算。显示层分别使用 `＋ / − / ×`，逻辑层只保存稳定 ASCII ID。

### 4.3 目标生成

目标不直接从任意范围随机，而从本局八个数字能构成的所有两数表达式中生成：

1. 枚举任意两个不同市场数字；
2. 枚举 `+ / - / *`；减法使用较大数减较小数来生成候选目标；
3. 只保留 `10..81` 的整数结果并去重；
4. 用无偏安全随机索引选择一个目标。

因此开局时至少存在一条使用市场牌可精确命中的表达式，但蛇形选牌可能把它拆散；产品只承诺题面可达，不承诺任一玩家必然拿到解。

### 4.4 安全随机索引

浏览器用 `crypto.getRandomValues` 生成无偏 `[0, maxExclusive)` 索引。若 `2^32` 不能整除上界，则拒绝落在尾部余数区间的值并重抽；安全随机不可用时显示错误，不退化到 `Math.random`。纯逻辑接受注入的 `randomIndex(maxExclusive)`，方便确定性测试。

## 5. 蛇形选牌与先后手

每局六步，若 `starter` 是开局方，`other` 是另一方：

```text
step 0  starter  选第一个数字
step 1  other    选第一个数字
step 2  other    选运算符
step 3  starter  选运算符
step 4  starter  选第二个数字
step 5  other    选第二个数字并结算
```

这让开局方先拿数字，另一方先拿运算符；最后一段再次反转。比赛开局方由安全随机硬币决定，后续三局严格交替，因此一方会开两局、另一方开一局，但谁获得这一个额外开局由每场比赛重新无偏决定。首版不宣称竞技级完全对称。

所有选择公开。拿到的第一数字固定是表达式左数，第二数字固定是右数；因此 `3 − 9 = -6` 合法，距离仍用 `abs(value - target)`。

## 6. 计分与结果

表达式值：

```text
a + b → a + b
a - b → a - b
a * b → a × b
```

双方距离均为 `abs(value - target)`：

- 距离更小者获得 1 分；
- 距离相同则本局平局，双方都不加分；
- 距离为 0 标记“正中靶心”，但不增加额外分；
- 三局全部完成后比较总分，可得到珊瑚胜、蓝方胜或整场平局。

结果文案只描述算式和距离，不写“数学更好”“聪明”或关系评价。

## 7. 状态机

```text
intro
  └─ START_MATCH(plan, starter) → drafting(step=0)

drafting
  ├─ PICK_NUMBER(value) → drafting(next step)
  ├─ PICK_OPERATOR(id) → drafting(next step)
  └─ sixth valid pick → round-result(score updated once)

round-result
  ├─ round < 3: NEXT_ROUND(plan) → drafting(step=0, starter alternates)
  └─ round = 3: SHOW_MATCH_RESULT → match-result

match-result
  └─ RESTART → intro
```

权威状态至少包含：

```text
phase, roundIndex, matchStarter, starter, stepIndex,
scores, target, availableNumbers, availableOperators,
hands, roundResult
```

约束：

- `START_MATCH` 只从 intro 接受合法 plan 与 `starter 0|1`；
- 当前玩家和当前牌种只由 `starter + stepIndex` 派生，不重复存字段；
- 数字只能在数字步选择且必须仍在市场，运算符同理；
- 重复点击、错误牌种、已拿走牌、未知 token 和非 drafting 阶段保持原引用；
- 第六次合法选择同步计算两式、距离、winner 与新比分，只有这一条 Gate 能进入 round-result；
- `NEXT_ROUND` 只接受下一份合法 plan，清空 hand 与 roundResult，保留比分并交替 starter；
- 第三局必须先看局结果，再明确进入 match-result；
- 状态、数组、hand、plan 与 result 深冻结，不修改调用方对象；畸形状态安全回到初始状态。

## 8. 纯逻辑接口与测试

`logic.js` 使用经典脚本 factory，同时支持 `file://` 与 Node 测试：

```text
createInitialState()
createRoundPlan(randomIndex)
isValidRoundPlan(plan)
startMatch(state, plan, starter)
pickNumber(state, value)
pickOperator(state, id)
nextRound(state, plan)
showMatchResult(state)
restartMatch(state)
turnForStep(starter, stepIndex)
kindForStep(stepIndex)
evaluateHand(hand)
scoreRound(target, hands)
```

至少测试：

- 生成八张唯一 `1..12` 数字，目标在 `10..81` 且可由市场精确到达；
- 无偏随机索引回调边界、非法返回值和 plan 深冻结；
- 两种 starter 的六步玩家序列与三类牌种；
- 数字/运算符牌只能在正确步骤选择且只能使用一次；
- 加、减、乘、负结果、精确命中、普通胜和等距平局；
- 第六步只结算一次，结果阶段重复输入不加分；
- 三局 starter 交替、比分保留、第三局后才进入 match-result；
- 重赛清空状态，畸形输入与调用方数组保持安全。

## 9. 浏览器编排与键盘

- intro 点击“开始凑靶”时生成首局 plan 和无偏 starter；随机结果先于任何纸牌动画；
- drafting 根据当前 kind 只启用相应牌轨，另一轨保留但 disabled；
- 数字键 `1..9` 直接选对应牌；`0` 不代表 10，数字 10–12 必须用按钮，避免多键歧义；
- 运算符步接受 `+ / - / *`，小键盘乘号由 `*` 映射；
- `event.repeat` 忽略；Tab / Enter / Space 保留原生按钮语义；
- 每次合法选择后把焦点移到当前轨第一张可用牌，局结果与最终结果的唯一主按钮自动聚焦；
- 选择动画只做 160ms 盖章/移位，不是第二份状态机；
- `prefers-reduced-motion` 下取消位移和盖章弹跳，规则同步推进。

## 10. 本地与数据边界

- 不使用 fetch、XHR、WebSocket、CDN、远程字体、localStorage、sessionStorage、IndexedDB、Cache API、Service Worker、账号、统计或遥测；
- 市场、目标、手牌、比分与结果只在当前页面内存中，刷新即清空；
- 不读取照片、文件、麦克风、摄像头、剪贴板、位置或传感器；
- 没有隐藏题面或私人内容；所有策略信息在正常界面公开。

## 14. 验收 Gate

### 14.1 自动检查

- 目标可达、数字唯一、随机索引边界和 plan 冻结；
- 六步蛇形顺序、牌种 Gate、牌唯一消费和表达式顺序；
- 三种运算、负结果、距离、胜/平与只结算一次；
- 三局 starter 交替、比分和完整重赛；
- catalog 入口、A 级直接打开、无网络/存储/权限 API；
- `node --check`、目标测试、`npm test`、`npm run verify`、`git diff --check` 通过。

### 14.2 真实浏览器

1. 从 intro 开始并确认随机 starter 与目标；
2. 用鼠标完成一局六步，验证错误轨 disabled、已拿牌消失、表达式顺序正确；
3. 用键盘数字和 `+ - *` 完成至少一局，系统 repeat 不重复选牌；
4. 覆盖精确命中、普通胜和等距平局的受控 plan；
5. 三局全部完成后比分只累计三次，最终胜/平结论正确；
6. 重赛清空比分、手牌、结果并生成新 plan；
7. 正常会话控制台 0 error / 0 warning，Network 无公网请求；
8. 根门户能打开作品，返回链接正确。

### 14.3 响应式与忠实度

- 1504×1046 概念原生视口完整显示标题、靶纸、双方纸、指令和两条牌轨；
- 390×844 与 320×760 无横向溢出，所有触控牌/按钮至少 48px；
- reduced motion 不影响规则反馈；
- 最终同次 `view_image` 比较桌面概念、移动概念和最新浏览器截图；
- 忠实度账本至少核对色板、方格纸、标题、靶纸、玩家纸、牌轨、当前状态、移动堆叠与文案差异。
