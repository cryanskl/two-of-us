# “这一颗，绕回来找你” Brainstorm：秘密瞄准、完整一轮与一次反弹

- 日期：2026-07-24
- 稳定工作 ID：`heart-catapult`
- 对应调研：[`247-heart-catapult-research.md`](./247-heart-catapult-research.md)
- 目标：冻结首版产品边界，供 spec、design、plan 和生产实现共同使用

## 1. 想做出的感觉

两个人面对同一块小小场地，各自在看不到对方参数的时候，决定这颗心要抬多高、
送多远。等两份选择都锁定，才一起看它们飞出去：有的越过、有的提前落下，有的
在软垫上弹一下，刚好碰到对面的城堡。

一轮应有四段情绪：

1. **接管**：轮到我，上一份参数已经完全收起；
2. **瞄准**：只看自己的角度与力度，不看完整预测答案；
3. **一起放飞**：两颗爱心依次出现，但比分暂时不动；
4. **完整结算**：两发都结束，再同时增加本轮命中并判断是否领先。

这不是伤害或摧毁城堡。命中表现应像把一颗心送进对方窗台，比分写“送达次数”，
而不是生命、攻击或爆炸伤害。

## 2. 冻结的产品一句话

> 每轮你们轮流偷偷调角度和力度。两人都锁定后，爱心依次飞出；它可以落地反弹
> 一次。完整轮结束时，先累计送达 3 次并领先的人获胜。

30 秒教学只再补三句：

- 左右按钮或滑杆调整角度和力度；
- 锁定后不能改，也不会给下一位看到；
- 同轮一起到 3 次不抢先，继续一轮直到有人领先。

## 3. 四种方向与决定

| 方向 | 体验 | 结论 |
| --- | --- | --- |
| 公开轮流发射 | 第一位射完，第二位看着参数回应 | 排除；后手可直接照抄或镜像 |
| 同时实时发射 | 双键盘边蓄力边释放 | 排除；输入设备冲突，且与实时对抗样板重叠 |
| 风向、地形与武器 | 每回合随机条件，多种弹体 | 排除；公平、教学、物理和许可面失控 |
| 秘密瞄准 + 完整轮 + 单次反弹 | 两份参数密封，依次播放，联合结算 | **采用**；读人、公平、可复现且首局清晰 |

单次地面反弹是首版唯一特殊物理。它产生“这颗心绕回来”的辨识度，同时仍可用
一个水平面、一次衰减和有限 tick 完整测试。

## 4. 采用的阶段结构

```text
intro
  → handoff(first seat)
  → aiming(first seat)
  → handoff(second seat)
  → aiming(second seat)
  → reveal-ready
  → flying(first shot)
  → flying(second shot)
  → round-result
      ├─ handoff(next round)
      └─ complete
```

关键决定：

- 每轮首位瞄准者交替；
- 首位播放者与首位瞄准者一致，但播放顺序只是表现；
- 两发开始前，权威逻辑已经确定各自轨迹与终点；
- 第一发播完不计分、不判断胜负；
- 第二发播完后一次性结算两份结果；
- 一方达到至少 3 次且领先才 complete；
- 同分达到目标继续延长，不设隐藏 tie-break；
- 最多进行 12 个完整轮；第 12 轮仍无人达到目标且领先则以平局结束；
- 新局回到相同镜像规则，不保留历史或自动改难度。

## 5. 瞄准与答案提示

首版使用有限档位而不是连续浮点拖拽：

- 原生 range 和减/加按钮改变角度档位；
- 原生 range 和减/加按钮改变力度档位；
- 页面显示明确整数值；
- 可显示投石器朝向和很短的方向线；
- 不显示完整预测轨迹、落点阴影、命中提示或“最佳参数”。

这样玩家能理解操作方向，却仍需根据上轮公开轨迹调整。两位玩家共享同一组规则，
但不会在瞄准阶段看到对方本轮参数。

## 6. 完整轮公平

若第一颗播放时刚好达到 3 次便立即结束，播放顺序就变成额外优势。采用版本把一轮
视为不可拆分的公平单元：

```text
roundHits = [shot0.hit ? 1 : 0, shot1.hit ? 1 : 0]
nextScores = previousScores + roundHits
winner =
  nextScores[0] >= 3 && nextScores[0] > nextScores[1] ? 0 :
  nextScores[1] >= 3 && nextScores[1] > nextScores[0] ? 1 :
  null
```

因此：

- `2:2` 时双方都命中，进入 `3:3` 并继续；
- `3:3` 时一方命中、另一方未命中，得到 `4:3` 并结束；
- 一方已经领先且达到目标时，不再进入下一轮；
- 不用首发席位、播放时间、反弹次数、力度或轨迹长度破平。

## 7. 规则与动画分离

锁定第二份参数后，纯逻辑一次性生成两份冻结 shot result：

```text
{
  outcome: "direct-hit" | "bounce-hit" | "miss",
  bounceCount,
  terminalReason,
  frames
}
```

`frames` 只供表现读取。正常动画、掉帧、后台恢复和减少动态都消费同一份结果：

- 正常模式按时间映射 frame index；
- 减少动态可只显示起点、反弹点和终点；
- 页面切后台不会继续派发规则 action；
- 恢复后只恢复表现或等待显式继续；
- 重复、迟到或旧 generation 的动画完成回调必须 no-op。

物理常量、命中判断、bounceCount 和比分不得在 app/CSS/Canvas 中复制。

## 8. 热座隐私

公开信息：

- 双方称呼与累计送达次数；
- 当前轮数、交接对象和阶段；
- 已经公开的历史结果；
- 当前瞄准者自己的草稿参数；
- 播放到当前发时，当前发已经公开的轨迹。

尚未公开的信息：

- 已锁定但尚未进入对应 flying 阶段的角度与力度；
- 第二位瞄准时的第一份参数；
- 第一发播放时的第二份参数与轨迹；
- 未锁定草稿。

阶段切换必须卸载旧控件和文本，不用 CSS 隐藏保存。Escape、blur、hidden 和
`pagehide` 会进入遮屏；未锁定草稿被丢弃，已锁定权威输入仍只在内存中保留。

开发者工具可以读取内存，因此这是“正常同屏交接隐私”，不是加密协议。首版不加
PIN、commit-reveal 哈希、双设备或服务端裁判。

## 9. 代码原生视觉方向

首版采用“两座纸雕城堡与一条软垫地面”：

- 背景是暖夜色 CSS 渐变，不使用照片或纹理包；
- 左右城堡由原创 DOM/CSS 或简单 Canvas 几何镜像绘制；
- 城堡目标是窗台上的空心心形槽，不表现破坏；
- 地面像一条有缝线的软垫，第一次触地给出克制的压缩反馈；
- 爱心为原创几何，轨迹使用少量点或细线，不做爆炸粒子；
- 中央 DOM 显示轮次与阶段，左右 DOM 始终显示 `n / 3`；
- 交接阶段以不透明纸帘覆盖场地和参数；
- complete 保留两座完整城堡，只突出本局先送达的一方。

Canvas 可以负责场地与飞行，但标题、玩家、比分、输入、状态、结果和按钮都保留在
真实 DOM。首版不需要 ImageGen、外部图标、字体、贴图、音频或第三方素材。

这份 brainstorm 只冻结代码原生方向；精确颜色、字号、间距、阶段构图和响应式由
后续 design 文档审查。

## 10. 文案语气

| 场景 | 文案方向 |
| --- | --- |
| 标题 | 这一颗，绕回来找你 |
| 副标题 | 两份秘密角度，一次软软的反弹。看看谁先达到目标并领先。 |
| 交接 | 轮到你瞄准。等 TA 不看屏幕后，再点“我接好了”。 |
| 锁定 | 就按这个角度送出去 |
| 待放飞 | 两颗心都准备好了。现在一起看它们飞。 |
| 直接命中 | 这一颗，直接送到了。 |
| 反弹命中 | 绕了一下，还是找到你了。 |
| 未命中 | 差一点。记住这条线，下一轮再来。 |
| 延长轮 | 现在是 {左方比分} 比 {右方比分}。还是平局，那就再送一轮。 |
| 获胜 | 这一局，TA 先达到目标并领先了。 |

默认称呼使用“你”和“TA”。若 spec 允许配置称呼，也只提供两个简短文本字段，不
提交真实姓名、纪念日或私人消息。

## 11. 可访问与降级

- 角度、力度和比分始终用文字与数字表达，不只靠投石器方向或颜色；
- range 具备 label、当前值与减/加按钮，支持方向键；
- 锁定、接管、放飞、继续和重开使用原生按钮；
- 阶段切换后把焦点放到稳定标题或首个主动作；
- live region 只播报公开阶段、当前发结果和完整轮结算；
- 不在 live region 提前播报另一份 sealed aim；
- 目标尺寸、焦点可见性和对比度按 WCAG 2.2 验收；
- reduced-motion 下跳过逐帧飞行但保留反弹点、终点和同一结果；
- forced-colors 下使用系统边框、文字与按钮，不依赖渐变；
- Canvas 不可用时，页面仍显示规则、输入和一条明确不可播放说明；
- JavaScript 不可用时只显示公开说明，不伪造可玩状态；
- 320 CSS px 和 400% zoom 不横向溢出。

## 12. 明确不做

首版不加入：

- 随机风向、移动目标、随机或可破坏地形；
- 多面墙、斜面、多次反弹或复杂刚体；
- 爆炸、伤害梯度、城堡生命细分；
- 坦克/角色移动、武器、技能、道具或连击；
- 反弹额外加分、力度奖励或轨迹长度破平；
- 完整落点预测、自动推荐参数或 AI 对手；
- 倒计时、联网、账号、房间、排行榜或存档；
- 用户自定义胜利分数、物理常量或大量难度设置；
- 音频、震动、远程资源、外部字体或物理库；
- 自动刷新、统计、埋点或后台自动推进。

## 13. 进入 spec 的冻结决定

brainstorm 冻结以下内容：

1. 稳定 ID `heart-catapult`，主分类双人对抗，A 级本地直开；
2. 镜像固定场地、秘密瞄准、两发依次播放、完整轮联合计分；
3. 目标 3 次且必须领先；同轮一起达到则延长；
4. 最多 12 个完整轮；轮次封顶仍无人达到目标且领先则平局；
5. 每颗爱心最多一次地面反弹，第二次落地/越界/超时 miss；
6. 有限角度档、整数力度、Q12 查表、固定 tick 和连续线段检测；
7. 右席只镜像渲染，规则层只有一套左到右局部坐标；
8. 第二人瞄准和第一发播放期间均不泄露尚未公开参数；
9. 代码原生纸雕城堡与软垫地面，零第三方运行依赖和素材；
10. 生产 `ATTRIBUTION.md` 固定五个 MIT 来源并声明零复制；
11. 首版排除风、随机地形、移动、爆炸、道具、联网和商业游戏表达。

规格阶段只把这些决定变成精确常量、状态、动作、公开 DTO、物理 oracle、配置、
DOM 和验收合同，不重新发明玩法。
