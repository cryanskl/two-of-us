# 跟着光，长成一棵树：原创替代 Love Tree 的规格

- 状态：`implemented`
- 日期：2026-07-28
- 作品：`experiences/surprises/light-grown-tree/`（A 级 · 单人惊喜）

## 为什么做这一个

[Love Tree](../experiences/surprises/love-tree/) 是仓库里少数直接迁入的第三方作品：运行文件来自一个现成的 HTML5 表白页压缩包，依赖 jQuery 与 Jscex，并附带一段商业音乐；`docs/README.md` 也把“LoveTree 商业音乐的替换方案”列为未决事项。

对一个把「借鉴与来源声明」写进验收 Gate 的仓库来说，这是最薄弱的一处：它无法像其他作品那样声明“零复制”。本作的目标是提供一个**同类型但完全自有**的选择——同样是“树 + 情书 + 相守时间”，但玩法、代码、视觉与文案全部独立。

## 核心决策

### 一、树的形状是接收者的操作记录，而不是预设动画

Love Tree 点一下就播放一段固定的生长动画。本作把这一步交还给接收者：每长一节，所有枝条朝**光当时所在的方向**生长，因此最终的树是“对方把光带到过哪些地方”的直接结果。同一条光轨迹永远长出同一棵树，不同轨迹长出不同的树。

这也是这份规格里唯一真正的产品主张：**这棵树只有这一个人能长出来**。

### 二、生长是纯函数，不使用 `Math.random`

`growOnce(state)` 只依赖前一个状态和当前光的位置。抖动来自一个标准整数散列对「枝条 id + 步序」的映射，因此完全可重放，也可以在 `logic.test.js` 里断言“同一条轨迹得到同一棵树”。

### 三、方向合成必须保证树一直向上

生长方向 = 枝条自身方向的惯性 + 恒定向上的偏置 + 朝光的牵引，最后再用最小仰角 `MIN_RISE` 兜底。

两条约束都是被实现过程中的真实问题逼出来的：

- 只有“朝光牵引”时，枝条会一路收敛到光点上，树冠塌成一个点；向上的偏置解决这个问题。
- 分叉之后，如果所有子枝都用同样的强度追光，它们会立刻拐回同一个方向，树冠仍然收拢。因此追光权重随分叉层级衰减、惯性随层级增强、向上偏置随层级减弱——越细的枝越守住自己的方向，树冠才铺得开。

### 四、可读性不依赖动画是否在跑

信的正文基础状态就是可读的最终状态，入场淡入只是一次性的加成（先标记 `data-entering`，下一帧摘掉）。动画被停用、过渡没跑或截图抢在前面，读到的都是文字而不是空白。

同理，`prefers-reduced-motion` 下直接呈现；画布不可用时显示替代说明，生长与信仍然可以完整完成；画面之外还有一份文字进度镜像和 live region 播报，全流程可以只用键盘完成。

### 五、准备者写错什么都不会挡住惊喜

`composeGrowthNote` 抛异常、返回非字符串、返回空串或返回超长文本，都会安全回退或截断；`togetherSince` 解析失败只是不显示相守时间，而不会显示一个错误的数字。
