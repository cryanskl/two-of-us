## 生成方向

初始自然语言设计简报要求：

- 完整本地双人抽象棋游戏，不做营销页；
- 暖象牙纸面、琥珀压纹蜂巢、酒红封蜡、蜜黄与暮紫棋子；
- 中文标题使用克制宋体，游戏控件使用系统无衬线体；
- 开放布局，不用卡片墙、导航、徽章、胶囊标签或玻璃拟态；
- 进行态包含回合、双席公开摘要、移动/封蜡模式、合法格纹理和拒绝原因；
- 触控格目标约 44px，颜色之外还用形状、纹理和文字；
- 无商业棋类名称、连边棋盘、边界长墙、品牌素材或第三方美术。

   两项均拒绝，文件未进入仓库。
2. 第二张桌面进行稿修正为 37 格，并删除所有额外快捷键；选为主视觉依据。
3. 第一张桌面开场稿底部行数错误；文件未进入仓库。
4. 第二张桌面开场稿以正确进行稿为底，保留 37 格；选用。
5. 手机与结果稿虽然反复强调 37 格，生成模型仍未稳定保持离散计数；仅保留它们
   的排版、材质与组件样式，明确排除棋盘几何和路线。

生成式视觉擅长气氛、层级、材质和组件语言，不负责离散图不变量。生产验收必须
回到逻辑生成数量、DOM 按钮数量、自动化测试和浏览器截图。

## 生产资产计划

用户确认视觉方向后，再做独立资产生成：

- 可平铺的暖象牙纸纹背景；
- 可用于 CSS clip-path 蜂巢格的琥珀压纹纹理；
- 透明背景蜜黄棋子；
- 透明背景暮紫棋子；
- 透明背景酒红封蜡；
- 必要时提供 1× 与 2×，并保留生成来源记录。

棋盘格、合法状态、焦点环、虚线路径、文字、数字和按钮仍由 HTML/CSS/SVG
代码原生生成；不会把整张概念图裁切成运行界面。
