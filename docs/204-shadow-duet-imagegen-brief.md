## 1. 视觉任务

为一个直接双击 `index.html` 即可打开的中文同机双人合作页面设计完整多状态界面。左席用 `W/A/S/D`、右席用方向键，触屏端各有四个原生姿势按钮；两人看见公开目标后自由试动作，在同一个定格窗中把正确姿势对连续留住六小拍。六幕依次完成后，页面展示共同影子合照与准备者写下的结语。

这不是摄像头姿态识别、霓虹四轨音游、舞蹈评分器、健身课程或写实人物摄影。目标气质是：午夜、背光、纸幕、两个人在家搭起的小剧场；有共同排练的轻松感，但不比较个人表现。

首轮必须生成十六张独立、清晰、可实现的完整页面概念，不用压缩总览或拼贴代替原生尺寸状态：

1. `S1`：1504×1046 desktop intro；
2. `S2`：1504×1046 desktop scene-intro，第一幕目标公开；
3. `S3`：1280×800 desktop dancing 准备区；
4. `S4`：1280×800 desktop dancing 定格窗；
5. `S5`：1280×800 desktop pose-result；
6. `S6`：1280×800 desktop missed；
7. `S7`：1504×1046 desktop act-result；
8. `S8`：1504×1046 desktop complete；
9. `S9`：390×844 mobile dancing 定格窗，双触控控制；
10. `S10`：390×844 mobile complete；

## 2. 冻结视觉方向

### 2.1 核心意象

方向为“午夜背光纸幕小剧场”：

- 页面背景是近黑靛蓝的房间与厚幕边，中央唯一主视觉是一块温暖琥珀背光纸幕；
- 纸幕有低对比粉灰纤维和轻微不均匀透光，不能像数字屏幕、摄像头画面或玻璃卡片；
- 两道深墨剪影严格左右分区、镜像朝向，中间留出组合轮廓；不生成五官、真人身份、服装品牌或写实身体；
- 定格窗用一条横向拍灯、清楚文字和静态分段刻痕共同表达；不用音符下落、判定线、连击或分数；
- 六幕记录像沿幕边逐张夹起的纸片接触印，不做卡片网格、排行榜或成就墙；
- 中文内容使用有纸本性格的清晰衬线回退，控件使用克制的无衬线回退；所有键位与按钮保持 code-native。

创意强度约 7/10，低到中密度。纸幕是唯一大形体；目标/当前姿势是规则层级，控制是操作层级，六张共同记录是完成层级。

### 2.2 页面构图

- 页头开放排版，不做导航、Logo、hero eyebrow、badge、pill、账户或设置区；
- desktop 主阅读流：题名/规则 → 当前幕与公开目标 → 纸幕舞台 → 窗口/稳定状态 → 左右席控制 → 共同记录 → 主动作；
- 两席控制是同一组件族的两个 fieldset，左右语义与视觉位置一致，不用玩家头像卡或颜色身份标签；
- scene-intro/pose-result/missed 的主动作靠近阶段说明，页面每阶段最多一个 `.primary-action`；
- act-result/complete 让六张共同记录从舞台边缘自然展开，但不遮挡舞台或变成 carousel/modal；
- 390px/320px 单列：目标 → 完整舞台 → 状态 → 左席四键 → 右席四键 → 记录/主动作；
- 844×390 可让舞台左置、状态与两席控制右置，语义顺序不变，允许必要纵滚但零横向滚；
- 不使用 dashboard、HUD、bento、card grid、tab、bottom nav、浮动工具条或全屏 overlay。

### 2.3 签名组件语言

允许的 4 个视觉母题：

1. **幕边场记刻痕**：当前幕编号与六幕进度沿同一条纸幕边缘呈现，必须同时有真实文字 `已定格 n / 6`；
2. **双席动作键**：八个原生按钮使用同一纸片按键组件族，姿势名比物理键更重要，pressed 用凹下、真实边框和 `aria-pressed`，不能只换颜色；
3. **横向拍灯**：准备区与定格窗共用同一舞台横带；亮起时文字从“先试动作”切换到“定格窗亮了”，不能依靠闪烁或移动理解；
4. **共同接触印**：每幕成功只留下目标名、共同完成和尝试次数；不记录个人快慢、失误、准确率或赢家。

不需要常规图标。若概念出现方向提示，只能使用与键位一致的 code-native 箭头文字；不用 emoji、第三方图标字体、音符、奖杯、相机或心率符号。

## 3. 状态概念合同

### S1 — desktop intro

- H1：`把影子，跳成我们`
- 固定说明：`四个姿势，两道影子。看准目标，在亮起的这一拍一起定格。`
- 中性纸幕只显示两道未摆目标姿势的静态站位剪影，不出现第一幕答案、定格进度或完成记录；
- 左右席控制区可说明键位词汇；八按钮复用生产原节点，但都使用 native `disabled` 与清楚不可操作样式，不表现 pressed/可开始计时；
- 唯一主按钮：`拉开幕布`
- 不显示 completion note、六幕合照、个人统计、分数或“摄像头未开启”。

### S2 — desktop scene-intro

- 显示 `第 1 幕：开幕·展翼。左边做“展开”，右边做“展开”。`
- 目标预览是两道向外展开的抽象剪影；它是公开答案，不做锁、模糊、猜题或倒计时；
- `已定格 0 / 6`、`第 1 次尝试` 可见；当前姿势均为 `还没有姿势`；
- 八按钮保持可辨识并复用原节点，但都使用 native `disabled` 与清楚不可操作样式，不表现持有；
- 唯一主按钮：`开始这一幕`
- 纸幕不自动开始、不闪烁、不播放音乐。

### S3 — desktop dancing 准备区

- 固定状态：`先试动作。拍灯亮起时，把正确姿势留住六小拍。`
- 第一幕目标仍公开；左席当前 `展开`，右席当前 `向内`，清楚显示一边还未对；
- 左席 `展开 A` 与右席 `向内 ←` 有真实 pressed/aria-pressed 形态；
- 稳定文本为 `稳定 0 / 6`，不显示 raw tick、毫秒、early/late 或命中百分比；
- 没有主动作、暂停按钮、进度 slider 或自动纠正。

### S4 — desktop dancing 定格窗

- 固定状态：`定格窗亮了——一起把姿势留住。`
- 第一幕两席都为 `展开`，纸幕剪影组成公开目标；对应两个按钮保持 pressed；
- 稳定文本选择中段 `稳定 3 / 6`，横向拍灯清楚亮起但不闪烁；
- `已定格 0 / 6`、`第 1 次尝试` 仍可见；
- 不加入分数、combo、perfect、倒计时数字、红绿个人判定或自动成功动画。

### S5 — desktop pose-result

- 阶段主文案：`这一幕接住了。`
- 共同记录新增 `第 1 幕 · 开幕·展翼 · 共同完成 · 第 1 次尝试`；
- 两席持有已释放，当前姿势均为 `还没有姿势`；八按钮复用原节点，全部 native `disabled` 且不再 pressed；
- 舞台可保留一次静态“接触印”，不用彩纸、奖杯、评级或满屏 glow；
- 唯一主按钮：`下一幕`
- 不提前展示下一幕目标。

### S6 — desktop missed

- 阶段主文案：`影子还没在同一拍站稳，再排这一幕。`
- 可中性说明 `窗口结束时：左边“展开”，右边“向内”。目标仍是两边“展开”。`；
- 只显示当前幕和 `第 1 次尝试`，不增加个人失误数、红叉、责怪语气或失败音效；
- 两席持有已释放；八按钮复用原节点，全部 native `disabled` 且不 pressed；已完成的旧记录（若有）保持不丢；
- 唯一主按钮：`再排这一幕`
- 不显示技术 tick、异常、刷新或“重新整局”。

### S7 — desktop act-result

- 阶段主文案：`六道影子，刚好跳成一支舞。`
- 六张共同记录按幕序完整可读：第一幕、第三至六幕均为 `第 1 次尝试`；第二幕 `屋檐·相接` 为 `第 2 次尝试`；
- 共同摘要显示 `六幕共同完成`、`一共尝试 7 次`、`重排 1 次`，不拆个人贡献；
- 纸幕可把六道轮廓叠成一条克制的胶片接触印，但每张记录仍是真实 DOM 文本；
- 唯一主按钮：`让幕布落下`
- completion note 尚未出现。

### S8 — desktop complete

- 阶段主文案：`幕布落下，合照留在这里。`
- 六张共同记录与共同摘要保持可读；
- 使用默认席位与 composer 结语：`你和TA，六次定格以后，影子也记住了我们。`
- 唯一主按钮：`再跳一次`
- 不加入分享、下载、相机、保存、排行榜、社交账号或自动重开。

### S9 — 390px mobile dancing 定格窗

- 同 S4 的第一幕目标、两席正确姿势、`稳定 3 / 6` 与精确状态；
- 舞台完整不裁切，八个按钮按左席四个、右席四个分组，每个至少 44×44px；
- 姿势名始终可见，键位可作为次级文字，不能只剩 W/A/S/D/箭头；
- 双 pointer 同时按住的两个按钮均有 pressed 状态；页面允许纵滚但不使用固定底栏；
- 零横向溢出，目标/状态不被控制区挤成不可读小字。

### S10 — 390px mobile complete

- 同 S8 的精确主文案、六张记录、共同摘要、默认结语与 `再跳一次`；
- 单列 DOM 阅读流，记录和结语在主动作前完整展开；
- 合照/接触印不覆盖文字，页面允许正常纵向滚动；
- 200% text 下仍能读出每幕标题、尝试次数与共同而非个人统计。

### S11 — 320px mobile missed

- 同 S6 的 missed 文案与中性左右姿势说明；
- 舞台宽度至少 296px、完整不裁切；八按钮保持姿势中文且至少 44px，主动作至少 48px；
- `再排这一幕` 不被 safe-area 遮挡；允许纵滚、零横溢；
- 不把失败说明压成 toast、红色警报卡、modal 或只靠图标的状态。

### S12 — 320px no JavaScript

- 只显示 H1、固定说明、中性无目标纸幕轮廓、提示 `请开启 JavaScript 后再一起排这支影子舞` 与本地隐私说明；
- 不显示当前幕、目标答案、tick/稳定、八个可操作按钮、共同记录、结语或主动作；
- 不显示安装、刷新、摄像头权限、下载或外部链接；允许纵滚、零横溢。

### S13 — 844×390 landscape dancing 定格窗

- 同 S4 的第一幕目标、正确姿势与 `稳定 3 / 6`；
- 纸幕约 360–420px 左置，目标/状态与两席 2×4 控制右置；
- 八按钮与主文本不能为了横屏缩成装饰，触控命中仍至少 44px；
- 不锁方向、不裁掉右席控制，必要时允许纵向滚动但零横向滚动。

### S14 — reduced-motion dancing 定格窗

- 同 S4 的可达规则状态与精确文本；
- 纸幕、拍灯、pressed 和稳定 3/6 都以静态边框/文字表达，不依赖剪影漂移、横带扫光、淡入、缩放或闪烁；
- 30Hz 规则含义不变，概念不增加“降动效模式”开关或技术说明。

### S15 — forced-colors dancing 定格窗

- 同 S4 的可达规则状态与精确文本；
- 使用系统背景/文字/按钮/Highlight、真实 border/outline、pressed 文本与虚实线区分左右席和窗口；
- 隐藏不必要背景纹理/阴影，不强制保色；目标、当前姿势、稳定 3/6 和八按钮仍完整；
- 不增加高对比模式开关或技术标签到生产页面。

### S16 — 图片阻断 dancing 定格窗

- 同 S4 的可达规则状态与精确文本；
- 背景和八姿势图集全部加载失败；用原创 CSS 基本轮廓、左右席标签、姿势中文和按钮 pressed 完整表达规则；
- 不显示破图图标、alt 泄漏、错误卡或下载建议；
- 页面仍能完成当前幕，图片不是成功判定或目标意义的唯一来源。

## 5. 组件、状态与实现边界

- H1、说明、幕标题、目标、当前姿势、稳定计数、按钮、记录、summary、结语、主动作和隐私说明必须是 code-native HTML；
- 页面只消费 public view；视觉不能从图片像素、剪影坐标、CSS animation 或现实时间推断成功；
- 两个席位控制是 persistent fieldset/legend 或等价语义，八按钮是稳定原生节点；只有 dancing 启用并以 `aria-pressed`/真实边框表达持有，其余阶段统一 native `disabled` 且不可操作；
- raw tick 不显示；准备/窗口状态由冻结主文案与稳定 `n / 6` 表达；
- 舞台、两个 fieldset、八按钮与 live region 始终复用同一节点；阶段标题、结果、共同记录增量与 completion note 才由 phase-owned DOM 创建/移除，不以 hidden/template 预置未来记录或结语；
- 每阶段最多一个主动作；按钮不可由整张概念截图、键帽位图或 Canvas 点击区替代；
- 图片只承担无语义舞台质感和剪影；图片失败时 CSS 轮廓与文字是正式降级，不是开发占位；
- focus 使用至少 3px 清楚 outline，不依赖 glow；pressed、窗口、成功/失败不能只靠颜色；
- motion 只允许克制的幕光/剪影换姿势过渡，尊重 reduced-motion；不得闪烁、抖屏、循环吸引注意或自动换幕。

## 6. 生产资产候选

概念接受后再生成独立生产资产，不能从完整概念截图裁切：

1. `paper-stage-bg.webp`：无人物、无文字、无键位、无场记答案的琥珀背光纸幕与靛蓝幕边；
2. `shadow-duet-poses.png`：2048×1024 透明八格姿势图集；固定 2 行 × 4 列，每格 512×512；第一行 `left`、第二行 `right`，每行从左到右固定 `high / wide / low / near`；每格四周至少 64px 透明 padding、统一脚底基线与人物比例，深墨单色、左右严格镜像朝向、无五官/服装品牌；
3. 可选 `paper-contact-grain.webp`：无字、低对比、可平铺的共同记录纸片纤维，仅在 CSS 无法忠实表达时使用。

不生成 Logo、按钮、键帽、文字、分数、图标、目标答案卡或完整 UI 位图。运行时使用透明 PNG 作为唯一 atlas 原件，不再转成有损 WebP；若八格无法保持比例、基线、padding 与朝向，必须重生成同一图集，不用八张风格漂移的独立人物图拼接。

每个生产资产必须记录完整 prompt、生成日期、工具、模型暴露状态、原生尺寸、格式、SHA-256、第三方输入“无”、使用位置、降级方式与是否进入运行时。

## 7. ImageGen 自然语言总简报

每张状态图都携带以下共同方向，再附加第 3 节的精确状态：

> 设计一套完整、可落地为本地 HTML/CSS/JavaScript 的中文同机双人合作定格舞页面，公开 H1“把影子，跳成我们”。视觉方向是“午夜背光纸幕小剧场”：近黑靛蓝房间与厚幕边、温暖琥珀背光纸幕、低对比粉灰纸纤维、两道严格左右分区且镜像朝向的深墨抽象剪影，以及沿幕边留下的六张共同接触印。气质亲密、轻松、有共同排练的仪式感，7/10 创意，低到中密度；纸幕是唯一大形体，不是摄像头画面或霓虹音游。页面不使用导航、Logo、巨型圆角外框、card grid、dashboard、HUD、排行榜或装饰性 UI。左右席各四个原生姿势按钮属于同一组件族，姿势中文比键位更重要；目标、当前姿势、稳定 0–6、记录和所有中文 UI 保持 code-native、清楚可读，不烘焙进背景或人物资产。严格保持阶段：intro 不提前显示第一幕答案；scene-intro 公开目标但不自动开始；dancing 由 pressed 按钮、当前姿势、静态拍灯和稳定文字表达；missed 不责怪个人；act-result/complete 才展开六幕记录，complete 才出现私人结语。不要标题上方 eyebrow/kicker/badge/pill，不要摄像头取景框、真人照片、五官、健身课程、霓虹四轨、下落音符、歌曲/BPM、分数、combo、perfect、准确率、赢家、奖杯、彩纸、emoji、健康指标、心率、闪烁、震屏、自动换幕、分享或额外控件。设计必须具备清楚的中文排版、可提取的颜色/字体/间距/边框/组件规则、可实现的响应式结构，并能在 reduced-motion、forced-colors、图片阻断和无 JavaScript 时完整降级。

## 8. 接受 Gate

十六张概念必须逐张原尺寸 `view_image`；任一命中即重做：

1. 只画纸幕 hero/人物剪影，没有完整页面、目标、状态、双席控制和后续记录；
2. intro 提前出现第一幕答案、稳定计数或完成记录；
3. scene-intro/dancing/missed/pose-result/act-result/complete 阶段内容错序或未来内容提前出现；
4. 八按钮不像同一原生组件族、姿势中文缺失、pressed 不清楚、非 dancing 看起来仍可操作或被键帽图片替代；
5. 定格窗依靠闪烁/颜色/移动理解，缺少真实状态与 `稳定 n / 6`；
6. missed 责怪个人、显示个人错误/速度/分数，或清掉旧共同记录；
7. act-result/complete 六幕标题缺失、错序，第二幕不是第 2 次且其余五幕不是第 1 次，尝试求和不满足 `1+2+1+1+1+1=7`，summary 变成个人比较或 complete 缺默认结语；
8. 390/320/844px 横溢、裁舞台、控制重叠、按钮小于 Gate、主动作不可达；
9. 出现摄像头、真人、写实摄影、品牌人物、健身/健康、霓虹音游、奖杯、emoji 或第三方 trade dress；
10. 使用导航、卡片网格、巨型 wrapper、badge/pill、假指标、模式开关或未经许可的额外控件；
11. 各状态纸幕、剪影比例/朝向、幕边、按钮或中文字体明显漂移；八格 atlas 不是固定 left/right 两行与 high/wide/low/near 四列，或 cell 尺寸、透明 padding、脚底基线不一致；
12. 真实 UI 文本被烘焙进背景/图集，或只能靠整张概念截图实现；
13. reduced-motion、forced-colors、图片阻断或无 JavaScript 删除必要语义、伪造完成或让玩法不可达；
14. 依赖自动循环、闪烁、抖动、透明、glow 或颜色表达窗口/pressed/成功/失败。

接受前必须提取并冻结：背景颜色性质、完整 token、字体回退、内容/控件字号与行高、spacing scale、舞台/剪影比例、左右按钮组件、focus/pressed/窗口/disabled、六幕记录布局、移动/横屏重排、允许首屏文案、图标清单（预期为空）、资产清单和至少五项 fidelity ledger。

用户明确接受后，概念才升级为生产视觉规格。接受前不得创建 `experiences/co-op/shadow-duet/index.html`、`app.js` 或 `style.css`。

## 9. 浏览器保真 Gate

概念接受不等于实现验收。页面完成后仍必须验证：

- `1504×1046`、`1280×800`、`844×390`、`390×844`、`320×568`；
- 200% text 与约 320 CSS px 的 400% zoom；
- intro、scene-intro、dancing 准备/窗口、pose-result、missed、act-result、complete 与 no-JS；
- 纯键盘、双 pointer、同席第二 pointer、capture throw fallback、up/cancel/lostcapture 乱序、blur/hidden/pagehide；
- 可控 RAF 的首帧、倒退/非法 timestamp、长帧最多 5 tick、无双循环、退出后无迟到 STEP、恢复不追后台时间；
- reduced-motion、forced-colors、图片阻断与八按钮 `elementFromPoint()`；
- 最大合法席位名与 120 字素结语回退边界；
- 零横向溢出、零 console error/warning、零公网/失败请求、零 storage/permission/camera/audio。

每次 UI 改动先用 Chrome MCP 验证对应状态；最终使用 Browser/IAB 完整完成六幕并截图。同一 QA pass 对接受概念与最新浏览器截图分别执行 `view_image(detail="original")`。fidelity ledger 至少比较文案、布局、舞台比例、剪影方向、配色、字体、间距、控制状态、响应式和降级十项；任何设计评审会指出的可修问题都必须继续修正。
