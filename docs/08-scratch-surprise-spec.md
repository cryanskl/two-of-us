# A 级“爱的刮刮卡”规格

## 1. Brainstorm 结论

这款作品用于“一人准备、另一人打开”的轻量惊喜。首批只提供一张礼物卡：打开页面后刮掉遮罩，达到阈值便完整揭晓约会邀请、礼物券或一句私人承诺。

| 方案 | 价值 | 复杂度与风险 | 本批决定 |
| --- | --- | --- | --- |
| 一张刮刮卡 | 流程短，适合直接赠送 | 重玩变化少 | 采用 |
| 多卡组与随机奖励 | 内容丰富 | 引入分组、抽取与状态保存 | 不采用 |
| Canvas 像素遮罩 | 鼠标、触摸均可获得真实刮开感 | 要处理高分屏、尺寸变化和进度计算 | 采用 |
| 图片遮罩/礼物照片 | 更个性化 | 产生素材路径、版权和隐私管理 | 后续可选增强 |
| 只有手势、没有按钮 | 惊喜感强 | 键盘和运动能力受限用户无法完成 | 不采用 |
| “直接揭晓”降级 | 保证任何输入方式都能完成 | 会缩短悬念 | 采用，作为次要按钮 |

## 2. 用户流程

1. 准备者编辑 `config.js` 中的称呼、引导语、礼物标题、正文、落款和按钮文案；
2. 把整个作品目录交给对方，对方双击 `index.html`；
3. 页面先展示被遮罩覆盖的礼物卡；
4. 用户用鼠标或手指来回擦除遮罩，页面显示简短进度提示；
5. 已擦除面积达到 55% 后，遮罩自动淡出并完整揭晓；
6. 键盘用户或不方便持续拖动的用户可以点击“直接揭晓”；
7. 揭晓后保持最终卡片，不自动刷新、不存档、不上传。

## 3. 最小配置

`config.js` 使用现有 A 级作品一致的普通全局对象，不采用 ES Modules，保证 `file://` 可直接运行。首批字段：

```text
eyebrow, title, instruction,
giftLabel, giftTitle, giftText,
closing, sender, revealButtonText
```

配置只承载文案，不允许 HTML 字符串；页面统一使用 `textContent` 写入，避免私人文案意外变成可执行标记。55% 阈值和画笔尺寸属于交互规则，首批固定在逻辑中，不额外暴露配置。

## 4. Canvas 擦除模型

遮罩 Canvas 覆盖在真实礼物卡上方：

- 初始绘制纯色涂层、轻量纹理和“从这里刮开”提示；
- 擦除时使用 `globalCompositeOperation = "destination-out"` 和圆头线段；
- 指针坐标归一化为 0–1 线段，移动端与桌面端共享同一逻辑；
- Canvas 尺寸变化时重绘遮罩并重放归一化擦除线段，不因旋转屏幕而恢复成未刮状态；
- 指针移动阶段只绘制，不逐帧扫描整张画布；在一笔结束或达到节流间隔后抽样 alpha，计算透明区域比例；
- 达到 55% 后进入一次性的 `revealed` 状态，停止采样并禁用 Canvas 指针事件。

进度采样允许使用固定步长而不是遍历每个像素；它只决定何时自动完整揭晓，不需要作为精确百分比展示。

## 5. 可访问与降级

- Canvas 提供说明性 `aria-label`，但不把它当作唯一操作入口；
- “直接揭晓”使用原生 `<button>`，键盘可聚焦并触发；
- 揭晓结果使用 `aria-live="polite"` 宣布；
- `prefers-reduced-motion` 下取消遮罩淡出和庆祝位移动画；
- JavaScript 不可用时，礼物正文仍存在于 HTML 中，遮罩交互不可用但不显示伪完成状态；
- 不自动播放声音，不请求摄像头、麦克风、通知或存储权限。

## 6. 文件结构与测试

```text
experiences/surprises/scratch-surprise/
├── index.html
├── styles.css
├── config.js
├── logic.js
├── logic.test.js
├── app.js
└── README.md
```

`logic.js` 保持无 DOM 的纯函数，至少测试：

- 坐标归一化与边界裁剪；
- 透明 alpha 抽样比例；
- 低于阈值不揭晓，达到阈值只进入一次完成状态；
- 空样本不会误判完成。

## 7. 本地与隐私边界

- 等级：A，直接双击 `index.html`；
- 公网依赖：无；第三方运行依赖：无；
- 页面不发起 `fetch`、XHR、WebSocket、统计或远程字体请求；
- 私人称呼、礼物内容与落款只保存在准备者编辑的本地 `config.js`；
- 公开仓库默认只提交示例文案，不提交真实地址、票据、兑换码、照片或其他不希望公开的内容。

## 8. 借鉴与来源声明边界

- 传统实体刮刮卡：采用“擦除表层后揭晓内容”的通用玩法机制，不复制任何商业刮刮卡的视觉、文案或素材；
- [5SSS/canvas-scratch-card](https://github.com/5SSS/canvas-scratch-card)（MIT）与 [SaifJerbi/scratch-card](https://github.com/SaifJerbi/scratch-card)（MIT）：在仓库调研阶段用于确认 Canvas 擦除机制的浏览器可行性；本作品不复制、改写或打包其源码、组件 API、样式、示例文案与素材；
- 本仓库“隔屏画猜”：复用仓库内部已经验证的归一化指针线段与尺寸重绘经验，但刮除状态、进度采样、视觉和页面代码重新实现。

作品 README 必须保留上述三条边界，不能只写“独立实现”而省略实际调研过的开源项目。

## 9. 验收标准

- 根 `index.html` 与作品目录双击路径都能打开；
- 鼠标拖动和移动端触摸都能连续擦除；
- 达到阈值后完整揭晓，重复拖动不会二次触发；
- 未达到阈值时不会提前消失；
- 调整为 390×844 后无横向溢出，Canvas 尺寸变化不恢复已擦区域；
- “直接揭晓”可用键盘完成；
- Chrome 控制台无 warning/error，页面不产生公网请求；
- `npm test`、`npm run verify` 与 `git diff --check` 通过；
- README 包含完整“借鉴与来源声明”。
