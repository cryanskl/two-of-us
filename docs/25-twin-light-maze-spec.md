# A 级「双光点归巢」同机合作迷宫规格

> 建立日期：2026-07-17 · 状态：待实现 · 目标入口：`experiences/co-op/twin-light-maze/`

## 1. 本批补齐的能力

仓库已经有 A 级轮流交接合作、A 级同屏对抗和多种 C 级双设备合作，但还没有“同一设备、两人同时控制、空间机关互相依赖”的合作作品。

「双光点归巢」让珊瑚光点与青色光点在同一张网格迷宫里移动。一人踩住压力板，另一人穿过对应门；最后两个人都站到自己的光门才完成关卡。任何一人都不能独自通关，合作不是文案包装，而是关卡状态的必要条件。

本作品属于 A 级：HTML、CSS、经典脚本和本地图集都放在作品目录内，直接双击 `index.html` 即可游玩，不使用模块、`fetch`、本地服务、公网、账号或持久化。

## 4. 用户流程

1. 用户从门户或直接双击作品 `index.html`；
2. 首屏显示第一关、两名玩家、控制说明和“开始归巢”；
3. 开始后，珊瑚玩家用 WASD，青色玩家用方向键；触屏可使用底部两组方向盘；
4. 任一玩家站上压力板时，对应门打开；离开时门关闭，但门格上仍有玩家时不会夹住玩家；
5. 两人分别站到珊瑚与青色光门后进入本关完成；
6. 点击“下一关”进入下一张地图；第四关完成后显示“我们一起回来了”，可重新游玩；
7. 暂停、窗口失焦或页面隐藏时停止接收移动；“重来本关”恢复本关出生点。

## 5. 关卡数据模型

### 5.1 字符网格

每关使用等宽字符串数组：

| 字符 | 含义 |
| --- | --- |
| `#` | 墙 |
| 空格 | 可行走地面 |
| `1` / `2` | 珊瑚 / 青色出生点 |
| `x` / `y` | 珊瑚 / 青色出口 |
| `a` / `b` | A / B 组压力板 |
| `A` / `B` | A / B 组保持门 |

页面不直接信任关卡常量。`validateLevel()` 必须拒绝：非矩形、尺寸越界、未知字符、出生点或出口缺失/重复、门没有对应压力板、压力板没有对应门。

### 5.2 运行状态

```js
{
  phase: "ready" | "playing" | "paused" | "level-complete" | "game-complete",
  levelIndex: 0,
  players: [cellIndex, cellIndex],
  moveCount: 0,
  pauseReason: null | "manual" | "blur" | "hidden"
}
```

墙、门、压力板与出口来自冻结的关卡定义，不复制进运行状态。门是否开启、压力板是否按下和双方是否归巢都由当前玩家位置派生，不保存第二份布尔值。

## 6. 移动与机关规则

### 6.1 单步移动

`movePlayer(state, seat, direction)` 每次只移动一个格：

- 仅在 `playing` 接受输入；
- `seat` 只能是 0 或 1，方向只能是上、下、左、右；
- 越界、墙、另一名玩家或关闭的门都会保持原状态对象；
- 合法移动返回新的冻结状态并把 `moveCount` 加一；
- 玩家可以经过任一出口，但只有站在自己出口上才满足归巢条件。

### 6.2 压力板与门

某组压力板只要被任一玩家占据，对应门全部打开。门格上已有玩家时也视为临时打开，保证另一名玩家离开压力板后不会把玩家夹在不可移动状态；玩家走出该门格后，若压力板无人占据，门立即恢复关闭。

门状态计算顺序固定为：读取移动前位置 → 判断目标门当前是否开放 → 移动 → 从新位置重新派生全部门状态。不会在动画结束回调里修改规则。

### 6.3 共同胜利

一次合法移动后若 `players[0] === coralExit` 且 `players[1] === cyanExit`，同一个 reducer 返回值直接进入 `level-complete` 或 `game-complete`。单人先到出口不会锁死；他仍可离开帮助对方，再一起回来。

## 7. 输入模型

### 7.1 键盘

- 珊瑚：`KeyW / KeyA / KeyS / KeyD`；
- 青色：`ArrowUp / ArrowLeft / ArrowDown / ArrowRight`；
- 使用 `KeyboardEvent.code`，避免输入法和键盘布局改变角色；
- 每次非 repeat 的 `keydown` 只走一步；`keyup` 清理 held 集合；
- 拦截方向键默认滚动；暂停、失焦、页面隐藏和重新开始时清空 held 集合。

两键近同时按下会按浏览器事件顺序各结算一步。玩法没有抢先或同帧胜负，因此不需要人为构造“同时帧”；每次结算后都重新计算机关，结果确定且可测试。

### 7.2 触屏

移动端显示两组并排方向盘。每个方向按钮最小 52×52px，`pointerdown` 立即走一步并阻止文本选择；不实现长按连发，避免两个人共用手机时误触连续移动。中心图形只区分玩家，不是按钮。

## 8. 视觉系统

### 8.1 冻结方向

概念采用“夜间天文台平面图”：深靛蓝石面、温暖铜线、珊瑚圆缺口与青色菱形两枚玻璃光点。浪漫感来自“两束不同形状的光共同打开路径”，不使用散落爱心、情侣头像、彩屑或竞技比分。

设计 token：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#061321` | 页面深蓝黑背景 |
| `--stone` | `#111f31` | 迷宫地面 |
| `--ink` | `#f1d3a1` | 标题与主文字 |
| `--muted` | `#9d9a95` | 状态说明 |
| `--brass` | `#b8894e` | 线框、边界和按钮 |
| `--coral` | `#ff765e` | 珊瑚玩家与控制 |
| `--cyan` | `#4ed7ec` | 青色玩家与控制 |
| `--danger` | `#d88369` | 碰墙提示，不表示失败 |

字体只使用系统字体。标题用有宋体气质的 `Songti SC, STSong, serif`；HUD、正文与按钮用 `system-ui, PingFang SC, sans-serif`；关卡编号和按键使用 `ui-monospace, SFMono-Regular, monospace`。

### 8.2 桌面构图

- 适配冻结概念 1586×992，同时保证常见约 1280×800 内容区首屏可玩；
- 顶部只放返回、标题和 `第 n / 4 关`；
- 12×8 迷宫是唯一主视觉，宽度受高度和视口共同约束；
- 底部开放操作轨依次放控制图例、状态和暂停/重来/操作，不拆成卡片；
- 开始、下一关和重新游玩使用同一主动作位置，不弹出遮住整张迷宫的庆祝层。

### 8.3 移动构图

- 390×844 依次为紧凑顶栏、12×8 迷宫、状态、两组方向盘和底部工具；
- 比例与冻结移动概念一致，但允许压缩迷宫装饰边框，不能裁掉方向按钮；
- 320×700 可纵向滚动，但不得横向溢出；
- 触控按钮除颜色外还用圆缺口与菱形中心区分玩家。

### 8.4 图集映射

透明图集尺寸为 1448×1086，严格分成 4×3 个 362px 单元：

| 行 | 列 1 | 列 2 | 列 3 | 列 4 |
| --- | --- | --- | --- | --- |
| 1 | 珊瑚玩家 | 青色玩家 | A 板未按 | B 板未按 |
| 2 | A 板按下 | B 板按下 | A 门关闭 | B 门关闭 |
| 3 | 珊瑚出口 | 青色出口 | 地面 | 墙 |

CSS 只使用 `background-size: 400% 300%` 与固定 background-position 选择图块。透明图集由原始绿色背景稿通过一次性工具处理；作品运行不需要 Pillow、FFmpeg 或其他图像依赖。

## 10. 无障碍与隐私

- 玩家用颜色与圆缺口/菱形双重编码；
- 迷宫容器提供简短 `aria-label`，另有文本状态说明当前两人位置、压板和门；
- 每次关卡、暂停、碰撞和完成只在 `aria-live` 中播报必要变化，不逐格刷屏；
- 所有操作可键盘完成，触屏按钮有明确 `aria-label` 和焦点样式；
- `prefers-reduced-motion` 下移除移动、发光脉冲与碰撞摇晃，格位变化和状态完整保留；
- 不读取或保存昵称、按键、进度、照片或设备信息；不使用 localStorage、Cookie、IndexedDB、Cache API 或网络请求。
