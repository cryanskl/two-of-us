## 3. 真实浏览器全流程

先按仓库前端验收规则连接内置 Browser/IAB，本次环境返回 `No browser is available`，因此使用 Playwright CLI 的 headed Chromium 作为明确 fallback。Playwright CLI 阻止 `file://` 导航，所以交互验收通过 `python3 -m http.server 8765 --bind 127.0.0.1` 服务同一目录；A 级直开边界由经典脚本、相对资源、无远程 URL/网络 API与 catalog Gate 单独证明。

完整流程实际验证：

1. intro 只有标题、相机、快门与本地隐私说明；
2. 按快门后进入 `ejecting`，720ms 动画或 780ms 兜底只通过当前 token 推进；
3. 进入 `developing` 后相纸自动获得焦点，私人文案尚未进入正文或可访问快照；
4. 第一次 `←` 推进到 11%，再次 `←` 保持 11%；
5. 继续交替到第五次为 56%，剩余 4 次，五个圆点填充；
6. 九次完成后为 100%，照片滤镜归零，标题、地点、说明和留言才创建；
7. “再显影一次”回到 intro，相纸隐藏，私人 DOM 清空；
8. 鼠标在一次 pointer capture 中右移 66px、同侧再移、回中、左移 66px，只得到两次有效摇动，松开后抓取态清除。

## 4. 缺图回退与隐私边界

浏览器通过临时路由把 `config.js` 的照片改为不存在的 `./assets/missing-private-photo.png`，不修改仓库文件。结果：

- 缺图请求失败后只把图片源切到 `./assets/demo-bicycles.png`；
- 显影阶段提示“先用示例继续”，私人标题仍不在 DOM；
- 九次完成后显示注入的“保留的私人标题”和私人留言，证明图片回退没有覆盖已校验文案；
- 这次刻意制造的 404 是回退测试输入；正常配置会话控制台为 0 error / 0 warning。

静态 A 级页面只能承诺“不联网、不上传、不保存”和“完成前不进入 DOM”，不能对能读取仓库源码的人构成加密保密。README 已明确这条边界。

## 6. 视觉忠实度账本

概念：[1504×1046 即时相机显影台](assets/instant-photo/concept.png)。最终 QA 在同一次检查中以 `view_image` 原生尺寸并排查看概念和 56% Chromium 截图。

| 比较点 | 概念证据 | 实现证据与处理 |
| --- | --- | --- |
| 色板 | 粉蓝背景、珊瑚相机、象牙相纸、深海军蓝文字 | 固定设计 token 对齐；无 CSS 渐变，概念资产背景以四角采样色融合 |
| 标题层级 | 左上超大窄体标题与短副标题 | 位置、比例、两行顶栏和留白保持一致 |
| 主构图 | 相机占左下，相纸从机身上方覆盖，控制在右 | 桌面三块关系一致，相纸拥有真实可拖动 DOM 而不是概念裁图 |
| 显影层 | 半清晰照片与进度同步 | 56% 截图显示五个圆点、剩余四次、低饱和模糊照片 |
| 手势提示 | 双圆箭头、虚线中点和键盘提示 | 全部用代码原生 SVG/CSS 实现，且对应可用输入 |
| 信息层级 | 顶部百分比、右侧剩余次数、底部隐私 | 三处位置和语义一致；进度统一由 9 次权威状态派生 |
| 移动端 | 单列相纸、相机与控制 | 390px 独立页面验证堆叠，不在桌面绘制不可交互的假手机 |

### 首屏文案差异

标题“拍立得显影”、副标题“有些画面，要慢慢才看得清。”、动作“左右摇动这张照片”、解释“每次越过中线，影像会更清楚一点。”、剩余“还差 4 次”和隐私说明均逐字一致。概念的 58% 是构图示意；生产规则用 `round(5 / 9 × 100) = 56%`，以圆点数量和剩余次数为唯一真值，避免伪造不可达百分比。

### 有意偏差

- 概念相纸静态倾斜，生产页静止时保持正向便于阅读，只有真实拖动时随位移旋转；
- 概念相机带有“1980s instant”装饰，运行资产主动移除品牌式文字，只保留通用即时相机形态；
- 概念包含手机外壳插图，交付改为真实 390 / 320 响应式视口；
- 完成态增加私人标题、印章、说明、留言和重开按钮，这是核心惊喜闭环，概念只表现中途显影态。

偏差都有交互、可读性或来源边界理由；主构图、色板、文案层级、显影反馈和核心流程达到可签收忠实度。
