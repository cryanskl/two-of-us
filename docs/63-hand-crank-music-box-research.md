# A 级手摇音乐盒定向调研

> 调研日期：2026-07-18  
> 对应创意池：S04「手摇音乐盒」  
> 目标分类：单人惊喜；目标启动等级：A；核心运行时公网依赖：无  
> 本轮证据：开放标准、浏览器平台文档、博物馆馆藏元数据与仓库现有实现；未读取或复制第三方源码

## 1. 为什么现在做它

当前单人惊喜已覆盖拆信、刮开、转盘、照片、车票、礼盒、投递与口令解锁，但仍缺少一种需要接收者持续触摸、由动作亲手“演奏”出来的惊喜。手摇音乐盒能补上这块空白：摇柄不是进入页面后的装饰，而是旋律、进度和层景展开的共同输入。

首版定位为一个人预先写好结尾留言，另一人打开后持续顺时针转动摇柄。每拨过一个虚拟齿位就响一个原创合成音，并让纸雕场景再展开一层；完成固定圈数后，盒盖里的最终留言完全显露。无照片、无商业录音、无账户、无存储，也不以音频成功播放作为完成条件。

## 2. 一手证据与产品判断

| 来源 | 一手事实 | 对本作的约束 |
| --- | --- | --- |
| [W3C Web Audio API 1.0](https://www.w3.org/TR/webaudio-1.0/) | `AudioContext` 具有 `suspended / running / closed` 状态，恢复是异步操作 | 音频层必须接受启动失败；页面规则不能读取音频状态决定是否完成 |
| [W3C Autoplay Policy Detection](https://www.w3.org/TR/autoplay-detection/) | Web Audio 是否允许启动与用户激活有关 | 首次指针按下、键盘转格或显式“开始转动”都属于真实用户动作；不在加载时偷偷播放 |
| [MDN Web Audio API best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices) | 推荐在用户手势内创建或恢复音频上下文，并给用户静音等控制 | 摇柄动作调用仓库共享 `tone-player` 的 `ensureReady()`；保留可见静音按钮和纯视觉降级 |
| [Smithsonian：Paillard & Cie. Cylinder Music Box](https://americanhistory.si.edu/collections/object/nmah_605759) | 馆藏圆筒音乐盒以卷簧驱动圆筒，并使用一体式音梳 | 用“圆筒齿位 → 单音”的视觉隐喻，不照搬具体器物外观 |
| [Smithsonian 乐器目录研究 PDF](https://repository.si.edu/bitstreams/b8449723-a7f4-4b27-8ccb-f43ded30d579/download) | 圆筒上的凸点依次拨动不同长度的金属簧片，圆筒可由连续手摇或卷簧驱动 | 将连续角度拆成离散齿位；只有跨过新齿位才推进和发音，往回摆动不刷进度 |

Smithsonian 页面明确提示馆藏图片存在复用限制。因此本作只使用其文字元数据理解公共机械原理，不下载、不描摹、不分发馆藏图片。运行时纸雕图景将另行原创生成并记录来源。

## 3. 技术路线比较

| 路线 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 引入 Tone.js | 音序、合成器与调度成熟 | 对八到十六个短音过重；增加固定包和许可证文件 | 首版不引入 |
| 播放一段本地录音 | 音质稳定 | 需要音乐与录音授权；动作和声音容易脱节 | 不采用 |
| 复用 `shared/audio/tone-player.js` | 已有离线、失败回退与单音校验；零新增依赖 | 需要自行定义原创音高序列和节奏 | 采用 |
| CSS/Canvas 绘制全部美术 | 文件小 | 容易变成工程示意图，缺少礼物感 | 中央纸雕资产使用原创生成图；控件与状态仍由 HTML/CSS 渲染 |

`Tone.js` 只作为第二轮能力地图中的可选方向，本次不会下载、运行、阅读或复制其源码。首版需要的是“每跨过一个齿位安全播放一个短音”，仓库已有共享播放器已经满足；因此新增第三方运行时依赖为零。

## 4. 已锁定的首版边界

- 同一台设备，一个人准备、另一个人体验；
- `file://` 直接打开，断网完整可用；
- 鼠标和触屏可连续拖动摇柄，键盘与按钮可以逐格推进；
- 只计算合理范围内的顺时针角度增量；反向、跨象限和指针瞬移不能凭空增加圈数；
- 音频只在输入手势后尝试启动；静音、拒绝权限或设备不支持时仍正常展开层景；
- 旋律为仓库原创的短音高序列，不含采样、录音或商业歌曲片段；
- 最终留言只来自本地 `config.js`，不上传、不保存、不写入日志；
- 不加入曲库、录音导入、节拍评分、分享、账号、历史记录或自动播放。

## 5. 借鉴声明草案

本作借鉴传统圆筒音乐盒“旋转圆筒的凸点依次拨动音梳”的公共机械原理，并依据 W3C/MDN 文档处理浏览器音频状态与用户手势限制。没有从上述来源或任何开源音乐盒项目复制、改写或运行代码、视觉、旋律、文案和素材。

下一阶段的正式规格会继续记录：原创视觉概念及生成工具、运行时资产文件、共享播放器复用范围、所有可见文案和旋律来源。如果以后真正引入第三方代码或素材，必须新增文件级 `assets/ATTRIBUTION.md` 记录，不能把本页的“零复制”沿用到未知内容。

## 6. 进入设计前的 Gate

- 产品差异成立：它不是另一个点击揭信页，而是持续动作驱动的触觉惊喜；
- A 级成立：只依赖原生 HTML/CSS/JavaScript 和仓库已有的本地脚本；
- 版权边界成立：不使用第三方音乐、馆藏图片、字体或代码；
- 无声降级成立：声音是反馈，不是规则权威；
- 范围可控：一个机械装置、一个层景、一段原创短旋律、一个最终留言。

结论：通过定向调研 Gate，可以进入视觉概念与正式规格阶段。
