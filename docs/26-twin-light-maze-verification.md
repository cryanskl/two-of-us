## 3. Chrome 真实交互

使用真实 Chrome 页面完成以下流程：

1. 点击“开始归巢”，使用两套键盘控制按 BFS 路径完成第一关 28 步；
2. 点击“下一关”，依次以 18、28、35 步完成后三关，最终进入 `game-complete` 并显示“我们一起回来了”；
3. 点击“重新游玩”回到第一关出生点与 `playing`；
4. 暂停后发送移动键，玩家位置保持不变；点击继续后同一移动键正常前进一步；
5. “重来本关”恢复出生点并清零本关步数，“操作”对话框可以打开和关闭；
6. 390×844 下点击珊瑚方向盘向下，玩家从 2 行 2 列移动到 3 行 2 列；
7. 模拟 `prefers-reduced-motion: reduce` 后，格子 transition 与按钮 animation 均为 `0.00001s`，页面仍处于可开始的 `ready`；
8. 控制台 warning/error 均为 0。

键盘通关实际经过压力板、门与双方出口，而不是在页面内注入状态。每关的完成文案、关卡编号、步数和主动作都从真实 DOM 读取核对。

## 5. 视觉忠实度

最终桌面与 390×844 截图分别和 [`docs/assets/twin-light-maze/`](./assets/twin-light-maze/) 中两张冻结概念图逐张比较：

1. **文案**：标题、关卡编号、两人归巢语义、暂停/重来/操作和双控制说明与冻结方向一致；
2. **布局**：桌面保留顶栏、中央单一迷宫、底部开放操作轨；移动端依次为顶栏、迷宫、状态、方向盘和工具；
3. **排版**：标题使用系统宋体栈，状态与按钮使用系统无衬线，关卡与键位使用等宽字体；
4. **色彩**：深靛蓝石面、暖铜线、象牙文字、珊瑚与青色双光点与规格 token 一致；
5. **资产**：生产页只加载一张 4×3 透明图集；玩家通过伪元素覆盖在地形上，压板与门状态切换 background-position；
6. **容器**：迷宫保持 12:8，铜线外框、四向罗盘和开放操作轨构成同一观测台，不拆成卡片列表；
7. **响应式**：390px 保留并排双控，320px 才为保证触控尺寸改为纵向，桌面短视口仍一屏可玩；
8. **动效**：移动、发光和碰墙反馈只是视图投影；减少动态效果后规则、位置、门状态与完成条件完全保留。

有意差异是概念图使用自由形态墙体，而生产实现严格使用可测试的 12×8 图集格；这是为了让视觉、碰撞和 BFS 使用同一坐标体系。移动端还增加了首屏“开始归巢”和状态说明，避免打开后立即误触。两项差异都保留概念的构图与材质，不构成视觉漂移。
