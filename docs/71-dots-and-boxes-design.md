# 「这一格归谁」视觉设计清单

> 接受日期：2026-07-18。产品与规则依据为 [`70-dots-and-boxes-spec.md`](./70-dots-and-boxes-spec.md)。概念由 OpenAI ImageGen 生成，仅作为视觉规格，不在运行时显示。

## 1. 已接受概念

- [桌面进行态 1504×1046](./assets/dots-and-boxes/concept-desktop-playing.png)；
- [手机进行态 853×1844](./assets/dots-and-boxes/concept-mobile-playing.png)；
- [桌面终局态 1504×1046](./assets/dots-and-boxes/concept-desktop-finished.png)；
- 运行纸张纹理：[`../experiences/versus/dots-and-boxes/assets/paper-texture.png`](../experiences/versus/dots-and-boxes/assets/paper-texture.png)，1254×1254。

桌面采用约 36/64 的不对称双列：左侧是标题、规则、双方比分和当前回合，右侧是一张完整方格纸棋盘。手机按标题与规则 → 比分 → 棋盘 → 回合信息 → 主动作排列，不把棋盘缩成不可点击的缩略图。

## 2. 设计系统

| 类别 | 规则 |
| --- | --- |
| 桌面底色 | 炭褐 `#3c3631`，允许轻微颗粒或暗角，但不依赖远程图片 |
| 棋盘纸 | 暖象牙 `#f4eddd`，本地纹理只提供安静纸纤维；加载失败时回退纯色与 CSS 方格线 |
| 主文字 | 石墨 `#282824`；次要说明 `#6d665d` |
| 朱方 | 朱红 `#b43a28`，用于玩家一、已占边、格子淡填充和当前回合强调 |
| 蓝方 | 靛蓝 `#24569a`，用于玩家二、已占边、格子淡填充和当前回合强调 |
| 网格 | 冷灰 `#cfd3cf`，只做纸上辅助格，不承担可点击边状态 |
| 字体 | 标题和文学性文本使用本机宋体栈 `Songti SC` / `STSong`；数字与状态使用系统 sans-serif；不打包第三方字体 |
| 几何 | 薄纸、铅笔线、方格和克制阴影；按钮可有 2–6px 圆角，不使用胶囊、玻璃卡片或 dashboard 网格 |
| 动效 | 落边与圈格 160–260ms；终局纸张轻抬不超过 420ms；`prefers-reduced-motion` 关闭位移与缩放 |

## 3. 允许的首屏文案

首屏只允许以下代码原生文字，不从概念图裁切：

- 标题：`这一格归谁`；
- 桌面引导：`轮流连起相邻的点。圈住一格，它就归你，而且还能再走一步。`；
- 手机紧凑引导：`轮流连点，围成一格就继续。`；
- 两个配置玩家名与对应比分；
- `轮到朱方` / `轮到蓝方`；
- `还剩 16 格` 等动态剩余格数；
- 开场动作：`开始落笔`；
- 终局动作：`再来一页`；
- 终局标题：`朱方赢下这一页`、`蓝方赢下这一页` 或平局文案。

禁止新增模式选择、难度、排行榜、AI、联网、登录、分享、战绩、教学轮播、英文品牌或装饰性 badge。

## 4. 组件与资产清单

| 组件 | 概念证据 | 实现约束 |
| --- | --- | --- |
| 返回按钮 | 左上角细线返回箭头 | 原生链接 + 自制 SVG；这是全页唯一必要图标 |
| 比分区 | 左栏上下两方记分 | 姓名、颜色和数字同源于 view model；不做两张厚重卡片 |
| 棋盘纸 | 右侧完整 4×4 格纸面 | 9×9 CSS Grid 语义 DOM；纸纹是背景，点/边/格均由代码原生生成 |
| 25 个点 | 铅笔圆点 | 非交互装饰节点；不使用图片或 Unicode |
| 40 条边 | 点间细线 | 每条是至少 44px 的真实按钮，视觉线位于宽松命中区中央 |
| 16 个格子 | 朱红/靛蓝淡墨填充 | owner 只来自规范状态；一笔同时闭合两格时两格同时出现 |
| 回合状态 | 左栏手写式状态行 | 使用 `aria-live`，同一处更新回合、得分和继续落笔提示 |
| 主动作 | 深色矩形按钮 | 开场和终局复用一个明确主动作；对局中不显示重开按钮 |
| 终局结果 | 左栏结果 + 完整棋盘 | 不弹 modal，不遮住最终 16 格归属 |

## 5. 响应式提取

### 1504×1046

- 页面在首屏内完整显示，`scrollHeight <= clientHeight`；
- 左栏约占 36%，右栏约占 64%，棋盘纸主体约 660–760px；
- 标题约 68–82px，比分数字约 52–64px，规则约 18–22px；
- 棋盘完整露出，任何边的 44px 命中区不能被纸张阴影或装饰覆盖；
- 墨水瓶、实体笔、撕纸边只属于概念气氛，若影响棋盘或首屏高度就省略。

### 390×844

- 标题、双方比分和完整棋盘应在首屏建立关系；主动作或回合状态允许短滚动；
- 棋盘宽度不超过 `calc(100vw - 24px)`，仍保留 40 个至少 44px 的交互命中区；
- 用透明命中层互相交叠实现触控尺寸，视觉线仍保持纤细；相邻边需要稳定的层级和点击归属；
- 页面 `scrollWidth === clientWidth`，不能依赖隐藏横向溢出掩盖错误。

### 320×700

- 不隐藏规则、比分或棋盘功能，不通过低于 16px 的正文缩字解决空间问题；
- 允许纵向滚动，但不出现横向滚动；
- 44px 边按钮和可见焦点环继续有效，键盘操作不能因紧凑布局退化。

## 6. 图标与交互反馈

- 图标库存只有返回箭头 SVG；棋盘点、边、方格和结果装饰全部使用 HTML/CSS，不引入图标库；
- 未占边保持透明命中区，hover / focus 显示当前玩家颜色的预览线；触屏不依赖 hover 才能理解可操作性；
- 已占边使用 owner 色实线并禁用；不能只靠颜色表达，格子内同时放置 `朱` / `蓝` 的可读标记或等价隐藏文本；
- 一笔闭合格子后，状态行明确写出得分并说明仍由该玩家继续；
- 键盘焦点在开始后进入第一条空边，落笔后移动到下一条可用边，终局移到结果标题。

## 7. 生成式概念的已知非权威部分

- 桌面进行态概念显示 `3–2`，但画面中可见的占边与填格不足以推导该比分；运行版不得以概念图作为种子或测试 fixture；
- 桌面终局概念的 `9–7` 只用于终局密度和双色分布参考，不是固定对局脚本；
- 概念中的真实铅笔、墨水瓶、纸张撕边和手写字只表达材质方向；运行版文字必须是可选择、可缩放的代码原生文本；
- 生成图中的线宽、点距和局部点击面积不具备可访问性保证，运行版以 44px 目标和语义按钮为准；
- 所有比分、剩余格、回合与格子归属必须由同一状态机推导，不人工在 DOM 中维护第二份数据。

## 8. 运行资产与降级

- `paper-texture.png` 只铺在棋盘纸表面，使用低对比度混合，不能降低线条和文字对比；
- 若纹理缺失，使用 `#f4eddd` 加两组 CSS 线性渐变生成方格纸，全部玩法仍可用；
- 三张概念图只保存在 `docs/assets/dots-and-boxes/`，运行 HTML 不引用它们；
- 不使用远程字体、图片、音频、脚本、API 或 CDN。

## 9. ImageGen 提示词摘要

四次接受输出均使用 Codex 内置 OpenAI ImageGen：

1. 桌面进行态：1504×1046，炭褐桌面、36/64 双列、暖象牙 4×4 方格纸、朱红与靛蓝墨线、克制中文排版；
2. 手机进行态：390×844 目标单列，保留标题、比分、完整棋盘与大触控目标，不做卡片 dashboard；
3. 桌面终局态：同一视觉系统，完整 16 格归属与 `9–7` 结果密度，棋盘不被结果层遮挡；
4. 纸张纹理：无字、无物件、无中央折痕的均匀暖白方格纸，可无缝裁切并作为低对比运行背景。

第一版带明显中央拼缝的纹理已拒绝且未进入仓库。最终实现必须在 Browser 截图后与桌面/手机概念同轮原尺寸检查，并记录至少五项视觉忠实度账本、文案差异与主动偏离。
