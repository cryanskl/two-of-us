# A 级「纸上球局」规格

## 1. 定位与边界

- 创意池：V14「纸上足球」；
- 产品名：纸上球局；
- ID：`paper-soccer`；
- 主分类：双人对抗；
- 启动等级：A；
- 设备：同一台电脑或手机，轮流操作；
- 公网依赖：无；
- 账号、服务、长期存储：无；
- 首版核心：轮流画一条不重复线，利用旧点/边界连续行动，把球送入对方球门或困住对方。

首版不加入 AI、联网房间、悔棋、棋谱导入、排行榜、局面编辑器或可变球场。一次比赛只使用经典固定球场，结束后可以保留本次会话胜局并再踢一场。

## 2. 调研结论与规则选择

2026-07-18 复核的传统规则来源：

- [Paper Soccer Rules](https://paper.soccer/rules/)：8×10 球场、2×1 球门、八方向相邻移动、旧点/边界反弹、进球或无合法移动取胜；
- [Paper Football](https://www.paper-football.com/)：同样说明线段不可复用，反弹持续到落入新点。

本作采用可解释、适合静态 HTML 的确定版本：

1. 场内是横向 8 格、纵向 10 格，共 9×11 个格点；
2. 上下短边中央各有一个 2 格宽、1 格深的球门，代码中使用一个终局球门节点表示网内；
3. 每次只能走到正交或对角相邻格点；
4. 同一条无向线段不能再次使用，沿球场外边线的线段也不可走；
5. 落点在本次落笔前已有线相连，或落在球场边界，则当前玩家继续；
6. 落入上方球门红方获胜，落入下方球门蓝方获胜，因此乌龙球自然计给对方；
7. 借力后仍由当前玩家继续时，如果落点没有合法出口，则当前玩家被困并输掉本局；普通落入新点后一定还存在未用出口，不会立刻困住换手后的对方；
8. 红方固定向上攻、蓝方固定向下攻；第一局默认红方开球，之后开球策略由本地配置决定，默认交替。

## 4. 图模型

### 4.1 节点

场内节点用 `{ x, y }` 表示：

```text
x = 0..8
y = 0..10
```

上方球门终局节点为 `{ x: 4, y: -1 }`，可从 `(3,0)`、`(4,0)`、`(5,0)` 进入；下方球门终局节点为 `{ x: 4, y: 11 }`，可从 `(3,10)`、`(4,10)`、`(5,10)` 进入。球从 `(4,5)` 开始。

### 4.2 边

边是无向的。`edgeKey(a,b)` 必须先按 `y,x` 排序，再输出稳定字符串；因此 `a→b` 与 `b→a` 永远得到同一 key。状态只保存玩家真正走过的边；球场边线由合法移动生成器直接排除，不伪装成玩家轨迹。

### 4.3 访问与反弹

`wasVisitedBeforeMove(target, edges)` 只读取提交本次边之前的状态：

- 场内边界点永远视为已访问；
- 其他点只要已有任意玩家边相连即为已访问；
- 球门节点是终局，不参与反弹。

先计算 `bounce`，再追加新边。顺序不能反过来，否则所有新落点都会因为刚出现的边而错误反弹。

## 5. 权威状态与 reducer

```js
{
  phase: "intro" | "playing" | "complete",
  currentPlayer: "red" | "blue",
  starter: "red" | "blue",
  ball: { x, y },
  edges: [{ key, from, to, owner }],
  turnNumber: 1,
  moveNumber: 0,
  bounceChain: 0,
  scores: { red: 0, blue: 0 },
  winner: null | "red" | "blue",
  winReason: null | "goal" | "trap",
  lastMove: null | { owner, from, to, bounced },
  matchNumber: 1,
  revision: 0
}
```

所有公开状态及嵌套对象递归冻结；调用方坐标和数组不得与状态共享引用。

纯逻辑 API：

- `createInitialState(config?)`：整份校验本地配置，创建 intro；
- `start(state)`：仅 intro 进入 playing；
- `getLegalMoves(state)`：只返回当前球点可走的相邻/球门节点；
- `move(state, target)`：只接受当前合法目标；先判断旧点，再追加边并结算借力、换手、进球，或借力后的自困；
- `resolveNextStarter(policy, context)`：调用本地可选策略，异常或非法返回值统一回退为交替；
- `rematch(state, nextStarter)`：仅 complete 生效，保留胜局，清空本局轨迹并递增 match/revision；
- `resetSeries(state)`：仅 complete 生效，回到第一局 intro 并清空胜局；
- `isGameState(value)`：畸形状态不进入规则分支。

合法状态的非法操作返回同一引用；畸形状态通过公开动作安全回到初始状态，不抛异常。

## 6. 操作与回合反馈

### 6.1 同一规则入口

三种输入最终都调用 `move(state,target)`：

- 鼠标/触屏：点 SVG 中高亮的合法相邻格点；
- 键盘：`Q/W/E/A/D/Z/X/C` 对应左上、上、右上、左、右、左下、下、右下；
- 辅助控制：右侧/下方 3×3 方向按钮，中央为空。

禁用方向不触发 reducer；每次重渲染后焦点优先保留在刚使用的方向按钮，若该方向失效则聚焦第一个合法方向。SVG 合法点支持 Enter / Space。

### 6.2 可见信息

- 顶栏：返回门户、当前第几回合；
- 标题：`纸上球局`；
- 副标题：`一笔一脚，沿着旧线借力，把球送进对方球门。`；
- 当前回合：如 `红方进攻 · 朝上方球门`；
- 规则短句：`落到旧点或边线，可以继续走`；
- 会话胜局：红方 / 蓝方；
- 借力后：明确显示 `借到旧线，红方继续` 与连续次数；
- 普通落入新点：显示换手；
- 终局：说明进球、乌龙或困死，不用动画替代文字。

live region 只播报已发生的移动和下一个行动者，不重复整块棋盘。

## 7. 开球策略的本地配置

`config.js` 提供：

```js
{
  redName,
  blueName,
  firstPlayer,
  chooseNextStarter(context)
}
```

`chooseNextStarter` 是唯一允许准备者编写的行为函数。默认交替开球；也可以选择上一局输家开球或保持同一开球者。运行时把 `{ previousStarter, winner, winReason, matchNumber }` 的冻结副本传入，并只接受 `"red" | "blue"`；抛错、修改上下文或返回其他值都回退为交替。该配置只在本地执行，不上传。

## 8. 视觉规格

方向：旧校刊战术本（old school magazine tactics notebook）。

### 8.1 设计令牌

- 桌毡：深墨绿 `#173b2a`；
- 方格纸：暖米白 `#efe3c6`；
- 石墨：`#282c27`；
- 红方：番茄铅笔红 `#b83a2f`；
- 蓝方：钴蓝 `#255faa`；
- 黄铜：`#b08b4f`；
- 次级文字：`#cbbd9d`；
- 阴影：硬边深绿黑，不使用渐变。

标题使用本机中文 serif / slab fallback，HUD 与按键使用 monospace。主框以直角、双细线、虚线和硬偏移纸张阴影为主，不使用圆角卡片、霓虹、玻璃或外部字体。

### 8.2 桌面 1504×1046

- 左侧约 58% 为纵向 8×10 方格纸球场，完整展示上下球门；
- 右侧是开放式战术栏：导航、回合、标题、当前玩家、规则、胜局和 3×3 方向盘；
- 背景只使用无字桌毡与边缘文具资产；
- 首屏必须完整看见球场、控制和本地隐私页脚，无横向或纵向滚动。

### 8.3 移动 390px

顺序为导航、标题、回合/规则、纵向球场、比分、方向盘、页脚。球场占满可用宽度但保持正确 8:10 几何；3×3 按键每格至少 64px，高度自然滚动，不横向溢出。

- [1504×1046 桌面概念](assets/paper-soccer/concept-desktop.png)；

## 9. 响应式与无障碍 Gate

- SVG 有可见标题/描述，当前球点与合法目标都有文本标签；
- 合法 SVG 目标可 Tab 到达并用 Enter / Space 激活；
- 八方向按钮有方向、快捷键和目标坐标的 aria-label；
- 红蓝轨迹同时使用颜色与不同 dash/纹理，不只依赖颜色；
- 焦点描边在深绿和米白背景上都清晰；
- 320×760 无横向溢出，所有触控按钮至少 56px；
- reduced motion 取消球移动和纸张反馈动画，不改变 reducer；
- complete 的两个动作按 DOM 顺序自然可达。

## 10. 自动测试 Gate

至少覆盖：

1. 固定球场节点、球门连接与无向 edge key；
2. 中心八方向、边界和球门口合法移动；
3. 外边线、越界、重复边与反向重复边拒绝；
4. 新点换手、旧点继续、边界继续与连续借力；
5. 上下球门、乌龙和胜局累计；
6. 借力后当前玩家无出口时自困，胜局计给对方；
7. 非法阶段/目标保持原引用，畸形状态安全；
8. rematch 只从 complete 生效、开球策略回退和胜局所有权；
9. 调用方坐标、配置上下文与状态深冻结；
10. catalog A 级、经典脚本、相对资源、无网络/存储依赖。

整仓继续要求 `npm test`、`npm run verify` 与 `git diff --check` 通过。

## 11. 浏览器验收路径

1. intro 开球并确认首个合法方向获焦；
2. 用鼠标点一次新点，确认换手；
3. 用键盘制造一次旧点借力，确认同方继续；
4. 用方向盘完成一段连续借力；
5. 走到上/下球门，确认正确胜者与胜局；
6. 再踢一场，确认开球策略、清空轨迹和保留会话胜局；
7. 另走困死局面，确认 trap 终局；
8. 复核 intro / playing / complete 焦点和 live region；
9. 检查 1504×1046、390×844、320×760、reduced motion；
10. 用真实 Chrome `file://` 双击路径确认脚本、背景资产、SVG 和完整玩法不依赖服务。
