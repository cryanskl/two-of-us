## 1. 设计任务

具体对象是同一设备前轮流接管的两位玩家。页面的唯一工作，是在不泄露秘密参数的
前提下，让他们看懂当前轮到谁、当前能做什么，以及两颗爱心如何在完整一轮后共同
结算。

体验不是“摧毁对方”。城堡始终完整，命中是把爱心送进对面窗台。视觉必须同时表达：

1. 这是两个人共享的一张纸雕场地；
2. 当前只有一位玩家拥有输入权；
3. 一颗心可以在软垫上反弹一次；
4. 两发结束前比分不会提前变化；
5. 所有规则结果来自冻结逻辑，不来自 Canvas 动画。

生产 UI 只消费 `getPublicView(state)`，不得读取 authority state，也不得自行推导
角度、力度、比分、winner、history、frames、controls 或阶段文案。产品名“这一颗，
绕回来找你”是页面唯一 `h1`；`view.copy.title` 是随阶段替换的 `h2`，两者不能
合并或同时做一级标题。

## 2. 两遍设计结论

### 2.1 第一遍：主题内生方案

| 轴 | 冻结决定 |
| --- | --- |
| 主题 | 一张在暖夜里打开的纸雕立体贺卡 |
| 材料 | 厚纸、折痕、切口、软垫缝线，不用照片、贴图或拟真金属 |
| 色彩 | 5 个品牌色，纸面占主体，莓红只标记爱心和主动作 |
| 字体 | 系统宋体负责标题，系统黑体负责操作，系统等宽体负责角度、力度和比分 |
| 布局 | 顶部轮次与比分，中部 16:9 纸雕战场，桌面两侧是玩家席，下部只有当前动作 |
| 动效 | 只突出当前一颗心的飞行，以及第一次落地时软垫的一次压痕 |
| 记忆点 | 横贯场地的“回弹缝线”：它既是物理地面，也是每轮结果摘要的共同基线 |

桌面初始构图：

```text
┌──────────────────────────────────────────────────────────────┐
│  这一颗，绕回来找你       第 1 / 12 轮       送达目标 3 次  │
├──────────────┬───────────────────────────────┬───────────────┤
│  你 · 0 / 3  │                               │  TA · 0 / 3   │
│  左席状态    │       打开的纸雕贺卡          │  右席状态     │
│              │   城堡 ─── 软垫缝线 ─── 城堡 │               │
│              │       当前爱心与轨迹          │               │
├──────────────┴───────────────────────────────┴───────────────┤
│                 当前阶段标题与唯一主动作                     │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 第二遍：反模板校正

第一遍有三个可能滑向通用游戏页的地方，现已修正：

1. **深色背景加红色按钮**容易成为任意夜间小游戏。修正为深靛只做舞台外的夜幕，
   暖纸承担最大视觉面积；不做霓虹、玻璃拟态或发光边框。
2. **中间大卡片加两侧统计卡**容易成为仪表盘。修正为一张连续展开的纸面，玩家席
   是贺卡左右折页，不是三个彼此悬浮的圆角卡片。
3. **到处飘爱心粒子**会稀释主动作。修正为同一时刻只允许当前弹体、短轨迹点和
   一次软垫压痕；其他爱心只作为静态窗槽轮廓。

设计只在“回弹缝线”上花一次大胆预算。标题、按钮、比分和状态保持安静、直接，
不再加邮票、丝带、星星、纸屑或无限环境动画。

## 3. 视觉令牌

### 3.1 五色系统

首版只创作以下 5 个品牌色：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `ink-night` | `#202A44` | 夜幕、主要文字、深色边界 |
| `paper-warm` | `#F6E3C5` | 贺卡纸面、浅色文字、Canvas 纸雕主体 |
| `heart-berry` | `#A43D5C` | 当前爱心、唯一主按钮、命中强调 |
| `honey-glow` | `#D9A441` | 焦点辅助、胜者窗台、当前轮小标记 |
| `sage-stitch` | `#698573` | 软垫、缝线、已完成和中性辅助状态 |

规则：

- `ink-night` 对 `paper-warm` 承担所有长文本；
- `paper-warm` 对 `heart-berry` 只用于大号按钮文字；
- `honey-glow` 与 `sage-stitch` 不单独承载小号正文；
- hit、miss、当前席和胜负不能只靠颜色，必须同时有文字或形状；
- 阴影、半透明折痕和渐变只能由这 5 色派生，不新增第六个品牌色；
- forced-colors 不保留品牌色，改用 `Canvas`、`CanvasText`、`ButtonText`、
  `Highlight` 和系统边框。

实现前需用真实 CSS 与浏览器对正文、按钮、焦点和禁用态逐项复核 WCAG 2.2
对比度；设计稿中的颜色角色不能替代实测。

### 3.2 字体角色

不下载字体，不依赖某台设备必有的单一字族：

| 角色 | 系统字体栈 | 用法 |
| --- | --- | --- |
| 展示 | `"Songti SC", "STSong", "Noto Serif CJK SC", serif` | 产品名、阶段主标题、终局句 |
| 正文 | `"PingFang SC", "Microsoft YaHei", system-ui, sans-serif` | 规则、说明、按钮、结果 |
| 数据 | `ui-monospace, "SFMono-Regular", "Cascadia Mono", monospace` | `35°`、`10.5`、`2 / 3`、轮次 |

宋体只出现在一、二级标题，避免整页复古。数字使用等宽数字和
`font-variant-numeric: tabular-nums`，比分变化时版面不跳动。

建议字号：

- 产品名：桌面 `clamp(2rem, 3vw, 3.25rem)`，移动端不小于 `1.75rem`；
- 阶段标题：桌面 `1.75rem`，移动端 `1.375rem`；
- 比分：桌面 `2rem`，移动端 `1.5rem`；
- 正文与控件：`1rem / 1.6`，不以 `transform: scale()` 缩小；
- eyebrow 与数据标签：`0.75rem / 1.4`，字距不超过 `0.08em`。

### 3.3 间距、边界与层级

间距只使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64` CSS px。点击目标最小
`48 × 48` CSS px；相邻步进按钮间至少 8px。

纸雕不是圆角卡片集合：

- 外层贺卡用 2px 深靛实线和一条中央折痕；
- 玩家折页只用纸边、折痕和留白分区；
- 操作区可用 8px 小圆角，主舞台不用胶囊轮廓；
- 最多两层静态阴影：贺卡离开夜幕、城堡离开纸面；
- 不用模糊玻璃、发光描边、3D 翻转卡或倾斜透视跟随鼠标。

## 4. 页面信息结构

无论阶段如何变化，DOM 阅读顺序固定为：

```text
skip link
产品标题与一句规则
公开比分和轮次
当前阶段标题、状态、说明
当前阶段专属内容
唯一主动作
公开历史
借鉴声明入口
公开 live region
noscript 说明
```

视觉位置可在桌面把比分折页放到舞台两侧，但 DOM 不因响应式改变语义顺序。
每阶段只挂载自己的专属内容，不能用 `display:none` 保留上一位控件、value、
accessible name、`data-*` 或 Canvas 像素。

顶层稳定区域：

- **产品眉题**：“双人热座对抗”；
- **产品名**：“这一颗，绕回来找你”；
- **规则短句**：“秘密调好两份角度，完整一轮后一起结算。”；
- **比分条**：左右名字、`n / 3`、当前轮 `n / 12`；
- **阶段区**：直接消费公开 DTO 的 `copy` 五项；
- **主动作区**：任一阶段最多一个强调按钮；
- **历史区**：默认折叠为“已完成 n 轮”，展开后只展示已公开摘要。

## 5. 七个权威 phase 与十个可见子态

权威逻辑只有七个 phase，但 handoff、aiming、flying 因席位与公开权限不同，必须
拆成十个可见子态分别设计和验收。app-local privacy cover 与 Canvas failure 另作
覆盖态，不新增 authority phase。

| 可见子态 | 必须出现 | 必须结构性缺失 |
| --- | --- | --- |
| `intro` | 产品标题、教学、公开比分、目标、开始动作 | aim、result、frames |
| `handoff(first)` | 第一位接管者、轮次、中性纸帘 | range、参数形状、当前轮秘密 |
| `aiming(first)` | 第一位新草稿、两个 range、明确值 | sealed aim、result、frames |
| `handoff(second)` | 第二位接管者、中性“已锁 1 份” | 第一位值、方向线、投射姿态 |
| `aiming(second)` | 第二位新草稿、`lockedCount=1` | 第一份 aim、result、frames |
| `reveal-ready` | `lockedCount=2`、中性说明、开始放飞 | 两份参数、预画轨迹、差异化装填 |
| `flying(first)` | 第一位公开参数、第一发 Canvas、继续动作 | 第二份参数、frames、result 或占位 |
| `flying(second)` | 第一发公开摘要、第二位参数、第二发 Canvas | 不存在的未来秘密 |
| `round-result` | 两发摘要、双方增量、联合新比分、下一轮 | frames、第一发提前计分痕迹 |
| `complete(winner/draw)` | 终局类型、最终比分、公开历史、重开 | 当前 shotResults、frames、秘密草稿 |

handoff、aiming 和 reveal-ready 不展开历史，只显示累计公开比分；round-result
显示当前完整轮，complete 才允许展开全部公开历史。

### 5.1 `intro`

显示：

- 两座完整纸雕城堡和空软垫；
- 双方 `0 / 3`、`第 1 / 12 轮`；
- 三条 30 秒教学；
- 主按钮“开始这一局”。

主标题使用逻辑文案“把心投进对方的城堡”。教学固定为：

1. “轮流秘密选择角度和力度。”
2. “每颗心可以在软垫上反弹一次。”
3. “两发都结束后，达到三次并领先的人获胜。”

焦点：进入页先落在产品标题；用户启动后由新阶段接管焦点。

### 5.2 `handoff`

整个战场改画为一张不透明暖纸帘，只保留两座城堡的无参数剪影。纸帘不是覆盖旧
DOM；旧阶段节点和 Canvas 轨迹必须已卸载、清空并从中性场景重画。

显示：

- “第 {round} 轮”；
- “请把设备交给{name}”；
- “上一位的秘密选择不会显示。”；
- 主按钮“我接好了”。

禁止显示：

- 任一角度、力度、滑杆位置或方向线；
- 上一位的 draft、sealed aim、result 或 frames；
- “差一点”“命中”等可反推当前轮参数的提示。

焦点：阶段标题使用 `tabindex="-1"` 接收程序焦点；随后 Tab 到“我接好了”。

### 5.3 `aiming`

贺卡只把当前玩家一侧折页向前突出。对侧仍是无参数城堡，不显示任何输入形状。

控件顺序：

```text
当前玩家姓名
角度：减按钮 / 原生 range / 加按钮 / 当前值
力度：减按钮 / 原生 range / 加按钮 / 当前值
短方向线
“就按这个角度送出去”
```

角度显示如 `35°`，力度显示如 `10` 或 `10.5`。短方向线只表达朝向，不超过发射点
到场地宽度的 12%，不显示落点、命中颜色、虚线抛物线或推荐档位。

每个 range 都有独立可见 label、`aria-valuetext` 和 48px 步进按钮。主按钮与
brainstorm 用语保持一致：“就按这个角度送出去”。

焦点：接管后先落在阶段 `h2`，自然 Tab 的下一站是“角度”range；锁定后立即销毁
草稿控件并进入下一次 handoff。

### 5.4 `reveal-ready`

两份参数均已锁定，但仍是秘密。画面回到中性暖纸帘：

- 左右各显示一个“已锁定”文字标记；
- 不显示档位、方向线、弹体、结果或轨迹；
- 主标题“两颗心都已锁定”；
- 主按钮“让两颗心飞起来”。

“已锁定”只表示数量，不因参数不同改变位置、宽度、颜色或图形。焦点落在阶段标题，
再 Tab 到唯一主按钮。

### 5.5 `flying`

暖纸帘打开，当前公开的一颗心成为唯一运动对象。比分在两发结束前保持上一轮数值。

第一发：

- 显示“第 1 颗 / 共 2 颗”及当前席姓名；
- 公开当前发角度、力度、直接/反弹/miss 结果；
- Canvas 只绘制第一发 frames；
- 不创建第二发参数、摘要、frames 或可访问占位；
- 主动作“播放下一颗”。

第二发：

- 显示“第 2 颗 / 共 2 颗”；
- 上一发只保留一行已公开摘要；
- Canvas 只绘制第二发 frames；
- 主动作“查看本轮结果”。

当前结果文案：

| 结果 | 标题 | 辅助句 |
| --- | --- | --- |
| direct-hit | “这一颗，直接送到了。” | “爱心落进了对面的窗台。” |
| bounce-hit | “绕了一下，还是找到你了。” | “它在软垫上反弹了一次。” |
| second-ground | “这一颗停在软垫上。” | “下一轮可以换一个角度或力度。” |
| horizontal-exit | “这一颗飞出了贺卡。” | “记住这条线，下一轮再试。” |
| top-exit / timeout | “这一颗没有送到。” | “结果已经按固定规则记下。” |

动画完成、跳过和 reduced-motion 都不得改变文案、token 或比分。

### 5.6 `round-result`

战场恢复静态，两座城堡均完整。用同一条软垫缝线承托两发摘要：

```text
你：35° · 10 · 反弹送达    │    TA：40° · 9 · 未送达
本轮 +1                       本轮 +0
────────────────── 完整轮联合结算 ──────────────────
当前比分 2 : 1
```

两发摘要在 DOM 中同时出现，不按播放先后赋予视觉权重。若达到目标但仍同分，显示：

“现在是 {score0} 比 {score1}。还是平局，那就再送一轮。”

主按钮“交换先手，下一轮”。焦点先落在“第 {round} 轮完成”，live region 只播报一次
本轮双方增量和新比分。

### 5.7 `complete`

仍保留两座完整城堡，不出现裂纹、倒塌、烟雾或攻击姿态。

winner：

- 胜者窗台加一条蜜金纸边和文字“先达到目标并领先”；
- 标题使用逻辑生成的“{name}获胜。”；
- 显示最终比分与全部公开历史。

round-cap：

- 两座城堡保持相同权重；
- 标题“十二轮结束，本局平分。”；
- 明确显示 `round-cap` 是完整 12 轮后的平局，不暗示首发或轨迹破平。

主按钮“交换先手，再来一局”。焦点落在终局标题；按钮只有 revision 余量允许时可用。

## 6. 960 × 540 Canvas 舞台

Canvas 逻辑坐标与物理世界一一对应，不另造视觉坐标：

| 元素 | 冻结位置 |
| --- | --- |
| 逻辑画布 | `960 × 540` |
| 左城堡实体 | `x=60..136, y=376..480` |
| 右城堡实体 | `x=824..900, y=376..480` |
| 左发射点 | `(116, 408)` |
| 右显示发射点 | `(844, 408)` |
| 地面实体顶边 | `y=480` |
| 爱心圆心接触线 | `y=472` |
| 圆心活动边界 | `x=8..952, y>=8` |

CSS 只缩放显示尺寸；Canvas backing store 按设备像素比设置，但每一帧先回到
`960 × 540` 逻辑变换。不得用 DOM 尺寸重新积分、碰撞或更改 frame。

Canvas 固定 `aria-hidden="true"`，内部 fallback 文字只在 Canvas 不可用时由相邻
真实 DOM 状态接管。HTML intrinsic `width` / `height` 保持 `960 / 540`，正常 CSS
用流式容器收缩；无 CSS 时必须由语义外壳和 fallback 路径避免 960px 固有宽度在
320px 视口制造横溢，不能只依赖 `max-width: 100%` 作为无 CSS 证据。

### 6.1 绘制层级

从后到前固定为：

1. 深靛到暖纸派生色的静态夜幕；
2. 贺卡上沿和中央折痕；
3. 左右纸雕城堡；
4. `y=480` 的鼠尾草软垫顶边与表面缝线；
5. 当前公开轨迹的稀疏缝点；
6. 当前爱心；
7. 当前事件的一次性压痕或窗台强调。

Canvas 不画玩家名、比分、角度、力度、按钮、结果句或 live 文本。`y=472` 是半径
8px 爱心的圆心接触位置，不绘制成悬空的第二条地面线；爱心底部应恰好接触
`y=480` 的可见软垫。碰撞 AABB 不对玩家显示，但城堡窗台和实体轮廓必须与冻结
命中区域视觉对齐，不能制造“看起来穿过却 miss”的假边界。

### 6.2 原创几何

- 城堡：矩形纸层、两个折角塔顶、一个空心心形窗槽；
- 发射器：一只折纸托臂，不画弹弓、坦克、人物或武器；
- 爱心：两段三次 Bézier 与一个底部尖角；
- 软垫：水平色块、等距短缝和一次局部压缩；
- 轨迹：每隔若干冻结 frame 取一个小缝点，终点使用实线轮廓。

所有几何由 Canvas path 或 CSS 基本形状生成，不引用图片、emoji、图标库、商业
角色轮廓或第三方 SVG。

### 6.3 事件表现

- `flight`：当前爱心沿预生成 frame 移动，轨迹点逐步出现；
- `bounce`：接触位置的缝线向下压 6 逻辑 px 后恢复，只发生一次；
- `hit`：目标窗台由描边变为莓红实心 240ms，不闪白；
- `miss`：爱心停在 terminal frame，DOM 结果句同时出现；
- skip：直接绘制终点、必要的 bounce 点和最终轨迹；
- 后台恢复：不追赶动画，不自动派规则 action，等待用户显式继续。

不得从绘制完成、像素、rAF 次数或 CSS event 判断命中。

## 7. 六档响应式

### 7.1 `1728 × 906` 宽桌面

- 内容最大宽度 1480px，左右至少 32px 夜幕；
- 顶部产品名、轮次、目标在一行；
- 左右玩家折页各约 220px，中间舞台保持 16:9；
- 当前操作区位于舞台下方，两个 range 可同排；
- 历史摘要在最下方，不与舞台争夺首屏。

### 7.2 `1280 × 800` 标准桌面

- 左右折页各 176–192px，中间舞台至少 672px；
- 产品名可占两行，但比分与轮次不覆盖；
- 控件仍在舞台下方，label、range、数值保持四列对齐；
- 页面允许纵向滚动，不压缩 Canvas 比例。

### 7.3 `768 × 1024` 竖向平板

- 顶部产品名、轮次、比分依次堆叠；
- 玩家折页变成 Canvas 上方的左右二列比分条；
- Canvas 使用容器全宽 16:9；
- 操作区移到 Canvas 下方，两个参数各自一行；
- round-result 两发摘要仍可两列，200% text 时自动改为上下排列。

### 7.4 `390 × 844` 移动端

- 页面左右内边距 16px；
- 玩家名允许 12 code points 换行，不省略成无法区分的省略号；
- 舞台宽约 358px、高约 201px；
- 每组步进控件使用 `48px / minmax(0,1fr) / 48px` 网格；
- 主按钮占满内容宽度；
- 两发摘要上下排列，以席位标题而非左右位置区分。

### 7.5 `320 × 568` 最小宽度

- 左右内边距 12px，任何内容不得设置超过容器的固定最小宽度；
- 舞台宽约 296px、高约 166.5px；
- 产品标题与阶段标题自然换行；
- 比分条保持两列，但名字和分数分两行；
- range、减/加和当前值可拆成两行，按钮仍至少 48px；
- 允许纵滚，不允许 `scrollWidth > clientWidth`。

400% zoom 按此档处理，不另写缩放版，也不隐藏规则、结果或主动作。

### 7.6 `844 × 390` 矮横屏

- 使用“舞台 58% + 阶段操作 42%”双列；
- 顶部产品名缩为一行短标识，完整名称仍在文档标题和可访问名称；
- 比分压成舞台上方一条公开栏；
- 操作列允许独立自然增高，整页纵滚；
- 不因高度不足把按钮固定到底部或覆盖 Canvas；
- 系统键盘出现后仍可滚动到当前 range 和主按钮。

横屏规则的优先级高于同宽桌面规则；退出横屏后重新按容器布局，不保留视觉状态。

## 8. 隐私视觉合同

视觉层必须服从公开 DTO，不接触 authority state：

- handoff、aiming(second) 和 reveal-ready 每次都从中性 Canvas 全量重画；
- 不使用离屏 Canvas、CSS 自定义属性、`data-*`、隐藏 input 或缓存 DOM 保存 sealed aim；
- 第一发 flying 不创建第二发的参数、结果、路径、accessible name 或占位节点；
- 第二发 flying 才可创建第二发内容，同时只保留第一发公开摘要；
- 进入 round-result 后销毁全部 frames，只渲染 history 摘要；
- live region 不播报未公开参数；
- focus 顺序不会经过已卸载控件；
- blur、`visibilitychange(hidden)`、`pagehide`、Escape 立刻出现不透明本地遮屏并丢弃
  未锁定草稿；
- 遮屏文案只写“已遮住本轮操作。确认可以继续后重新接管。”，不包含姓名或档位。

privacy cover 不是盖在旧 aiming DOM 上：旧控件先卸载、Canvas 先清空、草稿先销毁，
再创建只含说明和“重新接管”按钮的独立 DOM；程序焦点落在遮屏标题，唯一下一焦点
是恢复按钮。恢复后从 canonical 默认档位创建全新草稿，不恢复旧 range 值。

热座隐私只覆盖正常 UI 交接，不声称抵御开发者工具读取内存。说明页必须如实保留
这一边界。

## 9. 焦点、输入与播报

### 9.1 焦点

- `:focus-visible` 使用至少 3px 外轮廓和 2px offset；
- 品牌模式使用蜜金轮廓配深靛内边，不只改变阴影；
- forced-colors 使用系统 `Highlight`，不得 `outline:none`；
- phase 转换先聚焦新阶段标题，再由 Tab 进入唯一主动作或首个 range；
- skip link 的目标是当前 `main`；
- 动画期间不移动焦点；动画完成也不自动触发下一发。

### 9.2 输入

- range 保留原生键盘语义；
- 减/加按钮文案包含对象，如“角度减一档”，不能只显示无名称符号；
- 触控目标最少 48px，按下态同时有边界和位置反馈；
- pointerdown 只表现按下，不锁定；
- 锁定只响应一次 click/键盘激活；
- 不做拖拽投石器、长按蓄力、双键盘同时输入或倒计时。

### 9.3 live region

只播报已经公开的转换：

- “轮到{name}接管。”
- “{name}正在秘密瞄准。”
- “本轮两份选择已经锁定。”
- “{name}的投射结果已经生成。”
- “第 {round} 轮已经联合结算。”
- winner 或 round-cap 终局。

范围值变化由原生控件自行播报，不复制到 live region；第一位锁定后只播报“请交换
设备”，不能念出其角度和力度。

## 10. 动效与 reduced-motion

正常模式只有一段有意义的编排：

```text
用户显式开始当前发
  → 爱心按预生成 frames 飞行
  → 可选一次软垫压痕
  → terminal frame
  → DOM 结果出现
  → 用户显式继续
```

建议总时长由 `terminalTick` 映射并限制在 900–2200ms；时长只影响观看，不影响
规则。不要加入页面载入逐字、比分滚轮、背景漂浮、按钮呼吸或无限闪烁。

`prefers-reduced-motion: reduce`：

- 不逐帧移动；
- 同一用户动作后立即画起点、可选 bounce 点和终点；
- 软垫不压缩，窗台不闪变；
- DOM 立即显示同一结果；
- 仍由同一个 token 化完成器且至多派一次 `COMPLETE_FLIGHT`；
- 不用淡入淡出延迟信息。

## 11. forced-colors 与高对比

进入 forced-colors：

- 夜幕渐变、阴影、纸张纹理和装饰折痕全部移除；
- 页面、舞台、玩家席和控件使用真实 1–2px 系统边框；
- 当前席增加“当前”文字，不靠蜜金；
- hit / miss 显示“送达 / 未送达”文字和不同线型；
- Canvas 仍为 `aria-hidden`，所有当前参数和结果保留在 DOM；
- 若 Canvas 系统色不可辨，允许隐藏装饰轨迹，但不能隐藏 DOM 结果；
- 焦点使用系统 Highlight，按钮保持原生高对比外观。

Windows High Contrast 下不得用 `forced-color-adjust:none` 强留整套品牌色。

## 12. no-CSS、no-JS 与 Canvas failure

### 12.1 无 CSS

语义 DOM 顺序仍能读懂产品名、规则、比分、阶段标题、label、range、结果和主动作。
不能依靠左右位置表达席位，所有区域有文本标题。每个 render 仍只存在当前子态
DOM；隐私不能依赖纸帘层叠或 `display:none`。Canvas 外壳不得因 960px intrinsic
宽度产生横溢，fallback 文字由相邻 DOM 提供。

### 12.2 无 JavaScript

`noscript` 只显示：

> 这个小游戏需要浏览器运行本地 JavaScript，才能计算两颗爱心的固定轨迹。它不会
> 联网，也不需要安装服务。

无 JS 时不展示假的可操作 range、开始按钮、比分进度或空 Canvas；同时保留作品介绍
和借鉴声明入口。

### 12.3 Canvas 不可用

`getContext("2d")` 返回 null 或抛错时：

- 显示持久状态：“当前浏览器无法显示飞行画面；角度、结果和比分仍会用文字呈现。”；
- 不反复初始化、不报无限错误、不写 console 私密参数；
- aiming 仍可使用 DOM 控件；
- flying 直接使用 reduced-motion 的 DOM 结果路径；
- 用户仍可显式“播放下一颗”或“查看本轮结果”，完成整局；
- 不从缺失的 Canvas 推断 miss，也不改变 frozen ShotResult。

这同时满足“无法观看轨迹”的诚实提示和“无需 Canvas 仍能完成操作”的降级目标。

统一使用：

| hit | 送达 |

| handoff | 把设备交给… |

| lock | 就按这个角度送出去 |

## 14. 明确不做

- 不使用外部字体、图片、音频、图标库、CSS 框架或 ImageGen 资产；
- 不画弹弓、坦克、人物、爆炸、可破坏城堡或商业游戏式关卡；
- 不做玻璃拟态、霓虹 HUD、排行榜面板、拟真物理仪表；
- 不显示完整预测线、落点阴影、命中概率或推荐参数；
- 不做主题切换、模式开关、自定义颜色或自定义物理；
- 不让装饰动画、Canvas 或 CSS 参与规则判断；
- 不用 hidden DOM、透明文字或 CSS 遮盖保存秘密；
- 不自动开始下一发、下一轮或新局。

## 16. 设计自检结论

### 16.1 合同一致性

- 没有新增玩法、物理常量、公开 DTO、状态或 action；
- 每轮仍是秘密瞄准、依次播放、完整轮联合结算；
- winner、延长轮和 12 轮平局表现与逻辑一致；
- Canvas 只消费公开 frames，右席只做显示镜像；
- 第一发不会泄露第二发，阶段节点结构性缺失；
- 视觉不使用商业作品的品牌、角色、弹弓、美术、声音或关卡表达。

### 16.2 两遍设计复核

- 主题来自纸雕城堡、贺卡折页和软垫反弹，不是可替换到任意小游戏的皮肤；
- 已移除玻璃卡、霓虹、统计仪表、粒子雨和散乱微动画；
- 唯一视觉冒险是“物理地面即回弹缝线”，其余元素保持克制；
- 颜色、字体、布局、文案和动效均能从本作规则解释；
- 六档响应式和五类降级都有明确结构，不依赖生产时临场补丁。

本设计可以进入语义 HTML 与 app 实施批次；若实现需要改变任何 authority state、
公开 DTO、Canvas 逻辑坐标或秘密可见时点，应回到规格修订，而不是在 UI 层扩张。
