# Love Tree 视觉自治决策

- 日期：2026-07-25
- 项目：`love-tree`
- 决策：视觉概念不再需要用户逐稿确认，总控可以直接推进生产实现
- 生效范围：`docs/366–368` 定义的 clean-room 重构和“暮蓝纸雕花园”概念

## 1. 用户授权

用户明确说明：

> 这个项目的视觉概念不需要用户确认，你可以直接执行。

因此，`love-tree` 从“等待用户视觉确认”改为“已授权实现”。这项授权仅属于
`love-tree`，不自动批准 `docs/365` 中其他视觉阻塞项目。

## 2. 仍然有效的 Gate

取消的是人工视觉确认门，不是质量门。生产实现仍须：

- 使用原创 HTML、CSS、JavaScript 和 code-native 控件；
- 只继承历史页面可观察的体验目标，不读取、复制或改写旧业务源码、动画参数、
  CSS、商业音乐、文案、压缩包或具体花冠图形；
- 忠实实现“暮蓝纸雕花园”、自然心形花冠、树根展信和桌面/移动构图；
- 完成开始、生长、揭晓、重播、声音开关与 `prefers-reduced-motion`；
- 通过项目测试、A 级直开合同、桌面/移动真实浏览器、键盘/触屏、焦点、
  forced-colors、无脚本降级和控制台检查；
- 用 `view_image` 对照概念与最终浏览器截图，并形成 fidelity ledger；
- 记录实际 bug、可复用 learn 和借鉴声明；
- 每个独立阶段分别提交。

## 3. 历史文件边界

当前授权允许直接实现和切换到不依赖旧代码的新入口，但不把“无需视觉确认”解释为
删除历史文件的授权。旧源码、商业音频和源包的物理删除仍按当前消息授权与 Git
安全规则单独处理。

## 4. 覆盖关系

本文覆盖 `366–368` 和概念台账中所有“必须等待用户视觉确认”的暂停语句。那些语句
继续保留为当时的流程证据；从本决策起，生产实现可以直接开始。

## 5. 借鉴声明

本文件只记录用户授权，不新增开源参考、第三方代码、图片、字体、声音或素材。
