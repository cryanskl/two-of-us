# 创意池 V20“蜂巢封路”定向调研：封路，但不能断路

- 调研日期：2026-07-24
- 对应创意：[`40-idea-backlog.md`](./40-idea-backlog.md) 的创意池 V20“蜂巢封路”
- 稳定工作 ID：`honeycomb-passage`
- 暂定体验名：`蜜径相逢`
- 建议目录：`experiences/versus/honeycomb-passage/`
- 建议启动等级：A（双击 `index.html`，无安装、服务、权限或公网）
- 本轮范围：候选审计、全网调研、brainstorm、来源与许可证复核；不创建生产目录

## 1. 结论

V20 适合成为下一款双人对抗作品。推荐进入规格的版本不是 Hex 换皮，也不是把
Quoridor 的方格和栅栏改成蜂巢，而是一个独立的“移动或封蜡”竞速：

- 棋盘是半径 3 的六角形蜂巢，共 37 格；
- 两枚棋子从左右尖端出发，各自争先抵达对面的任意边缘格；
- 每回合只能二选一：移动到相邻空格，或消耗 1 枚封蜡把一个空格永久封住；
- 每人只有 4 枚封蜡；
- 任何封蜡落下后，都必须让**双方**仍各有至少一条通向自己目标边的路线；
- 棋子不能跳过、交换或占据同一格；
- 第 16 个完整回合后仍无人抵达，则比较到目标边的最短剩余距离，再比较剩余
  封蜡；仍相同即平局。

核心闭环是：

```text
移动一格，缩短自己的路线
             ↘
              对手改道
             ↗
封住一格，但必须保留双方至少一条路
```

“不能把任何一方彻底封死”不是提示层约定，而是规则层合法性。每次候选封蜡都
在新棋盘上分别运行两次 BFS；只有两个目标仍可达，状态才允许推进。这是它相对
仓库现有路径游戏最清晰的机制增量。

## 5. Brainstorm：四种方向

| 方向 | 核心规则 | 结论 |
| --- | --- | --- |
| 六角连边棋 | 双方轮流落自己的颜色，先连接两边 | 排除；与 Hex 的标志性目标和仓库外部候选过近 |
| 方格栅栏赛跑 | 棋子移动或在格线之间放长墙，可以跳过对手 | 排除；会靠近 Quoridor 的棋盘、墙体与跳跃组合 |
| 蜂巢实时追逐 | 两人同时移动，走过的格子永久封闭 | 排除；与 `light-trail-hunt` 的实时留痕机制重复 |
| 六角竞速 + 占格封蜡 | 轮流移动或封住整格，封蜡必须保留双方路径 | **采用**；规则独立、触控自然、纯函数可穷举 |

采用方向保留“封路”的对抗张力，但明确不给玩家“彻底堵死对方”作为胜法。好的
封蜡应迫使对方绕路，也可能收窄自己的未来路线；胜负最终仍由棋子抵达目标决定。

## 6. 建议冻结的最小规则

### 6.1 棋盘与坐标

使用轴坐标 `(q, r)`，并以 `s = -q-r` 表示第三轴。半径 3 的合法格满足：

```text
max(abs(q), abs(r), abs(s)) <= 3
```

六个邻居由固定方向向量派生。棋盘共 37 格，不能用渲染后的像素位置反推逻辑
邻接。黄色棋子从 `(-3, 0)` 出发，目标是任意 `q = 3` 的边缘格；紫色棋子从
`(3, 0)` 出发，目标是任意 `q = -3` 的边缘格。

起点只是初始位置，不是必须保持开放的“家门”。棋子离开后，该格可在后续被
封蜡，只要封蜡后的双方可达性仍合法。

### 6.2 两种行动

每个半回合，当前玩家必须选择一个合法行动：

1. `MOVE(target)`：走到与当前格相邻、未被封蜡且未被另一枚棋子占据的格；
2. `SEAL(target)`：若自己仍有封蜡，把任意未封蜡且未被棋子占据的格永久封住。

首版不提供跳跃、推挤、交换、连续移动、斜跨、拆墙、移动封蜡、传送、技能卡或
撤销。选择行动模式后只需单击目标格，不要求拖拽。

### 6.3 封蜡合法性

候选 `SEAL` 必须经过同一条规则管线：

```text
candidateBlocked = blocked ∪ { target }
yellowHasPath = BFS(yellowPosition → any q=3, candidateBlocked)
purpleHasPath = BFS(purplePosition → any q=-3, candidateBlocked)
legal = yellowHasPath && purpleHasPath
```

路径检查：

- 把永久封蜡当作不可通行；
- 从当前棋子位置开始；
- 棋子本身所在格始终可作为 BFS 起点；
- **忽略另一枚棋子的临时占位**，因为对手下回合可能移动，不应被当成永久墙；
- 不要求路径是当前最短路，也不替玩家自动选路。

实际 `MOVE` 仍禁止进入对手所在格。由此区分“永久路线存在”与“本回合这个格能否
落脚”两个问题。

### 6.4 回合、终局与僵局

建议常量：

```text
BOARD_RADIUS = 3
STARTING_SEALS = 4
MAX_ROUNDS = 16
```

- 黄色先手；每当紫色行动结束，完整回合数加 1；
- 棋子移动到自己的目标边后立即获胜；
- 若轮到某人时既没有合法移动，也没有合法封蜡，另一方获胜，原因记为
  `immobilized`；
- 第 16 个完整回合结束仍无人抵达，分别用 BFS 计算两人当前到目标边的最短距离；
- 距离更短者胜；若相同，剩余封蜡更多者胜；仍相同即平局；
- 不以先手身份、历史移动数、像素位置或动画完成先后作为隐藏 tie-break。

回合上限不是倒计时：后台停留、设备性能和减少动态效果均不能改变剩余回合。
“抵达立即获胜”保留了直观竞速感；未来若实测发现先手优势明显，应另做交换先手
的两局制，而不是在首版暗加补偿资源。

## 7. 状态机与纯逻辑建议

```text
intro
  └─ START → playing
playing
  ├─ SELECT_MODE(move/seal) → playing
  ├─ ACT(target, legal) → playing / result
  ├─ ACT(target, illegal) → same state
  └─ no legal action / round cap → result
result
  └─ RESTART → intro
```

建议权威状态：

```js
{
  phase,
  activePlayer,
  round,
  selectedMode,
  players: [
    { position: { q, r }, sealsRemaining },
    { position: { q, r }, sealsRemaining }
  ],
  blockedKeys,
  history,
  result,
  revision
}
```

公开逻辑 API 最少包括：

- `createBoard(radius)`、`getNeighbors(cell)`、`isCellOnBoard(cell)`；
- `findShortestDistance(board, start, goal, blockedKeys)`；
- `hasRouteForBoth(state, candidateSeal)`；
- `getLegalMoves(state)`、`getLegalSeals(state)`、`getLegalActions(state)`；
- `move(state, target)`、`seal(state, target)`；
- `createInitialState(config?)`、`start(state)`、`restart(state)`；
- `getPublicView(state)`。

所有公开输入必须先正规化：拒绝未知键、getter、副作用原型、`NaN`、浮点坐标、
数组伪装、越界格和重复封蜡。状态、历史、view、棋盘与返回集合递归冻结，并与
调用方对象断开可变引用。合法状态上的非法行动返回同一引用，不增加 revision。

历史至少记录行动前后位置、封蜡库存、目标格、完整回合数和终局原因。规格与测试
应要求从初始状态顺序重放历史能重建当前棋盘，而不是把 DOM 当成真实状态。

## 8. 可测试性与穷举边界

半径 3 只有 37 格，首版不需要 A* 或第三方寻路库。BFS 最多访问 37 个节点；一次
枚举所有封蜡候选，即使对双方各跑一次 BFS，规模仍很小，正确性比微优化重要。

核心测试至少覆盖：

- 棋盘恰有 37 个唯一格，每个格的邻居数量符合角/边/内部位置；
- 两位玩家的目标边、起点和距离完全镜像；
- 初始最短距离均为 6；
- 移动只允许六邻接空格，不能跳过对手或进入封蜡；
- 合法封蜡同时减少库存、切换玩家并写入历史；
- 会切断任一方最后路线的封蜡被拒绝，状态引用和 revision 不变；
- BFS 可达性忽略对手临时占位，但 `MOVE` 不忽略；
- 库存为 0 时没有 `SEAL`；
- 到边立即胜、无行动判负、16 回合距离判定、封蜡库存 tie-break 和平局；
- 双方镜像状态经玩家/坐标镜像后，合法行动集合也镜像；
- `restart` 与首次加载深相等；
- 生产同源规则在可控状态空间内枚举，不出现“无结果且无合法行动”的悬空状态。

完整博弈树仍会随封蜡组合增长，不把“穷举所有可能对局”作为首版门槛。应穷举
棋盘几何、单步行动、关键封路夹具和镜像性质，再用固定种子的合法随机游走覆盖
长历史；随机只用于开发测试，不进入运行时规则。

## 9. 单设备交互、无障碍与生命周期

- 棋盘格使用原生 `<button>` 或具备等价按钮语义、名称和键盘处理的 SVG 控件；
- 每格可访问名称包含坐标、状态，以及在当前模式下“可移动 / 可封蜡 / 不合法”的
  原因，不能只靠黄色、紫色或蜂蜡纹理；
- 移动与封蜡是两个明确的模式按钮，当前模式用文字和 `aria-pressed` 同步表达；
- 不合法封蜡应在预览和状态消息中解释“会让一方无路可走”，不能静默吞掉点击；
- 触控目标按 W3C WCAG 2.2 的 24×24 CSS px 最低要求校准，桌面优先做到 44×44；
- 所有功能可单击完成，不把拖拽设为唯一方式；
- 行动后焦点移动到新棋子格或稳定的回合标题，不能落在已禁用的目标上；
- 状态区只播报一次“谁走到哪里 / 谁封住哪里 / 为什么拒绝 / 谁获胜”，不在焦点
  浏览每格时反复播报整盘；
- `prefers-reduced-motion: reduce` 下取消棋子滑动、蜂蜡铺开和胜利脉冲；
- `blur`、`visibilitychange`、`pagehide` 不自动行动、不扣回合、不宣告超时；
- 表现动画只消费已经提交的状态，`animationend` 不能成为切换玩家的规则条件。

## 12. 风险与进入规格的决策

| 风险 | 影响 | 规格阶段必须冻结的处理 |
| --- | --- | --- |
| 规则被误认成 Hex/Quoridor 换皮 | 原创性与借鉴说明不清 | 保持 37 格六角盘、移动棋子、占格封蜡、无跳跃；不使用其名称和视觉 |
| 一枚封蜡意外断路 | 对局进入无解状态 | 每次候选封蜡对双方各跑 BFS，规则层拒绝 |
| 双方循环移动 | 对局不结束 | 16 个完整回合上限 + 公开 tie-break |
| 对手临时占位被误当永久断路 | 合法封蜡被错误拒绝 | BFS 忽略对手，实际移动禁止重叠 |
| 先手优势 | 对抗公平感下降 | 首版承认固定先手；测试镜像，浏览器试玩后再决定是否做交换先手两局制 |
| 蜂巢格触控过小 | 手机误触 | 37 格上限、单击操作、明确模式、最低 24px 且目标 44px |

结论：进入独立规格，但规格必须先用纯逻辑夹具证明路径保全、镜像关系、终局与
16 回合收敛，再创建生产 UI。研究提交不把“可做”写成“已经实现”。
