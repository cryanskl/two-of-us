# 「光轨围猎」视觉设计与提取清单

> 视觉方向已通过 ImageGen 完整屏幕概念验证；实现契约见 [`76-light-trail-hunt-spec.md`](./76-light-trail-hunt-spec.md)。概念用于构图、色彩、密度和质感校准，不把生成图直接当作网页截图复刻。

## 1. 已接受概念

- [桌面进行态 1504×1046](../design/light-trail-hunt/desktop-playing.png)；
- [手机进行态 852×1846](../design/light-trail-hunt/mobile-playing.png)，纵横比对齐 390×844，实际尺寸以浏览器验收为准；
- [桌面平局态 1504×1046](../design/light-trail-hunt/desktop-draw.png)；
- [原创棋盘纸张纹理 1536×1024](../experiences/versus/light-trail-hunt/assets/board-texture.webp)。

三张主概念全部采用“午夜制图桌”方向：深靛蓝绘图纸、低对比黄铜坐标线、暖白字、青绿与珊瑚光墨。它与传统霓虹摩托视觉的距离足够大，也能在纯 Canvas 2D 中稳定实现。

## 2. 核心布局

### 2.1 桌面进行态

```text
┌────────────────────────────────────────────────────────┐
│ 光轨围猎        小满 1 — 0 阿昼        第 2 / 3 轮     │
│ 别追光，去改写它的边界。               围猎进行中       │
├──────────────────────────────────────┬─────────────────┤
│                                      │ 制图笔记         │
│            3:2 主棋盘                │ 两条短规则       │
│                                      │ 玩家图例         │
├──────────────────────────────────────┴─────────────────┤
│ 小满 A/D             暂停             阿昼 ←/→·J/L     │
└────────────────────────────────────────────────────────┘
```

- 页面最大内容宽度 `1424px`，左右安全边距至少 `32px`；
- 主棋盘桌面目标宽 `min(900px, 68vw)`，保持 `3:2`；
- 制图笔记栏只保留两条规则和双玩家图例，不照搬概念稿的长说明；
- 键位说明位于棋盘下方，暂停按钮在视觉中心；
- 背景装饰不使用真实尺子、圆规图片，以 CSS 细线和少量角标替代。

### 2.2 手机进行态

```text
┌──────────────────────┐
│ 光轨围猎             │
│ 小满 1—0 阿昼        │
│ 第 2/3 轮 · 进行中   │
├──────────────────────┤
│       3:2 棋盘       │
├──────────┬───────────┤
│ 小满     │ 阿昼      │
│ [1 ↶][1 ↷]│[2 ↶][2 ↷]│
│ A / D    │ ←/→·J/L  │
├──────────┴───────────┤
│        暂停          │
└──────────────────────┘
```

- `390px` 下页面内边距 `12px`，棋盘约 `366×244px`；
- 两组控制各占一半，组间用 1px 黄铜竖线和 12px 间隔；
- 四按钮 `56×56px`，显示玩家编号、方向箭头和完整 aria-label；
- `320px` 下按钮降到 `48×48px`，棋盘约 `296×197px`；
- 手机不显示桌面制图笔记栏；
- 标题、比分、轮次压缩为三行，不能让视觉装饰抢走纵向空间。

### 2.3 终局态

- 桌面把结果放在棋盘右侧，棋盘保留完整 fatal tick；
- 手机把结果放在棋盘下方，不能覆盖触控区或主按钮；
- 结果标题是真实 DOM，例如“同时撞线，平局”；
- 碰撞短因是“同格相撞 · 双方不得分”；
- 概念稿中的“再看这一局”不进入首版：输入日志已经保留，但本规格未定义回放控制；
- 首版只提供“下一轮”或“重新比赛”，避免虚假按钮和额外状态。

## 3. 设计令牌

```css
:root {
  --paper-950: #071523;
  --paper-900: #0a1c2d;
  --paper-850: #10263a;
  --ink-warm: #ead7ad;
  --ink-muted: #a9936a;
  --brass: #9a7644;
  --brass-dim: rgba(154, 118, 68, 0.34);
  --cyan: #66dfd3;
  --cyan-dim: rgba(102, 223, 211, 0.22);
  --coral: #ff805d;
  --coral-dim: rgba(255, 128, 93, 0.22);
  --danger: #ffc069;
  --focus: #fff1c8;
  --shadow-ink: rgba(0, 0, 0, 0.32);
}
```

### 3.1 字体

- 不下载或嵌入生成稿中的书法字体；
- 标题：`STSong, Songti SC, Noto Serif SC, serif`；
- 正文：`system-ui, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif`；
- 键位与比分数字：`ui-monospace, SFMono-Regular, Menlo, monospace`；
- 字号下限：正文 14px、触控按钮 18px、状态 14px；
- 行高下限 1.35。

### 3.2 线条与圆角

- 页面主分隔线：1px `--brass-dim`；
- 棋盘外框：1px `--brass`，内侧再加 1px 低透明线；
- 棋盘逻辑网格：1 device pixel、低于轨迹 4 倍以上对比；
- 按钮圆角 `2px` 或切角，不使用胶囊和大圆角卡片；
- 焦点环：2px `--focus`，offset 3px；
- 轨迹端帽为 round，但玩家 2 头部是菱形。

## 4. Canvas 绘制清单

从后向前绘制：

1. `board-texture.webp` 以 `cover` 铺在 Canvas CSS 容器背景；
2. Canvas 清屏为透明；
3. 绘制 `48×32` 的程序网格，垂直与水平线使用相同逻辑间距；
4. 绘制双方所有已提交轨迹；
5. 绘制当前头部；
6. fatal tick 绘制尝试位置和碰撞震点，但不把尝试格加入轨迹；
7. 可选绘制最近一格的短余辉；
8. reduced motion 下取消余辉呼吸和震点扩散。

玩家区别：

- 玩家 1：青绿色实线，每隔 4 个格出现短横纹，头部为带缺口圆环；
- 玩家 2：珊瑚实线，每隔 4 个格出现短斜纹，头部为菱形；
- 轨迹主线宽约格宽的 `0.22`，最小 2px、最大 7px；
- 光晕只允许一层低透明 shadow blur，不做多层霓虹；
- 碰撞点为 6–10 条短放射线，不持续闪烁。

## 5. 阶段视觉

| 阶段 | 棋盘 | DOM 主内容 | 主操作 |
| --- | --- | --- | --- |
| `ready` | 两个出生点与极短引线 | 标题、两句规则、键位 | 开始围猎 |
| `countdown` | 出生点保持 | 大号 3 / 2 / 1，状态 live region | 无 |
| `playing` | 完整实时轨迹 | 比分、轮次、状态 | 暂停、四转向按钮 |
| `paused` | 保留画面、轻降对比 | “制图暂停”与原因 | 继续 |
| `round-end` | 保留碰撞证据 | 本轮结果、短因、比分 | 下一轮 |
| `match-end` | 保留最后一轮 | 比赛结果、最终比分 | 重新比赛 |

暂停只降低棋盘对比度，不使用模糊；模糊会妨碍两位玩家讨论刚才的路线。

## 6. 允许文案

必须按以下文本实现，不能复制概念稿的偶发字形错误：

- H1：`光轨围猎`；
- 副标题：`别追光，去改写它的边界。`；
- ready：`两束光同时出发。左转或右转，别撞上任何旧轨。`；
- playing：`围猎进行中`；
- manual pause：`制图暂停`；
- hidden / blur：`离开页面，已为你们暂停`；
- stalled：`时间间隔过长，已安全暂停`；
- same destination：`同时撞线，平局`；
- head swap：`迎面换位，平局`；
- both dead：`同时熄灭，平局`；
- winner：`{name} 留住了这片边界`；
- draw support：`这一局谁也没抢走边界。`；
- start：`开始围猎`；
- pause：`暂停`；
- resume：`继续`；
- next：`下一轮`；
- restart：`重新比赛`。

不使用 eyebrow、营销口号、玩法标签胶囊、虚构联网状态或“AI 对手”等文案。

## 7. 原创资产

### `board-texture.webp`

- 来源：本项目 ImageGen 生产资产；
- 尺寸：1536×1024；
- 格式：WebP，约 31KB；
- 用途：棋盘 CSS 背景；
- 不承担坐标、边界或碰撞逻辑；
- 无文字、图标、轨迹、地图、字体或第三方标志；
- 加载失败时回退为 `--paper-900` 纯色与程序网格，玩法不受影响。

其他线条、图标、头部标记和 favicon 均使用原创 CSS / SVG / Canvas 几何，不引入外部素材。

## 8. 概念稿 fidelity ledger

实现后至少逐项对照：

1. 深靛蓝纸张质感与低对比黄铜网格；
2. 青绿缺口圆环与珊瑚菱形的双重身份区分；
3. 棋盘在桌面和手机都保持视觉主导；
4. 桌面比分、轮次与状态形成单条清晰信息带；
5. 手机四按钮按玩家左右分组且可同时按；
6. 暂停按钮不抢夺主视觉；
7. 终局保留碰撞现场，结果不覆盖棋盘；
8. 黄铜边线、暖白字与极小圆角共同维持制图桌质感；
9. 无紫粉渐变、玻璃卡片、胶囊或电影视觉借用；
10. 320px 下仍保留核心层级，不为装饰引入横向滚动。

## 9. 预先接受的刻意偏离

- 生成稿包含复杂圆规、尺子和地图角饰；真实页面只保留少量 CSS 刻线，降低资产重量与视觉噪声；
- 生成稿使用手写 / 书法质感字体；真实页面使用系统字体，保证离线、跨平台和中文缺字回退；
- 手机概念是 852×1846 高分辨率稿；浏览器实现以 390×844 和 320×700 的 CSS 像素 Gate 为准；
- 生成稿棋盘展示的格数是视觉近似；真实 Canvas 必须严格绘制 48×32；
- 终局概念的“再看这一局”暂不实现，因为首版规格没有定义回放 UI；
- 概念稿中的描述性长文缩短为两条规则，避免桌面笔记栏变成说明书。

## 10. 浏览器对照要求

- 截图必须使用原生目标 viewport，不缩放后伪装；
- 同一轮 QA 中同时查看已接受概念原图与最新浏览器截图；
- 记录 above-fold 文案逐字差异；
- 记录至少 5 项 fidelity ledger 和所有刻意偏离；
- 真实操作一次键盘和一次双 Pointer，再判断画面是否成立；
- 临时截图存放于系统临时目录，验收结束后不留在仓库。
