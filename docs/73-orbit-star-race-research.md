# A 级「轨道抢星」定向调研

> 调研日期：2026-07-18。目标是把创意池 V07「轨道抢星」收敛为一个可双击、无公网依赖、两人同机同时操作，并能用确定性状态机验证的短局对抗作品。

## 1. 选题结论

下一件作品采用：

- 作品名：**这一颗我先到**；
- 目录 ID：`orbit-star-race`；
- 主分类：双人对抗；
- 启动等级：A，直接双击本目录 `index.html`；
- 设备：一台电脑、平板或手机，两人同时操作；
- 核心动作：两颗卫星沿相反方向自动前进，双方只能逐层升轨或降轨；低轨更快、高轨更慢，在正确时机切回目标星所在轨道完成拦截；
- 首版边界：三层圆轨、共享星流、先得五颗且比分不相等者胜；同一步完全同时命中时双方共享，必要时加赛；不做真实航天模拟、自由推力、碰撞伤害、AI、联网、长期战绩或轨道编辑器。

当前对抗目录已有抢按、连续拉动、止盈、算式、图路径、顺序记忆、线框占地和局域网棋类，但没有“自动运动 + 只改变速度层级 + 同一目标竞争”的样板。它的核心可以在 30 秒内解释，去掉音频和私人图片后仍成立，也不要求服务或第三方运行依赖。

## 2. 物理事实与产品化边界

NASA 对开普勒第三定律的说明是：轨道周期平方与半长轴立方成正比，写作 `T² ∝ a³`；因此轨道越大，完成一圈所需时间增长得越快。对同一中心天体的圆轨道，可以把它改写为：

```text
T ∝ r^(3/2)
ω = 2π / T ∝ r^(-3/2)
```

这给游戏提供一个可信而清楚的方向：**降到内轨会更快，升到外轨会更慢**。本作只使用三个离散圆轨和归一化比例，不计算引力、质量、速度矢量、偏心率、燃料或转移轨道，也不声称是航天训练软件。

一手依据：

- [NASA Science：Orbits and Kepler’s Laws](https://science.nasa.gov/solar-system/orbits-and-keplers-laws/)；
- [NASA Goddard：Kepler’s Third Law applied to Earth satellites](https://imagine.gsfc.nasa.gov/descriptions/kepler3.html)；
- [NASA JPL Education：Exploring Exoplanets with Kepler](https://www.jpl.nasa.gov/edu/resources/lesson-plan/exploring-exoplanets-with-kepler/)。

三份资料只用于确认公开物理关系与表述边界，不复制教学图片、视频、课件、数据表或练习题。

## 3. 三层速度模型

首版使用归一化半径：

```text
rings = [0.82, 1.00, 1.22]
baseAngularSpeed = 0.60 rad/s
angularSpeed(r) = baseAngularSpeed × r^(-3/2)
```

近似结果：

| 轨道 | 归一化半径 | 角速度（rad/s） | 一圈约需 |
| --- | ---: | ---: | ---: |
| 内轨 | 0.82 | 0.81 | 7.8 秒 |
| 中轨 | 1.00 | 0.60 | 10.5 秒 |
| 外轨 | 1.22 | 0.45 | 14.1 秒 |

这些数值是游戏节奏参数，不对应真实公里或真实秒。双方使用同一速度表，但朱方顺时针、蓝方逆时针；差异只来自当前位置、当前轨道和玩家的切轨时机。

## 4. 玩法候选比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 完整牛顿引力 + 自由推力 | 物理表达丰富 | 首局难懂，数值积分和触控复杂，容易变成单人模拟器 | 不采用 |
| 椭圆轨道 + 远近点变速 | 更接近开普勒第二定律 | 画面读数和拦截判断负担过高 | 首版不采用 |
| 三层圆轨 + 自动前进 | 一眼能看懂内/中/外速度差，只需上下两键 | 必须防止瞬间连续跨层 | 采用 |
| 星星限时消失 | 增加紧张感 | 双方都错过会拖长或产生运气惩罚 | 不采用；目标保留到被捕获 |
| 单星共享目标 | 竞争关系直接，碰撞判定唯一 | 新星生成瞬间可能偏向某人 | 采用，并加入公开预告阶段 |
| 多星同时存在 | 路线选择更多 | 小屏信息过载，结算与公平性更难解释 | 首版不采用 |

每颗新星先公开预告 0.8 秒，期间双方仍可移动但不能得分；预告结束后，卫星与目标处于同一轨道且角距离进入捕获窗口才得分。捕获后短暂停顿并展示下一颗星；先得五颗且比分不相等者获胜，若双方同一步共享目标并同时达到五颗，则继续刷新加赛星。

## 5. 输入与公平边界

- 朱方使用 `W / S`，蓝方使用 `↑ / ↓`；手机提供左右两组“升轨 / 降轨”原生按钮；
- 每次合法输入只移动一层，按键 repeat 被忽略；切轨后有约 0.25 秒锁定，不能一口气从最内跳到最外；
- 角运动使用固定 `1 / 120` 秒步长，浏览器帧只负责累计时间与绘制；
- 两人同一步都进入捕获窗口时，先比较角距离；距离近者得星；差值低于明确 epsilon 时只生成一个共享 claim，双方各加一分；
- 星流由开始时注入的非零 32 位 seed 逐颗派生；逻辑层不直接调用 `Math.random`，测试可以传入固定 seed 和输入日志；
- 页面失焦或隐藏时不补算大段时间，返回后从当前画面继续，避免切回标签页直接结束一局。

这不是现实世界的卫星相撞：两位玩家可以在同一轨道互相穿过，碰撞只发生在卫星与共享星之间。

## 7. 本地实现与视觉边界

- 使用经典脚本、原生 DOM/CSS 与 `requestAnimationFrame`，作品目录可单独复制并通过 `file://` 运行；
- 逻辑状态只保存 seed、规范角度、离散轨道、冷却步数、当前星索引、claim 日志、阶段和固定步计数；分数、当前星与视图位置由这些事实派生，CSS transition 不拥有规则时间；
- 轨道与命中区由代码原生几何表达，卫星、星体和背景使用本项目生成的本地无字资产；文字、按钮、分数和状态保持 DOM 原生；
- 星星用位置、编号、形状和文字状态表达；比分不只依赖朱红/靛蓝颜色；
- `prefers-reduced-motion` 关闭拖尾、闪烁和装饰过渡，但保留玩法必需的轨道位置更新；
- 不保存比赛，不读取账户，不请求网络，不使用 Cookie、localStorage、远程字体、远程音频或 CDN。

## 8. 风险与验证 Gate

| 风险 | Gate |
| --- | --- |
| 不同帧率产生不同赢家 | 相同固定步输入在多种渲染帧分组下得到同一状态与捕获者 |
| 内轨速度方向写反 | 三层角速度严格单调递减，并对照 `r^(-3/2)` 测试 |
| 长帧或切回标签页跳过整局 | app 限制每帧累计量，hidden/blur 清空 accumulator，不补算离开时间 |
| 连续按键瞬间跨三层 | 忽略 repeat；冷却期间切轨动作保持同一状态引用 |
| 双方同时触星固定偏色 | 先按角距离，epsilon 内生成一次共享 claim，双方各加一分 |
| 新星生成在某人身上 | 0.8 秒公开 preview，preview 阶段禁止捕获 |
| 星流不可测试或偏斜 | 注入非零 32 位 seed；同 seed 与输入日志必须重放同一星流与 claim |
| 手机控制遮挡轨道 | 390px 与 320px 实测舞台、四个 48px 按钮、无横向溢出 |
| 动画成为规则时钟 | 终局、捕获与冷却只由固定步状态决定，reduced motion 轨迹相同 |
| 参考项目许可混淆 | README 固定四个 commit，逐项写许可证、素材边界与零复制声明 |

## 9. 借鉴声明结论

作品 README 与 `assets/ATTRIBUTION.md` 必须明确：

1. NASA/JPL 资料用于确认开普勒关系与科学表述边界，资料图片、视频、数据表和练习没有进入运行时；
2. 四个开源仓库只用于比较真实模拟、少输入轨迹、同机键区、构建复杂度和许可证义务，没有复制、改写、链接或引入代码、公式实现、依赖、视觉、音频、字体、SVG 或纹理；
3. 三层速度表、反向运动、先到五颗与共享加赛、预告 Gate、同时捕获裁决、中文文案、状态机、DOM、CSS 与测试均由本仓库原创；
4. ImageGen 生成的概念、背景、卫星与星体资产单独记录生成日期、用途、提示词边界和无图回退；
5. 作品是受开普勒关系启发的街机对抗，不冒充轨道预测软件或航天教学模拟器。
