# Two of Us：仓库分类与内容收录规范

## 1. 目标

把仓库整理成一个面向情侣、夫妻和伴侣的轻量互动 HTML 集合。每个已收录作品都应尽可能满足：

- 本地打开即可体验；
- 不要求注册账号；
- 不依赖远程数据库；
- 玩法、人数和启动方式清晰；
- 第三方代码的来源与许可证可追溯。

## 2. 主分类

| 目录 | 中文分类 | 参与方式 | 典型内容 |
| --- | --- | --- | --- |
| `experiences/surprises/` | 单人惊喜 | 一个人制作或配置，另一人体验 | 情书、纪念日、回忆时间线、照片故事、寻宝 |
| `experiences/co-op/` | 双人合作 | 两个人共同完成目标 | 你画我猜、默契问答、协作拼图、共同故事 |
| `experiences/versus/` | 双人对抗 | 两个人比较分数或争夺胜负 | 井字棋、五子棋、反应挑战、桌面冰球 |

现有 `love-tree` 归入 `experiences/surprises/love-tree/`。

## 3. 辅助标签

主分类之外，每个作品的 README 使用下列标签描述差异：

- **设备**：`单设备同屏`、`单设备轮流`、`双设备`；
- **输入**：`鼠标`、`触屏`、`键盘`、`摄像头`、`麦克风`；
- **时长**：`1–3 分钟`、`5–15 分钟`、`15 分钟以上`；
- **定制量**：`无需定制`、`改配置`、`替换素材`、`修改源码`；
- **隐私**：`纯本地`、`可选联网`、`必须联网`；
- **状态**：`已收录`、`待实现`、`仅作灵感`。

## 4. 离线等级

| 等级 | 启动条件 | 是否优先收录 |
| --- | --- | --- |
| A | 双击 `index.html` 即可运行 | 是，最高优先级 |
| B | 不需编译，但要先本地化外链资源或运行本地静态服务器 | 是 |
| C | 首次需要安装依赖和构建，产物可离线运行 | 谨慎 |
| D | 依赖远程 API、账号、WebSocket 服务或数据库 | 不直接收录，只记录灵感 |

## 5. 单个作品的标准结构

```text
experiences/<category>/<slug>/
├── index.html          # 体验入口
├── README.md           # 玩法、启动、定制、来源与许可证
├── assets/             # 当前作品独占资源（可按需拆 css/js/audio/images）
└── preview.*           # 可选预览图或短视频
```

第三方库如果只服务于一个作品，跟随该作品保存；确认有多个作品共用后，才迁入 `shared/`。这样可以保证复制单个目录后仍然可以独立运行。

## 6. 第三方项目收录门槛

必须逐项确认：

1. 有直接源码地址，而不是只有在线试玩页；
2. 许可证允许复制、修改和再分发；
3. 外链字体、脚本、图片和音频已识别；
4. 不在源码中携带密钥、统计代码或个人数据；
5. 已在断网或等效环境验证启动方式；
6. README 保留原作者、源项目、许可证和本仓库修改说明。

没有许可证的公开源码不得直接复制进仓库，只能收录在调研文档的“灵感”部分。

- 把现有 love tree 按上述结构归档；

- 不统一改写现有 love tree 的旧版依赖。

## 8. 验收标准

- 根 README 能在一分钟内说明仓库定位、目录与使用方式；
- love tree 从新路径打开后，脚本、样式、音频引用不丢失；
- 调研文档至少包含三大分类，并将“可直接引入”和“仅作灵感”分开；
- 每个有源码的重点候选都包含可点击来源与许可证判断；
- 所有 Markdown 相对链接可解析，Git 工作区只包含本任务相关改动。
