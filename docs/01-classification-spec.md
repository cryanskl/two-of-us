# Two of Us：仓库分类与内容收录规范

## 1. 目标

把仓库整理成一个面向情侣、夫妻和伴侣的本地优先互动体验集合。作品可以是纯 HTML，也可以使用本地服务器、局域网或本地模型。每个已收录作品都应尽可能满足：

- 在声明的本地启动等级下可完整体验；
- 不要求注册账号；
- 默认不依赖公网服务，不上传私人内容；
- 玩法、人数和启动方式清晰；
- 第三方代码的来源与许可证可追溯。

## 2. 主分类

| 目录 | 中文分类 | 参与方式 | 典型内容 |
| --- | --- | --- | --- |
| `experiences/surprises/` | 单人惊喜 | 一个人制作或配置，另一人体验 | 情书、纪念日、回忆时间线、照片故事、寻宝 |
| `experiences/co-op/` | 双人合作 | 两个人共同完成目标 | 你画我猜、默契问答、协作拼图、共同故事 |
| `experiences/versus/` | 双人对抗 | 两个人比较分数或争夺胜负 | 井字棋、五子棋、反应挑战、桌面冰球 |

现有 `love-tree` 归入 `experiences/surprises/love-tree/`。

## 3. 辅助标签

主分类之外，每个作品的 README 使用下列标签描述差异：

- **设备**：`单设备同屏`、`单设备轮流`、`局域网双设备`、`可选异地双设备`；
- **输入**：`鼠标`、`触屏`、`键盘`、`摄像头`、`麦克风`；
- **时长**：`1–3 分钟`、`5–15 分钟`、`15 分钟以上`；
- **定制量**：`无需定制`、`改配置`、`替换素材`、`修改源码`；
- **数据边界**：`不出当前设备`、`仅局域网传输`、`可选公网`、`必须公网`；
- **公网依赖**：`无`、`可选`、`必须`；
- **状态**：`已收录`、`待实现`、`仅作灵感`。

## 4. 本地启动等级

等级描述最终用户如何启动和连接，不用于表示开发难度或许可证风险。

| 等级 | 启动与连接方式 | 典型技术 | 收录要求 |
| --- | --- | --- | --- |
| A · 直接打开 | 双击 `index.html` 即可运行 | 原生 HTML/CSS/JS、Canvas、WebAudio | 资源随作品保存，`file://` 验证通过 |
| B · 一键本地服务 | 双击 `start.command` 或 `start.bat`，自动启动本地服务并打开浏览器 | ES Modules、`fetch()`、Service Worker、WebAssembly | 启动器可重复运行，退出方法清晰，不访问公网也能完成核心体验 |
| C · 局域网双设备 | 一台设备启动房间，另一台通过同一 Wi-Fi / 局域网加入 | 本地 HTTP、WebSocket、WebRTC、二维码加入 | README 说明主机与加入步骤，私人数据不离开局域网 |
| D · 本地重型 | 安装或携带本地运行时、模型或大型资源后启动 | 本地 AI、语音识别、3D 引擎、大型素材包 | 提供可复现安装/启动流程，列明磁盘、权限和硬件要求 |

A 最便携，但 A–D 都是正式目标。等级越高，README 和启动器需要承担越多环境检查与错误提示。

### 公网依赖单独标注

- **无**：断开公网后核心体验仍完整；这是默认目标。
- **可选**：仅异地联机、分享或内容下载需要公网；本地核心仍可用。
- **必须**：核心流程离不开外部 API、账号、云数据库或第三方房间服务；通常只作灵感，除非能提供本地替代方案。

## 5. 单个作品的标准结构

```text
experiences/<category>/<slug>/
├── index.html          # 体验入口
├── README.md           # 玩法、启动、定制、来源与许可证
├── start.command       # B/C/D 级按支持平台提供：macOS 一键启动器
├── start.bat           # B/C/D 级按支持平台提供：Windows 一键启动器
├── server/             # B/C/D 级可选：本地服务或运行时
├── models/             # D 级可选：本地模型或其下载说明
├── assets/             # 当前作品独占资源（可按需拆 css/js/audio/images）
└── preview.*           # 可选预览图或短视频
```

第三方库如果只服务于一个作品，跟随该作品保存；确认有多个作品共用后，才迁入 `shared/`。这样可以保证单个作品目录连同已声明的运行时、模型和依赖能够独立部署运行。

## 6. 第三方项目收录门槛

必须逐项确认：

1. 有直接源码地址，而不是只有在线试玩页；
2. 许可证允许复制、修改和再分发；
3. 外链字体、脚本、图片和音频已识别；
4. 不在源码中携带密钥、统计代码或个人数据；
5. 已按声明的 A–D 等级验证启动方式，并单独核验公网依赖；
6. README 保留原作者、源项目、许可证和本仓库修改说明。

没有许可证的公开源码不得直接复制进仓库，只能收录在调研文档的“灵感”部分。

## 8. 验收标准

- 根 README 能在一分钟内说明仓库定位、目录与使用方式；
- love tree 从新路径打开后，脚本、样式、音频引用不丢失；
- 每个正式作品按声明的 A–D 等级验收，断网时的核心能力与限制写清楚；
- 调研文档至少包含三大分类，并将“可直接引入”和“仅作灵感”分开；
- 每个有源码的重点候选都包含可点击来源与许可证判断；
- 所有 Markdown 相对链接可解析，Git 工作区只包含本任务相关改动。
