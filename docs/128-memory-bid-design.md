# “这一串，我还记得”视觉设计冻结

- 日期：2026-07-19
- 状态：实现前视觉真源与生产资产已冻结；最终浏览器 fidelity 待验收
- 工作 ID：`memory-bid`
- 产品规格：[127-memory-bid-spec.md](./127-memory-bid-spec.md)
- 生成方式：OpenAI ImageGen；没有输入第三方图片

## 1. 视觉命题

这是“一张深夜旅站失物竞拍桌上的记忆账簿”：墨蓝木桌承接共同观看的安静，羊皮纸账簿承接报价与复盘，暗红票签承接当前承诺，黄铜细线标出四轮进度。它是温柔而克制的双人对抗，不是赌场、拍卖行后台、脑力训练仪表盘或商业声光玩具。

视觉层级冻结为：轮次与比分 → 当前阶段任务 → 唯一主行动 → 当前轮历史 → 本机隐私说明。桌面竞价态使用一张横向打开的账簿，约 `24 / 52 / 24` 三段；终局使用 `46 / 54` 双栏；移动证明态是真实单列，不把桌面画面整体缩小。

## 3. 设计令牌

### 3.1 色彩

| 角色 | 值 |
| --- | --- |
| 桌面夜蓝 `--night` | `#08131d` |
| 抬升夜蓝 `--night-raised` | `#121f2b` |
| 账页 `--paper` | `#eadcbd` |
| 深账页 `--paper-deep` | `#d8c39f` |
| 纸上墨色 `--ink` | `#2c241d` |
| 夜色文字 `--light-ink` | `#ead3a8` |
| 黄铜 `--brass` | `#a77d46` |
| 亮黄铜 `--brass-bright` | `#d7b36f` |
| 承诺暗红 `--oxblood` | `#7b251f` |
| TA 蓝灰 `--rival` | `#52677d` |
| 成功 `--success` | `#416b4c` |
| 警示 `--warning` | `#735443` |
| 焦点 `--focus` | `#f4c76d` |

物件强调色沿用规格，但按钮不能只靠色彩区分。账页是真正的偏暖羊皮纸，不是白色；桌面是真正的深墨蓝，不额外覆盖彩色滤镜或半透明洗色层。

### 3.2 字体与尺度

- 标题、大比分、当前报价：`Songti SC`, `STSong`, `Noto Serif CJK SC`, Georgia, serif；
- 按钮、说明、历史、状态：系统无衬线栈；
- 不下载字体；中文缺字时以系统字体自然回退；
- 桌面 H1 `clamp(2rem, 4vw, 4.5rem)`，移动主标题不超过 `2.25rem`；
- 正文不低于 `15px`，控件文字不低于 `16px`，触控目标不小于 `44×44px`；
- 分数与报价启用等宽数字特性，避免数字变化导致跳动。

### 3.3 间距、边框与动效

- 间距刻度：`4 / 8 / 12 / 16 / 24 / 32 / 48px`；
- 普通圆角 `8px`，主票签 `10px`，不使用 24px 以上泡泡圆角；
- 账页边框 1px 暖灰，重点双边框为 1px 暗红 + 2px 内侧黄铜；
- 控件反馈 `140ms`，阶段显隐 `180ms`，物件票签落位 `220ms`；
- `prefers-reduced-motion: reduce` 下装饰与位移动画归零；自动展示的 900/250ms 规则计时不改变，手动模式提供无自动切换的等价路径。

## 4. 布局合同

### 4.1 桌面竞价与展示

- `>= 900px`：顶部安静横栏，标题在左，比分与四轮进度在右；不增加导航、徽章或第二标题；
- 主账页最大宽 `1180px`，桌面竞价为 `24 / 52 / 24` 三段；左段历史可内部滚动，中央只保留一个当前报价焦点，右段只保留当前合法动作；
- reveal 阶段沿用同一账页但取消三段，中央展示单件纪念物；不能提前渲染其余七件；
- intro 在同一账页中用左右两种播放方式，不另造营销 hero；
- round-result 使用上方八件序列、下方证明前缀的单一对照带，不制造八张独立卡片。

### 4.2 桌面终局

- `46 / 54` 双栏：左侧标题、大比分和一句结论；右侧四行账簿复盘；
- 每行固定显示轮次、证明者与报价、结果文本、得分者；成功用圆形勾，首错用三角警示，始终有完整文字；
- 结语纸条与“再记四轮”横跨下方，主动作在 1280×800 内可见。

### 4.3 移动

- 390×844 与 320×700 均为单列；顶部只保留短标题、比分和轮次，不重复副题；
- proof 顺序固定为：阶段标题 → 承诺数量 → 证明槽 → 2×3 物件按钮 → 撤回/清空 → 提交 → 认输；
- 五格证明槽可横向等分或 `3+2` 换行，不能横向滚动；六件按钮固定 2×3，插画高度在 68–92px 间自适应；
- 390×844 下主提交动作必须无需滚动可见；320×700 可纵向滚动，但不能横向溢出或遮住焦点；
- round-result 和 match-result 将桌面双栏顺序改为结论 → 对照/四轮记录 → 结语 → 主动作。

## 5. 图集坐标与故障回退

透明图集为精确 3×2 均分，每格 512×512：

| ID | 行/列 | CSS `background-position` |
| --- | --- | --- |
| `ticket` | 1 / 1 | `0% 0%` |
| `camera` | 1 / 2 | `50% 0%` |
| `shell` | 1 / 3 | `100% 0%` |
| `key` | 2 / 1 | `0% 100%` |
| `mug` | 2 / 2 | `50% 100%` |
| `map` | 2 / 3 | `100% 100%` |

所有 sprite 使用 `background-size: 300% 200%`、固定 `aspect-ratio: 1` 与 `background-repeat: no-repeat`。图集不可用时，`::before` 的 CSS 轮廓占位仍保留物件编号与名称；背景不可用时使用纯 `#08131d` 和边框。图片不包含焦点、得分、匹配、首错、按钮文字或交互热区。

## 6. 阶段投影与首屏文案锁

| 状态 | 首屏允许出现 | 明确隐藏 |
| --- | --- | --- |
| intro | 标题、副题、四轮规则、两种模式、开始、隐私 | seed、序列、比分历史 |
| reveal | 短标题、比分、轮次、当前序号、单件物件或遮挡、暂停/继续/下一件 | 已看物件列表、未来物件、竞价控件 |
| bidding | “我能记得更多”、当前报价、合法更高数字、出价记录、“就到这里” | 当前轮答案、物件图集列表、证明草稿 |
| proof | “轮到{player}证明”、bid、证明槽、六件候选、撤回/清空/提交/认输 | 正确前缀、匹配提示、完整序列 |
| round-result | 本轮结论、八件序列、证明、首错/认输、比分、下一轮/总结果 | 未来轮答案、编辑控件 |
| match-result | “四轮都收好了”、胜负/平局、大比分、四轮账簿、结语、重开 | seed、当前输入、竞价控件 |

允许的图标只有：四轮圆点/线、圆形勾、三角首错、暂停/继续、删除、清空、锁与六件纪念物。没有装饰性 eyebrow、标签胶囊、时间戳、模式徽章、奖杯、分享、音量、排行榜或伪统计。

## 7. ImageGen 输入与处理链

所有生成均为全新生成、无参考图：

1. 桌面竞价态：要求完整 16:10 游戏屏、静默顶部栏、三段账簿、当前前 4 件、合法 5–8、暗红主动作、无赌场/计时/商业四色圆盘。
2. 移动证明态：要求完整移动屏、五个顺序槽、六件编号候选、焦点钥匙、禁用提交与主动认输；保持同一墨蓝/羊皮纸/黄铜语言。
3. 桌面结算态：要求 3–1、四轮逐行复盘、无奖杯/彩纸/排行榜；保持同一账簿与结语纸条。
4. 生产背景：要求俯视 16:10 墨蓝木桌，台灯和夹件只在极端边缘，中央大面积留白；禁止 UI、文字、纪念物与标识。
5. 生产图集：要求严格 3×2 六件物件、纯 `#ff00ff` 无阴影背景、无文字/品牌/额外物件；使用技能脚本 `remove_chroma_key.py` 的 `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill` 去背。

图集去背第一次调用系统 Python 因缺少 Pillow 失败且没有生成文件；改用工作区共享 Python 后成功。透明统计为 `1,052,188 / 1,572,864` 个全透明像素、`9,596` 个部分透明像素，alpha 范围 `0..255`；六个网格位置均保留不透明主体。
