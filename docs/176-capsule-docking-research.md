# A 级“转一点，推一点，刚好回家”定向调研

调研日期：2026-07-21

对应创意：`C20 太空舱对接`

建议目录：`experiences/co-op/capsule-docking/`

建议等级：A（单设备同屏、`file://` 直开、无第三方运行依赖）

## 1. 调研结论

C20 适合实现成一座近距离对接训练台：姿态席只掌握左右姿态喷口，推进席只掌握主推与反推；两个人共同控制同一艘舱体，把它送入空间站接口，并同时压低位置误差、线速度、船头角度和角速度。

正式方向采用 **双席权限分离 + 60Hz 定点整数物理 + 五条件稳定对接**：

- 姿态席使用 `A / D`，只能改变角速度；推进席使用 `J / L`，只能沿当前船头施加正向或反向加速度；
- 舱体位置、速度、角度和角速度全部属于同一个公开状态，两席没有隐藏信息；
- 世界使用百分之一单位的定点整数，角度用 256 格环和固定正弦/余弦表，不让浏览器浮点或 SVG 像素决定结果；
- 每个 60Hz tick 先读取两席持有输入，再更新角速度、角度、线速度和位置，最后统一检查碰撞与对接 Gate；
- 对接要求进入小型捕获框，同时满足低横向/纵向速度、船头对齐、低角速度、两席均松手，并稳定保持 30 tick；
- 撞上空间站外壳或飘出安全区只重试当前航段，已经完成的接口不丢失；
- 三个固定航段改变初始纵向偏移、船头和漂移，但不随机、不计时、不计燃料、不评分，也不比较谁失误。

题名建议为“转一点，推一点，刚好回家”，目录为 `capsule-docking`。

## 2. 与现有作品的机制边界

| 作品 | 谁控制什么 | 完成核心 | 与 C20 的差异 |
| --- | --- | --- | --- |
| `lighthouse-passage` | 灯塔席提供照明；小船席独自掌握操舵、推进和倒车 | 航标、照明、港区、低速、船头共同成立 | C20 不做信息不对称；同一舱体的旋转和推进被拆给两席，任何一席都不能独自驾驶 |
| `steady-together` | 两席分别托天平两端 | 支撑、球位、球速和梁角安全时推进路线 | C20 是二维自由漂移、船体局部推力和角速度；没有天平、滚珠或路线自动推进 |
| `moving-home-together` | 两席分别推家具两端 | 双端意图合成平移/旋转，穿过固定障碍 | C20 有惯性、线速度、角速度和反推；不是直接位置微步，也不做多边形家具过门 |
| `tethered-heart` | 两席各控制一个角色 | 双角色通过绳带约束共同穿越 | C20 只有一个共享刚体，没有绳带、双角色或相互碰撞 |
| `orbit-star-race` | 两位各控制自己的轨道高度 | 利用轨道角速度抢星 | C20 是合作、近距离手动对接；不模拟轨道周期、不竞争、不生成星星 |

因此，C20 的机制增量不是“又一个太空皮肤”，而是仓库首个 **两席分别掌握同一刚体的转动与平动权限，并通过多变量稳定窗共同完成** 的样板。

## 3. Brainstorm：四个方向与取舍

### 方向 A：完整轨道会合模拟

加入引力、轨道要素、相对运动、燃料预算和远距离会合，再进入近距对接。它有教育价值，但需要大量导航知识、参数解释和长时间操作，也容易被误解为真实训练工具。

**结论：不采用。** 本作从已经完成远距离会合的“近距离安全框”开始，不声称模拟真实任务。

### 方向 B：一人驾驶、一人读仪表

一席掌握全部旋转/推进，另一席只能看到速度或给口头指令。这会与“灯塔与小船”的信息不对称结构接近，而且规则无法证明读表席真的参与。

**结论：不采用。** 四个控制权限必须硬拆给两席。

### 方向 C：轮流提交离散指令

双方交替选择“左转 5°、推进一格、反推一格”，系统一次执行。它非常易测，但失去原始创意中的同时控制、惯性和临场配合。

**结论：不采用。** 离散指令可作为未来低动态辅助模式，不承担首版核心。

### 方向 D：双席连续近距对接

姿态席持续修正船头，推进席根据当前船头给正/反推；两席共同观察同一状态。接口只在多个条件连续稳定后捕获。

**结论：采用，进入规格冻结。**

## 4. 冻结世界与数值方向

研究阶段冻结以下量纲方向，正式规格应逐项给出精确常量与自检：

| 项 | 建议值 | 说明 |
| --- | ---: | --- |
| 世界 | `1000 × 620` | 规则坐标；SVG `viewBox` 只投影 |
| `POSITION_SCALE` | `100` | 位置和速度均使用百分之一世界单位 |
| `ANGLE_STEPS` | `256` | 一圈 256 格，0 指向屏幕右侧，顺时针增加 |
| `TRIG_SCALE` | `16384` | 固定 256 项正弦/余弦整数表 |
| 规则频率 | `60 tick/s` | rAF 只累积并派发固定 tick |
| 单帧追赶 | 最多 5 tick | 超额丢弃，防后台恢复追赶风暴 |
| 舱体半径 | `22` | 规则用圆形保守碰撞；视觉可有不越界的舱翼 |
| 线加速度 | 每 tick `3` 定点单位 | 正推/反推沿当前船头方向 |
| 最大线速度 | 每轴 `240` | 防止高速穿越窄接口 |
| 角加速度 | 每 tick `1` angle step/tick | A/D 独占，双按视为 0 |
| 最大角速度 | `4` steps/tick | 约 5.625°/tick 上限 |
| 安全阻尼 | 无输入时每轴/角速度向 0 靠近 1 | 解释为近距训练台辅助阻尼，不冒充真空物理 |
| 稳定窗 | `30 tick` | 0.5 秒连续满足，不靠 CSS 动画 |

线性更新建议全部使用整数截断和安全上界：

```text
angularVelocity ← clamp(damp(angularVelocity) + torque, -4, 4)
angleIndex      ← mod(angleIndex + angularVelocity, 256)
velocity        ← clamp(damp(velocity) + heading(angleIndex) × thrust, limits)
position        ← position + velocity
```

这里是独立设计方向，不复制任何引擎的积分实现或参数。正式规格必须冻结“先阻尼还是先加速度、使用更新前还是更新后角度施力、整数除法朝零还是向下”等顺序，并用重放测试证明。

## 5. 空间站碰撞与接口 Gate

建议空间站固定在右侧，接口朝左开放：

- 上外壳：`x = 840..1000, y = 0..270`；
- 下外壳：`x = 840..1000, y = 350..620`；
- 接口后墙：`x = 860..1000, y = 270..350`；
- 安全通道：两片外壳之间的 `y = 270..350`；
- 对接中心约为 `(820, 310)`，舱体鼻端在后墙前保留至少 3 个世界单位。

舱体规则碰撞使用圆与 AABB 的最近点距离，不读取 SVG `getBBox()`、像素 alpha 或视觉边框。每个物理 tick 从上一位置到新位置分成足够小的整数微步，或采用 swept circle/AABB，避免高速一步穿墙；具体方案在规格中冻结并以独立 oracle 验证。

连续 30 tick 同时满足以下条件才完成当前航段：

1. 舱体中心进入约 `x = 805..835, y = 296..324` 的捕获框；
2. `|vx| <= 0.50`、`|vy| <= 0.25` 世界单位/tick；
3. 船头与对接轴最短角差不超过 5/256 圈格（约 7.03°）；
4. `|angularVelocity| <= 1`；
5. A、D、J、L 全部松开；
6. 本 tick 没有碰撞，也没有飘出世界安全边界。

任一条件失效，稳定计数立即归零，但只要没有碰撞/越界就可继续修正。碰到接口不是成功；错误角度、过快、仍在喷气或旋转过快都不会捕获。

NASA 的 Orion 近距离对接资料把最终接近描述为同时控制接口相对位置、速度、姿态和姿态率；本作仅借用这四类公开概念来设计可读 Gate，不使用真实飞行参数、导航算法或安全结论，也不是航天训练软件。[NASA NTRS 原始资料](https://ntrs.nasa.gov/citations/20070025134)

## 6. 三个固定航段

三个航段共用同一空间站和 Gate，只改变公开初态：

| 航段 | 名称 | 起点方向 | 初始状态意图 | 必要配合 |
| ---: | --- | --- | --- | --- |
| 1 | 靠近·把船头转回来 | 中线左侧、船头向右下偏 | 位置静止，角度约 `+45°` | 姿态席先回正，推进席再给短推并反推收速 |
| 2 | 修正·从上方落回轴线 | 左上、船头约 `+22.5°` | 带少量向下漂移，目标在右下 | 两席交替改变方向和速度，不能一路长按 |
| 3 | 回家·带着余速停稳 | 左下、船头约 `-22.5°` | 带少量向上/向右余速 | 姿态席压角速度，推进席用反推把速度压入窗口 |

正式规格不能只凭直觉宣称可解：应先用同一纯 reducer 写一个开发期 BFS/beam-search 或固定控制序列验证器，产出至少一条每航段可重放的金路径；生产包不暴露答案或搜索器。每条金路径必须包含姿态席和推进席的有效 action。

## 7. 合作必要性

规则层可证明，而不是依赖文案：

1. 只有姿态席动作能改变 `angularVelocity`，推进席不能写角度字段；
2. 只有推进席动作能产生线加速度，姿态席不能写速度字段；
3. 每航段从远离接口的位置开始，初始 `vx` 不足以自然到达，完全没有推进输入时位置不可能进入捕获框；
4. 每航段初始船头均超出 ±5 格角度窗；完全没有姿态输入时，推进只能沿一条错误轴线前后运动，无法同时进入接口的 x/y 捕获框与角度窗；
5. 成功还要求两席松手与 30 tick 稳定，因此持续压键不能蒙混过关；
6. 三条完成记录都要求两席输入日志中至少出现一个有效姿态 pulse 和一个有效推进 pulse。

同机页面仍无法证明物理上是两个人；一个人可以操作两组键。这属于同机信任边界，README 应诚实说明，不引入摄像头、账号或行为识别。

## 8. 输入、暂停与失败边界

- 姿态席：`KeyA` 左姿态喷口、`KeyD` 右姿态喷口；
- 推进席：`KeyJ` 主推、`KeyL` 反推；
- 键盘 `keydown/keyup` 转成精确 `PRESS/RELEASE` action；repeat 是 no-op；
- 触屏每席两个原生 button，pointer capture 后用 `pointerup/cancel/lostpointercapture` 对称释放；
- 同席双按互相抵消，不产生更大加速度；跨席同时输入在同一个 tick 原子读取；
- blur、hidden、pagehide、Escape 清空四键并退回当前航段说明页；物理重置到该航段固定初态，但不增加 attempt；
- 碰撞/越界进入 `failed`，记录稳定原因 `hull-contact / drifted`；点击重试才增加 attempt 并回到同航段固定初态；
- 成功后持续按键、旧 pointer、旧 rAF accumulator 或过期 action 都不能推进下一航段。

重置整段而不是保留失焦时的半途物理状态，是为了避免系统中断后玩家回到一艘正在漂移的舱体，也让重放与恢复边界更清楚。

## 9. 状态机与实现草案

建议七阶段：

1. `intro`：角色权限、四项仪表和安全说明；
2. `leg-intro`：当前航段初态、目标和两席确认；
3. `approaching`：接受 PRESS/RELEASE/TICK，更新纯物理；
4. `failed`：撞壳或越界，当前航段重试；
5. `docked`：稳定 30 tick，保留本段共同记录；
6. `mission-result`：三次接口记录与共同尝试汇总；
7. `complete`：配置结语与重新开始。

候选动作：`START`、`BEGIN_LEG`、`PRESS { seat, control }`、`RELEASE { seat, control }`、`TICK { count }`、`SUSPEND`、`RETRY_LEG`、`NEXT_LEG`、`FINISH`、`RESTART`。

权威 state 至少包含 `phase / legIndex / pose / velocity / angleIndex / angularVelocity / heldControls / stableTicks / attempt / completedLegs / lastResult / revision`。公共 view 可公开全部即时仪表和 Gate 状态，但不得公开金路径、未来控制序列或搜索器。

## 13. 浏览器标准与可访问性

- 物理键使用 W3C [KeyboardEvent code values](https://www.w3.org/TR/uievents-code/)，不依赖键盘字符布局；
- 双触点依据 W3C [Pointer Events](https://www.w3.org/TR/pointerevents3/)，处理 capture、cancel 与 lost capture；
- rAF 只作调度，规则推进使用固定 tick；隐藏和恢复依据 W3C [Page Visibility](https://www.w3.org/TR/page-visibility-2/)；
- 可访问性以 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 为基线：四键至少 44×44px，主动作至少 48px，焦点清晰，200% zoom 可完成；
- 位置误差、速度、角度、角速度和稳定计数都提供文本/仪表，不以颜色、旋转动画或 SVG 向量作为唯一信息；
- reduced-motion 关闭星点漂移、喷焰和镜头缓动，但固定物理与对接窗口不变；
- forced-colors 使用系统色、线型、文字和边框保留两席、危险壳体与安全 Gate。

## 14. 视觉方向

视觉采用“纸质近地轨道训练台”，避免写实 NASA/SpaceX 仿制与通用霓虹驾驶舱：

- 深炭蓝舱窗、暖灰空间站、珊瑚红姿态喷口、青绿色主推/反推、象牙白仪表刻度；
- 舱体与空间站采用原创几何，不使用真实机构、任务徽章、国旗、航天品牌或现役接口造型；
- 舞台居中，左右控制席等权；五个 Gate 仪表围绕接口而非堆在顶部卡片；
- ImageGen 只生成无字轨道训练背景、桌面/移动/完成概念和可选空间站材质；舱体 hitbox、接口、安全框、仪表、按钮与文字由代码绘制；
- 生成图失败时使用纯色世界与 SVG 几何仍可完整游玩。

建议响应式 Gate：

| 视口 | 必须通过 |
| --- | --- |
| 1504×1046 | 无横纵滚动；标题、舞台、五项 Gate、两席控制和主动作同屏 |
| 1280×800 | 无横向滚动；舞台不小于 720×446，全部即时仪表可见 |
| 390×844 | 世界保持完整宽高比；两席控制上下但 DOM/视觉顺序一致；四键 ≥44px |
| 320×568 | 零横向溢出；舞台 ≥296px 宽；允许必要纵滚；仪表不只显示缩写 |

还需验证 200% zoom、reduced-motion、forced-colors、图片阻断、双 pointer、纯键盘、焦点和四按钮中心 `elementFromPoint()`。

## 15. 风险与进入规格的 Gate

| 风险 | 规格前冻结处理 |
| --- | --- |
| 与灯塔靠港重复 | 明确两席直接拆分同一刚体的转动/平动权限；无照明、航标、暗礁和单席全驾驶 |
| 物理好看但不可解 | 用正式 reducer 搜索/构造三条金路径并完整重放；生产不暴露路径 |
| 浮点和帧率导致重放漂移 | 百分之一位置、256 角格、整数 trig 表、60Hz 固定 tick、最多 5 tick 追赶 |
| 高速穿过空间站 | 微步或 swept circle/AABB；独立 oracle 覆盖擦边、角点和跨越 |
| 长按旋转后难以停下 | 有界角速度和明确 RCS 辅助阻尼；仪表公开角速度，不做隐藏自动驾驶 |
| 两席持续压键也能蒙对 | 对接 Gate 要求四键全松并连续稳定 30 tick |
| 失焦造成 stuck thrust | SUSPEND 原子清四键并重置当前航段，不计失败 |
| 真实航天误导 | 明示近距合作游戏、归一化辅助物理、非训练软件；不展示真实单位或安全建议 |
| 参考项目素材权利复杂 | 正式来源只研究代码机制；零第三方运行文件；所有视觉独立生成或代码绘制 |
