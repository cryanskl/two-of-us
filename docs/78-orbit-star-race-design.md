# 「这一颗我先到」视觉设计清单

> 接受日期：2026-07-18。产品、规则与状态权威以 [`74-orbit-star-race-spec.md`](./74-orbit-star-race-spec.md) 为准。概念与运行纹理由 OpenAI ImageGen 生成；概念图只作视觉基准，不进入运行页面。

## 1. 已接受概念

- [桌面进行态 1504×1046](./assets/orbit-star-race/concept-desktop-playing.png)；
- [手机进行态 853×1844](./assets/orbit-star-race/concept-mobile-playing.png)，与 390×844 同纵横比；
- [桌面终局态 1504×1046](./assets/orbit-star-race/concept-desktop-finished.png)；
- 运行星图：[`star-chart.png`](../experiences/versus/orbit-star-race/assets/star-chart.png)，1254×1254；
- 运行精灵图：[`orbit-sprites.png`](../experiences/versus/orbit-star-race/assets/orbit-sprites.png)，1254×1254，深蓝哑光底四宫格。

核心视觉不是通用太空 HUD，而是一台铺满舞台的黄铜星盘：三条轨道、中央太阳、两枚反向运行的朱红/钴蓝卫星，以及全局唯一一颗待争夺金星。比分和按钮保持开敞排版，不把玩法拆成 dashboard 卡片。

## 2. 设计系统

| 类别 | 规则 |
| --- | --- |
| 页面底色 | 午夜海军蓝 `#06131f`；运行纹理只增加低对比蚀刻星图 |
| 深层表面 | `#0b1b2a`，用于舞台暗部与控件底面 |
| 黄铜主色 | `#c99a50`；亮边 `#e3c183`；只用于星盘、目标与关键数字 |
| 朱方 | `#d8482e`；卫星、姓名、轨道切换反馈同色 |
| 蓝方 | `#2e6edb`；卫星、姓名、轨道切换反馈同色 |
| 主文字 | 暖金 `#e4c38b`；次要文字 `#9c8b70`；正文必须满足可读对比 |
| 字体 | 标题用本机宋体栈 `Songti SC` / `STSong` / `SimSun` / `Georgia`；状态与数字用系统 sans-serif；不下载字体 |
| 几何 | 细黄铜刻线、放射刻度、开放式分数轨；按钮是带边框的仪器键，不使用玻璃拟态或大胶囊 |
| 动效 | 卫星匀速绕行、切轨 180–260ms、捕获闪光不超过 360ms；`prefers-reduced-motion` 下取消非必要缩放与光晕 |

## 3. 桌面、移动与终局容器

### 1504×1046 进行态

- 主区约为 35/65 双列：左侧放标题、两行规则、局势说明；右侧容纳完整星盘；
- 顶部用一条开放分数轨显示 `朱方 分数 : 分数 蓝方`，不放重复卫星图标；
- 星盘直径约 620–720px，三轨必须完整露出，目标星和两位玩家不被文字遮挡；
- 两组控制放在底部相对两端，朱方使用 `W / S`，蓝方使用 `↑ / ↓`，触控按钮与键盘语义同源；
- 1504×1046 首屏不产生纵向或横向滚动。

### 390×844 与 320×700

- 顺序固定为：标题与短规则 → 比分 → 星盘 → 状态 → 两列控制；
- 星盘宽度不超过 `calc(100vw - 24px)`，三条轨道、目标和两枚卫星仍能区分；
- 两方按钮并列，每个真实按钮至少 56px 高；320px 可纵向滚动，但不得横向溢出；
- 不靠缩小到 16px 以下隐藏信息，不省略分数、轨道或当前目标状态。

### finished

- 保留完整星盘、最终比分和已经留下的捕获刻痕；
- 操作区收敛为一个 `再绕一圈`，不弹 modal、不遮挡最终位置；
- 概念中的 `6–5` 只表达加赛后的终局密度，不是固定对局或测试 fixture。

## 4. 原生代码组件

| 组件 | 实现约束 |
| --- | --- |
| 返回入口 | 原生链接和自制 SVG 箭头；不引入图标库 |
| 分数轨 | 只从 view model 派生姓名、分数、领先与共享捕获；不手工维护第二份比分 |
| 星盘 | HTML/CSS/SVG 原生三环、刻度与轨道标签；背景图不承载碰撞几何 |
| 两枚卫星 | 图集裁切叠加代码原生定位；DOM 各只有一个权威玩家对象 |
| 目标星 | 图集裁切；位置、轨道和编号只来自 `deriveStar` |
| 中央太阳 | 图集裁切；纯装饰，`aria-hidden=true` |
| 切轨控件 | 四个语义按钮；键盘和 Pointer 最终都调用同一个 `shiftOrbit` |
| 状态行 | `aria-live` 更新预备、争夺、共享捕获、领先与终局文案 |
| 主动作 | intro 为 `开始抢星`，finished 为 `再绕一圈`；live 不暴露重开 |

概念分数轨旁的卫星小图标主动删除，因为它们容易被误读为第三、第四个状态对象。页面里的文字、分数、轨道、按钮和动态位置都必须由代码渲染，禁止从概念图裁字或裁界面。

## 5. 图集裁切与降级

`orbit-sprites.png` 是 2×2 四宫格：左上朱方卫星、右上蓝方卫星、左下目标星、右下中央太阳。实现使用 `background-size: 200% 200%` 与四个角的 `background-position` 裁切。由于生成器输出的是 RGB 哑光 PNG 而非真实透明 PNG：

- 精灵容器底色与页面统一为 `#06131f`；
- 外缘使用径向 mask 渐隐，消除方格边界；卫星长翼仍需保留足够 mask 半径；
- JS 预载图集失败时给根节点加 `asset-missing`，回退为 CSS 朱/蓝圆点、四芒星与中央黄铜圆；
- `star-chart.png` 失败时回退为纯色加低对比 CSS 径向星点；
- 资产缺失只降低细节，不能改变 hit test、比分、轨道或胜负。

第一版精灵图的“透明棋盘格”实际被烘焙进 RGB 像素，已拒绝且未进入仓库。复现与解决方案见 [`../bugs/2026-07-18-imagegen-fake-transparent-sprite-atlas.md`](../bugs/2026-07-18-imagegen-fake-transparent-sprite-atlas.md)。

## 6. 文案与可访问性

允许的核心文案：

- 标题：`这一颗我先到`；
- 规则：`只管升轨和降轨。内轨更快，先碰到五颗星的人赢。`；
- 首屏状态：`两颗卫星已经就位` / `看准星轨，再一起出发。`；
- preview：`第 N 颗星正在亮起` / `先看清它在哪条轨道。`；live：`第 N 颗星可以争了` / `内轨更快，外轨更稳。`；
- 控制：`升一轨` / `降一轨`；
- 开场动作：`开始抢星`；
- 终局动作：`再绕一圈`。

轨道与按钮不能只靠颜色区别；卫星提供可读的 `朱` / `蓝` 隐藏标签，当前轨道用“内轨 / 中轨 / 外轨”文字表达。焦点环使用对应玩家色加暖金外缘。页面隐藏后重置 RAF accumulator，恢复时不补跑整段时间。

## 7. 视觉忠实度验收账本

浏览器验收必须把同一状态的运行截图与本清单中的原尺寸概念图同轮查看，并至少记录：

1. 桌面 35/65 构图与星盘主次关系；
2. 黄铜、朱红、钴蓝、午夜蓝的色彩关系；
3. 三环、两卫星、单目标星的对象数量与遮挡；
4. 390×844 的标题、比分、星盘、状态、控制顺序；
5. finished 不遮挡星盘且只保留一个主动作；
6. 主动偏离：删除分数轨装饰卫星、所有实时数字改由状态机生成；
7. 资产失败、`prefers-reduced-motion`、320px 和键盘焦点降级。
