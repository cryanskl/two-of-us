# Tangram Heart Duet Brainstorm：从七巧板到“七片同心”

> 上游调研：[`docs/326-tangram-heart-duet-research.md`](./326-tangram-heart-duet-research.md)
>
> 历史候选代号：`tangram-heart-duet`
>
> 正式发布 ID / 名称：`seven-piece-duet` / **七片同心**
>
> 结论：采用“分席持片、无轮次共铺一形”，保持 **Conditional Go**

## 1. 本轮要决定什么

研究已经证明 A 级本地实现可行，但“七巧板”本身通常是单人拼形。Brainstorm 要选择一个让两人合作成为规则结构、又不与现有项目重复的最小版本。

冻结前提：

- 同一设备、同一块公开拼形板；
- 七枚凸多边形片，全部使用、不得重叠、不得越界；
- A 席与 B 席各有一组片和独立控制路径；
- 四局交换片组归属；
- 无网络、存储、权限或运行依赖；
- 规则使用整数格元，不用物理引擎或浮点布尔运算；
- 只借鉴传统七片拼形的抽象机制，代码、坐标、题面、视觉和文案独立；
- 不实现自然人身份认证，“归属”只约束席位 action。

## 2. 四个方向

### 方向 A：分席持片，无轮次共铺一形

两人面对同一个轮廓。A 席只能操作其三或四片，B 席只能操作另一组；双方不轮流，可以同时预览或交错提交。七片精确覆盖目标时共同完成。

体验句：

> 你放你的几片，我放我的几片；最后严丝合缝的那一刻，属于我们。

优点：

- 双人结构直接来自片的权限分割，不依赖计时或排行榜；
- 一块共享板让双方必须观察整体和彼此的空间需求；
- 适合鼠标交错、双触点并行和完整键盘等价；
- 与照片交换、双盘竞速、共享刚体和丝带物理都有明确边界；
- 可用纯 reducer 和集合相等做确定性测试。

风险：

- 同一自然人仍能伸手使用两个席位，页面不能证明真实身份；
- 两个预览若争用同一区域，提交顺序会使后一动作失败；
- 三片和四片组的操作量不同；
- 自由拖动若没有清晰吸附，会在手机上显得费力。

控制：

- 文案明确“各守一席”，不宣传身份认证；
- action 带 seat，规则只允许移动本席片；
- 冲突按浏览器接收的提交顺序串行处理，后一动作无损回退；
- 两组面积各半、四局换组；
- 位置、旋转、翻面全部离散；首版旋转冻结为 90° 四分之一转，拖动只是格点预览。

结论：**采用**。

### 方向 B：共同握住一片，合力放下

A 席控制平移，B 席控制旋转；每片必须两人同时确认后才能放入目标。

优点：

- 每一片都要求即时沟通；
- 单片操作职责很清楚；
- 双人同步感强。

问题：

- 本质是双方共同控制一个刚体，接近 `moving-home-together`；
- 若使用持续键位合成，又接近 `tethered-heart` 的共同载荷；
- 手机双指、键盘 ghosting 和握手超时会扩大输入 Gate；
- 七片仍需串行处理，等待感重。

结论：拒绝。它把独立片组的独特性换成仓库已有的共享对象控制。

### 方向 C：严格轮流，一人一片

A 席放一片后锁定，B 席放一片，再交回 A 席；非法位置撤销本回合。

优点：

- 单手机操作非常清晰；
- 状态机和输入冲突小；
- 每一步都有“轮到你”的交流节奏。

问题：

- 接近 `constellation-relay` 的轮流构形；
- 等待方无法处理自己的片，合作被回合规则人工制造；
- 七片为奇数，首尾归属和公平需额外解释；
- 不能体现双方同时观察并协调空间。

结论：拒绝。可作为未来独立“轮流拼词/连线”体验，不混入首版。

### 方向 D：双盘同题竞速

双方各有完整七片和同一个目标，先拼完者胜。

优点：

- 规则熟悉，胜负明确；
- 双方全程忙碌；
- 同一题面便于解释公平。

问题：

- 直接落入 `dual-maze-race`、`photo-slider-race` 的“双盘同题竞速”产品形态；
- 需要在 320px 同时容纳十四片和两块盘；
- 双人是对抗而非合作，与本候选目的相反；
- 两套完整几何状态和 Pointer 命中区使移动端质量下降。

结论：拒绝。不用计时、步数或排名给普通七巧板包装双人性。

## 3. 决策

选择 **方向 A：分席持片，无轮次共铺一形**。

选择理由按优先级排序：

1. 规则增量来自席位权限和共享空间，最能与仓库现有项目去重。
2. 两人都能在对方未完成时继续调整自己的片，等待最少。
3. 一块板在小屏上比双盘更可靠。
4. 整数格元集合能精确验证，可保持 A 级零依赖。
5. 鼠标、触摸和键盘可以共享“选择 → 预览 → 提交/取消”语义。

不混合 B、C 或 D。首版没有双人同时确认、严格轮流、竞速、计分或排行榜。

## 4. 首局体验

### 4.1 打开

首屏立即显示：

- 标题“七片同心”；
- 一句话：“各守一组片，一起铺满同一个轮廓”；
- A 席和 B 席的符号、颜色/纹理与当前片组；
- 四个固定目标只显示名字和轮廓缩略图；
- “开始第一形”主按钮；
- “怎样操作”和“本地隐私”短说明。

不要求输入姓名、选择图片、联网或安装依赖。

### 4.2 认识归属

开始后：

1. 目标轮廓位于中央；
2. A 席托盘在左/上，B 席托盘在右/下；
3. 每片同时标注席位字母、几何符号和纹理；
4. 帮助用一句话说明“本席控件只移动本席片；同机没有身份锁，请各守一席”；
5. 首局预选双方各一片，但不自动移动或放置。

### 4.3 拼形

- 选中片后可拖动到格点预览；
- 控制按钮可左转、右转；只有平行四边形可翻面；
- 合法预览显示目标内的实线边界与“可放下”；
- 越界显示哪一部分超出，冲突显示相撞片 ID，不只变色；
- 释放/“放下”时才提交；
- 已放片仍可由所属席位重新拿起调整；
- 另一席可同时预览，但每个提交按事件到达顺序验证；
- 无提示按钮、自动完成或解答轮廓。

### 4.4 换形和完成

七片并集严格等于目标后：

- 片缝短暂收束，reduced motion 下直接切换；
- 显示“这一形，是两边一起补全的”；
- 列出双方本局各完成了几片，只作事实回顾，不评高低；
- 下一局交换细片组/大片组；
- 第四局后显示共同完成四形和“再拼一次”。

刷新不保留进度，不制造“已保存”状态。

## 5. 席位、片组与公平

### 5.1 为什么按面积对半

如果简单按 3/4 片随机分，可能一方长期持有大部分面积或难片。固定为：

- 细片组：大三角 + 中三角 + 两小三角，四片，面积 1/2；
- 大片组：大三角 + 正方形 + 平行四边形，三片，面积 1/2。

片数不等，但面积相等；两组的认知负担不同。四局换组不是为了产生分数，而是让双方都体验两种任务。

### 5.2 席位隔离

每个动作显式包含 `seatId` 和 `pieceId`。规则层先查：

1. phase 允许操作；
2. piece 存在；
3. 当前关卡中 piece 的 owner 等于 seat；
4. rotation/flip/position 合法；
5. 候选格元不越界、不与已放片重叠。

任何一步失败都返回同一 state 引用或等价 no-op，并给调用层稳定 reason code。DOM 的 class、父节点或颜色不能作为权限来源。

### 5.3 冲突不是输赢

双触点可能让两片同时预览在同一空位。浏览器最终仍会按事件顺序调用 reducer：

- 先到的合法提交进入状态；
- 后到动作根据新状态重新验证；
- 若冲突，后一片回到上一个已提交姿态或托盘；
- live region 报告“位置已被占用，请一起调整”；
- 不增加错误数，不指定责任人。

不建立“同时释放必须原子合并”的复杂协议；合作游戏无需虚构同毫秒公平。

## 6. 四个目标的内容方向

Brainstorm 只冻结内容原则，不冻结坐标或网络常见题面。四个工作名：

1. **相拥**：紧凑、近方形、适合教学；
2. **并肩**：横向展开，要求两组交错；
3. **归帆**：斜向重心，要求平行四边形翻面；
4. **同路**：非对称收束，作为最终综合题。

这些名字不能反推临摹现成“人、船、动物”等七巧板轮廓。内容实现必须从七片的原创标准解组合生成 target 格元，再以抽象名解释；若成形偶然过于像知名角色、标志或仓库既有视觉，应重排并重新指纹。

心形可以成为未来通过原创审计的第五形，但不进入首版四形，也不作为标题主视觉。这样主动拉开与 `tethered-heart` 的题材距离。

## 7. 视觉方向

### 7.1 推荐：双纸色、单轮廓

关键词：

- 深墨蓝或暖灰背景；
- A 席为珊瑚线纹，B 席为青绿点纹；
- 目标像一张留白卡纸；
- 拼片使用纯 CSS/SVG 颜色、纹理和席位角标；
- 片缝清楚，完成后仍保留细缝，不伪装成一张图片；
- 不使用布艺、丝带、刺绣、照片、星线、迷宫墙或搬家纸箱。

布局中心始终是一块目标板，两侧/上下是两个托盘。移动窄屏使用“上方 A 托盘—中央板—下方 B 托盘”，但中央板在双方操作时始终可见。

### 7.2 非颜色信息

- A 片角标为圆点，B 片角标为短横；
- 两组使用不同重复纹理；
- 片名和席位写进可访问名称；
- 合法/冲突/越界分别用实线勾、交叉线、外溢箭头加文字；
- 完成状态用标题和轮廓合拢，不只变为绿色。

### 7.3 暂不生成图片资产

首版全部规则对象用 SVG/CSS 绘制，不需要 ImageGen、照片或第三方纹理。这样更容易证明坐标与视觉原创，也保持目录可复制和 A 级零资产依赖。

## 8. 输入方案比较

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 直接拖片 + 离散吸附 | 触屏直觉；两指可并行 | 取消、冲突和遮挡需定义 | 采用，释放才提交 |
| 点击片，再点击目标格点 | 鼠标简单 | 目标格点太密，触摸命中区不足 | 不作为主路径 |
| Tab + 方向键 + 控制按钮 | 不依赖拖拽；精确 | 需要清晰焦点和选择态 | 作为完整等价路径 |
| A 席 WASD、B 席方向键持续移动 | 双人同时感强 | ghosting、全局快捷键与焦点冲突 | 不作为首版必需路径 |
| 自由角度或 45° 旋转 | 接近实体拼图 | 浮点/无理坐标、吸附和可用性成本高 | 拒绝，冻结 90° 四分之一转 |
| 双击/长按旋转 | 控件少 | 不易发现，长按与辅助技术冲突 | 拒绝，使用明确按钮 |

## 9. 反馈与语气

推荐：

- “这片属于 A 席，请从 A 席控制区操作。”
- “还差 6 个小格元。”
- “与 B-方片重叠，请一起换个位置。”
- “七片刚好合上了。”
- “下一形交换片组。”

避免：

- “你拖错了”“某某拖后腿”；
- “证明谁更爱谁”；
- “绝对公平”“无法代操”；
- 用完成速度给双方排名；
- 把无障碍或隐私边界写成未经验证的绝对承诺。

## 10. 首版严格范围

必须有：

- 四个原创、可解、互不等价的固定目标；
- 七片、两组、四局交换；
- 选择、离散移动、左右旋转、平行四边形翻面、提交、取消；
- Pointer、鼠标、完整键盘路径；
- 精确格元合法性与完成判定；
- 重开本形、重新开始四形；
- 席位/状态/错误的可访问文本；
- 本地、隐私、借鉴和原创声明；
- 自动规则测试与 Chrome / `file://` 验收。

明确不做：

- 用户上传照片或题面；
- 在线房间、跨设备同步、二维码；
- 姓名、账号、排行榜、计时、分数、存档；
- 提示、撤销历史、自动求解、关卡编辑器；
- 随机题面或每日挑战；
- 自由旋转、物理碰撞、惯性和音频；
- 第三方库、远程字体、图标或素材；
- 心形首关或心形主视觉；
- 身份认证或“绝对不可代操”承诺。

## 11. Conditional Go 保持条件

Brainstorm 不把研究结论升级为 Go。进入实现前仍要冻结：

1. 七片的独立整数格元模板及面积证明；
2. 90° 四分之一转姿态表，尤其平行四边形翻面语义；
3. 四个原创目标的标准解、指纹和内容审计；
4. seat action 与 piece owner 的 reducer 合同；
5. Pointer 预览/提交/取消和并发冲突顺序；
6. 键盘完整完成路径；
7. 响应式、forced colors、reduced motion 和缩放 Gate；
8. README / ATTRIBUTION 的固定来源与零复制声明。

其中任一项只能通过复制上游坐标、轮廓或算法完成时，停止实施并判 No-Go。
