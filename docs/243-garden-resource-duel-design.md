# “这一朵，我先养开”代码原生视觉设计

- 日期：2026-07-24
- 稳定工作 ID：`garden-resource-duel`
- Brainstorm：[`241-garden-resource-duel-brainstorm.md`](./241-garden-resource-duel-brainstorm.md)
- 规格：[`242-garden-resource-duel-spec.md`](./242-garden-resource-duel-spec.md)
- 视觉生产方式：原创 HTML / CSS；不使用 ImageGen 或第三方素材
- 生产状态：设计冻结，可直接进入实现；无用户视觉确认 Gate

## 1. 设计目标

页面要像夜晚阳台上两个人各守一盆花，而不是赌场牌桌或儿童农场游戏。

三个目标按优先级排列：

1. 任何时刻先看懂当前是谁、现在需要什么、这一轮值几片花瓣；
2. 交接与秘密选择阶段不把上一位的牌留在视觉树或可访问树；
3. 胜负有开花反馈，但两盆花都保留，不表现枯萎、破坏或羞辱。

视觉只服务生产规则。花朵、卡片翻面和背景光都不能决定状态迁移。

## 3. 页面骨架

```text
app-shell
├── quiet-header
│   ├── title
│   └── phase/status
├── season-card
│   ├── round
│   ├── need
│   └── petal-value
├── garden-stage
│   ├── player-garden[0]
│   ├── reveal-zone / phase-panel
│   └── player-garden[1]
├── public-ledger
│   ├── scores
│   └── remaining-hand-summary
└── public-history
```

不同 phase 重建中央 `phase-panel`。不把选择按钮放在两盆花下面永久隐藏。

## 4. 双盆花

每盆花由语义化容器和装饰节点组成：

```text
figure.player-garden
├── figcaption：玩家名 + n/5 花瓣
├── flower[aria-hidden=true]
│   ├── stem
│   ├── leaves
│   └── 5 petal nodes
└── progress：具名公开进度
```

- 0 分：闭合花苞；
- 1–4 分：按固定顺序展开对应数量花瓣；
- 5 分及以上：五片全开，中心出现暖光；
- `progress` 与文字始终给出精确分数；
- 玩家 0 用陶土色花盆，玩家 1 用灰紫色花盆；
- 两方花朵几何完全相同，不用尺寸、亮度或位置暗示规则优势；
- 被虫害阻断时只在本轮公开记录旁出现短暂虚线，不让已开花瓣收回。

花瓣使用绝对定位的圆角椭圆 DOM/CSS，不用 SVG 文件、emoji 图片或外部图标。

## 5. 当前季节牌

中央上方始终显示公开季节：

```text
第 3 / 6 轮
这一次，需要雨露
本轮值 2 片花瓣
```

阳光与雨露同时通过文字、符号和边框表达：

- 阳光：`☀` + “阳光” + 实线暖金边；
- 雨露：`◇` 装饰 + “雨露” + 双线浅蓝边。

不使用只有颜色的圆点。未来季节不生成占位卡背数量，避免暗示可检查的内部牌堆。

## 6. 三类手牌

选择页的卡按钮：

| 牌 | 主标题 | 说明 | 非颜色纹理 |
| --- | --- | --- | --- |
| 阳光 | 阳光 · 剩 n 张 | 当前需要阳光时，得到本轮花瓣 | 放射短线 |
| 雨露 | 雨露 · 剩 n 张 | 当前需要雨露时，得到本轮花瓣 | 双层波纹 |
| 虫害 | 虫害 · 剩 n 张 | 挡住对方本轮匹配资源；自己不得分 | 斜向点列 |

- 剩余 0 张的牌不渲染为可选按钮；可在公开库存中显示 `0`；
- 点击后只添加 `aria-pressed=true` 和本地选中边框；
- “确认这张”是独立主按钮；
- 确认或遮屏后整个选择列表卸载；
- 牌背不显示牌种首字母、颜色或纹理。

## 7. phase 构图

### 7.1 intro

- 双盆闭合花苞位于左右；
- 中央是标题、三行规则和“开始这局”；
- 不显示随机 seed、未来季节、手牌按钮或空历史表；
- 无 JavaScript 时同一区域显示静态说明。

### 7.2 season

- 当前季节牌成为最高视觉层；
- 两边显示花瓣和剩余 `阳光/雨露/虫害` 数量；
- 中央主按钮“开始藏第 n 轮”；
- 第一选择席位以文字说明，不只给花盆发光。

### 7.3 handoff

- 花园舞台覆一层不透明度足够的磨砂门帘；
- 只显示“把屏幕交给 TA”“TA 接好后再继续”和“我接好了”；
- 背景公开花园可以模糊，但不能存在选择节点或秘密文本；
- 接管按钮得到焦点。

### 7.4 choosing

- 顶部仍显示当前需求和本轮价值；
- 只显示当前玩家名字、三类可用牌和确认/先遮住；
- 公共历史折叠成摘要，避免把注意力从选择移走；
- 不显示另一位已确认牌种，也不通过库存变化暗示它。

### 7.5 ready-to-reveal

- 两张统一的无信息卡背并排；
- 文案“两张牌都藏好了”；
- 只有“我们一起揭晓”主按钮；
- 卡背 DOM 不包含真实牌值、类名或可访问名称；
- 此阶段不自动翻牌。

### 7.6 round-result

- 两张公开牌从两侧进入中央；
- 结果句先说明阻断，再说明双方本轮花瓣；
- scores 和花朵一次更新；
- 主按钮“看看下一个季节”；
- 完整历史新增一行，使用文字表达牌种和结果。

### 7.7 match-result

- 单方达到 5：对应花全开，另一盆保留现有花瓣；
- 同轮达到：两盆同时全开；
- 回合上限胜：花瓣更多的一方全开作为庆祝表现，但数值仍显示实际分数；
- 平局：两盆以相同强度亮起；
- 显示最终比分、六轮公开历史、seed 和“再养一局”。

结果页不使用奖杯、排行榜、失败大字、枯萎动画、彩纸或连胜统计。

## 8. 动效

允许的动效：

- 卡片揭晓：180–240ms 位移与淡入；
- 新花瓣：220ms 缩放到 1；
- 季节牌切换：160ms 淡入；
- 终局花心：一次 420ms 柔和光晕。

禁止：

- 无限脉冲；
- 摇晃或闪烁虫害；
- 超过一次的庆祝循环；
- 用 animationend 推进状态；
- 页面后台恢复时补播整段动画。

`prefers-reduced-motion: reduce` 下所有位移、缩放和光晕直接关闭，只保留即时状态。

## 9. 响应式

### 9.1 宽屏 `>= 960px`

- 最大内容宽度 1180px；
- 双盆花 + 中央 phase panel 三列；
- history 位于下方全宽；
- 卡牌三列。

### 9.2 中屏 `600–959px`

- 双盆花保持两列，中央 panel 占下一整行；
- season card 横向；
- 卡牌三列或两列加一列，按实际宽度不截字。

### 9.3 窄屏 `< 600px`

- 顺序：season → 双方分数条 → phase panel → 两盆小花 → history；
- 卡牌单列；
- 主按钮全宽；
- 页面宽度 320px 时无横向滚动；
- 安全区使用 `env(safe-area-inset-*)` 作为额外 padding，不作为唯一间距。

横屏矮视口优先保证当前 phase 操作可见，history 可向下滚动，不固定大面积 header。

## 10. 键盘、焦点与状态消息

- intro/season/handoff/ready/result 切换后，焦点进入阶段标题，再由用户 Tab；
- choosing 进入第一张可用牌；选择后焦点移到确认按钮；
- 揭晓后焦点进入公开结果标题；
- 被遮屏时焦点回到接管按钮；
- 焦点环使用 `--focus`，不靠 box-shadow 与背景混在一起；
- `aria-live=polite` 只播报“进入第几轮”“两位已选好”“本轮公开结果”“终局”；
- 选择草稿、牌按钮浏览和已封存牌不进入 live region；
- 快捷键 `1/2/3` 只在 choosing 且非输入法组合时生效；
- Escape 只遮屏，不提交或取消已确认牌。

## 11. 强制颜色与无装饰降级

`@media (forced-colors: active)`：

- 背景使用 Canvas，文字使用 CanvasText；
- 面板、卡牌、花盆以系统 Border 区分；
- 选中态使用 `outline` 与 `aria-pressed`；
- 阳光/雨露/虫害保留完整文字；
- 装饰花瓣可简化，但 `n / 5` 与 progress 不消失。

若 CSS 部分失败，DOM 顺序仍按当前需求、操作、双方进度、历史排列，可完成游戏。

## 12. Fidelity ledger

| 设计决定 | 生产证据 |
| --- | --- |
| 夜晚双盆花园 | `app-shell`、双色花盆、纯 CSS 渐变与花朵 |
| 公开信息优先 | 每个非 intro phase 都有当前需求/价值/双方精确分数 |
| 秘密节点退出 | 阶段 DOM 测试与 Chrome 检查 |
| 两方公平 | 相同花朵几何、相同卡按钮、交替第一席位 |
| 温和阻断 | 虫害不回收旧花瓣、不出现枯萎表现 |
| 非颜色信息 | 牌名、说明、符号、纹理、数值 |
| 响应式 | 320×568、768×1024、1440×900 截图/尺寸检查 |
| 减少动态 | 媒体查询下所有规则相关状态即时呈现 |
| 强制颜色 | 系统色、outline、文字牌种和 progress |
| 零第三方资产 | 无 assets 目录、无远程 URL、`ATTRIBUTION.md` 明确原创范围 |

## 13. 设计冻结

生产实现应忠实落地本文件，不另加：

- 写实虫害、枯萎植物或破坏动画；
- 现成花卉插图、icon 包、外部字体或音频；
- 卡牌稀有度、库存商店、模式选项；
- 隐藏结果、随机视觉奖励或自动推进；
- 需要用户再次确认的视觉概念 Gate。

若实现受可访问性或窄屏约束需要偏离，先记录 fidelity ledger 的偏差与理由，再改
代码；不能以“更好看”为由牺牲阶段隐私和公开信息层级。
