# A 级“拼回这一刻”私人照片拼图规格

## 1. Brainstorm 结论

本批实现一个完全本地的 3×3 私人照片交换拼图：准备者从电脑或手机选择一张两人的照片，应用在浏览器内中心裁成方形并打乱成九块；体验者每次点选两块进行交换，直到拼回完整照片。

| 方案 | 优点 | 风险与成本 | 本批决定 |
| --- | --- | --- | --- |
| 3×3 任意两块交换 | 任意排列都可解；两次离散点击适合触摸和键盘；状态机小 | 玩法比不规则拼图轻 | 采用，完全自行实现 |
| 传统带空位滑块 | 规则经典 | 随机排列存在不可解局面，需要合法移动生成或奇偶校验 | 不采用 |
| Headbreaker 不规则拼图 | 拼片形状和拖拽更像真实拼图 | 浏览器 renderer 通常还要 Konva、bundle 和大量移动端拖拽 Gate | 本批不引入 |
| 照片翻牌配对 | 重玩性较好 | 需要多张成对素材，翻面计时和状态竞争更多 | 留作后续独立玩法 |
| 预先提交方形照片 | 实现最轻 | 私人照片容易误入公开仓库，且不符合“本地图片导入”路线 | 不采用 |
| 原生文件选择 + 一次性 Canvas 裁切 | 用户不改代码即可使用任意常见照片；不提交私人素材 | 需要管理原图与派生图两个 blob 生命周期 | 采用 |

作品名为“拼回这一刻”，目录 ID 为 `photo-swap-puzzle`，主分类为单人惊喜。首版由一人选择照片后把设备交给对方，也允许两个人在同一设备上共同完成。

## 2. 严格最小范围

只实现：

- 单张 JPEG / PNG / WebP 本地照片；
- 固定 3×3 九块；
- 第一次点选、再次点同一块取消、点第二块交换；
- 交换次数、当前选中态、完成态；
- “换一张照片”“重新打乱”“清除照片”；
- 完成后显示中心裁切的完整图片和一句固定结尾；
- 鼠标、单指触摸、Tab、Enter 与 Space 共用原生按钮路径。

明确不做拖拽、空位滑块、不规则拼片、旋转拼片、难度选择、计时、最佳纪录、提示、撤销、多图、裁切编辑器、下载、分享、账号、持久化、音频、彩纸或服务端。

## 3. 为什么是 A 级

页面使用经典相对脚本、相对样式、原生 File / Image / Canvas / Blob API，不使用 ES Modules、`fetch()`、CDN 或第三方依赖。直接双击作品 `index.html` 即可选择照片和完成拼图；统一门户只是入口，不是运行前提。

根依赖不会因此增加 Canvas 库、拼图库、图标库或构建工具。作品目录可以单独复制给对方。

## 4. 用户流程

1. 打开页面，看到用途、隐私承诺和照片要求；
2. 点击“选择一张照片”，浏览器原生选择器只接受 JPEG / PNG / WebP；
3. 应用检查 MIME、大小、可解码尺寸，再把照片中心裁成方形 JPEG 派生图；
4. 原始对象 URL 立即释放，派生图只留在当前页面内存；
5. 生成一个非完成态的 0–8 排列并显示九个按钮拼块；
6. 第一次点击选中一块；再次点同一块取消；点击另一块交换并把交换次数加一；
7. 排列成为 `[0,1,2,3,4,5,6,7,8]` 时锁定拼图、显示完整派生图和完成文案；
8. “重新打乱”复用同一派生图并清零次数；“换一张照片”先验证新图，失败时保留当前拼图；
9. “清除照片”或离开页面时释放全部仍由应用持有的对象 URL。

## 5. 文件与尺寸 Gate

纯逻辑接口：

```text
validateFileMetadata({ type, size })
assessImageDimensions({ width, height })
```

- MIME：`image/jpeg`、`image/png`、`image/webp`；
- 文件必须大于 0，最大 20 MiB；
- 宽高必须是正整数，短边至少 600px；
- 任一边超过 6000px 时拒绝，避免高像素照片在移动端解码占用过多内存；
- 不限制原图比例，不读取 EXIF、GPS、设备或拍摄时间；
- 解码失败、Canvas `toBlob()` 失败和不满足尺寸 Gate 都显示稳定错误，并保留当前有效拼图。

## 6. 中心裁切与图片生命周期

裁切不是交互编辑器，只做稳定的中心正方形：

1. 为原始 File 创建候选 URL；
2. `Image` 解码后得到自然宽高；
3. 取 `cropSize = min(width, height)`，以图片中心为裁切区域；
4. 输出边长为 `min(1200, cropSize)` 的 Canvas；
5. 先用页面纸色填充，再绘制中心裁切，输出质量 0.9 的 JPEG Blob；
6. 为派生 Blob 创建活动 URL，随后撤销原始候选 URL；
7. 新派生图准备完成后才撤销旧派生图并替换拼图。

连续选图使用递增 token。较慢的旧解码或 `toBlob()` 回调完成时必须先比较 token；过期结果只清理自己的 URL，不能覆盖后选照片。`pagehide` 与 `beforeunload` 共用幂等清理。

派生 JPEG 不继承原文件的 EXIF 元数据，但作品仍不声称自己是恶意文件扫描器或取证级元数据擦除工具。

## 7. 排列与状态机

逻辑层保持无 DOM 纯函数：

```text
createShuffledOrder(itemCount, unitValues)
createPuzzleState(order)
selectPosition(state, position)
isSolved(order)
getTileCoordinates(tileIndex, gridSize)
```

- 使用 Fisher–Yates；浏览器通过 `crypto.getRandomValues()` 提供 `[0,1)` 随机值，不使用 `sort(() => Math.random() - 0.5)`；
- 洗牌结果必须是 0–8 的完整排列；若极端随机值产生完成态，则把排列循环移动一位；
- 第一次点击只记录 `selectedPosition`，不计交换；
- 再次点击同一位置清除选择；
- 第二个不同位置只交换这两个位置，`moves + 1`；
- 每次交换后调用 `isSolved()`；完成后状态进入 `solved`，拒绝继续交换；
- “重新打乱”创建新状态并清除旧选择、次数与完成态。

每个 DOM 按钮的位置固定，不在交换时重建。应用只更新按钮对应的 `tileIndex`、背景位置和可访问名称，因此键盘焦点不会因 DOM 替换丢失。

## 8. 图片切片与可访问性

- 九块使用原生 `<button>`，共享派生方图 URL；
- `background-size: 300% 300%`，按目标行列设置 `0% / 50% / 100%` 背景位置；
- 选中态同时使用轮廓、轻微位移和 `aria-pressed`，不能只靠颜色；
- 可访问名称包含“原图第几行第几列的拼块、当前第几行第几列”，非视觉用户也能按目标位置交换；
- 当前选择、交换次数、错误和完成通过 `aria-live="polite"` 宣布；
- 完成图使用真实 `<img>`，alt 为“已经拼好的私人照片”，不猜测照片内容；
- 所有主按钮至少 48px 高，390×844 和 320px 宽度无横向溢出；
- `prefers-reduced-motion` 下取消交换位移动效与完成淡入；
- JavaScript 不可用时显示明确说明，不伪装成可玩的拼图。

## 10. 隐私与资源边界

- 公网依赖：无；第三方运行依赖：无；
- 不使用 `fetch`、XHR、WebSocket、form submit、localStorage、IndexedDB、Cache API、Service Worker 或云同步；
- 文件名不进入 URL、服务端日志、DOM 文案或持久化；
- 原始照片与派生图都只存在当前浏览器上下文；
- 仓库不提交示例情侣照片、用户照片、相册封面、远程字体、音乐或统计脚本；
- Network 验收只允许当前 `file:` 页面及相对 CSS / JS，或统一本地服务下的等价 localhost 请求。

## 11. 借鉴与来源声明

- 传统九宫格交换拼图：只采用“点选两块交换直至还原”的通用玩法机制，状态、代码、视觉、文案和测试均独立实现；
- [flbulgarelli/headbreaker](https://github.com/flbulgarelli/headbreaker) 3.0.0（ISC）：调研阶段用于比较不规则拼片、拖拽和自动验证能力；本作品不安装其 npm 包，不复制其 bundle、源码、API、视觉、文案或素材；
- [ahmedknasr-dev/Vanilla-JavaScript-Memory-Card-Game](https://github.com/ahmedknasr-dev/Vanilla-JavaScript-Memory-Card-Game)（MIT）：调研阶段用于比较照片翻牌机制；本作品不复制其代码、布局、专辑图片或素材；
- 本仓库“回到那一天”：只复用本仓库自行实现的 File → blob、递增 token 和幂等清理经验，不复用 Pannellum 代码或依赖。

许可证于 2026-07-15 通过两个上游仓库当前 `LICENSE` 文件复核。Headbreaker npm 当前版本为 3.0.0，浏览器 renderer 的包依赖仍声明 `konva ^6.0.0`；这些依赖均不进入本作品。

若未来改为引入 Headbreaker 或翻牌上游代码，必须另行保存许可证与版权通知，不能继续沿用“只调研、未复制”的声明。

## 12. 自动测试

至少覆盖：

- 合法 MIME、空文件、超大文件和非法大小；
- 最小短边、最大边和非法尺寸；
- 洗牌是完整排列、注入随机值后可预测、初始不为完成态；
- 首次选择、重复取消、第二次交换、交换次数；
- 非法位置不改变状态；
- 完成后锁定，重新打乱清空状态；
- 九块背景行列坐标覆盖四角与中心；
- catalog 与 verifier 能找到 A 级入口、README 和全部相对资源。

## 13. Chrome 验收

- 空状态、验证中、游戏中、选中、完成、错误和清除状态均可见；
- 页面内生成有效 JPEG File，完成中心裁切并显示九块；
- 固定随机输入或受控状态完成整局，完成图与文案出现；
- 非图片、短边过小、损坏图和快速连续选择不覆盖当前有效拼图；
- 清除后派生 URL 被撤销，九块背景和完成图不再引用旧 URL；
- 鼠标点击、Tab + Enter / Space、390×844 和 320px 宽度通过；
- 控制台无未处理异常，Network 无公网请求；
- 概念图与最终桌面 / 移动截图通过 `view_image` 对照。

## 14. 完成标准

- 双击 `index.html` 即可打开并选择本地照片，不需要 setup 或 start；
- 有效照片能生成可解、非完成态的 3×3 拼图；
- 任意两块交换、取消选择、完成锁定、重新打乱和清除均正确；
- 无效替换保留当前拼图，快速选图与离开页面不会遗留应用 URL；
- 390×844 与 320px 无横向溢出，键盘焦点稳定；
- README 明确隐私、尺寸、A 级启动、移动边界和完整借鉴声明；
- `npm test`、`npm run verify`、脚本语法检查和 `git diff --check` 通过；
- 规格、实现和 QA / 学习沉淀分别形成清晰提交边界。
