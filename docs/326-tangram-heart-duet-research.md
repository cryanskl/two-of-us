# Tangram Heart Duet：七片协作拼形调研

> 调研日期：2026-07-25  
> 候选代号：`tangram-heart-duet`  
> 推荐发布 ID：`seven-piece-duet`  
> 推荐中文名：**七片同心**  
> 分类：`co-op`  
> 运行等级：A，经典脚本、相对路径、`file://` 直开  
> 调研结论：**Conditional Go**

## 1. 执行结论

这个候选可以继续，但不应直接按“爱心七巧板”落地。低差异版本会同时撞上现有照片拼图、共享刚体搬运和爱心牵引题材；推荐把产品核心冻结为：

> 两位玩家各自拥有一组不可代操的凸多边形，在同一块公开拼形板上，通过离散平移、旋转和有限翻面，把七片共同铺满一个原创轮廓。

首版只做一台设备、同屏合作、四个固定原创轮廓。每局使用全部七片，片间不得重叠，轮廓内不得留空。两组面积相等但片数分别为四片与三片；每局交换归属组，让双方轮流承担细片和大片。

推荐从 `tangram-heart-duet` 改名为 `seven-piece-duet`，原因不是规避传统玩法名称，而是：

- “Tangram”容易让实现误以为要复刻某个现成七巧板程序；
- “Heart”把内容收窄为爱心，和 `tethered-heart`、仓库大量心形表达产生不必要的题材重叠；
- “七片同心”保留情侣合作语气，同时把差异落在“独占片组共同铺形”。

若总控要求保留原 ID，机制和原创边界仍必须按本文执行；文件名保留候选代号只是编排事实，不代表最终产品名已经冻结。

## 2. 调研问题

本轮回答：

1. 传统七片拼形能否用无依赖经典 JavaScript 在 `file://` 下稳定实现？
2. 怎样让“双人”成为规则必要条件，而不是两个人轮流玩一款单人拼图？
3. 怎样与 `photo-swap-puzzle`、`moving-home-together`、`dual-maze-race`、`tethered-heart` 保持可测试差异？
4. 怎样不用浮点多边形布尔运算，也能精确判断越界、重叠和完成？
5. 鼠标、触摸和键盘怎样共享一套可取消、可恢复的动作协议？
6. 参考开源项目时，哪些只借鉴抽象机制，哪些内容明确不复制？

## 3. 当前仓库事实与重复审计

`experiences/catalog.json`、相关规格和现有实现表明，仓库已经覆盖照片换块、双端搬运、连续牵引、轮流连边和双盘迷宫等相邻体验。候选只有守住“独占片组 + 同一目标 + 精确铺形”才有增量。

| 相邻项目 | 已有核心 | 低差异风险 | 本候选必须保持的差异 |
| --- | --- | --- | --- |
| `photo-swap-puzzle` | 本地照片被切成九个矩形；点两块任意交换，恢复原顺序 | 如果七片只是在槽位间交换，就只是换皮拼图 | 不使用照片、九宫格或任意交换；凸片可离散旋转/翻面/平移，规则验证几何占格 |
| `moving-home-together` | 双方持续控制同一张沙发两端，在 S 形走廊内平移旋转 | 如果双方共同拖一块大拼片，就是共享刚体搬运 | 每人只操作自己的若干独立片；没有连续速度、走廊、双端合成、碰撞微步或松手保持 |
| `dual-maze-race` | 两块独立同构迷宫、同 tick 竞速、换席计分 | 如果双方各拼一块盘比速度，就会变成双盘竞速 | 只有一块共享目标；没有胜负、计时、赛程、积分或双方独立终点 |
| `tethered-heart` | 两条连续丝带共同牵引一个有惯性的布艺心 | 以心形为唯一视觉会形成题材近似，双人共同影响也可能误读 | 不使用丝带、张力、惯性、危险物或共享载荷；默认目标包不以心形为唯一或首个目标 |
| `constellation-relay` | 双方严格轮流沿公开轮廓追加边，避免相交和无解前缀 | 若首版强制轮流放一片，节奏接近轮流构形 | 不设轮次；双方可随时操作自己的片，核心是片组归属和精确覆盖，不是连边 |
| `twin-light-maze` | 两个角色在同一地图以压力板和门互相依赖 | 都是同屏合作 | 本候选没有角色移动、机关、出口或实时方向键并发 |

### 3.1 低差异版本一律拒绝

- 一方负责拖，另一方只负责旋转同一片；
- 把一张情侣照片切成七片再拼回；
- 双方各有同一轮廓，以速度或步数决胜；
- 双方必须严格轮流放片；
- 用自由旋转、碰撞引擎和惯性把片“撞进”目标；
- 只做一个心形轮廓，并沿用布艺、丝带或刺绣视觉。

这些版本分别回退到共享对象、照片拼图、双盘竞速、轮流构形、物理搬运或心形牵引，不进入后续规格。

## 4. 推荐机制

### 4.1 七片与归属

首版使用传统七片构成这一通用事实：两枚大直角等腰三角形、一枚中三角形、两枚小三角形、一枚正方形和一枚平行四边形。具体坐标、比例表达、片 ID、初始布局和目标轮廓必须由本仓库独立推导并记录生成过程，不读取或转写上游坐标。

把面积分成相等的两组：

- 细片组：一枚大三角形、一枚中三角形、两枚小三角形，共四片、总面积二分之一；
- 大片组：另一枚大三角形、正方形、平行四边形，共三片、总面积二分之一。

四局按 `AB → BA → AB → BA` 交换两组归属。双方总共各控制两局细片组、两局大片组。归属是规则权限：对方的 Pointer、键盘命令或 DOM 激活不能提交该片动作。

### 4.2 无轮次共同铺形

- 所有目标信息公开，没有隐藏题面或私聊阶段。
- 两位玩家可以同时或交错调整自己的片，不等待回合。
- 选择和拖动只产生预览；只有释放或键盘“放下”才尝试提交。
- 非法提交返回原状态，不惩罚、不归因任何一方。
- 完成只属于双方，不统计个人分、移动次数或“最后一片英雄”。
- 每局完成后交换片组；四局完成显示共同收束文案。

这使合作必要性来自权限分割，而不是文案：任何一位玩家都没有提交全部七片所需的合法权限。

## 5. 精确几何可行性

### 5.1 不采用浮点多边形布尔运算

直接用 Canvas/SVG 像素或浮点多边形求交判断完成，会产生 epsilon、边界接触、不同缩放和浏览器舍入问题；引入 clipping/物理库又违背首版最小依赖。

推荐使用**原子三角格元**作为权威规则：

- 逻辑平面是固定整数方格，每个方格沿冻结对角线分为两个直角等腰原子三角形；
- 每一片由一组原子三角格元 key 构成；
- 每个目标也是一组原子格元 key；
- 平移、45° 离散旋转和仅平行四边形允许的翻面，先变换整数顶点，再规范化为格元集合；
- 合法位置要求片的格元集合是目标集合子集，且与已提交片集合交集为空；
- 完成要求七片均已提交，七片格元并集与目标集合严格相等。

集合 key 需要稳定、无浮点：

```text
cellKey = `${x}:${y}:${diagonal}:${half}`
```

其中 `x/y`、对角线方向和半格标志均为整数枚举。实现前必须用独立生成器证明旋转/翻面后的格元数量和面积保持不变，不能把上游多边形顶点抄成常量。

### 5.2 渲染与规则分层

- 逻辑层只接受 piece ID、owner、整数位置、`rotationIndex` 和 `flipped`；
- SVG 可按同一整数顶点绘制片和目标；
- CSS transform、DOM 像素、Pointer 坐标和动画不能回写为权威状态；
- Pointer 坐标只量化到最近合法格点，形成候选 action；
- 预览可以半透明，但不进入完成判定；
- 目标缩放只改变投影，不改变格元 key。

因此同一动作日志在不同 DPR、视口和刷新率下应得到深相等终态。

## 6. 输入与可访问性

### 6.1 Pointer / 触摸

- 每片是可聚焦的原生按钮或具有等价按钮语义的 SVG 控件；
- `pointerdown` 只建立 `{pointerId, generation, pieceId, owner}` 会话；
- 移动只更新候选预览；
- `pointerup` 才提交合法位置；在释放前拖回起点可取消；
- `pointercancel`、`lostpointercapture`、页面隐藏、窗口失焦和重开都撤销预览，不提交动作；
- 每个 pointerId 只能绑定一片；第三根手指不夺取已有会话；
- 两枚 Pointer 可同时操作双方各自的一片；
- 拼片直接命中区在常见移动视口至少 48×48 CSS px；这是仓库产品 Gate，不冒充 WCAG 的法定尺寸。

### 6.2 鼠标

鼠标走同一 Pointer 路径。单鼠标不承诺“同时拖两片”，但双方可无轮次交错操作；规则不依赖并发事件时序。鼠标右键、中键和 hover 不是必需路径。

### 6.3 键盘

- Tab 顺序进入双方片组和各自控制区；
- Enter/Space 选择或放下当前片；
- 聚焦片时，方向键按一个格点移动预览；
- “左转”“右转”“翻面”“放下”“撤销本片”均有可聚焦原生按钮，不以全局单字符快捷键作为唯一入口；
- 平行四边形之外的片不显示可用翻面动作；
- 对方片被触发时显示权限说明，状态不变；
- 焦点在输入、帮助或非棋盘控件时不拦截方向键；
- 状态区只播报选择、合法放置、非法原因、换局和完成，不逐格播报拖动坐标。

首版不要求同一物理键盘同时控制两片，避免 keyboard ghosting 成为合作成败条件。

### 6.4 视觉与响应式 Gate

- 归属同时用玩家名、纹理/符号、边框和颜色表达；
- 目标空白、合法预览、冲突、越界、已放置和完成都有非颜色信息；
- 明显 `:focus-visible`，不因重渲染丢失焦点；
- `prefers-reduced-motion` 关闭吸附飞行、庆祝漂浮和脉冲，不改变规则；
- forced colors 下轮廓、片边界、焦点、归属符号仍可区分；
- 200% 与 400% 浏览器缩放可操作，不禁止页面缩放；
- 验收视口至少覆盖 320×568、390×844、844×390、768×1024、1440×900。

## 7. A 级、依赖与隐私合同

### 7.1 A 级成立条件

作品目录使用：

- 相对 `index.html`、CSS 和经典 `<script src>`；
- 原生 HTML、CSS、SVG、Pointer Events；
- 无 ESM、`fetch()`、XHR、WebSocket、CDN、远程字体、远程图片或 Service Worker；
- 无 npm 运行依赖、无安装步骤、无构建前置；
- 直接双击作品目录的 `index.html` 能完成四局。

统一入口不是运行前提。项目目录可以单独复制给对方。

### 7.2 隐私

候选不需要姓名、照片、文件、音频、摄像头、麦克风、位置、设备传感器或账号。首版：

- 零网络；
- 零存储，包括 local/sessionStorage、IndexedDB 和 Cache API；
- 零权限请求；
- 不采集按键、Pointer 轨迹、完成时间、设备信息或遥测；
- 页面刷新即回到初始状态。

若未来允许自定义称呼，也只能从本地配置脚本读取并做纯文本输出；本轮不把它加入范围。

## 9. 原创内容与污染防线

进入实现前必须：

1. 用本仓库独立脚本或书面推导生成七片格元模板；
2. 以目标格元集合反向组合原创轮廓，不临摹网络题面；
3. 每个目标保存唯一 ID、格元集合、标准解和内容指纹；
4. 执行平移、旋转、镜像归一化去重，确保四个目标彼此不是简单变换；
5. 对仓库现有心形、星形、房屋、纸鹤等高频视觉做人工近似审查；
6. 不把调研上游截图、demo 或轮廓作为 ImageGen、设计工具或开发提示的输入。

首版推荐抽象、非具象的原创轮廓名，如“相拥”“并肩”“归帆”“同路”；名称只是叙事，不引用现实品牌、角色或作品。若无法证明轮廓独立生成，保持 Conditional Go，不能用“传统题面”作为权利兜底。

## 10. 测试与浏览器 Gate

### 10.1 纯规则

- 七片格元数量、面积和凸性固定；
- 所有允许旋转/翻面保持格元数量；
- 非法 piece、owner、坐标、rotation、flip、action 不改变状态；
- 对方不能提交不属于自己的片；
- 越界、正面积重叠、未覆盖和缺片不完成；只沿边接触合法；
- 七片并集严格等于目标才完成；
- 同一动作日志重复运行深相等；
- 重开与首次状态深相等；
- 四个目标都有仅用生产 action 的 golden replay；
- 目标指纹在平移、旋转和镜像归一化后互异。

### 10.2 浏览器

- 鼠标完整完成一局；
- 键盘不依赖拖拽完整完成一局；
- 两枚真实触点同时操作双方各一片，取消其中一枚不提交也不影响另一枚；
- 非法释放回到已提交状态，焦点和 live 文案正确；
- 320×568、390×844、844×390、768×1024、1440×900 无不可达控件或横向玩法溢出；
- 200%、400%、reduced motion、forced colors 和键盘焦点通过；
- `file://` 完成四局，控制台无错误，零远程请求、零存储、零权限。

### 10.3 仓库

- 项目测试、`npm run verify`、`git diff --check` 通过；
- 静态扫描无 ESM、网络、存储、远程 URL 和新增依赖；
- README 与 ATTRIBUTION 固定来源、原创边界和 A 级合同一致；
- catalog 只在全部 Gate 通过后由总控单独集成。

| 变成普通单人拼图 | 分类与产品增量失真 | 片组权限不可绕过、每局交换归属、共同完成无个人计分 | 权限测试必须证明任一方都不能单独合法提交全部七片 |
| 浮点边界误判 | 同一布局在不同浏览器结果不同 | 原子格元集合为权威，SVG 仅投影 | 所有完成和冲突判定不读取像素或 epsilon |
| 原创轮廓误用网络题面 | 权利和借鉴声明失真 | 独立生成、指纹、标准解和内容审计 | 四个目标全部有可追溯原创记录 |
| 三/四片组体验不均 | 一方操作量或难度长期偏斜 | 面积各半，四局换组 | 可用性实测双方都在每局产生有效操作，整场两组各控制两次 |

| 与 `tethered-heart` 题材重叠 | 新体验被理解为爱心换皮 | 改名、四个抽象轮廓、心形不作首个或唯一目标 | 视觉提案通过独立审查 |
| 上游污染 | 声明“独立实现”不可信 | 不读源码、不用截图/题面/坐标，固定来源边界 | ATTRIBUTION 与 git diff 人工复核 |

## 12. Go / No-Go

当前判断：**Conditional Go**。

可以进入 brainstorm、规格和实施计划；只有以下条件同时满足才转为 Go：

1. 总控接受“七片同心 / `seven-piece-duet`”或确认保留原 ID 但采用相同机制边界；
2. 原子格元模型可表达七片全部允许姿态且无浮点判定；
3. 四个目标独立生成、可解、互不等价，并通过内容审计；
4. 权限分割在 Pointer、鼠标和键盘路径均不可绕过；
5. 真实双触控、键盘等价、响应式、降动效和 forced colors 通过；
6. `file://` 四局、零依赖、零网络、零存储、零权限通过；
7. README/ATTRIBUTION 完整记录固定来源和零复制边界。

若精确格元无法承载自然的七片旋转，或只能靠复制现成坐标/轮廓才能完成，判 **No-Go**；不以加入多边形库或降低原创审计来掩盖。
