# C 级“我们的地点”Brainstorm

- 日期：2026-07-25
- 工作 ID：`our-place-guess`
- 输入：[`330-our-place-guess-research.md`](./330-our-place-guess-research.md)
- 本阶段范围：选择玩法方向、分类和最小闭环；不写生产代码
- 结论：选择 **合作类 C 级“你记得，我们在哪里”**

## 1. 产品机会

地图猜点本身很常见，真正适合这个仓库的不是“懂多少世界地理”，而是：

> 同一句只属于两个人的回忆，会把你们带回同一个地方吗？

这句话带来四个设计约束：

1. 题目来自两个人的共同经历，不来自公共城市题库；
2. 双方都要做出选择，不设置固定出题者；
3. 先各自回答，再同时揭晓，保留“原来你也记得”的瞬间；
4. 结果鼓励复盘回忆，不把距离误差变成关系评价。

## 2. 候选方案

### 方案 A：最近的人获胜

每轮给出一座城市或一句公开线索，两人同时落点，距目标更近者得分。

优点：

- 规则一句话能讲清；
- 天然适合双设备和密封提交；
- 对抗反馈直接。

拒绝原因：

- 与 Posio 的核心体验最接近；
- 需要较大的公共地点题库；
- 地理知识强者会持续碾压，情侣语义弱；
- 触屏误差、地图投影和网络时序都会被理解为竞技公平问题；
- 目录已有足够多清晰胜负的 versus 作品，不值得用近似机制再占一项。

### 方案 B：轮流藏地点

一人选择目标地点并写线索，另一人在地图上猜；下一轮换角色。

优点：

- 支持临时发挥，不用预制题包；
- 对方的线索天然有私人感。

拒绝原因：

- 与 `lan-pictionary` 的“掌握秘密题目者 → 猜题者 → 换角色”高度同构；
- 现场选择精确坐标和写线索会拖慢开局；
- 出题者需要知道如何在无地名地图上准确落点；
- 主机迁移和角色秘密同步更复杂。

### 方案 C：双人密封回忆落点

房主导入一组私人地点卡。每轮双方看到同一条回忆线索，各自在离线世界图上落点并提交。两份提交都到齐后才显示目标、双方落点和共同成绩。

优点：

- “我们的地点”是题目本身，不是美术包装；
- 两人每轮都参与，没有固定出题者；
- 复用成熟的密封回合，不增加共享依赖；
- 结果页天然适合讲“你为什么点这里”；
- 与 Posio 的公共地理对抗形成明确原创边界。

风险：

- 房主知道自己导入的答案，可能占信息优势；
- 私人地点文件的格式与错误反馈需要极简；
- 只有世界轮廓时，小范围地点不适合精确点选；
- 双方可以口头告诉对方答案，无法技术防作弊。

处理方式：

- 明确它是合作回忆仪式，不是防作弊竞技；
- 题包最好由第三方准备、由其中一人提前准备后隔一段时间游玩，或使用双方都知道但未必能精确定位的回忆；
- 成绩采用宽松档位，不比较谁更好；
- 先各自提交再交流是推荐礼仪，不宣称安全强制；
- 首版只做世界尺度的地点，不做街道或建筑级定位。

**采用。**

### 方案 D：会合点

双方分别收到不同线索，各自落点，两点中点越接近目标越好。

优点：

- 两个人的答案会真正合成为一个几何结果；
- 与常规最近点玩法不同。

拒绝原因：

- 中点规则难以从情侣语义自然解释；
- 两个很差、方向相反的答案可能意外得到好成绩；
- 不利于回忆复盘；
- 需要额外解释投影和球面中点，首版认知负担过高。

可作为未来独立实验，不进入本作。

## 3. 分类决定

最终分类：**co-op**。

不是 versus 的原因：

- 结算只产生共同等级，不产生单轮赢家或总冠军；
- 使用两人误差中的较差值，让“双方都靠近”才得到更高共同成绩；
- 结果文案引导互相讲述记忆线索；
- 不显示个人排行榜、连胜、胜率或“拖后腿”评价；
- 触控精度差异不会被包装成胜负。

它仍有并排比较两枚 pin 的视觉张力，但这是共同回忆差异的揭晓，不是对抗排名。

## 4. 冻结的一句话玩法

> 看一段只属于你们的回忆，各自在离线世界图上留下第一枚落点；两枚都密封后，一起揭晓那个真正的地方。

## 5. 最小体验闭环

```text
启动本地门户
→ 两台设备创建 / 加入五位码房间
→ 房主选择“虚构示例题包”或从本机导入私人 JSON
→ 双方确认准备
→ 显示同一条回忆线索
→ 双方分别落点、调整、确认并密封
→ 两人都提交后同时揭晓目标和两枚落点
→ 显示各自距离、共同档位和复盘问题
→ 下一轮
→ 四轮共同总结
```

首版固定四轮。私人题包可以多于四张，由房主在开局时随机抽取四张；不足四张不能开始。

## 6. 地点卡

### 6.1 用户看见的内容

每张卡在提交前只公开：

- 标题，例如“那次错过末班车以后”；
- 一句线索，例如“我们在海边坐到路灯熄灭”；
- 可选的时间提示，例如“初秋”；
- 当前回合与总回合数。

提交前不显示：

- 目标经纬度；
- 城市、国家或地址；
- 其他卡片；
- 房主本地文件名和路径；
- 结果结语。

### 6.2 结果内容

两人都提交后才显示：

- 目标 pin；
- 两枚玩家 pin；
- 各自大圆距离；
- 本轮共同档位；
- 准备者写的一句结果结语；
- 一个固定复盘问题：“你刚才先想起的是哪一幕？”

### 6.3 默认与私人题包

默认题包必须完全虚构，作用是让任何人不准备文件也能走完整流程。它不能伪装成仓库作者的真实关系记录。

私人题包：

- 使用原生文件选择器；
- 文件只由房主浏览器读取；
- 不上传本地服务，不转发给另一端；
- 完整卡组不写入浏览器存储；
- 只按阶段发送当前公开字段和最终揭晓字段；
- 成员变化、刷新或服务重启即丢弃。

首版使用 JSON，是因为它可离线、可审计、无需解析库，也便于提供模板和校验错误位置。首版不提供页面内题包编辑器、地址搜索、照片导入或地图选点制题。

## 7. 回合内交流

推荐礼仪是“都提交之前先不说地点，揭晓后再讲为什么”，但不做技术防作弊：

- 不申请麦克风；
- 不提供内置聊天；
- 不遮挡现实中的口头交流；
- 不宣称密封协议能防止查看源码、窥屏或房主记住答案；
- 产品文案使用“先把第一感觉留在地图上”，不使用“禁止交流”“作弊”等竞技措辞。

这样既保留惊喜，也符合情侣面对面玩的现实情境。

## 8. 共同结算

### 8.1 为什么用较差距离

如果用平均值，一个人的精准答案可能掩盖另一个人的完全偏离；如果用两点间距离，只能衡量彼此一致，无法判断是否接近目标。

采用：

```text
jointDistance = max(playerADistance, playerBDistance)
```

它表达“只有两个人都走到附近，这段回忆才共同抵达”。

同时显示两人的公里数，但不标记“赢家”“更好”“较差玩家”。共同档位只由 `jointDistance` 决定。

### 8.2 总结

四轮后显示：

- 四轮共同档位；
- 两人都进入目标 200 km 内的回合数；
- 最接近共同抵达的一轮；
- 固定结语和准备者可选的整场结语。

不累加成一个看似精密的总公里数，不做排行榜和历史保存。

## 9. 视觉方向

关键词：

- 夜行纸图；
- 两枚不同形状的珐琅 pin；
- 细线把两个人的记忆牵向同一颗目标星；
- 温暖墨色、雾蓝海面、旧金色经纬网；
- 世界轮廓是背景，不是地理工具站。

差异化要求：

- 不使用 Posio 的页面结构、颜色、图标或地图风格；
- 不使用在线地图常见的瓦片、缩放控件和地点标签；
- 不模拟护照、登机牌等已被旅行产品过度使用的版式；
- 玩家 pin 由形状、文字和颜色共同区分；
- 目标在揭晓前不以隐藏 DOM、透明图层或 CSS 变量存在。

## 10. 无障碍与输入方向

首版从设计阶段冻结：

- 地图操作既支持触屏/鼠标，也支持键盘；
- 点按后先放置可调整 pin，另按“密封这枚落点”才提交；
- 方向键移动，Shift + 方向键细调；
- 地图具有可读的当前经纬度粗略描述，但不显示地名；
- 所有状态变化通过克制的 `aria-live` 文案宣布；
- pin 不只靠颜色区分；
- 触控主按钮至少 48 px；
- 320、390、768、1280 px 无横向溢出；
- `prefers-reduced-motion` 下取消飞线和 pin 弹跳；
- `forced-colors` 下轮廓、焦点、pin 和按钮仍可辨认。

## 11. 首版明确不做

- 公共城市、国旗或地标题库；
- 最近者获胜；
- 账号、昵称、头像、历史记录和排行榜；
- 公网匹配或公共服务器；
- 在线地图、瓦片、地址搜索和反向地理编码；
- GPS、定位、相机、麦克风和照片；
- 街道或建筑级猜点；
- 题包可视化编辑器；
- AI 生成线索；
- 断线续局；
- 观战、第三人和分享链接；
- 音乐、音效和振动；
- Django、Redis、Leaflet 或新 npm 依赖。

## 12. 名称候选

| 名称 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 我们在哪里 | 直接 | 像定位工具，也像关系疑问 | 不采用 |
| 猜猜我们的地点 | 清楚 | 功能名，惊喜感弱 | 可作目录说明 |
| 两枚落点 | 机制明确 | 情绪不够 | 不采用 |
| 地图记得我们 | 有画面 | 地图像主语，略偏文艺 | 备选 |
| **你记得，我们在哪里** | 同时含“你”“我们”“记得”和地点问题 | 稍长 | **采用** |

冻结：

- 目录展示名：`你记得，我们在哪里`
- 工作 ID：`our-place-guess`
- 短说明：`看同一段回忆，各自密封落点，再一起揭晓真正的地方。`

## 13. 进入规格的条件

本方案满足调研的 Go Gate：

- 分类为 co-op；
- 不采用 Posio 的公共地理对抗；
- 私人题包只在房主浏览器内存；
- Natural Earth 固定物理 land 数据可离线派生；
- 复用现有 C 级房间与密封提交；
- 无新依赖、无在线瓦片、无公共服务器；
- 经纬度、大圆距离和移动端输入有明确公平边界；
- 代码、地图数据、视觉资产和外部概念可分别声明。

下一阶段规格应冻结题包 schema、状态机、公开/秘密 view、房间消息、距离公式、断线行为和浏览器 Gate。
