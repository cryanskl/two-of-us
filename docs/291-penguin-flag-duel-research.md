# 企鹅冰原夺旗：research

## 结论

- 候选 ID：`penguin-flag-duel`
- 对外标题：企鹅冰原夺旗
- 分类：双人对抗
- 运行等级：A
- 决策：**Conditional Go**

可以进入设计与实现，但安装进目录前必须同时通过固定步物理、键盘矩阵与双指触控、确定性重放、后台暂停、响应式和原创素材六组门槛。若实现只剩“在冰面互撞”或“先碰中央目标得分”，则与现有作品重复，应判 No-Go。

## 研究问题

V18“冰面企鹅夺旗”要解决的不是能否画出两只企鹅，而是：

1. 单个本地 HTML 能否提供低摩擦但仍可控的双人实时竞技；
2. 夺旗闭环是否足以区别于仓库中已有的相扑、轨迹封锁与目标竞速；
3. 同一台设备上的键盘与触控能否承载两个玩家同时输入；
4. 不依赖服务器、网络、构建器、图片包或第三方物理库时，规则能否确定性重放；
5. 切后台、帧率抖动、窄屏与降动效条件下，比赛是否仍公平。

### 重复判定

以下三个版本不应实现：

- 企鹅版软软相扑：只靠冲撞出界；
- 冰面星轨竞速：碰到中央旗立即加分；
- 自由移动的纸上足球：把物体推入球门。

唯一值得推进的版本是：

> 一面中立旗位于对称冰场中央；玩家利用惯性抢旗，持旗者被对手有效碰撞会掉旗，只有携旗进入自己的基地才得分。

旗帜的“占有状态”和“返程风险”是产品身份，不能作为可选增强。

## 本地直开与运行等级

目标形态是一个 A 级作品：

- 入口为 `index.html`，双击 `file://` 直接打开；
- 仅使用本地经典脚本、CSS 与内联 SVG；
- 不使用 ES module、`fetch`、WebSocket、Service Worker、远程字体、CDN、服务器、数据库或运行时权限；
- 不把 `localStorage`、IndexedDB 或下载文件作为开局条件；
- 刷新后重置，不宣称跨设备或持久化。

物理、状态机和重放都可用原生 JavaScript 完成。候选不需要引入完整物理引擎；固定地图、两个圆形玩家、一面旗和少量轴对齐障碍适合专用整数求解器。

## 核心玩法假设

### 最小比赛

- 一张左右镜像的固定冰场，一面中立旗；
- 左右各一名玩家和一个己方基地；
- 第一位触旗者携旗；若两人同刻等距触旗，旗保持无主；
- 持旗者与对手发生有效碰撞时先掉旗，掉旗后的短暂锁定避免原地反复拾取；
- 携旗进入己方基地后得 1 分，重置站位和旗；
- 先到 3 分立即获胜；90 秒有效比赛时间结束时高分者胜，同分为平局；
- 暂停、倒计时和得分重置不消耗有效比赛时间。

### 为什么是低摩擦而不是无摩擦

完全无阻尼会让一次误操作持续到撞墙，降低第一次上手的可控性。应采用：

- 每个固定 tick 施加离散方向加速度；
- 每 tick 施加很弱的速度衰减，表现“冰感”；
- 限制最高速度，并确保单 tick 位移小于最薄障碍的安全厚度；
- 墙面与玩家碰撞使用有限弹性，不制造持续增能；
- 持旗者降低加速度和上限速度，使拦截有意义。

Box2D 3.1.0 的官方 Simulation 文档建议固定时间步，说明阻尼与接触摩擦不同，并警告离散模拟中的 tunneling；本候选只借鉴这些工程原则，不引入 Box2D，也不复制其求解器。

## 确定性与同刻规则

### 固定步

- 逻辑固定为 60 Hz；
- `requestAnimationFrame` 只负责累积时间和渲染；
- 每帧最多补 5 个 tick；
- 帧间隔超过 250 ms 时自动暂停，而不是把整段时间追赶进比赛；
- 逻辑层不读取当前时间、DOM、随机数或帧率。

### 整数状态

位置和速度使用定点整数；输入归一为 9 种意图：静止和八方向。斜向量、碰撞法线、阻尼、回弹与速度上限均使用固定查表或整数除法。这样可以：

- 从同一初始状态和逐 tick 输入日志得到完全相同的末态；
- 让 30、60、144 Hz 渲染调度得到相同逻辑状态；
- 用严格等值测试捕获结算顺序漂移。

### 每 tick 结算顺序

1. 读取两席归一化意图；
2. 同时计算加速度、持旗减速、阻尼和速度上限；
3. 同时积分两个玩家；
4. 解算边界、障碍与玩家碰撞；
5. 若持旗者本 tick 与对手有效碰撞，先掉旗；
6. 对无主旗做拾取判定；同刻等距保持无主；
7. 对仍持旗者做己方基地得分判定；
8. 更新掉旗计时、比赛计时和终局。

“碰撞掉旗”早于“进基地得分”，可避免双方看到同一接触却得到不同解释。终场 tick 上先完成拾取/掉旗/得分，再检查时间，因此压哨得分有效。

## 对称地图

研究建议固定逻辑画布 `1024 × 640`，左右镜像：

- 旗位于 `(512, 320)`；
- 玩家出生点位于 `(160, 320)` 与 `(864, 320)`；
- 基地位于左右边缘等宽区域；
- 障碍若保留，必须成镜像对出现；
- 所有镜像关系由单侧参数派生，并用测试证明，而不是手工录入两套数据。

地图不做程序随机化。固定地图既降低重放成本，也让双方能学习惯性路线。

## 键盘矩阵与触控

### 键盘

键盘使用 `KeyboardEvent.code` 读取物理键位：

- 左席：`KeyW`、`KeyA`、`KeyS`、`KeyD`；
- 右席：四个方向键；
- 同席相反方向同时按下时该轴归零；
- 斜向输入使用固定查表，不能比直线更快。

普通键盘可能在三个或更多键的特定组合上 ghosting 或 blocking。不能仅因为单键都能触发，就宣称“双人键盘完整支持”。开局前提供四步可跳过自检，依次验证：

1. `W+A` 与 `↑+←` 同时按住；
2. `W+D` 与 `↑+→` 同时按住；
3. `S+A` 与 `↓+←` 同时按住；
4. `S+D` 与 `↓+→` 同时按住。

任一步失败时明确提示“当前键盘可能漏键，建议改用双指触控”。自检不阻止开局，但未通过时不能把键盘路径标记为完整验收通过。

### 触控

- 左右各一个 3×3 八方向按键盘；
- 每席同一时刻只接受一个所属 pointer；
- 使用 Pointer Events 与 pointer capture；
- `pointerup`、`pointercancel`、`lostpointercapture` 均清空该席；
- 两席可被两个触点同时控制；
- 每个方向按钮至少 44×44 CSS px，高于 WCAG 2.2 的 24×24 最低要求；
- 单鼠标只能操作一席，不宣称能完成完整双人比赛。

键盘和触控最终都只产生同一套 9 值逻辑意图，重放不记录原始 DOM 事件。

## 暂停、公平与恢复

以下任一情况发生时应立即清空按下态、清空 accumulator 并进入暂停：

- `document.visibilityState === "hidden"`；
- `window.blur`；
- `pagehide`；
- 动画帧间隔超过 250 ms；
- 玩家按 Escape 主动暂停。

恢复必须由显式按钮或 Escape 触发，随后进行 90 tick（1.5 秒）中性倒计时；倒计时不接收移动输入。后台时间、暂停时间和恢复倒计时都不计入 90 秒有效比赛时间。

## 响应式、可访问性与降动效

- 冰场用内联 SVG 的 `viewBox` 保持统一逻辑坐标；
- 桌面横向布局：计分/时间、冰场、两席控制说明；
- 窄屏优先横向比赛区域；若竖屏空间不足，控制盘分置冰场下方两侧，不裁掉比分和暂停；
- 在 320 CSS px 宽和 200% 缩放下仍能开始、暂停、控制和查看结果；
- 玩家除颜色外还用“左/右”、不同围巾几何和基地纹样区分；
- 所有非游戏性按钮可键盘聚焦且有可见焦点；
- `prefers-reduced-motion: reduce` 下去掉庆祝位移、粒子、晃动与连续背景漂移；物理运动是玩法信息，保留但不增加镜头缩放或闪烁；
- 状态变化用短文本和 `aria-live` 通知，不让分数只存在于画面里。

## 视觉与素材策略

企鹅、旗、基地、冰裂纹和图标均用项目内原创 CSS/内联 SVG 几何绘制：

- 不使用真实品牌、影视角色、游戏角色轮廓；
- 不下载现成企鹅图、表情包、图标包或字体；
- 角色由椭圆躯干、腹部、喙、脚、围巾等基础几何组合；
- 两席不仅换色，还改变围巾尾端和基地纹样；
- 如未来增加任何外部素材，必须先固定来源、版本、许可、版权人和复制范围，并补 `ATTRIBUTION.md`。

## 决策门槛

### Go 到实现

允许进入实现，因为：

- A 级本地直开技术上成立；
- 独特闭环明确；
- 不需要第三方运行依赖；
- 确定性输入和状态边界可测试；
- 视觉可以完全原创。

### 安装前仍是 Conditional

必须完成以下证明后才能改为最终 Go：

1. 单元测试证明同刻拾旗、撞落优先、压哨得分、平局和镜像公平；
2. 30/60/144 Hz 调度及输入日志重放严格一致；
3. `file://` 冷启动零网络请求、零控制台错误；
4. 键盘四组矩阵自检和两 pointer 同时控制均完成；
5. hidden/blur/pagehide/长帧都暂停且恢复不偷跑；
6. 320 px、200% 缩放、降动效和非颜色区分验收通过；
7. 企鹅及所有视觉元素确认是代码原创，无未声明外部素材。

任何一项无法满足，候选保持未安装；若核心夺旗闭环被删减，直接 No-Go。
