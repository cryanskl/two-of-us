# A 级「靠近一点」规格

## 1. 定位与 brainstorm 结论

- 调研候选：C12「情侣问题卡」；
- 产品名：靠近一点；
- ID：`closer-cards`；
- 主分类：双人合作；
- 启动等级：A；
- 设备：同一台电脑或手机，面对面轮流回答；
- 公网依赖、账号、录音、存储、计时与评分：均无；
- 首版核心：一场只认真聊六张卡；每张卡由一席先说、另一席再说，双方都说完才收好；任何一席都可以中性地换一张。

当前作品覆盖了绘画、动作、解谜、节奏和语音合作，但还没有一款“坐下来就能聊”的低压力互动。首版选择谈话卡，而没有选择另一款棋盘或反应玩法，是因为它同时适合情侣、夫妻、对象，也适合任何愿意认真听彼此说话的两个人，并且不依赖设备性能或游戏经验。

brainstorm 比较过三个方向：

| 方向 | 优点 | 首版结论 |
| --- | --- | --- |
| 自由抽无限卡 | 最简单 | 缺少结束感，容易变成题库浏览器 |
| 六张对话仪式 | 有清楚节奏，20–40 分钟可完成 | 采用 |
| 关系问卷与匹配分 | 有结果反馈 | 不采用；评分会把倾听变成考试 |

首版不加入题库选择、关系诊断、匿名作答、历史记录、收藏、在线房间、AI 追问或私人答案输入。答案只在现实空间中说出，页面不接收、不显示，也不会保存答案。

## 3. 一场六张卡

1. intro 说明“六张卡，不评分，只认真听完”；
2. 点击开始后生成一份 24 张卡的唯一顺序，首六张必须覆盖三个主题；
3. 当前卡先显示卡背，点击“翻开这张”才展示问题；
4. 卡面明确谁先说；先说者点击“我说完了”后，页面把发言权交给另一席；
5. 后说者点击“我也说完了”，进入短暂的“收好这张”确认；
6. 点击“收好这张”计入一张完成卡，首发席下一张严格交替；
7. 任一公开卡都可以“换一张”；跳过不计完成、不评价原因，但会消耗当前卡并保持下一张首发交替；
8. 完成六张后显示共同完成页；可以重新开始并生成新顺序。

没有倒计时，也没有“必须回答”。跳过不出现扣分、警告、失败色或关系评价。若 24 张卡都被换完仍未完成六张，则安全结束为“今晚先聊到这里”，不会循环或抛错。

## 4. 原创题库

固定 24 张，三个主题各 8 张：

- `today` / 今天：当下感受、小事、照顾与最近的变化；
- `us` / 我们：共同经历、彼此被看见的时刻与相处习惯；
- `tomorrow` / 以后：轻量愿望、一起尝试的事与未来生活画面。

问题写作 Gate：

- 能由任意两个人自然回答，不默认婚姻年限、性别角色、同居、育儿或经济状况；
- 不要求披露创伤、性经历、密码、财务或第三方隐私；
- 不把某种答案定义成“正确”“更爱”或“更默契”；
- 每题只问一个中心问题，口语长度控制在 18–42 个汉字；
- 允许轻松、具体和带画面的回答，避免治疗师或调查问卷口吻。

## 5. 洗牌与首发公平

UI 提供 `randomIndex(max)`，优先使用 `crypto.getRandomValues` 与拒绝采样；能力缺失时使用由时间和高精度时钟播种的本地 xorshift32，避免引入第二种题序 API。此处随机只改变体验顺序，不涉及安全或胜负。

纯逻辑先分别 Fisher–Yates 洗牌三个主题，再按随机主题轮转组成 24 张唯一计划。前六张必须每个主题至少出现一次，且同一主题不能连续超过两张。配置策略返回合法卡 ID 时只把该卡移到计划首位，不复制卡片。

首发席默认从配置的 `firstSpeaker` 开始，之后按“已处理卡数”严格 A/B 交替；完成和跳过都会换首发，避免某一席连续承担先说压力。

## 6. 权威状态机

```js
{
  phase: "intro" | "card-back" | "first-speaking" |
         "second-speaking" | "settle" | "complete",
  plan: ["today-small-good", "us-seen", "tomorrow-slow-day"],
  cursor: 0,
  completedIds: [],
  skippedIds: [],
  firstSpeaker: "a",
  currentSpeaker: null | "a" | "b",
  endReason: null | "six-complete" | "deck-exhausted",
  revision: 0
}
```

公开状态、数组、配置上下文和返回对象递归冻结，不与调用方共享可变引用。

### 6.1 纯逻辑 API

- `createInitialState(config?)`：整份校验名字、首发和目标张数，创建 intro；
- `startSession(state, deck, randomIndex, chooseOpeningCard?)`：只在 intro 生成唯一、平衡计划并进入 card-back；
- `revealCard(state)`：只在 card-back 展示当前题并进入 first-speaking；
- `finishSpeaking(state)`：first-speaking 交给另一席；second-speaking 进入 settle；
- `settleCard(state)`：只在 settle 把当前 ID 计入完成并前进；第六张进入 complete；
- `skipCard(state)`：公开卡阶段都可跳过，把当前 ID 计入 skipped 并前进；
- `restartSession(state)`：只在 complete 返回全新 intro；
- `getCurrentCard(state, deck)`：返回当前卡的冻结副本或 `null`；
- `isGameState(value)`：畸形公开状态不进入规则分支。

合法状态上的非法阶段动作保持同一引用；畸形状态经公开动作安全回初始状态，不抛异常。计划耗尽进入 complete 且 `endReason="deck-exhausted"`。

## 7. 本地配置与用户可贡献点

`config.js` 提供：

```js
{
  aName: "A 席",
  bName: "B 席",
  firstSpeaker: "a",
  sessionSize: 6,
  chooseOpeningCard({ cardIds, themeIds }) {
    // TODO: 可以返回一张合法卡的 ID，也可以保留 null。
    return null;
  }
}
```

`sessionSize` 是首版六张仪式的固定 schema 值，不作为可变题数开关；改变它会使标题、进度点、完成文案与会话时长失去一致性，因此非法值整份回退。

`chooseOpeningCard` 是准备者可以亲手写的 5–10 行策略：返回 `null` 使用平衡随机；返回合法 ID 就让某张有私人意义的原创题成为开场；抛错、修改冻结上下文或返回非法值会安全回退。名字和策略只在本机运行，不上传、不保存。

## 8. 视觉规格

方向：深夜编辑式谈话沙龙。唯一视觉焦点是一张暖纸白问题卡；左侧席位与六点轨道用克制朱红细线连起来。避免爱心堆叠、疗愈应用渐变、玻璃拟态、胶囊、题库网格和伪数据。

### 8.1 设计令牌

- 午夜靛蓝背景：`#171a2b`，是真正的深色染底，不是黑色渐变；
- 暖纸白卡：`#f2e9d7`；
- 卡面深墨：`#242437`；
- 朱红动作：`#c65a4a`；
- 浅沙辅助文字：`#cfc3ae`；
- 发言席高亮：朱红文字、实心进度点与 1px 织线；
- 卡片圆角 12px，按钮圆角 4px，不做胶囊；
- 标题/问题使用本机中文 serif，控制文字使用 system sans-serif；
- 阴影低而真实，不使用 CSS 渐变或发光。

### 8.2 桌面 1504×1046

- 顶栏：返回、居中标题/短句、右侧进度；
- 左侧约 28%：A/B 席、六点竖向轨道和隐私承诺，不套独立卡片；
- 右侧约 72%：唯一一张大纸卡与动作区；
- 卡面问题 34–42px，最多三行；
- 首屏完整看见问题、当前席、主按钮、换一张与隐私说明，无滚动。

### 8.3 移动 390×844

- 顶栏、标题短句、横向双席轨道、纸卡、主按钮、换一张、隐私说明依次排列；
- 16–20px 页面边距，问题 25–29px，按钮至少 48px 高；
- 允许短距离自然纵向滚动，不横向溢出；
- 320×760 时仍可滚动到全部动作，不缩小触控尺寸。

### 8.5 图标清单

只允许一个返回箭头，使用文本箭头 `←` 或与字体同重的 1.5px SVG；不引入图标库。进度点、红线和卡面分隔线由 CSS 生成，不作为装饰图标。

## 9. 可访问性、隐私与阶段 DOM

- 所有动作是原生 button，焦点环至少 2px；
- `aria-live` 只播报翻卡、换席、完成和跳过，不重复整页；
- 当前席同时用文字、位置和颜色表达；进度同时有 `x / 6` 与点位；
- 题卡翻面不是规则等待；`prefers-reduced-motion` 下直接切换；
- 卡背阶段 DOM 不渲染当前问题；问题只在 reveal 后出现；
- 页面没有输入框、麦克风、网络请求、localStorage、cookie、IndexedDB 或 Service Worker；
- 页面隐藏不会清空公开题目或改变进度；刷新才重开，且不会恢复旧会话；
- 任一公开题都能用“换一张”跳过；键盘焦点按主动作 → 换一张的稳定顺序移动。

## 10. 自动测试 Gate

至少覆盖：

1. 24 张原创卡、三个主题各 8 张、ID 唯一与文案长度；
2. 配置整份回退、名字去空白、首发、目标张数和深冻结；
3. 平衡洗牌唯一性、前六张三主题覆盖与同主题不超过两连；
4. 开场卡策略合法前置、非法值/抛错/变异回退；
5. intro → card-back → first-speaking → second-speaking → settle；
6. 完成卡计数、首发交替与六张 complete；
7. 三个公开阶段均可跳过，跳过不计完成但切换首发；
8. 牌库耗尽安全结束；
9. 非法动作保持原引用，畸形状态安全回退；
10. 阶段 DOM：卡背无题目，答案永不进入 DOM；
11. catalog 为 A 级且目录无网络、存储和远程资源；
12. 1504×1046、390×844、320×760 的溢出、触控尺寸和焦点。

整仓继续要求 `npm test`、`npm run verify` 与 `git diff --check` 通过。

## 11. 浏览器验收路径

1. 从门户进入 intro，确认无需安装且隐私承诺可见；
2. 开始后检查卡背 DOM 不含题目，再翻卡；
3. 完整走一张：A 先说 → B 再说 → 收好；
4. 第二张确认首发切换；
5. 分别在 first-speaking、second-speaking、settle 阶段换一张；
6. 完成六张，确认无分数、输赢、关系评语或答案记录；
7. 重开确认新计划且旧状态不恢复；
8. 禁用 Web Crypto 或注入确定性索引，确认回退仍可用；
9. 真实 Chrome `file://` 直开，无控制台错误和网络请求；
10. 1504×1046、390×844、320×760 与 reduced motion 检查；
11. 对照概念图完成至少五项保真账本：构图、色值、字阶、纸卡、席位轨道、动作层级。
