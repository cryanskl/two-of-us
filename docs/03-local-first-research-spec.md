# 第二轮本地优先调研规格

> 调研日期：2026-07-15 · 对应目标：A/B/C/D 四级本地启动体系

## 1. 研究目的

上一轮调研以“纯静态、双击 HTML”为主要筛选条件，较完整地覆盖了 A 级作品，但会漏掉三类同样适合情侣体验的项目：需要 localhost 的浏览器应用、同一局域网内的双设备玩法，以及本地 AI/语音/3D 等重型体验。

第二轮调研要回答：在默认本地运行、无需账号、私人数据不上传的前提下，哪些现有开源项目、组件和技术底座可以支撑 A–D 四级情侣互动体验？

## 2. 调研范围

### 玩法范围

- **单人惊喜**：一个人准备，另一人打开体验；
- **双人合作**：两个人共同创作、交流或完成目标；
- **双人对抗**：两个人比较分数、速度、策略或胜负。

### 启动范围

| 等级 | 本轮重点 |
| --- | --- |
| A | 补充可以直接引入或重写的高质量静态项目 |
| B | 核验适合用一键启动器封装的 localhost、PWA、WASM 和框架项目 |
| C | 寻找可改成本地 WebSocket/WebRTC、二维码加入和局域网房间的双设备项目 |
| D | 寻找完全本地的 AI、语音识别、姿态/手势、3D 与大型素材技术底座 |

异地公网房间可以记录为可选增强，但不把“必须使用第三方云服务”视为 A–D 的组成部分。

## 3. 每个候选的必填证据

| 字段 | 要求 |
| --- | --- |
| 名称与直链 | 指向原始仓库、官方文档或原作者页面 |
| 适合玩法 | 惊喜 / 合作 / 对抗，可多选但需给出主用途 |
| 目标等级 | 按最终用户启动方式标 A / B / C / D，不按开发难度标级 |
| 公网依赖 | 无 / 可选 / 必须，并说明现状与本地替代路径 |
| 运行架构 | 静态、localhost、WebSocket/WebRTC、WASM、本地模型等 |
| 许可证 | 以仓库许可证文件或包元数据为准；未声明则只作灵感 |
| 可复用价值 | 玩法、UI、房间层、输入能力、引擎或组件 |
| 改造要点 | 为达到目标等级必须删除、替换或封装的部分 |
| 置信度 | 已核验 / 待实机复测 / 仅方向线索 |

## 4. 证据优先级

1. 原作者仓库中的 `LICENSE`、README、源码、release 和示例；
2. 项目官方文档和官方演示；
3. npm、PyPI、Hugging Face 等官方包或模型页面；
4. 聚合页和文章只用于发现，不用于作许可证结论。

搜索快照只能说明 2026-07-15 当天看到的状态。真正引入前，仍需固定 commit/tag，再复核许可证、素材、远程请求和构建产物。

## 5. 输出物

- 一份横跨三类玩法与 A–D 等级的第二轮总报告；
- 在已有惊喜、合作、对抗调研中加入第二轮增量索引；
- 更新文档总览与推荐实现顺序；
- 生成与 Markdown 同源的 PDF 研究报告；
- 不在本轮复制第三方源码，也不实现具体玩法。

## 6. 验收标准

- 新增或重新核验至少 48 个有一手来源的候选，B/C/D 各有实质覆盖；
- 每个重点候选都能回答目标等级、公网依赖、许可证和本地化路径；
- 明确区分“本机后端”与“公网后端”，不把 Node、WebSocket 或数据库自动判为不可收录；
- 明确区分“构建方式”与“用户启动方式”；
- 所有本地 Markdown 链接可解析，PDF 可正常打开并包含中文文本；
- Git 改动只包含本轮调研文档与生成报告。
