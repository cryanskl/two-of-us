# C 级首款作品规格：同心解锁

## 1. Brainstorm 结论

第一款 C 级作品的目标不是做内容最多的游戏，而是证明统一运行底座可以支持一台电脑启动、两台设备加入、实时协作和安全退出。

评估过三个最小方向：

| 方向 | 优点 | 首批风险 | 结论 |
| --- | --- | --- | --- |
| 局域网你画我猜 | 用户熟悉，后续价值高 | 画布同步、题目权限和回合状态一次引入过多 | 下一批 |
| 双人抢答 | 协议简单 | 与现有同屏反应力对决体验重复 | 暂缓 |
| 双方同时按住解锁 | 必须实时合作，事件极少，断线行为清楚 | 需要稳定处理按住/松开与计时 | 本批实现 |

## 2. 用户流程

1. 主机双击根目录 `start.command` 或 `start.bat`；
2. 两台设备从门户打开“同心解锁”；
3. 一方创建房间并看到 5 位房间码；
4. 另一方输入房间码加入；
5. 双方同时按住各自按钮 2.5 秒；
6. 两端都展示解锁成功；
7. 任一方可发起重新开始。

主机门户已有局域网二维码。首版不再生成第二个房间二维码，避免在尚未验证短码流程前扩大 API；房间 URL 分享列为可选增强。

## 3. 最小状态机

`offline → lobby → connected → charging → unlocked`

- `offline`：从 `file://` 打开或 Socket.IO 不可用，提示使用启动器；
- `lobby`：已连接本地服务，可创建或加入房间；
- `connected`：房间内已有两位成员，等待按住；
- `charging`：本地和远端都处于按住状态，开始 2.5 秒进度；
- `unlocked`：任一端计时完成后广播 `unlock`，两端进入成功状态。

收到成员减少、松开或 `reset` 时取消当前进度。断线后返回可操作提示，不保留虚假的远端按住状态。

## 4. 协议复用

不新增服务端专用事件，只使用共享运行时：

- `room:create`：创建房间；
- `room:join`：通过短码加入；
- `room:state`：获得成员数量和角色；
- `room:action`：承载 `hold`、`unlock`、`reset`；
- `disconnect`：显示连接丢失并停止计时。

`hold` 的数据只有 `{ active: boolean }`，不上传姓名以外的私人内容，不写数据库。

## 5. 验收标准

- 必须通过根启动器使用，README 标记 `C 级 / 公网依赖：无`；
- 两个独立浏览器会话可以创建、加入并互相看到按住状态；
- 只有双方同时按住满 2.5 秒才解锁；提前松开会清零；
- 任一端重置后两端同时回到等待；
- 一方断开后另一端取消进度并显示等待同伴；
- 无 CDN、公共 WebSocket、外部字体、统计或云存储；
- README 包含准确的“借鉴与来源声明”；
- 自动化测试覆盖纯状态逻辑，Chrome 覆盖两端真实交互。

## 6. 借鉴边界

玩法采用“双方同时按住按钮完成共同目标”的通用合作机关，由本仓库独立设计视觉、状态机和实现。实时传输复用共享运行时中的 Socket.IO 4.8.1（MIT），只调用公开 API，不复制第三方示例源码、视觉或素材。

实现日期：2026-07-15。

- `logic.test.js` 覆盖双方按住、2.5 秒阈值、提前松开、远端解锁前置校验、重置、成员变化和重复成员状态；
- 仓库 `npm test` 共 14 项通过，`npm run verify` 确认 5 个作品入口、资源与借鉴声明完整；
- Chrome 两个独立页面实际创建并加入同一房间，双方状态互相可见；
- 一端提前松开后，两端进度都回到 0%，没有误解锁；
- 两端同时按住后，两端都显示成功、进度 100%，控制台无错误或警告；
- 任一端点击“再解锁一次”，两端同时恢复未按住状态；
- 关闭一端后，另一端显示“等待同伴”、按钮禁用且瞬时状态清零；
