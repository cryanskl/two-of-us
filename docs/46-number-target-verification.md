## 3. 真实浏览器完整实玩

先连接内置 Browser/IAB，本次环境返回 `No browser is available`，因此按前端验收规则使用 Playwright CLI 的 headed Chromium 作为明确 fallback。CLI 不接受 `file://` 导航，交互验收通过 `python3 -m http.server 8766 --bind 127.0.0.1` 服务同一目录；A 级直开能力由经典脚本、相对资源、catalog 和静态边界测试共同证明。

一次完整随机比赛实际走完：

1. 第 1 局目标 14，蓝方先手；用鼠标依次完成 `12 − 2 = 10` 和 `1 ＋ 11 = 12`，珊瑚方得 1 分；
2. 第 2 局目标 20，珊瑚方先手；全程键盘完成 `4 × 5 = 20`，命中“正中靶心”，另式为 `1 ＋ 9 = 10`；
3. 第 3 局目标 10，蓝方先手；鼠标选择 12 和 3，键盘完成余下牌，蓝方得到 `3 ＋ 7 = 10`；
4. 点击“看最终比分”，显示珊瑚方 `2 : 1`；“再来三局”清空比分、目标与手牌并回到 intro；
5. 数字 10–12 只能通过牌面按钮，数字 1–9 和 `+ - *` 键均可选择；错误牌轨全程 disabled；
6. 每次选择后焦点进入下一种可用牌轨，局结果与最终结果的唯一主按钮自动聚焦。

正常会话控制台为 0 error / 0 warning。网络清单只有 6 个 `127.0.0.1:8766` 同源 GET：`index.html`、`styles.css`、`logic.js`、`copy.js`、`app.js`、`assets/target-board.png`；没有公网请求。

等距平局、负数结果和重复结算使用生产 reducer 的确定性测试覆盖；随机浏览器会话覆盖普通胜、两次精确命中和完整三局，没有为了制造随机平局修改生产状态。

### 首屏文案差异

生产 drafting 首屏与规格锁定文案一致：`数字凑靶`、`轮流拿牌，把算式推到离靶心最近的位置。`、`目标`、`现在轮到 …`、当前选择指令、双方名称、`等待完成`、两条牌轨、规则和隐私说明。没有增加 eyebrow、统计卡、玩法分组或第二 CTA。

概念移动稿把当前方和动作合成“珊瑚方 · 选择第一个数字”，生产页拆为标题与说明两行，以匹配桌面指令卡和屏幕阅读器层级；语义和词句不变。

### 有意偏差

- 移动概念靶环上的 `-2 / -5 / -10 / -20` 会让人误以为存在扣分区，生产资产主动移除，只显示真实绝对距离结果；
- 概念玩家纸展示一张已选牌，最终截图选择 step 0，刻意展示六个虚线空槽与首张牌的键盘焦点；真实选择后会进入概念所示的混合状态；
- 移动概念是 852×1846 长画布，交付用真实 390×844 和 320×760 视口验收，玩家纸与市场通过自然滚动到达；
- 概念含装饰性夹子、手指和裁角，生产页只保留纸张、星标、硬阴影和当前标签，避免装饰覆盖按钮或被误认为输入控件；
- 桌面概念靶纸是圆形裁纸，运行靶图带方格纸方形底板，换来与页面背景自然融合且无需运行期抠图依赖。

偏差都有规则清晰、可访问性或本地资产边界理由；主构图、色板、层级、牌轨、响应状态与核心流程达到可签收忠实度。
