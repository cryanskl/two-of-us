# `taboo-description-duel` Brainstorm：两个人如何公平地绕词

- 日期：2026-07-25
- 前置调研：[`263-taboo-description-duel-research.md`](./263-taboo-description-duel-research.md)
- 候选工作名：`taboo-description-duel`
- 冻结生产 ID：`word-detour-duel`
- 冻结名称：`绕词对决`
- 本轮范围：玩法分叉、两人适配与最小范围决策；不创建生产目录或 UI

## 1. 先回答三个关键问题

### 1.1 它是合作还是对抗

**分类为友谊对抗。** 两位玩家在每个口头回合里需要合作完成猜词，但四回合结束后
比较双方作为描述者时的净分。它不是互不信任的竞技系统，也不承诺自动防作弊。

若只统计共同总分，会与 `hot-seat-pictionary` 的“轮流看词、共同猜词、共同累计”
过近；若让猜词者得分，描述者会有故意给差线索的激励；若让描述者得分，则猜词者
理论上可以故意不猜。三者都不能从程序上消除社交信任，描述者计分至少让“绕开
限制讲清楚”成为可比较的核心能力，因此采用。

### 1.2 谁判断踩词

**描述者即时自报，双方在回合后共同复核。**

浏览器不录音、不转写，也没有第三位裁判。进行中由描述者点击“踩词”，回合结束后
公开本回合已经使用的卡片与结果；双方若一致认为误记，可以在复核页更正单卡结果。
复核修改属于显式的共同确认，不伪装成机器检测。

### 1.3 怎样保证机会对称

**四个描述回合、每人两回合、每回合六张、同一计时设置、牌组按主题和难度分层。**

不使用“时间内无限抽卡”，因为较快操作设备、触屏误触或浏览器计时边界会让机会数
不同。每回合最多六张，即使选择计时模式，双方也只有相同上限。

## 2. 玩法方向比较

### 2.1 方向 A：连续口头描述 + 即时三动作

描述者看着当前卡，猜词者背对屏幕。猜中后描述者点“猜中”，踩词点“踩词”，
不想继续点“跳过”，页面立即显示下一张，直到到时或六张用完。

优点：

- 语言互动强，规则能在 30 秒内讲清楚；
- 不需要麦克风、输入法、网络、服务或第三方依赖；
- 与画猜的差异来自口头线索和禁用提示，而不是视觉换皮；
- 原生按钮足够覆盖鼠标、触屏和键盘；
- 每回合最多六张，状态机和测试可收敛。

缺点：

- 违规只能靠自报与共同复核；
- 猜词者需要主动不看屏幕；
- 玩法本质依赖口头表达与理解。

**结论：采用为首版主玩法。**

### 2.2 方向 B：固定卡数、不计时逐张完成

每位描述者依次完成六张卡，没有倒计时，只比较猜中和踩词。

优点：

- 没有时间压力，适合需要更多阅读或表达时间的参与者；
- 计时器、后台节流和最后一秒竞态不影响结果；
- 双方机会天然相同。

缺点：

- 玩家可在每张卡上无限思考，竞技张力较弱；
- 一局时长没有上限；
- 如果一方频繁停顿，另一方只能等待。

**结论：不单独做第二套状态机；作为设置中的“不计时”模式保留。** 不计时模式
仍是每回合六张、猜中/踩词/跳过和回合后复核，只把 deadline 设为 `null`。

### 2.3 方向 C：输入文字线索，由程序拦截禁词

描述者输入一句线索，程序做规范化和禁词匹配，猜词者再输入答案。

优点：

- 可以自动拦截完全匹配的目标词和禁用提示；
- 不需要录音；
- 状态更容易测试。

缺点：

- 中文分词、同音、谐音、拆字、拼音、emoji 和委婉表达无法可靠判定；
- 只检查字符串会产生“看起来自动执法，实际大量漏判”的错觉；
- 两人需要反复交接设备，口头交流的节奏消失；
- 会与文字猜谜、密码破译和问答类作品靠近。

**结论：排除。** 不能用一个不完整的字符串过滤器冒充自然语言裁判。

### 2.4 方向 D：麦克风 + 自动语音裁判

描述者讲话时页面持续识别，出现目标或禁用提示就自动判罚。

优点：

- 理论上减少自报；
- 视觉上可以做实时转写和高亮。

缺点：

- 浏览器支持、中文识别质量、方言、同音与噪声均不稳定；
- 默认语音识别可能访问远程服务，破坏 A 级离线与隐私合同；
- 需要麦克风权限、录音状态、拒绝/撤销/中断和语言包降级；
- 自动误判会直接影响胜负；
- 即使转写正确，也不能可靠判定词根、语义替代和规则争议。

**结论：首版和可选增强都排除。** 若将来研究，必须作为独立 B/D 级作品，不在
本 A 级目录内做渐进增强。

## 3. 计分方向比较

| 方案 | 猜中 | 踩词 | 跳过 | 问题 | 结论 |
| --- | ---: | ---: | ---: | --- | --- |
| 只计猜中 | `+1` | `0` | `0` | 自报踩词没有代价，容易弱化限制 | 排除 |
| 猜中加分、踩词扣分 | `+1` | `-1` | `0` | 简单、限制有意义；分数可能为负 | **采用** |
| 猜中加分、跳过扣分 | `+1` | `-1` | `-1` | 不会的卡和违规同罚，鼓励硬拖 | 排除 |
| 速度乘数 | 基于剩余时间 | 基于剩余时间 | `0` | 最后一秒竞态、设备差异、可访问性变差 | 排除 |
| 猜词者和描述者都得分 | 双方共享 | 双方共享 | `0` | 最终无法比较个人描述能力 | 排除 |

冻结公式：

```text
turnScore  = correctCount - foulCount
matchScore = sum(player's two turnScore)
```

最终只比较 `matchScore`。分数相同就是平局，不按用时、跳过、按钮速度或最后一张
加赛。结果页可以展示 `correct / foul / skip` 统计，但它们不充当隐藏 tiebreaker。

## 4. 牌组与题量方向

### 4.1 排除运行时随机抓 24 张

完全随机可能让一位玩家拿到更多高难卡或某个不熟悉主题。即使 seed 可重放，也不
等于难度对称。浏览器随机也没有给这款信任型游戏增加有价值的安全性。

### 4.2 排除双方使用同样的题卡

第二位描述者会在第一位回合复核时看到答案与禁用提示，不能再次使用同卡。

### 4.3 采用三套预平衡牌组

72 张原创卡按：

```text
6 themes × 3 difficulties × 4 cards = 72 cards
```

构建期生成三套 `deckVariant`，每套 24 张且互不重复。每套再拆为四个 hand，每个
hand 恰好：

- 六个主题各一张；
- 难度 1 两张；
- 难度 2 两张；
- 难度 3 两张；
- 六个目标词和全部禁用提示通过规范化唯一性检查。

玩家在 setup 选择三个不泄题的中性牌组名：

```text
纸飞机 / 晚风 / 星灯
```

牌组名不对应难度，默认“纸飞机”。算法不在浏览器临时洗牌，`createMatch()` 根据
选定 variant 读取冻结 schedule；测试可以逐个证明四个 hand 的主题和难度分布。

这样做的代价是同一 variant 的顺序可被记住，但本作不声称防止熟悉源码的玩家
作弊。72 张足以让连续三局不重复；未来增加题卡必须先扩展平衡生成器与原创审计，
不能向配置尾部随便追加。

## 5. 回合数量与节奏

冻结常量：

```text
PLAYER_COUNT   = 2
TURN_COUNT     = 4
TURNS_PER_SEAT = 2
CARDS_PER_TURN = 6
TIMER_OPTIONS  = 30 / 60 / 90 / null
DEFAULT_TIMER  = 60
```

描述顺序：

```text
第 1 回合：玩家 1 描述，玩家 2 猜
第 2 回合：玩家 2 描述，玩家 1 猜
第 3 回合：玩家 1 描述，玩家 2 猜
第 4 回合：玩家 2 描述，玩家 1 猜
```

首位不随机，setup 明示玩家 1 先开始。重开回到同一初始状态；如果双方想交换先后，
在新局设置中交换座位即可。首版不引入掷硬币、自动轮换上局赢家或跨局记录。

每个描述回合：

1. 中性交接页显示当前描述者和“猜词者请背对屏幕”；
2. 描述者确认独自看屏幕后，才创建第一张秘密卡 DOM；
3. 未计时时，描述者主动按“开始本回合”；此刻建立 deadline；
4. 描述者在六张内依次记录猜中、踩词或跳过；
5. 到时或第六张处理后，立即卸载秘密卡并进入中性结束页；
6. 两人确认都可看屏幕后，才创建本回合公开复核表；
7. 双方可共同更正已用卡的 outcome；
8. 点击“确认本回合结果”后冻结 turn，进入下一次交接或总结果。

计时模式如果六张提前完成，立即结束，不等待倒计时归零。到时不会自动把尚未出现
的卡记为跳过；只有实际进入过 `describing` 的卡进入回合记录。

## 6. 复核机制

### 6.1 为什么要能更正

描述者可能误点相邻按钮，双方也可能在看到禁用提示后才意识到刚才说过其中一个。
如果完全不可改，只能重开整局；如果任意时刻可改，历史会失去冻结边界。

### 6.2 冻结规则

只在 `turn-review` 阶段允许：

```text
RECLASSIFY_CARD { cardId, outcome: correct | foul | skip }
```

约束：

- `cardId` 必须属于当前已结束回合且实际出现过；
- 每次更改直接从不可变记录重算当前回合分，不做增量加减；
- 未出现的未来卡不能进入复核；
- 复核页醒目标注“请两人一致后更正”；
- 点击 `CONFIRM_TURN` 后，该回合记录永久冻结；
- 后续回合和结果页不能再修改旧回合；
- 不记录谁点击了更正，也不伪装成独立裁判判决。

复核页公开目标、四个禁用提示和最终 outcome，但不公开当前 variant 的未来词卡。

## 7. 遮屏方案比较

### 7.1 用 CSS 隐藏同一张卡

**排除。** `display:none` 虽然不可见，但很容易因为样式错误、动画或可访问树处理
失误重新暴露；同一节点继续存在也让阶段测试难以证明边界。

### 7.2 DOM 按阶段创建与卸载

**采用。**

- `handoff` 只有角色、说明和确认按钮；
- `card-ready/describing` 才创建当前卡；
- 到时、暂停、失焦或回合完成立即移除整棵秘密子树；
- `turn-ended` 仍只显示中性说明；
- `turn-review` 只创建已用卡；
- `match-result` 只显示四个冻结回合摘要。

词库仍存在于 JavaScript 内存，不能抵御开发者工具。DOM 卸载解决正常流程泄漏，
不是加密。

### 7.3 翻面动画遮挡

**排除为安全机制。** 卡片可以有静态“背面”视觉，但不能依赖 3D rotate 或动画
结束来决定秘密是否消失。reduced-motion 和旧动画事件都不能改变阶段。

## 8. 暂停与中断

### 8.1 手动暂停

描述回合提供“暂停并遮住”按钮。点击后：

- 先计算并冻结本段已用时间；
- 卸载当前秘密卡；
- 进入 `interrupted` 中性交接页；
- 恢复需要当前描述者再次确认；
- 恢复后重建同一张卡和新的 deadline；
- 暂停不改变卡、结果、分数或 revision 以外的游戏事实。

双方可以通过暂停获得额外思考时间，因此它属于信任模型的一部分。设置中的“不计时”
才是正式无压力模式；不要用反复暂停当作可访问性替代。

### 8.2 系统中断

`blur / hidden / pagehide` 与手动暂停进入同一 `interrupted`，但原因标记为
`system`。重复事件是 no-op。恢复可见不会自动显示秘密或继续计时。

`beforeunload` 不弹自定义阻止对话框，不写 Storage 恢复战局。刷新或关闭页面即
丢失当前局，符合零持久化合同。

## 9. 最小状态机草案

```text
intro
  → setup
  → handoff
  → card-ready
  → describing
  ↔ interrupted
  → turn-ended
  → turn-review
  → handoff / match-result
  → intro (restart)
```

说明：

- `card-ready` 已显示当前卡，但 timer 未启动；
- `describing` 接受三种 outcome；
- `interrupted` 不含秘密 DOM；
- `turn-ended` 是从秘密态到公共复核的第二道交接确认；
- `turn-review` 只允许更正当前刚结束回合；
- 第四回合确认后进入 `match-result`；
- restart 深清理 match、deck schedule、timer token、review draft 和 UI 私密节点。

不单设 `complete`：`match-result` 已是完整终局，有结果、统计、再来一局和返回作品集。

## 10. 文案与同意边界

默认使用“玩家 1 / 玩家 2”，不假定恋爱关系、性别或称谓。`config.js` 可允许准备者
改成两个 1–12 字的公开称呼，但默认仓库不提交私人名称。

规则页必须直接说明：

> 这是信任型友谊赛。页面不会录音或自动判断你说了什么；描述者请主动记录踩词，
> 回合后由两个人一起复核。

遮屏页必须说明：

> 猜词者请背对屏幕。描述者确认只有自己能看到后，再打开题卡。

复核页必须说明：

> 现在两个人都可以看屏幕。若刚才误点，或共同确认说到了禁用提示，只在这里更正。

任何一方都可以在 setup 选择不计时，也可以在回合中暂停；没有“不许退出”“输家
惩罚”“情侣默契差”等羞辱文案。

## 11. 视觉范围暂不决策

本轮只冻结信息层级，不选择生产视觉：

- 卡面必须优先展示一个目标与四个禁用提示；
- 三个结果动作不能只用颜色或图标区分；
- 计时数字和当前卡序号始终是文字；
- 公共计分区不得在秘密阶段暗示未来卡；
- 不采用商业版蜂鸣器、卡槽、包装、logo、字体或配色；
- 不生成或引入图片、音频和第三方字体。

视觉提案应在实现 UI 前单独确认；本 plan 只允许后续先实现纯配置、逻辑与测试。

## 12. 决策记录

| 决策 | 采用 | 排除 |
| --- | --- | --- |
| 产品名 | `绕词对决 / word-detour-duel` | `Taboo` 及其翻译/变体品牌 |
| 主玩法 | 口头描述 + 三结果按钮 | 文字过滤、语音自动裁判 |
| 分类 | 两人信任型友谊对抗 | 强安全竞技、纯共同分 |
| 回合 | 四回合，每人描述两次 | 无限轮、随机加赛 |
| 题量 | 每回合六张 | 时间内无限抽卡 |
| 牌组 | 三套冻结平衡 schedule | 浏览器临时纯随机 |
| 计时 | 30/60/90/不计时 | 只能倒计时 |
| 计分 | 猜中 +1、踩词 -1、跳过 0 | 速度乘数、隐藏 tiebreaker |
| 平局 | 允许平局 | 突然死亡、抢答 |
| 违规 | 自报 + 回合后共同复核 | 虚假的自动检测 |
| 秘密 | 阶段创建/卸载 DOM | CSS 翻面承担保密 |
| 中断 | 暂停并遮屏，主动恢复 | 后台继续或恢复自动显卡 |
| 运行 | A 级、零权限、零网络 | 麦克风、服务、Storage |

## 13. 进入规格的冻结条件

规格必须继续满足：

1. 状态机的每个 action、guard、no-op 与公开投影精确化；
2. 72 张词卡只冻结 schema、平衡规则和原创 Gate，本阶段不生产实际内容；
3. `deckVariant → 4 hands × 6 cards` 可由纯函数验证；
4. 计时使用注入时钟和 token，不读取 CSS 或 interval 次数；
5. `interrupted`、`handoff`、`turn-ended` 不泄露秘密字段；
6. 复核只能改当前回合，确认后不可变；
7. 分数从历史纯派生，平分直接判平；
8. 测试明确程序公平与社交信任的边界；
9. UI、图像和视觉风格仍未获生产授权。
