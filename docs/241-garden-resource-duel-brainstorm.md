# “这一朵，我先养开” Brainstorm：有限手牌、共同季节与温和阻断

- 日期：2026-07-24
- 稳定工作 ID：`garden-resource-duel`
- 对应调研：[`240-garden-resource-duel-research.md`](./240-garden-resource-duel-research.md)
- 目标：冻结首版产品边界，供 spec、design、plan 和生产实现共同使用

## 1. 想做出的感觉

这不是一场“把对方花踩坏”的游戏，而是两个人坐在一起，知道彼此都只剩几次
照料和捣乱机会，然后把一张牌藏在手心里。

每轮应形成三个连续情绪：

1. **读局面**：现在需要阳光还是雨露，这轮值几片花瓣，对方还剩什么；
2. **藏选择**：我现在照料、留到更值钱的后面，还是猜 TA 会照料并放虫害；
3. **一起揭晓**：两张牌同时翻开，花瓣生长或这一轮落空。

输的一方不会被删除旧成果，赢的一方也不能靠连续破坏滚雪球。六轮结束后，页面
应像两盆都被认真照料过的花，而不是一边繁盛、一边枯死。

## 2. 冻结的产品一句话

> 看当前季节需求，轮流遮屏藏一张有限手牌；匹配需求就长花瓣，虫害能挡住对方
> 这一轮。先得到 5 片花瓣的人，让花先开。

首局教学只解释这句话和三张牌：

- 阳光：当前需要阳光时得分；
- 雨露：当前需要雨露时得分；
- 虫害：阻断对方本轮本来能得到的花瓣，自己不得分。

“牌用过就没有了”“本轮值多少花瓣”直接写在牌区和季节区，不另加教程轮。

## 3. 采用的体验结构

```text
intro
  → season
  → handoff(first seat)
  → choosing(first seat)
  → handoff(second seat)
  → choosing(second seat)
  → ready-to-reveal
  → round-result
  → 下一轮 season / match-result
```

关键决定：

- 两人使用同一屏幕和同一套规则；
- 每轮第一位选择者交替；
- 选择顺序不等于结算顺序，两张牌总是联合结算；
- 季节牌堆开局确定，当前轮公开，后续顺序隐藏；
- 不提供撤销已确认选择；
- 不使用倒计时、抢按、拖拽、联网或人工裁判；
- 结果页可以立即重开，新局生成新的共同季节顺序。

## 4. 为什么是“公共季节”

如果六轮需求全部预先公开，玩家只需把资源牌放到最高价值的匹配轮，推理会过于
机械；如果双方各自获得隐藏随机需求，公平又难以当场确认。

采用的折中是：

- 牌堆固定含 3 次阳光需求和 3 次雨露需求；
- 开局用 seed 洗牌；
- 每轮只公开当前需求；
- 已出现的需求和双方已用手牌进入公开历史。

因此两人面对完全相同的随机环境，也能根据剩余牌堆组成推断未来。seed 只用于
复现季节顺序，不参与胜负或破平。

## 5. 为什么花瓣值逐步上升

六轮价值为：

```text
1 / 1 / 2 / 2 / 3 / 3
```

它建立两个相反诱因：

- 现在打出匹配资源，可以锁定较小但较稳的花瓣；
- 留到后面可能得到 3 花瓣，但对方更容易从剩余手牌读出你的意图并用虫害阻断。

5 花瓣的开花阈值允许第四轮起出现终局，又不会让前两轮一次猜中就决定整场。

## 6. 虫害的语气与边界

生产文案把虫害写成“这一轮来捣乱”，不写“毁掉”“偷走”“杀死”：

- 只阻断本轮尚未产生的花瓣；
- 永不扣除已有花瓣；
- 永不把对方花瓣转给自己；
- 打到不匹配资源或另一张虫害时直接浪费；
- 每人整局只有两张；
- 牌一旦揭晓便进入公开弃牌历史。

这让虫害是一种有成本的读人行为，而不是领先方持续压制落后方的工具。

## 7. 热座隐私

隐私目标是“正常共同使用时不提前看到”，不是密码学安全：

- 交接页只显示“请把屏幕交给谁”，不显示上一位选择；
- 选择页只渲染当前玩家仍可用的牌；
- 确认后立即卸载选择节点和草稿；
- 两人都确认后仍先进入中性揭晓页；
- blur、页面隐藏、`pagehide`、Escape 会遮屏并丢弃未确认草稿；
- 已确认选择保留在 JS 内存，因此开发者工具仍可检查；README 必须坦白说明。

不引入 PIN、密码、加密提交、摄像头辨识或双设备协议。若以后要求抵御主动检查，
应另立 C 级版本，而不是在 A 级单页里制造虚假安全感。

## 8. 代码原生视觉方向

首版不生成或引入图片。视觉采用“夜晚阳台上的双盆小花园”：

- 背景：深墨绿到暖黑的纯 CSS 渐变；
- 主体：左右两盆原创 CSS 花，花瓣数由公开得分驱动；
- 中央：本轮季节牌，显示需求、轮次和花瓣价值；
- 手牌：纸片式原生按钮，使用文字、符号和边框纹理共同区分；
- 交接：中央窄门帘/磨砂层，只保留接管按钮；
- 揭晓：两张牌从两侧进入，但动画只消费已提交状态；
- 结果：两盆花都保留，胜者先开，平局则一起开。

不使用写实虫子、枯萎植物、商业卡牌框、现成园艺图标、外部字体、粒子库或 Canvas。
花朵几何由本作 DOM/CSS 独立实现。

## 9. 语气与默认文案

建议主文案：

| 场景 | 文案方向 |
| --- | --- |
| 标题 | 这一朵，我先养开 |
| 副标题 | 六张牌，六个季节。照料、保留，或者猜猜我这一手。 |
| 交接 | 轮到你藏一张。把屏幕交给 TA，再点“我接好了”。 |
| 待揭晓 | 两张牌都藏好了。现在，一起看看这一轮。 |
| 单方开花 | 这一朵先开了。下一局，换你读懂我的手。 |
| 同轮开花 | 这一轮，两朵刚好一起开。 |
| 回合耗尽 | 六个季节走完了，看看谁留下了更多花瓣。 |

默认称呼使用“你”和“TA”，放在 `config.js` 中可编辑；不把真实姓名、纪念日或
私人消息写入版本库。

## 10. 可访问与降级

- 三张牌都是大号原生按钮，名称包含牌种、剩余数量和本轮作用；
- 支持键盘和触控，不要求悬停；
- 颜色之外同时使用 `☀`、水滴文字、虫害文字与不同边框；
- 花朵进度旁始终显示 `n / 5 花瓣`；
- 状态消息只播报公开内容；
- 减少动态时，卡牌直接切换，花瓣不缩放或飘落；
- 强制颜色模式下取消装饰渐变，保留系统边框和文字；
- JavaScript 不可用时显示明确说明，不展示假的可玩界面；
- 小屏按纵向排列，确保交接和选择时不需要横向滚动。

## 11. 明确不做

首版不增加：

- 玩家自定义牌库；
- 多种花、花语配方或养成存档；
- AI 对手；
- 在线房间；
- 音效、背景音乐和震动；
- 成就、连续胜场、排行榜；
- 道具连锁、虫害抗性或资源偷取；
- 回看对方未公开草稿；
- 自定义回合数、阈值或“简单/困难”模式；
- 自动刷新、新局默认设置或远程统计。

这些都不是当前最小闭环的必要条件。

## 12. 进入规格的决定

brainstorm 冻结以下内容：

1. 六轮、相同六张有限手牌、三阳光三雨露公共季节牌堆；
2. `1/1/2/2/3/3` 花瓣值与 5 花瓣开花；
3. 虫害只阻断当轮，不删除旧成果；
4. 热座顺序录入、联合揭晓和原子结算；
5. 代码原生双盆花园，不需要视觉确认 Gate；
6. A 级双击直开、零第三方运行时与零第三方素材；
7. 生产目录必须带固定来源和零复制借鉴声明。

规格阶段只把这些决定变成精确状态、动作、公开 DTO、随机牌堆和验收合同，不再
重新发明玩法。
